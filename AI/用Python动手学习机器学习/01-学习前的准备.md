# 第1章 学习前的准备

## 本章在整本书中的位置

本章不是安装软件的前言，而是在定义实验规则：机器学习的结论必须能被数据、代码和评估过程共同复现。后面所有直线、分类器、神经网络和聚类算法，都只是这个实验规则下的不同模型。

## 1.1 关于机器学习

### 1.1.1 学习机器学习的窍门

本书最适合采用“先动手、再解释、再抽象”的循环，而不是先背完全部数学。每次实验都做三件事：先画数据和输出，再写模型与损失，最后用一个小扰动观察结论是否改变。

真正的学习成果不是记住 `fit()` 的用法，而是能从数据出发重新回答：任务是什么、假设是什么、损失为什么这样写、参数如何更新、模型会在哪些新数据上失败。

#### 三条线同时走

1. **直觉线**：画数据、画模型、画损失，先看现象。
2. **数学线**：明确每个符号的形状、目标函数和导数方向。
3. **代码线**：用最少的 NumPy 代码复现一小步，再用 Keras 或 scikit-learn 对照。

只走代码线会变成调参；只走数学线会失去反馈；三条线相互校验，才知道理解是否真的落地。

#### 每个算法都做“五问”

1. 输入 $x$ 和目标 $y$ 的形状是什么？
2. 模型能表达哪些关系，不能表达哪些关系？
3. 损失为何适合这个目标？
4. 优化步骤如何改变参数？
5. 训练集之外的失败会长什么样？

### 1.1.2 机器学习中问题的分类

从第一性原理看，机器学习是在有限观测数据上选择一个函数。给定样本

$$
\mathcal D=\{(x_i,y_i)\}_{i=1}^{n},
$$

我们选择带参数的模型 $f_\theta(x)$，让它在训练数据上表现好，同时希望它对没有见过的数据也表现好：

$$
\theta^*=\arg\min_\theta \frac1n\sum_{i=1}^{n}L(f_\theta(x_i),y_i).
$$

这里有三个不能省略的词：

- **函数**：模型把输入映射为输出；它可以是直线、概率函数或神经网络。
- **有限数据**：我们永远只看到了现实的一小部分，不能把训练集记忆当成理解。
- **损失**：必须先定义什么叫错，以及不同错误的代价是否相同。

| 问题 | 已知信息 | 输出 | 本书对应章节 | 典型工业任务 |
|---|---|---|---|---|
| 回归 | 每个输入有连续目标 | 温度、价格、需求量 | [[05-有监督学习-回归]] | 需求预测、能耗估计 |
| 二分类/多分类 | 每个输入有类别标签 | 概率或类别 | [[06-有监督学习-分类]]、[[08-深度学习应用-MNIST]] | 欺诈识别、缺陷判定、OCR |
| 聚类 | 没有人工标签 | 潜在分组或软归属 | [[09-无监督学习]] | 客户分群、设备工况发现 |
| 强化学习 | 通过行动得到奖励 | 策略/行动 | 本书不展开 | 控制、游戏、资源调度 |

一个实用判断法：如果业务方能给出正确答案，先考虑监督学习；如果只能给出相似/不同或异常/正常的弱信号，先考虑聚类、密度估计或异常检测；如果预测会改变环境，必须把反馈回路纳入评估。

### 1.1.3 本书的结构

本书先准备 Python 和 Jupyter，再用 NumPy 表达向量/矩阵，用图形建立直觉，用数学解释导数与概率，随后依次进入回归、分类、神经网络、图像识别和无监督学习。这个顺序是按依赖关系排列的：

```text
Python/NumPy → 图形 → 数学 → 回归 → 分类 → 神经网络 → CNN/MNIST → 无监督学习
```

第 5 章的线性回归是后续训练过程的最小模板；第 6 章把连续输出变成概率；第 7 章把模型写成可组合的函数；第 8 章说明数据结构会反过来决定网络结构；第 9 章则去掉标签，改为推断隐藏分配。

## 1.2 安装 Python

书中代码面向较早版本的 Python/NumPy/Keras；当前 TensorFlow/Keras 的 API 继续演进。稳定的做法是为本书建立独立虚拟环境，并记录版本：

```powershell
python -m venv .venv-ml-book
# Windows PowerShell
.\\.venv-ml-book\\Scripts\\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy matplotlib jupyter tensorflow scikit-learn
python -c "import numpy, matplotlib, tensorflow, sklearn; print(numpy.__version__, matplotlib.__version__, tensorflow.__version__, sklearn.__version__)"
```

安装后先验证 `python --version`、`python -m pip --version` 是否指向同一个环境，再导入 NumPy 创建数组。不要把系统 Python、Anaconda Python 和虚拟环境混在同一个终端里。

## 1.3 Jupyter Notebook

Jupyter 的价值不是能分格运行代码，而是把叙述、公式、代码和图放到同一个可执行实验里。

### 1.3.1 Jupyter Notebook 的用法

一个 notebook 可以理解为带有执行状态的实验记录。建议按“导入与版本 → 数据 → 可视化 → 模型 → 评估 → 结论”的顺序组织单元格。重启内核后从头运行一次，能发现依赖隐藏状态的错误。

### 1.3.2 输入 Markdown 格式文本

Markdown 单元格用来写假设、公式、数据说明和观察结果。公式可用 LaTeX 表达，例如 `$$J(w)=\\frac{1}{n}\\sum_i L_i$$`。代码和解释分开，读者才能区分程序做了什么和作者认为它意味着什么。

### 1.3.3 更改文件名

文件名最好包含主题和版本，例如 `ch05_linear_regression_v1.ipynb`。不要用“最终版”“最终版2”表达版本；把数据、代码和依赖版本写进 notebook 的开头或 Git 提交记录。

每个 notebook 建议保留：

- 环境版本与随机种子；
- 数据来源、形状和单位；
- 训练/验证/测试如何切分；
- 运行结果与失败观察；
- 最后把可复用函数整理成 `.py` 文件。

## 1.4 安装 Keras 和 TensorFlow

当前 TensorFlow 官方安装页建议使用 `pip` 安装，并根据操作系统与 CPU/GPU 情况选择方案；Keras 也可以作为 TensorFlow 中的高层 API 使用。读本书时应把“安装成功”与“书中代码完全不改就能运行”区分开：前者是环境问题，后者还涉及 API 版本。

### 版本漂移：把报错当成接口契约

翔泳社 FAQ 已记录旧版 Anaconda 代码在新版本中会报错，例如旧式 `np.reshape(xx0, xn * xn, 1)` 应改为更清晰的 `xx0.reshape(xn * xn)`，某些旧的转置操作也应删除。当前 Keras 通常建议把输入形状写成 `keras.Input(shape=...)`，而不是把 `input_shape` 直接塞进第一层。

这背后的原则是：**错误信息不是算法失败，而是库的接口契约变了**。处理顺序应是：

1. 看变量的 `shape`、`dtype` 和实际值；
2. 查当前版本的官方文档；
3. 写一个最小例子确认改法；
4. 把最终版本和改动原因记录下来。

### Keras/TensorFlow 的最小验证

```python
import keras
from keras import layers

model = keras.Sequential([
    keras.Input(shape=(4,)),
    layers.Dense(8, activation="relu"),
    layers.Dense(1),
])
model.summary()
```

这段代码只验证框架可导入、输入形状可建立、权重能创建；它还没有证明数据预处理、损失函数和评估协议正确。

## 工业视角：环境是模型的一部分

线上系统不仅保存权重，还要保存预处理、特征顺序、依赖版本和输入输出协议。一个准确率很高但无法在服务端重现的 notebook，不是可交付的模型。至少应记录：

```text
数据版本 -> 特征处理版本 -> 代码提交号 -> 依赖版本 -> 模型权重 -> 评估集与指标
```
