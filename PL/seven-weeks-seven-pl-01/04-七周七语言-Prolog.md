
# 第4章 Prolog：当一门语言决定"不告诉你怎么做，只告诉你是什么"

> 💡 前三章 Ruby → Io，你一直在**"对象 + 消息 + 状态变更"**​ 这条 OOP 主线上游走——Ruby 是丰富的类 OOP，Io 是极简的原型 OOP。第四章 Prolog 是一次**范式大跳跃**：它彻底抛弃了"告诉计算机执行步骤"的命令式思维，转而让你**声明"什么是真的"**，然后让计算机的推理引擎自己去搜索证明。这一跳是为后面 Scala、Erlang、Clojure、Haskell 的函数式范式做心理铺垫——因为声明式思维是函数式编程的共同祖先。

## 4.1 关于 Prolog：逻辑编程的鼻祖

Prolog 由 Alain Colmerauer 和 Robert Kowalski 于 **1972 年**在法国马赛大学提出，是**逻辑编程（Logic Programming）**范式的第一个，也是最成功的实现。它的理论根基是：

- **Horn 子句**：一阶谓词逻辑的一个可判定子集
- **SLD 消解（Selective Linear Definite clause resolution）**：1965 年 Robinson 提出的消解原理的工程化版本
- **Kowalski 的"程序的过程解释"**：1974 年提出，把逻辑公式解释为可执行的过程
    
🌱 **底层洞见**：Prolog 诞生于一个宏大的历史抱负——**日本第五代计算机系统计划（1980 年代）**曾把 Prolog 作为核心语言，希望用它实现人工智能。虽然这个计划最终未达预期，但它留下了一个深刻的问题：

> **"如果计算机能自动推理，程序员还需要写算法吗？"**

Prolog 的回答是：**不需要。你只需描述问题的逻辑结构，推理引擎负责搜索解空间。**

这就是声明式编程（Declarative Programming）最核心的主张——**"指定问题的约束，而非解决问题的算法"**。

## 4.2 第一天：一名优秀的司机——事实、规则与合一

### 4.2.1 基本概况

Prolog 的程序由三部分组成：

1. **事实（Facts）**：无条件为真的 Horn 子句
2. **规则（Rules）**：带条件的 Horn 子句
3. **查询（Queries）**：要证明的目标

```
% 事实
human(socrates).
father(zeb, john_boy_sr).

% 规则
mortal(X) :- human(X).
ancestor(X,Y) :- father(X,Y).
ancestor(X,Y) :- father(X,Z), ancestor(Z,Y).
```

💡 **与 Ruby/Io 的根本差异**：Ruby/Io 中你写的是"动作"（方法执行、状态变更）；Prolog 中你写的是"命题"（X 是人、Y 是 Z 的父亲）。**前者描述"怎么做"，后者描述"是什么"**。

### 4.2.2 基本推论和变量

Prolog 的变量以大写字母开头（`X`、`Who`、`What`），代表"未知值"而非"可变的存储位置"：

```
?- human(Who).
Who = socrates.
```

⚠️ **关键认知**：Prolog 的变量**不是命令式语言中的赋值变量**。它们更像数学中的未知数 x——在合一（unification）过程中被绑定到一个值，且绑定后在该次查询中保持不变（单赋值）。

### 4.2.3 填空

这是 Prolog 最反直觉也最迷人的能力——**同一个规则可以"正向"用，也可以"反向"用**：

```
?- father(zeb, john_boy_sr).      % 正向：zeb 是 john_boy_sr 的父亲吗？ → yes
?- father(zeb, Who).              % 反向：zeb 是谁的父亲？ → Who = john_boy_sr
?- father(Who, john_boy_sr).      % 反向：谁的儿子是 john_boy_sr？ → Who = zeb
```

🎯 **为什么这么设计**：因为 Prolog 用的是**合一（unification）**而不是赋值。合一是对称的——`father(zeb, X)` 和 `father(zeb, john_boy_sr)` 合一时，`X` 被绑定为 `john_boy_sr`。无论变量在哪个位置，合一机制都能"反过来"推导出可能的值。

> 💡 **洞见**：这种"双向性"是逻辑编程独有的超能力。在命令式语言中，`y = f(x)` 只能由 x 算 y；在 Prolog 中，`f(x, y)` 可以由 x 求 y，由 y 求 x，甚至由 x+y 的约束求所有可能的 (x,y) 组合。**规则即关系，关系天然双向**。

### 4.2.4 合一，第一部分 ⭐ 本章最核心的机制

**合一（Unification）**是 Prolog 的匹配引擎，规则如下：

|合一情形|行为|
|---|---|
|常量与常量|完全相同才成功|
|变量与常量|变量绑定到该常量|
|变量与变量|两变量共享绑定|
|结构与结构|函数符同名、参数个数相同，且对应参数逐一合一成功|

```
?- f(X, Y) = f(a, b).     % X=a, Y=b
?- point(X, Y) = point(10, 20).   % X=10, Y=20
?- point(X, Y) = circle(R).       % 失败（函数符不同）
```

💡 **底层洞见**：合一不仅是模式匹配，更是**双向赋值**。它是 Prolog 能在"两个方向上使用规则"的根本原因，也是后面 Scala 的模式匹配、Erlang 的模式匹配的**精神祖先**——这些语言都从 Prolog 这里继承了"用结构匹配来解构数据"的思想。

### 4.2.5 实际应用中的 Prolog

作者在这一节展示了 Prolog 在自然语言处理、专家系统、符号推理等领域的经典应用。Prolog 特别适合：

- **专家系统**：医学诊断、法律推理、配置管理
- **自然语言解析**：DCG（Definite Clause Grammar）
- **约束满足问题**：数独、排课、调度

这些领域的共同点：**问题的逻辑结构清晰，但算法复杂**——正好是 Prolog 的甜区。

巩固事实、规则、查询、合一的基础。

## 4.3 第二天：离瓦普纳法官开演还有15分钟——递归、列表与双向规则

### 4.3.1 递归 ⭐ 声明式语言的"循环"

Prolog 没有 `for`/`while`，**递归是唯一的重复机制**：

```
child(anne, bridget).
child(bridget, caroline).
child(caroline, donna).

descend(X, Y) :- child(X, Y).
descend(X, Y) :- child(X, Z), descend(Z, Y).
```

查询 `descend(anne, Who)` 会系统性地展开：`Who = bridget; Who = caroline; Who = donna`.

⚠️ **陷阱：子句顺序至关重要**。如果写成：

```
descend(X, Y) :- descend(Z, Y), child(X, Z).  % 危险！
```

Prolog 会陷入无限递归——因为它先尝试证明 `descend(Z, Y)`，而这个目标又需要 `descend(...)`，永无止境。

💡 **洞见**：这揭示了声明式编程的一个深层真相——**"声明"并不等于"无序"**。虽然你写的是逻辑命题，但 Prolog 的证明策略（深度优先 + 从左到右）决定了**子句顺序直接影响搜索效率和终止性**。这是声明式理想与过程式现实之间的妥协。

📌 **尾递归优化**：Prolog 通常会对尾递归做优化——当递归调用是规则体中最后一个目标时，复用调用栈帧，避免栈溢出。这是声明式语言处理"循环"的标准技术，后面 Erlang、Scala、Haskell 都会沿用。

### 4.3.2 列表和元组

Prolog 有两种复合结构：

- **列表 `[1,2,3]`**：变长，可用 `[Head|Tail]` 解构
- **元组 `(1,2,3)`**：定长，可用 `(A,B,C)` 解构

```
?- [Head|Tail] = [1,2,3].    % Head=1, Tail=[2,3]
?- (A,B,C) = (1,2,3).        % A=1, B=2, C=3
```

🎯 **`[Head|Tail]` 是 Prolog 列表处理的灵魂**。它让你用结构匹配递归地遍历列表——这一模式会被 Erlang 完整继承（`[H|T]`），也会在 Scala 的模式匹配中以 `@tail` 等形式出现。

### 4.3.3 列表与数学运算

Prolog 的数学是特殊的——`=` 是合一而非赋值，`is` 才是算术求值：

```
?- X = 1+2.      % X = 1+2（结构是 1+2，未求值）
?- X is 1+2.     % X = 3（is 强制求值）
?- 2+3 = 5.      % no（结构不同）
?- 2+3 is 5.     % yes
```

`count` 和 `sum` 的实现展示了声明式递归的典型形态：

```
count(0, []).
count(Count, [Head|Tail]) :- 
    count(TailCount, Tail), 
    Count is TailCount + 1.
```

💡 **洞见**：注意 `Count is TailCount + 1` 出现在递归调用**之后**——这就是尾递归的逆序累积。声明式语言的"循环"总是以这种"递归 + 模式匹配 + 反向计算"的形态出现。

### 4.3.4 在两个方向上使用规则 ⭐ 本章最优雅的演示

`append(List1, List2, List3)` 表示"List3 是 List1 和 List2 的连接"：

```
append([], L, L).
append([H|T], L, [H|R]) :- append(T, L, R).
```

这个规则可以**四向使用**：

```
?- append([1,2], [3,4], Z).     % 正向：Z = [1,2,3,4]
?- append(X, [3,4], [1,2,3,4]). % 反向求前缀：X = [1,2]
?- append([1,2], Y, [1,2,3,4]). % 反向求后缀：Y = [3,4]
?- append(A, B, [1,2,3,4]).     % 双向：所有拆分方案
```

最后一个查询会系统地生成所有可能的 `(A, B)` 组合——这正是数独、八皇后等问题求解的基础机制。

🎯 **为什么这件事如此重要**：`append` 展示了逻辑编程的最高境界——**一段代码，四种用法**。命令式语言需要为"连接"、"拆分前缀"、"拆分子串"、"枚举所有拆分"写四个不同的函数；Prolog 一个规则搞定全部。这是因为合意的对称性让"输入"和"输出"的界限消失了——**只有约束，没有方向**。

## 4.4 第三天：维加斯的爆发——搜索即计算

### 4.4.1 解决数独问题 ⭐ 声明式威力的高潮

数独在 Prolog 中的解法震撼之处在于——**你几乎是在"直接描述数独规则"**：

```
% 每个格子的值是 1-9
digit(1). digit(2). ... digit(9).

% 所有 digit 互不相同
all_diff([]).
all_diff([H|T]) :- not member(H, T), all_diff(T).

% 每行、每列、每个 3x3 宫格 all_diff
valid([]).
valid([H|T]) :- all_diff(H), valid(T).
% ... 列和宫格的约束 ...

% 求解：填充空格，满足所有约束
solve(Puzzle) :- ...
```

Prolog 的推理引擎会自动：

1. 用 `digit(1..9)` 为每个空格生成候选值
2. 用 `all_diff` 等约束剪枝
3. 通过回溯系统地搜索解空间
4. 找到第一个满足所有约束的解
    
🎯 **洞见**：数独的 Prolog 解法几乎是"问题陈述的代码直译"。你不需要设计算法——不需要考虑"先填哪个格子"、"用什么启发式"。你只声明：

- 格子取值是 1-9
- 同行/同列/同宫的数字互不相同
- 给定数字不能改
    
**剩下的搜索工作全部由 Prolog 的回溯引擎自动完成**。

> 💡 这就是声明式编程的承诺：**"你描述问题，机器找答案"**。代价是——你可能失去对"搜索效率"的控制。这是 Prolog 的甜区和陷阱并存之处。

### 4.4.2 八皇后问题

eight queens 是另一个经典搜索问题：在 8×8 棋盘上放置 8 个皇后，互不攻击。

Prolog 的解法依然是"声明约束"：

```
% 用列表表示每行皇后的列位置
% [4,2,7,3,6,8,5,1] 表示第1行第4列、第2行第2列...

valid_queens([]).
valid_queens([H|T]) :- 
    not_attack(H, T, 1), 
    valid_queens(T).

not_attack(_, [], _).
not_attack(Y, [Y1|Ylist], Dist) :-
    Y =\= Y1,
    abs(Y - Y1) =\= Dist,
    Dist1 is Dist + 1,
    not_attack(Y, Ylist, Dist1).
```

Prolog 会系统性地枚举所有可能的列组合，用 `not_attack` 剪掉冲突的，最终找到所有 92 个解。

💡 **洞见**：八皇后展示了 Prolog 处理**组合爆炸**问题的优雅性。如果用命令式语言写，你需要手动管理栈、显式回溯、小心处理状态；Prolog 中这些全部由推理引擎隐式处理。**但这也暴露了 Prolog 的根本局限——搜索策略不可控**。你只能通过子句顺序和 cut 操作符（`!`）粗略引导搜索，无法做精细的算法优化。

### 4.4.3–4.4.4 第三天自习与趁热打铁

作者总结了 Prolog 的核心优势与不足：

**核心优势**：

1. **表达力极高**：复杂逻辑关系用少量规则表达
2. **双向性**：规则天然可逆，一份代码多种用途
3. **自动搜索与回溯**：无需手动实现 DFS/回溯
4. **适合符号推理**：专家系统、NLP、编译器
    
**不足之处**​ ⭐ 全局观的关键：

1. **性能不可控**：回溯搜索可能导致指数级时间复杂度
2. **封闭世界假设（Closed World Assumption）**：无法证明为真的即为假——这在开放世界中会导致反直觉结果
3. **算法控制力弱**：你不能直接控制搜索策略
4. **数值计算笨拙**：`is` 操作符、cut 操作符让纯逻辑染上过程式色彩
5. **主流采用有限**：除了特定领域（NLP、专家系统），鲜少用于通用软件开发

## 🧭 Prolog 章与全书脉络的连结

```
命令式/OOP ←——————————————→ 声明式
Ruby, Io                 Prolog
（怎么做）                （是什么）
   │                         │
   │                         │
   ├──→ Scala ──┐            ├──→ 函数式范式的前奏
   │    (OOP+FP) │            │    （Haskell, Clojure, Erlang）
   │            ▼            │
   └──────────► Erlang        │
                (模式匹配、
                 递归、不可变)
```

**Prolog 在全书中的四个"桥梁"作用**：

1. **命令式 → 声明式的范式跃迁**：前三章你学的都是"对象接收消息、改变状态"；Prolog 让你第一次体验"描述逻辑、让机器推理"。这种思维转换是后面函数式语言（Haskell、Clojure、Erlang）的心理准备——**函数式编程本质上是"受约束的声明式编程"**。
    
2. **模式匹配的祖先**：Prolog 的合一机制 `[Head|Tail] = List` 是后面所有函数式语言模式匹配的鼻祖：
    
    - **Scala**：`case Head :: Tail => ...`
    - **Erlang**：`[H|T] -> ...`
    - **Haskell**：`x:xs -> ...`
    - **Clojure**：`(when (seq? coll) (let [[h & t] coll] ...))`
        
    学完 Prolog，你会发现**函数式语言的模式匹配不过是合一的特例**。
    
3. **递归即循环**：Prolog 让你彻底摆脱 `for`/`while`，只用递归表达重复。这一思想被 Haskell、Erlang、Scala 完整继承——**在函数式语言中，递归（尤其是尾递归）是唯一的循环**。
    
4. **不可变性的伏笔**：Prolog 的变量是单赋值的——一旦绑定就不再改变。这与后面 Clojure 的"不可变数据结构"、Haskell 的"纯函数"、Erlang 的"进程状态隔离"在哲学上一脉相承。**逻辑编程的单赋值变量，是函数式不可变性的逻辑源头**。
    

> ⚠️ **重要对比**：Prolog 证明了声明式的威力，但也暴露了其代价——**搜索不可控、性能难优化**。后面四门函数式语言（Scala、Erlang、Clojure、Haskell）都在做同一件事：**保留声明式的表达力，但通过类型系统、不可变性、Actor 模型等手段，把"失控的搜索"变回"可控的计算"**。

## 📝 本章核心 takeaway（可直接记入笔记）

1. **Prolog 不是"另一门语言"，而是"另一种计算模型"**——基于 Horn 子句的逻辑编程，用 SLD 消解做自动推理
2. **合意是 Prolog 的灵魂**：对称的、双向的、既是模式匹配又是赋值
3. **声明式 = "描述约束而非算法"**：数独、八皇后的解法几乎是问题的直译
4. **递归是唯一的循环**：`[Head|Tail]` 解构 + 递归 = 列表处理的标准范式
5. **封闭世界假设是双刃剑**：简化了推理，但限制了表达力
6. **Prolog 的不足是后面四门函数式语言的设计动机**：如何在保留声明式表达力的同时，恢复对计算的控制？
7. **模式匹配、递归、单赋值——这三个概念从 Prolog 流向了几乎所有现代函数式语言**
