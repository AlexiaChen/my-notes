
# 第6章 模块（Modules）——读书笔记

> 💡 前5章你一直在 GHCi 里玩：函数、类型、递归、高阶函数。第6章第一次把你拉到"文件级"——**一个 Haskell 程序如何由多个 `.hs` 文件组成？类型、类型类、函数怎样被打包成可复用的单元？**​ 表面上看，模块不过是"命名空间管理"；但深层里，模块是 Haskell 实现**抽象数据类型（ADT）**和**​ invariants（不变式）保护**的唯一机制。这一章是你从第5章"用标准库的高阶函数"走向第7章"自己定义类型与类型类"的桥梁——因为**自定义类型一旦定义，立刻就要面对"导出哪些构造器、暴露哪些函数"的 API 设计问题**。

## 🎯 全局脉络：模块在解决什么"真问题"

前5章所有代码都在一个文件（甚至 GHCi 单行）里。但真实软件有两个无法回避的问题：

**问题一：名字冲突。**

`Prelude` 里有 `filter`，`Data.List` 里也有 `filter`，`Data.Map` 里还有个 `filter`。当你的项目导入多个模块，谁来保证 `filter` 指向哪里？

**问题二：封装与不变式保护。**

第7章你会学到自定义代数数据类型。但"定义类型"只是开始——**谁有权构造这个值？谁能看到内部表示？**​ 如果不能控制这些，类型的"不变式"（invariant）就会被外部代码破坏。例如有理数 `Rat 2 4` 应该是"约分后的 `1/2`"，但如果外部能直接调用 `Rat` 构造器，不变式立刻崩塌。

模块机制的双重使命由此而来：

|使命|机制|受益方|
|---|---|---|
|命名空间隔离|`import qualified`|调用方|
|API 边界控制|显式 export list|实现方|

> 📌 **洞见**：模块的真正威力不在"导入"，而在"导出控制"。一个模块可以通过 export list 精确决定——**暴露哪些函数、暴露类型但不暴露构造器、还是连类型本身都隐藏**。这是 Haskell 实现"抽象数据类型"的标准手法，也是大型 Haskell 项目能保持可维护性的根基。

## 🔍 逐节洞见

### 6.1 载入模块 —— 四种导入姿势与限定导入的最佳实践

LYAH 详细介绍了 `import` 的几种形式：

**① 默认导入**

```
import Data.List
```

把所有导出名灌进当前命名空间。`Data.List` 的 `filter` 会遮蔽 `Prelude` 的 `filter`——**非常容易造成命名冲突**，通常不推荐。

**② 限定导入（Qualified Import）—— 现代 Haskell 的最佳实践**

```
import qualified Data.Map as M
```

导入模块，但**不将其函数放入全局命名空间**。调用时必须加前缀：`M.insert`、`M.lookup`。

> 💡 **为什么 `qualified` 是工程标配？**​ 因为 `Data.Map`、`Data.Set`、`Data.Text` 这些容器库都定义了名字很通用的函数（`map`、`filter`、`fromList`、`insert`、`lookup`）。如果不限定导入，名字冲突是必然的。现代 Haskell 代码库的标准写法是：
> 
> ```
> import qualified Data.Map as M
> import qualified Data.Set as S
> import qualified Data.Text as T
> ```
> 
> 这与 Python 的 `import numpy as np` 完全等价。

**③ 选择性导入**

```
import Data.List (sort, nub)
import Data.List hiding (sort)
```

只导入需要的名字，或隐藏冲突的名字。这种写法在小型脚本里常见，但在大型项目里不如 `qualified` 安全。

**④ GHCi 里载入模块**

```
:m + Data.List
```

或在启动 GHCi 时 `ghci -package-conf=...`。

> ⚠️ **工程箴言**：默认导入（`import Data.List`）看似方便，实则是技术债。当项目增长到几十个模块时，名字冲突会让你痛不欲生。**永远优先用 `qualified`**——这是 Haskell 社区几十年踩坑后的共识。

### 6.2 用模块里的函数解决问题 —— 标准库模块的实战巡览

这一节是"标准库模块的实战巡览"，作者带你用 `Data.List`、`Data.Char` 等模块解决具体问题。**这些函数的底层实现，其实就是第4章你手写的递归 + 第5章的高阶函数**。作者在这里展示的是：**标准库不是魔法，而是把你前5章学的技能"产品化"**。

**核心标准库模块速查**：

|模块|关键函数|用途|
|---|---|---|
|`Data.List`|`sort`、`nub`、`group`、`sortOn`、`foldl'`、`scanl`、`scanr`|列表操作全集|
|`Data.Char`|`isDigit`、`isAlpha`、`isUpper`、`toUpper`、`digitToInt`|字符分类与转换|
|`Data.Map`|`fromList`、`insert`、`lookup`、`member`、`keys`、`elems`|关联映射（下一节详述）|
|`Data.Set`|`fromList`、`insert`、`member`、`union`、`intersection`|有序集合|

**几个值得品味的细节**：

**① `foldl'` 与严格性**

第5章讲过 `foldl` 在惰性求值下会堆积 thunk，导致空间泄漏。标准库提供**严格左折叠**​ `foldl'`（注意撇号）：

```
import Data.List (foldl')

sum' :: (Num a) => [a] -> a
sum' = foldl' (+) 0
```

`foldl'` 在每一步都强制求值累加器，避免 thunk 堆积。**这是 Haskell 性能调优的基本功**。

**② `Data.Char` 与凯撒密码**

凯撒密码的本质是 `chr (ord c + shift)`。作者用 `Data.Char` 的 `ord`/`chr` 配上第5章的 `map`，几行代码实现加密解密。这展示了**模块 + 高阶函数的组合威力**：标准库提供原子操作，高阶函数提供组合框架，你只需填"业务逻辑"。

**③ `nub` 与去重**

```
import Data.List (nub)
nub [1,2,2,3,3,3]  -- [1,2,3]
```

`nub` 是 O(n²) 的（基于列表的 `elem`）。**工程提醒**：生产代码处理大数据集时应改用 `Data.Set` 的 `toList . fromList`，复杂度 O(n log n)。

> 📌 **洞见**：这一节的真正教学意图是——**标准库模块是你前5章所学的最终形态**。你手写过 `foldr`，标准库就有 `foldr`；你手写过 `map`，标准库就有 `map`；你手写过 `elem'`，标准库就有 `elem`。**模块的 existence 本身就是"模式被抽象、被复用"的证据**。当你在第11章遇到 `Functor`、`Foldable` 这些类型类时，会发现标准库模块的海量函数，本质上都是这几个类型类方法的特例。

### 6.3 映射键与值 —— 从关联列表到 `Data.Map`

这一节讲"键值映射"的两种实现：

**① 关联列表（Association List）**

```
phoneBook :: [(String, String)]
phoneBook = [("Alice", "123"), ("Bob", "456")]
```

查找用 `lookup`：

```
lookup "Alice" phoneBook  -- Just "123"
```

关联列表是 O(n) 查找。**适合小数据量和教学演示**。

**② `Data.Map` —— 生产级键值映射**

```
import qualified Data.Map as M

-- 从关联列表构建
phoneMap :: M.Map String String
phoneMap = M.fromList phoneBook

-- 插入、查找、删除
M.insert "Carol" "789" phoneMap
M.lookup "Alice" phoneMap  -- Just "123"
M.delete "Bob" phoneMap
```

`Data.Map` 底层是**大小平衡的二叉搜索树**（具体是 Adams' balanced BST），查找/插入/删除均为 O(log n)。

> 💡 **为什么 `Data.Map` 必须用 `qualified` 导入？**​ 因为它定义了 `map`、`filter`、`null`、`size` 等与 `Prelude` 冲突的名字。用 `M.map`、`M.filter` 调用是 Haskell 社区的铁律。

**`Data.Map` 的 API 设计启示**：

观察 `Data.Map` 的函数签名，你会发现一个规律——**几乎所有函数都带 `Ord k` 约束**：

```
insert :: Ord k => k -> a -> Map k a -> Map k a
lookup :: Ord k => k -> Map k a -> Maybe a
```

这是因为 `Map` 内部是 BST，键必须可排序。**类型类约束不是装饰，是数据结构物理属性的类型级表达**——这呼应了第2章的核心思想："类型即语义"。

> 📌 **洞见**：`Data.Map` 是"抽象数据类型"的范例——用户看到的是 `Map k a` 类型，但**构造器不对用户开放**。用户只能通过 `fromList`、`insert`、`empty` 等"智能构造器"创建 Map，从而保证内部 BST 的平衡不变式不被破坏。这正是下一节"制造我们自己的模块"要教你的核心技能。

### 6.4 制造我们自己的模块 —— 模块是 ADT 的载体

这一节是全章的高潮。作者教你如何写一个 `.hs` 文件，用 `module` 关键字声明模块名，并通过 export list 控制对外接口。

**基本语法**：

```
module MyUtils where

add :: Int -> Int -> Int
add x y = x + y
```

没有 export list，默认导出所有顶层定义。

**显式导出控制**：

```
module MyUtils (add, Double) where

type Double = Double

add :: Int -> Int -> Int
add x y = x + y

internalHelper :: Int -> Int
internalHelper = (+1)  -- 不导出，仅模块内部使用
```

**精确控制数据类型与构造器的导出**：

```
module Tree (Tree(Leaf, Branch)) where

data Tree a = Leaf a | Branch (Tree a) (Tree a)
```

这表示：导出 `Tree` 类型及其两个构造器 `Leaf`、`Branch`，但**不导出其他内部函数**。

更复杂的控制：

```
module Tree (Tree(..)) where          -- 导出类型和所有构造器
module Tree (Tree()) where            -- 只导出类型，不导出任何构造器（完全抽象）
module Tree (Tree(Leaf, Branch)) where -- 导出类型 + 指定构造器
```

> 💡 **`Tree()` 模式是 Haskell 实现"抽象数据类型"的关键**：用户知道 `Tree a` 这个类型存在，但**无法自己构造 Tree**——必须通过你提供的智能构造器。这让你能在构造时强制不变式。

**智能构造器（Smart Constructor）模式**：

```
module Rational (Rational, makeRational, numerator, denominator) where

data Rational = Rat Integer Integer

-- 智能构造器：自动约分
makeRational :: Integer -> Integer -> Rational
makeRational n d = let g = gcd n d in Rat (n `div` g) (d `div` g)

numerator :: Rational -> Integer
numerator (Rat n _) = n

denominator :: Rational -> Integer
denominator (Rat _ d) = d
```

外部用户**无法**直接写 `Rat 2 4`（因为 `Rat` 构造器未导出），只能通过 `makeRational 2 4` 得到约分后的 `1/2`。**不变式被模块边界保护了**。

> 📌 **洞见**：智能构造器模式是 Haskell 工程的核心 idiom。它让"数据有效性检查"成为**创建数据的唯一入口**，从而在类型系统的辅助下，把非法状态变为不可表示（impossible to represent）。这是"让非法状态无法被类型化"这一函数式设计原则的标准实现。

**模块名与文件路径的对应关系**：

```
module Utils.Baz where  -- 文件必须位于 Utils/Baz.hs
```

模块名的层级结构对应目录结构。这是 Haskell 项目组织的基本约定。

```

**一条主线串起来看**：

1. **第2-5章**：你学会了类型、递归、高阶函数——这些是"模块内部的构件"
    
2. **第6章（本节）**：你学会把这些构件**打包成模块**，通过 export list 控制对外接口，通过智能构造器保护不变式
    
3. **第7章**：你定义自己的代数数据类型。此时模块导出控制立刻变得至关重要——**导出哪些构造器，决定了用户是"使用 ADT"还是"窥探实现细节"**
    
4. **第8章**：你为自定义类型编写 `Show`、`Eq`、`Ord` 等类型类实例。这些实例声明**必须位于模块内**，成为模块 API 的一部分
    
5. **第11-13章**：`Functor`、`Monad` 等高级抽象，每个都有对应的类型类实例，分布在不同的标准库模块里。**理解模块的导入导出机制，是理解"为什么 `fmap` 在 `Data.Functor`、为什么 `>>=` 在 `Prelude`"的前提**
    

> 💡 **如果你只记住一件事**：**模块是 Haskell 实现"抽象数据类型"的唯一机制**。没有模块的 export 控制，`data` 定义的私有性就无从谈起；没有智能构造器模式，不变式就无法在类型层面被强制。第7章你以为在学"如何定义自己的类型"，其实你在学"如何用模块把这些类型封装成工业级的 API"——而第6章就是这堂课的预习。

## 🛠 实际工程启示

**1. 永远优先 `qualified` 导入**

```
-- 反模式
import Data.Map
import Data.Set

-- 推荐
import qualified Data.Map as M
import qualified Data.Set as S
```

这是 Haskell 大型项目的铁律。名字冲突的代价远超多敲几个字符。

**2. 显式导出列表是专业素养**

```
-- 反模式：默认导出所有
module MyModule where

-- 推荐：精确控制
module MyModule (publicFunc1, publicFunc2, MyType(..)) where
```

显式导出让重构更安全——你可以放心删除/重命名未导出的内部函数，而不必担心影响外部用户。

**3. 用智能构造器保护不变式**

```
module Money (Money, makeMoney, amount) where

data Money = Money { amount :: Integer }

makeMoney :: Integer -> Maybe Money
makeMoney n
  | n >= 0    = Just (Money n)
  | otherwise = Nothing
```

让"创建 Money"必须通过 `makeMoney`，从而在类型层面排除负数金额。**这是 Haskell "make illegal states unrepresentable" 理念的核心实践**。

**4. 模块组织遵循单一职责**

现代 Haskell 项目常采用如下模块结构：

```
MyApp.Types      -- 共享数据类型
MyApp.Db        -- 数据库逻辑
MyApp.Api       -- HTTP 接口
MyApp.Config    -- 配置
```

每个模块职责清晰，通过 qualified 导入互相协作。

**5. `Data.Map` 的性能特征要记牢**

- 查找/插入/删除：O(log n)
    
- 前5章手写的关联列表查找：O(n)
    
- 大数据集下，务必用 `Data.Map` 或 `Data.HashMap`（后者是哈希实现，平均 O(1)）
    

**6. 循环依赖是模块系统的天敌**

Haskell 不允许模块 A 导入 B 且 B 导入 A。设计时遵循"依赖单向流动"原则：底层模块（Types）→ 中层模块（Logic）→ 顶层模块（Main）。

**7. 标准库模块的"高阶函数化"启示**

当你浏览 `Data.List` 的几十个函数时，会发现它们几乎都能用 `map`/`filter`/`fold` 组合而成。**这验证了第5章的核心论点**：高阶函数是"模式抽象"的终极武器。模块只是把这些抽象好的模式"打包分发"给全世界的 Haskell 程序员。

**8. 隐藏 Prelude 的高级玩法**

在极少数场景下（如领域特定语言），你可能需要隐藏 Prelude 的某些函数：

```
module MyDSL (module Prelude, module MyDSL) where
import Prelude hiding (return, (>>=))
import qualified MyDSL
```

这种手法在构建嵌入式 DSL（EDSL）时常见，是模块系统灵活性的极致体现。

## 一句话收束

> 第6章不是在教你"如何 import"，而是在揭示 Haskell 工程化的核心秘密：**模块是抽象数据类型的载体，export list 是 API 契约的声明，智能构造器是不变式的守护者**。前5章你学的类型、递归、高阶函数，都是"模块内部的构件"；而模块本身，是把这些构件**封装成工业级可复用单元**的机制。当你在第7章定义自己的 `Tree`、`Maybe`、`Either` 时，会立刻用到本章的智能构造器模式——通过隐藏构造器、暴露智能构造器，让"非法状态无法被表示"成为类型系统的自然推论。而当你在第11-13章面对 `Functor`、`Monad` 等高级抽象时，会发现它们不过是分布在各个模块里的类型类实例——**理解模块的导入导出，是理解整个 Haskell 标准库组织架构的前提**。模块系统看似平淡，却是 Haskell "小内核、大库"哲学的物理承载：语言本身只提供最小原语，所有丰富性都通过模块系统组织起来，分发给每一个 Haskell 程序员。
