
# 第5章 高阶函数（Higher Order Functions）——读书笔记

> 💡 第4章让你相信"递归是函数式编程的循环"。第5章做了一件更厉害的事：**把递归本身的"模板"抽象出来了**。你以为在学 `map`/`filter`/`fold`，其实你在学一个更深刻的真相——**常见计算模式可以被封装成"函数的函数"**，从此你不再写递归，你**组合**递归。这一章是 Haskell 从"能写"跨越到"写得好"的分水岭，也是通往第11章 Functor、第12章 Monad 的真正起点。

## 🎯 全局脉络：这一章在打破什么、建立什么

前三章你学到的所有列表处理函数——`maximum'`、`reverse'`、`elem'`、`zip'`——都有一个**隐藏的共同骨架**：

```
处理列表 xs：
  若 xs 为空 → 返回基准值
  若 xs 为 (x:xs') → 用 x 和 (处理 xs') 的结果做点什么
```

第4章你为**每一个具体函数**手写一遍这个骨架。第5章问了一个致命的问题：

> **"既然骨架都一样，能不能把这个骨架本身写成一个函数，把'做点什么'作为参数传进去？"**

答案是能。而这个"函数的函数"，就叫**高阶函数**（Higher-Order Function）。

> 📌 **洞见**：高阶函数之所以可能，前提是**函数是一等公民**（第1章铺垫过）——函数可以像 `Int`、`String` 一样被存入变量、作为参数传递、作为返回值。Haskell 里"高阶函数"的定义是：**至少满足以下一条的函数——接受函数作为参数，或返回函数作为结果**。

这一章建立的**三条支柱**：

**支柱一：柯里化**​ —— 多参函数的本质是一串单参函数

**支柱二：map / filter**​ —— 把"遍历列表"这个模式参数化

**支柱三：fold**​ —— 把"递归模板"本身参数化，是这一章的皇冠

## 🔍 逐节洞见

### 5.1 Curried Functions —— "多参函数"是个善意的谎言

Haskell 官方定义：**每个函数只接受一个参数**。那为什么 `max 4 5` 看起来像两个参数？秘密是——`max 4` 先返回一个函数，这个函数再接受 `5`。

看 `max` 的类型签名：

```
max :: (Ord a) => a -> a -> a
```

因为 `->` 是**右结合**的，它等价于：

```
max :: (Ord a) => a -> (a -> a)
```

读作："`max` 接受一个 `a`，返回一个类型为 `a -> a` 的函数"。

验证：

```
ghci> max 4 5
5
ghci> (max 4) 5
5
```

两行完全等价。`max 4` 本身是一个合法的函数——它"记住"了第一个参数是 4，等待第二个参数进来比较。

**部分应用（Partial Application）**：

```
multThree :: (Num a) => a -> a -> a -> a
multThree x y z = x * y * z

ghci> let multTwoWithNine = multThree 9
ghci> multTwoWithNine 2 3
54
```

`multThree 9` 的类型是 `Num a => a -> a -> a`——一个等待剩下两个参数的函数。

> 💡 **为什么柯里化是革命性的？**

因为它让"**创建专用函数**"变得免费。看这段真实场景：

```
-- 非柯里化思路：不得不写匿名函数
filter (\x -> isPrefix "ftp://" x) urls

-- 柯里化思路：部分应用直接生成新函数
filter (isPrefix "ftp://") urls
```

`isPrefix "ftp://"` 本身就是一个完整的、"专用于检测 ftp 前缀"的函数——**你没写匿名函数，但得到了一个匿名函数的效果**。这种"零成本专业化"是高阶函数大放异彩的前提。

> 📌 **洞见**：柯里化不是语法糖，它是**函数式编程的"组合力学"基础**。没有柯里化，`map (+1)` 这种写法就不可能——`(+1)` 正是 `(+)` 的部分应用。`(+)` 的类型是 `Num a => a -> a -> a`，部分应用后得到 `Num a => a -> a`，正好匹配 `map` 的第一个参数类型 `(a -> b)`。

**中缀运算符的部分应用**：

```
ghci> (^2) 5
25
ghci> (2^) 5
32
```

`(^2)` 是"平方函数"，`(2^)` 是"2 的 N 次方函数"。这种写法叫 **section**。

### 5.2 高阶函数 —— 把递归模板抽象掉

这是全章的心脏。让我们用 Haskell 教材里的经典例子看 `map` 是怎么被"提炼"出来的。

**第一步：观察两个看似无关的函数**

```
squareAll :: [Int] -> [Int]
squareAll [] = []
squareAll (x:xs) = (x * x) : squareAll xs

lengthAll :: [[a]] -> [Int]
lengthAll [] = []
lengthAll (xs:xss) = (length xs) : lengthAll xss
```

它们**处理的数据不同**（整数列表 vs 列表的列表），**做的操作不同**（平方 vs 求长度），但**递归骨架完全相同**。

**第二步：抽象出共同点**

两者的共同模式是："遍历列表，对每个元素应用某个函数 `f`，收集结果"。把 `f` 变成参数：

```
map' :: (a -> b) -> [a] -> [b]
map' f [] = []
map' f (x:xs) = f x : map' f xs
```

**第三步：原来 `squareAll` 和 `lengthAll` 就是 `map` 的特例**

```
squareAll = map' (^2)
lengthAll = map' length
```

> 📌 **洞见**：`map` 不是"对列表的每个元素做变换"——`map` 是**"遍历列表"这个递归模式的参数化版本**。它把"做什么变换"抽出来作为参数，把"怎么遍历"封装在自己的递归定义里。

同理，`filter` 是"按条件筛选"模式的抽象：

```
filter :: (a -> Bool) -> [a] -> [a]
filter p [] = []
filter p (x:xs)
  | p x       = x : filter p xs
  | otherwise = filter p xs
```

教材里精辟地总结：**高阶函数让我们能把常见的编程模式封装成函数，从而快速构建简洁而强大的程序。这能提高生产效率与可靠性，因为程序更短、更易理解、由经过良好测试的组件构成**。

**为什么高阶函数如此重要？**

1. **捕获模式，一次抽象，处处复用**：你注意到自己在反复写"对每个元素做 X"这种形状的代码，就把它变成 `map`，把变化的部分（函数）传进去
    
2. **构建领域特定语言（DSL）**：Haskell 的许多库本质上是高阶函数的集合，组合起来就像针对某个领域的迷你语言（解析器、GUI、打印机等）
    
3. **启用代数推理与编译器优化**：像 `foldr` 这样的高阶函数有"定律"（如融合法则），可以用来推理和优化程序

### 5.3 Lambdas —— 用完即弃的匿名函数

有些函数你只用一次，不值得起名。Haskell 的 lambda 以 `` 开头：

```
ghci> map (\x -> x + 3) [1,2,3]
[4,5,6]
```

Lambda 同样支持模式匹配，但对单个参数只能用一次模式匹配，匹配失败会报错。

> 💡 **何时用 lambda？**​ 当你需要"临时拼一个函数"传给 `map`/`filter`/`fold` 时。但要注意——**很多时候部分应用比 lambda 更优雅**：

```
-- 不够优雅
map (\x -> x + 3) [1,2,3]

-- 更优雅：利用部分应用
map (+3) [1,2,3]
```

> ⚠️ **工程箴言**：能用部分应用就不用 lambda，能用 `where`/`let` 里命名函数就不用匿名 lambda。lambda 是工具，不是默认选择。过度使用 lambda 会让代码难以阅读——这正是第3章 `where` 存在的意义。

### 5.4 Fold —— 全章皇冠，"递归模板"本身被参数化

如果说 `map` 抽象了"遍历并变换"，`filter` 抽象了"遍历并筛选"，那 `fold` 抽象的是**更底层的东西——递归本身**。

**右折叠 `foldr`**：

```
foldr :: (a -> b -> b) -> b -> [a] -> b
foldr f v [] = v
foldr f v (x:xs) = f x (foldr f v xs)
```

**最直观的心智模型**：**`foldr f v` 把列表里的 `:` 替换成 `f`，把 `[]` 替换成 `v`**。

验证：

```
[1,2,3]  ≡  1 : (2 : (3 : []))

foldr (+) 0 [1,2,3]
  ≡  1 + (2 + (3 + 0))
  ≡  6
```

**震撼的事实**：大量"看起来不像递归"的函数，都能用 `foldr` 一行写出：

```
sum     = foldr (+) 0
product = foldr (*) 1
and     = foldr (&&) True
or      = foldr (||) False
length  = foldr (\_ acc -> 1 + acc) 0
reverse = foldr (\x acc -> acc ++ [x]) []
(++ ys) = foldr (:) ys
map f   = foldr (\x acc -> f x : acc) []
filter p = foldr (\x acc -> if p x then x:acc else acc) []
```

> 📌 **洞见**：`foldr` 揭示了一个深层真相——**列表的本质就是 `:` 和 `[]` 的组合**。任何对列表的递归处理，归根结底都是在决定"怎么处理 `:`"和"怎么处理 `[]`"。`foldr` 把这两个决定权交给你，于是它成了"递归的递归"。

**左折叠 `foldl`**：

```
foldl :: (b -> a -> b) -> b -> [a] -> b
foldl f v [] = v
foldl f v (x:xs) = foldl f (f v x) xs
```

`foldl` 从左向右累积，尾递归友好但**在惰性求值下有缺陷**——它会产生巨大的 thunk（未求值表达式）。生产代码应该用严格的 `foldl'`（来自 `Data.List`）。

**`foldr` vs `foldl` 的本质区别**：

|维度|`foldr`|`foldl`|
|---|---|---|
|结合方向|右结合：`1 + (2 + (3 + 0))`|左结合：`((0 + 1) + 2) + 3`|
|处理顺序|从最后一个元素开始|从第一个元素开始|
|惰性友好|✅ 支持无穷列表|❌ 必须遍历完|
|典型用途|构造新列表、惰性计算|累加求和（用 `foldl'`）|

> ⚠️ **为什么 `foldr` 能处理无穷列表？**​ 因为 `foldr` 是惰性的——它先生成外层结构，只有当消费者需要时才会向内求值。这是第1章 `[1..]` 无穷列表能被 `take 10` 消费的真正机制：`take 10 (foldr ...) [1..]` 只求值它需要的那部分。

**Cornell 教材的总结**：**对于许多数据结构，只需提供 fold，就能推导出 `map`、`filter`、`app` 等几乎所有高阶函数**。换句话说，fold 是列表操作的"母函数"——这一点直接预示了第11章 `Foldable` 类型类的设计哲学。

### 5.5 函数组合 —— `(.)` 与 point-free 风格

函数组合的数学定义：`(f ∘ g)(x) = f(g(x))`。

Haskell 里：

```
(.) :: (b -> c) -> (a -> b) -> a -> c
f . g = \x -> f (g x)
```

**组合的魅力：point-free 风格（无点风格）**

```
-- 有点风格（pointful）
sumOdds xs = sum (filter odd (filter (>0) xs))

-- 无点风格（point-free）
sumOdds = sum . filter odd . filter (>0)
```

右侧完全不出现 `xs`——因为函数组合让"函数的函数"自然涌现。

> 💡 **Point-free 不是炫技，是"意图的提纯"**。当你写 `sumOdds = sum . filter odd . filter (>0)`，你在说："`sumOdds` 就是先做 `>0` 过滤，再做 `odd` 过滤，最后求和"——**这是一个管道声明，而不是一个计算过程**。这种"声明管道而非指令步骤"的思维，正是函数式编程的精髓。

> 📌 **洞见**：`(.)` 的类型 `(b -> c) -> (a -> b) -> a -> c` 在柯里化视角下读作："接受一个 `b -> c` 和一个 `a -> b`，返回一个 `a -> c`"。**函数组合本身是高阶函数**——它接受函数，返回函数。这是第12章 Monad 组合子 `(<=<)` 和第11章 `Category` 类型类的雏形。

## 🧬 跨章节连接：高阶函数是怎么"长"出整本书的

```
第1章 函数是一等公民
  ↓
第3章 模式匹配 + 守卫（递归的语法工具）
  ↓
第4章 结构递归（手写递归模板）
  ↓
第5章（本节）高阶函数（递归模板的参数化）
  │
  ├── 柯里化 ──────────────► 贯穿全书
  │                          每个多参函数都是柯里函数
  │                          ↓
  │                          第11章 Applicative 的 (<$>) 等组合子
  │
  ├── map ────────────────► 第11章 Functor 的 fmap
  │                          map 是 [] 上的 fmap 特例
  │                          fmap 是"对任意容器做变换"的广义 map
  │
  ├── fold ───────────────► 第11章 Foldable 类型类
  │                          fold 是 [] 上的 fold 特例
  │                          Foldable 是"对任意可折叠结构做 fold"的广义化
  │
  ├── 函数组合 (.) ────────► 第12章 Monad 的 (<=<) 与 Category
  │                          函数组合是"无效应计算"的组合
  │                          (<=<) 是"带效应计算"的组合
  │
  └── 部分应用 ────────────► 第13章 Monad 组合
                              (f <=< g) 本质是 (.) 的效应版本
```

**一条主线串起来看**：

1. **第4章**：你手写 `map'`、`filter'`、`foldr'` 的递归定义——每个都是独立的
    
2. **第5章（本节）**：你发现这三个递归定义**共享同一个骨架**——于是你把骨架抽象成 `map`/`filter`/`fold`，把"变化的部分"以函数参数形式传入
    
3. **第11章**：你进一步发现——不止列表，`Maybe`、`Tree`、`IO` 都有类似"map 操作"的需求。于是你定义 `Functor` 类型类，`fmap` 就是 `map` 的广义化
    
4. **第12章**：你发现不止 `map`，连"函数组合"也有广义版本——当两个函数都带有"效应"（如可能失败、可能读环境、可能产生多个结果）时，组合规则变了。这就是 `Monad` 和 `(<=<)`
    

> 💡 **如果你只记住一件事**：**第5章的 `map` 是列表专属的 `fmap`，`foldr` 是列表专属的 `fold`，`(.)` 是无效应函数的组合子。第11-13章所做的一切，就是把这些列表专属的组合子，推广到"任意容器/任意效应"上去**。你今天学的每一个高阶函数，都是未来某个类型类的具体实例。

## 🛠 实际工程启示

**1. 用高阶函数替代手写递归**

99% 的列表处理都可以用 `map`/`filter`/`fold`/`zipWith` 表达。手写递归容易出错（边界条件、模式顺序），高阶函数则经过充分测试且意图清晰。

**2. 善用部分应用，少用 lambda**

```
-- 反模式
map (\x -> x * 2) xs
filter (\x -> x > 0) xs

-- 推荐
map (*2) xs
filter (>0) xs
```

部分应用更短、更易读、且让"数据的流动"一目了然。

**3. 优先 `foldr` 处理列表构造**

因为 `foldr` 惰性、支持无穷列表、且组合子写法优雅。`foldl'` 仅在你明确需要严格左结合累加时用（如 `sum` 的生产版本）。

**4. 学会 point-free 风格，但别滥用**

```
-- 好的 point-free：清晰表达了管道
processUsers = map userName . filter isActive . sortBy age

-- 坏的 point-free：为了无点而无点，反而难懂
f = ((+) . (*2)) . (3 `div`)
```

经验法则：**当 point-free 让意图更清晰时用；当为了消掉参数而写出复杂组合时，退回 pointful**。

**5. 高阶函数是 DSL 的基石**

Haskell 的解析库 Parsec、HTML 库 lucid、测试库 HUnit——本质上都是高阶函数的集合。理解第5章，你就能读懂这些库的"迷你语言"设计哲学：**用高阶函数表达领域原语，用函数组合搭建领域逻辑**。

**6. 柯里化支撑了 Haskell 的"轻量级依赖注入"**

```
-- 数据库操作依赖连接
queryUser :: DBConnection -> UserID -> IO (Maybe User)

-- 部分应用"注入"连接，得到一个专用函数
withProdDB :: UserID -> IO (Maybe User)
withProdDB = queryUser prodConnection

-- 可以像普通函数一样传递
fetchAndProcess :: UserID -> IO (Maybe ProcessedUser)
fetchAndProcess = fmap process <$> withProdDB
```

这是 Haskell 工程里"依赖注入"的标准手法——**不需要框架，柯里化就够了**。

**7. `fold` 是递归的递归**

当你面对自定义数据类型（第7章）时，为它实现 `fold` 操作（即 `Foldable` 实例）几乎是免费的——一旦有了 `fold`，`map`、`filter`、`length`、`null`、`toList` 等全部自动获得。这是 Haskell 数据建模的黄金法则。

## 一句话收束

> 第5章不是在教你 `map`/`filter`/`fold` 怎么用，而是在揭示函数式编程最深的奥秘：**模式可以被参数化，递归可以被抽象，组合可以被提升为函数**。柯里化让"创建专用函数"变得免费，高阶函数让"复用递归模板"成为可能，`fold` 把"递归本身"变成了可传递可组合的值——而函数组合 `(.)` 则是把这种"函数的函数"推向极致的宣言。这一章的每一个概念，都是第11章 `Functor`、第12章 `Monad` 的**具体而微的预演**：`map` 是列表的 `fmap`，`foldr` 是列表的 `fold`，`(.)` 是无效应函数的 `(<=<)`。你以为在学五个独立的技巧，其实你在学**整个 Haskell 抽象体系的生成语法**——从今往后，"写 Haskell"不再是"写递归"，而是"组合高阶函数"。
