```
   ↓         ↓                ↓

（State/Reader/Writer）   （Monad 的堆叠组合）
```

**这一章是 Monad 抽象的"第一次完整实战"**。第十六章你学了 `>>=` 的数学定义和 IO 实例——但 IO 单子的"依赖性"还不够直观（因为 IO 动作的执行细节被运行时系统隐藏）。而**列表单子的 `>>=` 是看得见的、可计算的**——它就在你眼前展开成笛卡尔积，又通过 `[]` 实现剪枝。

Haskell 报告中明确定义了列表的 Monad 实例 ：

```
instance Monad [] where
  (>>=) :: [a] -> (a -> [b]) -> [b]
  xs >>= f = concat (map f xs)
  return x = [x]
```

**🔑 洞见一：列表单子的 `>>=` 就是"对每个元素应用 f，再 concat"**

`xs >>= f` 做的事：

1. 对 `xs` 中每个元素 `x`，计算 `f x`（得到 `[b]`）
    
2. 把所有 `[b]` 用 `concat` 拼起来
    

这正是"非确定性计算"的语义——从一个非确定性值出发，对每个可能的结果继续非确定地计算，最后汇总所有可能性。

## 17.1 列表单子与数组归纳

### 列表即非确定性值

"列表单子"的核心直觉是——**[a] 可以表示一个"非确定性的 a"**：

```
-- 一个可能是 1、2 或 3 的整数
nondet :: [Int]
nondet = [1, 2, 3]

-- 对它进行平方，得到"可能是 1、4 或 9 的平方结果"
squared :: [Int]
squared = fmap (\x -> x * x) nondet  -- [1, 4, 9]
```

**🔑 洞见二：列表有两种语义，别混淆**

Haskell 列表有两重身份 ：

|视角|含义|
|---|---|
|**集合视角**​|`[a]` 是一个包含若干 `a` 的集合|
|**非确定性视角**​|`[a]` 是一个"可能是其中任意一个 `a`"的非确定性值|

在 Monad 语境下，我们强调**第二种语义**。`[1,2,3]` 不是"三个数的集合"，而是"一个未知的数，可能是 1、2 或 3"。

### 用 `>>=` 做非确定性计算

```
-- 一个非确定性整数
nondet :: [Int]
nondet = [1, 2, 3]

-- 根据它的值，做进一步的非确定性选择
result :: [(Int, Int)]
result = nondet >>= \x -> 
  if even x 
    then [x, x * 10]  -- 偶数展开为两个可能
    else [x]          -- 奇数只有一个可能
-- result = [1, 2, 20, 3]
```

**关键观察**：`result` 的长度不是固定的——它取决于 `nondet` 中每个元素"展开"出的可能性数量。这正是非确定性计算的威力：**可能性可以动态增殖或收缩**。

### 数组归纳法（Induction on Arrays）

韩冬在 17.1 节提到"数组归纳"——这是用列表单子做递推的思想基础。以八皇后为例：

- **基本情况**：0 个皇后，只有一种摆法——空棋盘 `[[]]`
    
- **归纳步骤**：要在 n×n 棋盘上摆 n 个皇后，先摆 n-1 个皇后（得到所有合法的部分解），再对每个部分解尝试在第 n 列放一个新皇后，过滤掉不安全的摆法
    

这正是图灵社区文章中给出的 `queens` 函数结构 ：

```
queens 0 = [[]]
queens m = [x:xs | xs <- queens (m-1), x <- [1..8], safe x xs 1]
```

**🔑 洞见三：数组归纳 = 列表单子的递归展开**

`queens m` 的定义揭示了列表单子的本质力量：

1. `queens (m-1)` 返回"所有可能的 (m-1) 皇后摆法"的列表
    
2. 对每种摆法 `xs`，尝试新皇后放在第 `x` 列（x ∈ [1..8]）
    
3. `safe x xs 1` 过滤掉不安全的选择——**返回 `[]` 即剪枝**
    
4. 列表推导式自动做 `concat`，汇总所有可能性
    

如果用 `>>=` 显式写出：

```
queens :: Int -> [[Int]]
queens 0 = [[]]
queens m = queens (m-1) >>= \xs ->
           [1..8] >>= \x ->
           if safe x xs 1 
             then return (x:xs) 
             else []
```

**这就是"列表单子的依赖性"**——后续的列选择 `[1..8]` 依赖于前文的摆法 `xs`，而 `safe` 检查可能返回 `[]`（剪枝）。这是 Applicative 绝对做不到的——因为 `[1..8]` 的"起点"和"过滤条件"都动态依赖于 `xs`。

## 17.2 八皇后问题：Monad 威力的经典展示

### 问题描述与 `safe` 函数

图灵社区文章给出了经典的 `safe` 函数 ：

```
safe :: Int -> [Int] -> Int -> Bool
safe _ [] _ = True
safe x (x1:xs) n = x /= x1 && x /= x1+n && x /= x1-n && safe x xs (n+1)
```

**`safe x xs n` 的含义**：

- `x`：新皇后要放的列号
    
- `xs`：已有皇后的列号列表（从第一行开始）
    
- `n`：新皇后与已有皇后之间的"行距离"（从 1 开始）
    
- 检查三个条件：
    
    1. `x /= x1`：不在同一列
        
    2. `x /= x1+n`：不在右下对角线（`x1+n` 是右下对角位置）
        
    3. `x /= x1-n`：不在左下对角线（`x1-n` 是左下对角位置）
        
    
- 递归检查下一个已有皇后，`n+1`（行距离增加 1）
    

### 完整解法

图灵社区文章给出的 `queensN` 函数 ：

```
queensN :: Int -> [[Int]]
queensN n = queens n
  where
    queens 0 = [[]]
    queens m = [x:xs | xs <- queens (m-1), x <- [1..n], safe x xs 1]
```

**运行结果**（以 6 皇后和 8 皇后为例）：

```
*Main> mapM_ print $ queensN 6
[5,3,1,6,4,2]
[4,1,5,2,6,3]
[3,6,2,5,1,4]
[2,4,6,1,3,5]

*Main> mapM_ print $ queensN 8
[4,2,7,3,6,8,5,1]
[5,2,4,7,3,8,6,1]
[3,5,2,8,6,4,7,1]
...
[1,7,4,6,8,2,5,3]
...
[5,7,2,6,3,1,4,8]
```

**🔑 洞见四：这是 Monad 威力的直接证明**

注意 `queens m` 的列表推导式——它等价于：

```
queens m = queens (m-1) >>= \xs ->
           [1..n] >>= \x ->
           if safe x xs 1
             then return (x:xs)
             else mzero  -- 即 []
```

**这是 Monad "依赖性"的教科书案例**：

1. **第一个 `>>=`**：`queens (m-1)` 的结果（所有部分解）决定了下一步要处理的 `xs`
    
2. **第二个 `>>=`**：`[1..n]` 是"独立的"非确定性选择，但它的过滤条件 `safe x xs 1` **依赖 `xs`**
    
3. **`mzero`（即 `[]`）**：`safe` 检查失败时返回 `mzero`，根据 MonadPlus 定律 `mzero >>= f = mzero`，整个计算短路
    

如果用 Applicative 写，你无法表达"第二个列表 `[1..n]` 的过滤条件依赖第一个列表的结果 `xs`"——因为 Applicative 的 `<*>` 要求所有参数独立。

### `queensN` 的 foldM 改写

图灵社区文章还给出了用 `foldM` 改写 `queensN` 的方式 ：

```
queensN :: Int -> [[Int]]
queensN n = foldM (\xs _ -> 
                    [1..n] >>= \x ->
                    if safe x xs 1 
                      then return (x:xs) 
                      else []) [] [1..n]
```

**🔑 洞见五：foldM 让"累积式非确定性搜索"成为模式**

`foldM` 的类型是 ：

```
foldM :: Monad m => (a -> b -> m a) -> a -> [b] -> m a
```

它做"Monad 版的左折叠"——对列表中的每个元素，用 Monad 函数更新累积值，全程在 Monad 上下文中。

在八皇后问题中：

- **累积值**：当前已摆放的皇后列号列表 `xs`
    
- **每次迭代**：尝试在下一行放一个新皇后（列号 `[1..n]` 中筛选）
    
- **起点**：空列表 `[]`
    
- **迭代次数**：`[1..n]`（即 n 次）
    

**这种"用 foldM 做搜索"的模式，是动态规划和搜索算法的通用套路**——后面 17.4.6 节会详细讲解 foldM。

## 17.3 MonadPlus：为 Monad 添加"选择"与"失败"

### MonadPlus 类型类

Haskell 2010 报告的定义 ：

```
class Monad m => MonadPlus m where
  mzero :: m a
  mplus :: m a -> m a -> m a
```

**列表和 Maybe 的实例**​ ：

```
instance MonadPlus [] where
  mzero = []
  mplus = (++)

instance MonadPlus Maybe where
  mzero = Nothing
  Nothing `mplus` ys = ys
  xs `mplus` _ys = xs
```

### 🔑 洞见六：MonadPlus = "Monad 版的选择/失败"

MonadPlus 给 Monad 添加了两个能力：

1. **`mzero`**：代表"失败/空计算"
    
2. **`mplus`**：代表"选择/二选一"
    

定律 ：

```
-- Monoid 定律
mzero `mplus` m = m
m `mplus` mzero = m
m `mplus` (n `mplus` o) = (m `mplus` n) `mplus` o

-- 左零律（关键）
mzero >>= f = mzero
-- 右零律
v >> mzero = mzero
```

**左零律的含义**：一旦计算中出现了 `mzero`，整个 `>>=` 链立即短路——这正是八皇后问题中 `safe` 检查失败时返回 `[]` 能够实现剪枝的数学基础。

### 🔑 洞见七：guard 函数——MonadPlus 的过滤器

`guard` 是 Control.Monad 中的经典函数 ：

```
guard :: MonadPlus m => Bool -> m ()
guard True  = return ()
guard False = mzero
```

**它的作用**：在 do 块中根据布尔条件"过滤"计算——条件为 True 时继续，为 False 时整个 do 块变成 `mzero`。

用 guard 改写八皇后：

```
queens :: Int -> [[Int]]
queens 0 = [[]]
queens m = queens (m-1) >>= \xs ->
           [1..8] >>= \x ->
           guard (safe x xs 1) >>
           return (x:xs)
```

**🔑 洞见八：guard 是"列表推导式过滤"的 Monad 版本**

回忆一下列表推导式：

```
[x:xs | xs <- queens (m-1), x <- [1..8], safe x xs 1]
```

其中的 `safe x xs 1` 就是过滤器。在 do 语法中，`guard (safe x xs 1) >> return (x:xs)` 完全对应这个过滤器——`guard` 条件不满足时返回 `mzero`，触发左零律短路。

### 🔑 洞见九：MonadPlus 与 Alternative 的关系（重要更新）

这是本章**最需要澄清的现代视角**。在 Haskell 的历史演进中：

- **早期**：`MonadPlus` 是独立的类型类，与 `Alternative` 无关
    
- **现代（GHC 7.10+）**：`MonadPlus` 已成为 `Alternative` 的子类 ：
    

```
class (Alternative m, Monad m) => MonadPlus m where
  mzero = empty
  mplus = (<|>)
```

**这意味着**：在现代 Haskell 中，`MonadPlus` 只是"既是 Alternative 又是 Monad"的类型类的别名。对于列表：

- `mzero = empty = []`
    
- `mplus = (<|>) = (++)`
    

> 💡 **实践建议**：在现代 Haskell 代码中，**优先使用 `Alternative`（`empty` 和 `<|>`）而非 `MonadPlus`（`mzero` 和 `mplus`）**——因为 `Alternative` 更通用（适用于所有 Applicative），而 `MonadPlus` 主要是为了向后兼容 。但在阅读老代码（如本书）时，你需要认识 `mzero` 和 `mplus` 的语义。

### msum 函数

`msum` 是 `MonadPlus` 版的 `concat` ：

```
msum :: MonadPlus m => [m a] -> m a
msum = foldr mplus mzero
```

对于列表：`msum [[1,2],[3,4],[5,6]] = [1,2,3,4,5,6]`——就是把列表的列表 concat 起来。对于 Maybe：`msum [Nothing, Just 3, Just 5] = Just 3`——取第一个 `Just`。

## 17.4 结构控制函数：Monad 的标准工具箱

这一节是本章**最实用**的部分——Haskell 标准库提供了一组"Monad 版"的列表函数，它们是每个 Haskell 程序员的日常工具。

### 17.4.1 sequence / sequence_

**定义**​ ：

```
sequence :: Monad m => [m a] -> m [a]
sequence = foldr mcons (return [])
  where mcons p q = p >>= \x -> q >>= \y -> return (x:y)

sequence_ :: Monad m => [m a] -> m ()
sequence_ = foldr (>>) (return ())
```

**语义**：

- `sequence`：按顺序执行一系列 Monad 动作，收集所有结果
    
- `sequence_`：同上，但丢弃结果（只关心副作用）
    

**🔑 洞见十：sequence 在列表单子中的行为是"笛卡尔积"**

```
sequence [[1,2], [3,4]] 
-- = [1,2] >>= \x -> [3,4] >>= \y -> return (x,y)
-- = [(1,3), (1,4), (2,3), (2,4)]
```

**这就是为什么 sequence 在非确定性计算中如此重要**——它自动做笛卡尔积展开。

**在 IO 单子中的行为**：

```
sequence [putStrLn "a", putStrLn "b"]
-- 打印 "a" 然后 "b"，返回 [(), ()]
```

### 17.4.2 mapM / mapM_

**定义**​ ：

```
mapM :: Monad m => (a -> m b) -> [a] -> m [b]
mapM f as = sequence (map f as)

mapM_ :: Monad m => (a -> m b) -> [a] -> m ()
mapM_ f as = sequence_ (map f as)
```

**语义**：把 Monad 函数映射到列表上，按顺序执行。

**🔑 洞见十一：mapM_ 是"遍历并执行"的最常用形式**

```
-- 打印列表中的每个元素
mapM_ print [1, 2, 3]
-- 打印：
-- 1
-- 2
-- 3
-- 返回：()

-- 在处理 IO 时极常用
processFiles :: [FilePath] -> IO ()
processFiles files = mapM_ processFile files
  where processFile f = do
          content <- readFile f
          putStrLn $ "File " ++ f ++ ": " ++ show (length content) ++ " chars"
```

**`forM` 和 `forM_`**：参数翻转的版本，适用于"lambda 在右侧"的场景 ：

```
forM :: Monad m => [a] -> (a -> m b) -> m [b]
forM = flip mapM

-- 使用示例
forM [1, 2, 3] $ \x -> do
  putStrLn $ "Processing " ++ show x
  return (x * 2)
-- 打印处理信息，返回 [2, 4, 6]
```

### 17.4.3 replicateM / replicateM_

**定义**：

```
replicateM :: Monad m => Int -> m a -> m [a]
replicateM n mx = sequence (replicate n mx)

replicateM_ :: Monad m => Int -> m a -> m ()
replicateM_ n mx = sequence_ (replicate n mx)
```

**语义**：重复执行 Monad 动作 n 次。

**🔑 洞见十二：replicateM 在非确定性计算中产生"所有可能的组合"**

```
-- 抛三次硬币的所有可能结果
replicateM 3 ["H", "T"]
-- = [["H","H","H"], ["H","H","T"], ["H","T","H"], ["H","T","T"],
--    ["T","H","H"], ["T","H","T"], ["T","T","H"], ["T","T","T"]]
-- 共 8 种组合（2^3）
```

**在 IO 中**：

```
-- 读取 3 行
lines <- replicateM 3 getLine
```

### 17.4.4 forever

**定义**​ ：

```
forever :: Monad m => m a -> m b
forever act = let act' = act >> act' in act'
```

**语义**：无限重复执行一个 Monad 动作。

**🔑 洞见十三：forever 是"事件循环"的 Monad 版本**

```
-- 一个简单的 REPL
main :: IO ()
main = forever $ do
  putStr "> "
  line <- getLine
  if line == "quit"
    then return ()  -- 注意：这不会退出，因为 forever 忽略返回值
    else putStrLn $ "You said: " ++ line
```

**⚠️ 注意**：`forever` 真的会永远执行。要退出，通常需要 `exitSuccess` 或抛出异常：

```
import System.Exit

main :: IO ()
main = forever $ do
  line <- getLine
  when (line == "quit") exitSuccess
  putStrLn $ "Echo: " ++ line
```

### 17.4.5 filterM

**定义**​ ：

```
filterM :: Monad m => (a -> m Bool) -> [a] -> m [a]
filterM _ [] = return []
filterM p (x:xs) = do
  b <- p x
  ys <- filterM p xs
  return (if b then x:ys else ys)
```

**语义**：Monad 版的 filter——谓词函数返回 `m Bool` 而非 `Bool`。

**🔑 洞见十四：filterM 是"有副作用的过滤"**

```
-- 过滤出存在的文件
import System.Directory (doesFileExist)

existingFiles :: [FilePath] -> IO [FilePath]
existingFiles paths = filterM doesFileExist paths

-- 使用
main = do
  files <- existingFiles ["a.txt", "b.txt", "c.txt"]
  print files  -- 只打印存在的文件
```

**在列表单子中**：

```
filterM (\x -> [even x, odd x]) [1, 2, 3]
-- = [[2], [1, 3], [1, 2, 3]]  -- 非确定性过滤
```

### 17.4.6 foldM / foldM_

**定义**​ ：

```
foldM :: Monad m => (a -> b -> m a) -> a -> [b] -> m a
foldM f a [] = return a
foldM f a (x:xs) = f a x >>= \y -> foldM f y xs

foldM_ :: Monad m => (a -> b -> m a) -> a -> [b] -> m ()
foldM_ f a xs = foldM f a xs >> return ()
```

**语义**：Monad 版的左折叠——每一步都可能产生 Monad 效果。

**🔑 洞见十五：foldM 是"累积式 Monad 计算"的通用模式**

```
-- 安全的累加（遇到负数则失败）
safeSum :: [Int] -> Maybe Int
safeSum = foldM (\acc x -> 
                  if x >= 0 
                    then Just (acc + x) 
                    else Nothing) 0

safeSum [1, 2, 3]    -- Just 6
safeSum [1, -2, 3]   -- Nothing
```

**在 IO 中**：

```
-- 逐行读取并累积到状态中
import qualified Data.Map as M

type WordCount = M.Map String Int

countWords :: FilePath -> IO WordCount
countWords path = do
  content <- readFile path
  foldM (\m word -> return $ M.insertWith (+) word 1 m)
        M.empty (words content)
```

**回到八皇后问题**：

```
queensN :: Int -> [[Int]]
queensN n = foldM (\xs _ -> 
                    [1..n] >>= \x ->
                    if safe x xs 1 
                      then return (x:xs) 
                      else []) [] [1..n]
```

**这就是 17.2 节提到的 foldM 改写版本**​ ——它把"递推构建皇后摆法"表达为"对 [1..n] 的 foldM"：初始状态是空棋盘 `[]`，每次迭代尝试在下一行放置新皇后，返回所有可能的累积状态。

## 📝 本章核心洞见总结

> **洞见一：列表 `[]` 是最天然的 Monad 实例**。
> 
> `xs >>= f = concat (map f xs)`——对每个元素应用 f，再 concat。这正好对应"非确定性计算"的语义：从一个非确定性值出发，对每个可能的结果继续非确定地计算，汇总所有可能性 。

> **洞见二：列表有两种语义，Monad 强调"非确定性"**。
> 
> 集合视角下 `[a]` 是"若干 a 的集合"；非确定性视角下 `[a]` 是"一个未知的值，可能是其中任意一个 a"。在 Monad 语境中，第二种语义才是关键 。

> **洞见三：八皇后问题是 Monad "依赖性"的教科书案例**。
> 
> `queens m = queens (m-1) >>= \xs -> [1..n] >>= \x -> guard (safe x xs 1) >> return (x:xs)`——第二个列表 `[1..n]` 的过滤条件依赖第一个 `>>=` 的结果 `xs`。这是 Applicative 绝对做不到的 。

> **洞见四：MonadPlus 为 Monad 添加"选择"与"失败"**。
> 
> `mzero` 代表失败，`mplus` 代表选择。左零律 `mzero >>= f = mzero` 是剪枝的数学基础——一旦计算中出现 `mzero`，整个 `>>=` 链立即短路 。

> **洞见五：guard 是"列表推导式过滤"的 Monad 版本**。
> 
> `guard True = return ()`，`guard False = mzero`。在 do 块中使用 guard，可以实现与列表推导式 `| condition` 完全等价的过滤效果 。

> **洞见六：在现代 Haskell 中，MonadPlus 已成为 Alternative 的子类**。
> 
> `mzero = empty`，`mplus = (<|>)`。实践中应优先使用 Alternative（更通用），MonadPlus 主要是历史兼容 。但在阅读老代码（如本书）时，需要认识 `mzero` 和 `mplus` 的语义。

> **洞见七：sequence 在列表单子中做笛卡尔积**。
> 
> `sequence [[1,2], [3,4]] = [(1,3),(1,4),(2,3),(2,4)]`——自动展开所有可能的组合。这是非确定性搜索的基石 。

> **洞见八：foldM 是"累积式 Monad 计算"的通用模式**。
> 
> 八皇后问题的 `queensN` 可以用 foldM 优雅地表达：`foldM (\xs _ -> ... ) [] [1..n]`——初始状态为空棋盘，每次迭代尝试放置新皇后，返回所有可能的累积状态 。

> **洞见九：结构控制函数是 Monad 版的列表函数**。
> 
> `mapM` 对应 `map`，`filterM` 对应 `filter`，`foldM` 对应 `foldl`，`replicateM` 对应 `replicate`——它们让普通函数"升级"到 Monad 上下文。带有 `_` 后缀的版本（`mapM_`、`sequence_` 等）丢弃结果，只关心副作用 。

> **洞见十：replicateM 在非确定性计算中产生幂集式的组合**。
> 
> `replicateM 3 ["H","T"]` 产生 8 种所有可能的硬币抛掷序列——这是组合爆炸的自然表达 。

## 🛠️ 实践建议

1. **用列表单子做非确定性搜索**：
    
    ```
    -- 所有和为 10 的三元组
    triples = do
      x <- [1..10]
      y <- [1..10]
      z <- [1..10]
      guard (x + y + z == 10)
      return (x, y, z)
    ```
    
2. **用 guard 做过滤**：
    
    ```
    -- 所有勾股数
    pythags = do
      z <- [1..50]
      y <- [1..z]
      x <- [1..y]
      guard (x*x + y*y == z*z)
      return (x, y, z)
    ```
    
3. **用 foldM 实现动态规划**：
    
    ```
    -- 斐波那契（带状态传递）
    fib :: Int -> Integer
    fib n = head $ flip evalStateT 0 $ foldM step 1 [1..n]
      where step a _ = do
              b <- get
              put a
              return (a + b)
    ```
    
4. **用 filterM 做有副作用的过滤**：
    
    ```
    import System.Directory (doesFileExist)
    
    existingFiles :: [FilePath] -> IO [FilePath]
    existingFiles = filterM doesFileExist
    ```
    
5. **用 mapM_ 遍历并执行**：
    
    ```
    processAll :: [FilePath] -> IO ()
    processAll files = mapM_ processFile files
      where processFile f = do
              content <- readFile f
              putStrLn $ f ++ ": " ++ show (length content) ++ " chars"
    ```
    
6. **用 replicateM 生成组合**：
    
    ```
    -- 所有长度为 3 的二进制串
    bins = replicateM 3 ['0', '1']
    -- ["000","001","010","011","100","101","110","111"]
    ```
    
7. **验证 MonadPlus 定律**：
    
    ```
    monadPlusLaws :: (MonadPlus m, Eq (m a)) => m a -> m a -> Bool
    monadPlusLaws x y =
      (mzero `mplus` x) == x &&
      (x `mplus` mzero) == x &&
      (x `mplus` (y `mplus` mzero)) == ((x `mplus` y) `mplus` mzero)
    ```

第十八章"更多 Monad"（推测包含 State、Reader、Writer）会在本章基础上往前推一步——**展示 Monad 不仅仅是"非确定性"和"IO"，它可以建模各种各样的有状态计算**：

- **State Monad**：隐式传递状态（如计数器、随机数生成器、解释器环境）
    
- **Reader Monad**：只读环境（如配置、数据库连接）
    
- **Writer Monad**：累积日志（如调试输出、性能统计）
    

更深远的连接：

- **第二十四章 Monad Transformers**：多个 Monad 的堆叠组合——`StateT`、`ReaderT`、`WriterT` 等。它们都建立在 `Monad` 类型类之上，而本章学的 `liftM`、`foldM` 等函数在 Transformer 栈中同样适用
