
# 第十四章 单位半群和一些有趣的应用函子 —— 读书笔记

## 14.1 单位半群：可结合累积的代数抽象

### Monoid 的数学定义

Haskell 标准库的类型类定义 ：

```
class Semigroup m => Monoid m where
  mempty :: m              -- 单位元
  mappend :: m -> m -> m   -- 二元运算
  mconcat :: [m] -> m      -- 默认 foldr mappend mempty
  -- 运算符别名：(<>) = mappend
```

必须满足三条定律 ：

```
-- 左单位元
mempty <> x = x

-- 右单位元
x <> mempty = x

-- 结合律
(x <> y) <> z = x <> (y <> z)
```

### 🔑 洞见一：Monoid 的本质是"可结合的累积"

`mappend`（即 `<>`）必须满足结合律——这意味着**累积的顺序不重要**。你可以从左往右累积，也可以从右往左累积，结果一样。

这一点至关重要，因为：

- **并行化**：`(a <> b) <> (c <> d)` 可以并行计算两侧再合并
    
- **增量计算**：可以逐步累积，随时获取中间结果
    
- **树形重组**：`foldr` 和 `foldl` 给出相同结果（对于 Monoid）
    

Haskell wiki 明确指出：

> _"The main thing to understand about a series of values merged by (<>) is that the order that they are evaluated doesn't matter."_

### 🔑 洞见二：为什么一个数字类型有两个 Monoid 实例？

`Int` 既可以在加法下是 Monoid（`Sum Int`，单位元 0），也可以在乘法下是 Monoid（`Product Int`，单位元 1）。但 Haskell 不允许同一类型有多个 Monoid 实例——解决方案是 `newtype` 包装 ：

```
newtype Sum a = Sum { getSum :: a }
instance Num a => Monoid (Sum a) where
  mempty = Sum 0
  Sum x <> Sum y = Sum (x + y)

newtype Product a = Product { getProduct :: a }
instance Num a => Monoid (Product a) where
  mempty = Product 1
  Product x <> Product y = Product (x * y)
```

**这正是第九章 newtype 的威力展示**——用 `newtype` 为同一底层类型挂不同的 Monoid 实例。这是 "zero-cost abstraction" 的经典应用。

### 🔑 洞见三：Monoid 与折叠（fold）的深度对应

Haskell 维基百科揭示了一个关键联系：

> _"It is closely related to the Foldable class, and indeed you can think of a Monoid instance declaration for a type m as precisely what you need in order to fold up a list of values of m."_

`mconcat :: [m] -> m` 就是"用 Monoid 把列表折叠成单个值"。这意味着——**任何 Monoid 实例，天然就是一个可折叠的结构**。这条联系会在第二十二章 Foldable 中爆发威力。

### 14.1.1 Endo 单位半群：自映射的组合

`Endo` 是 Haskell 标准库中最优雅的 Monoid 实例之一 ：

```
newtype Endo a = Endo { appEndo :: a -> a }

instance Monoid (Endo a) where
  mempty = Endo id
  Endo f `mappend` Endo g = Endo (f . g)  -- 函数组合
```

### 🔑 洞见四：Endo 揭示了"函数组合本身就是 Monoid"

`a -> a` 类型的函数（自映射/自同态）在函数组合 `(.)` 下构成一个 Monoid：

- **单位元**：`id`（恒等函数）
    
- **二元运算**：`(.)`（函数组合）
    
- **结合律**：`(f . g) . h = f . (g . h)`（函数组合天然满足）
    

`Endo` 这个新类型包装，把这个数学事实"提升"为 Haskell 的类型类实例。

### 🔑 洞见五：Endo 是"函数序列的组合器"

考虑你需要依次应用多个变换：

```
import Data.Monoid

let transforms = [Endo (+1), Endo (*2), Endo (^2)]
let combined = mconcat transforms  -- Endo ((+1) . (*2) . (^2))
appEndo combined 3  -- (3 + 1) * 2 ^ 2 = 4 * 2 ^ 2 = 4 * 4 = 16
```

**`mconcat` 把 `[a -> a]` 折叠成 `a -> a`**——这正是"函数序列的组合器"。这个模式在后续章节中会反复出现：

- 第二十二章 `foldMap` 的本质
    
- 透镜库中的 `Endo` 用于组合修改操作
    
- 解析器组合子中的变换链
    

### 14.1.2 自由单位半群：列表即自由 Monoid

这是本章**最具数学深度**的一节。

### 🔑 洞见六：列表是自由单位半群

数学上，由集合 `a` 生成的**自由单位半群**（free monoid）就是所有 `a` 的列表，运算为 `++`，单位元为 `[]` 。

Haskell 中：

```
instance Semigroup [a] where
  (<>) = (++)

instance Monoid [a] where
  mempty = []
```

### 🔑 洞见七：自由 Monoid 的"自由"意味着什么？

"自由"这个词有精确的数学含义 ：

> _"A free monoid, intuitively, is a monoid which satisfies only those equations above (结合律和单位元), and, obviously, all their consequences."_

翻译过来：**自由 Monoid 只满足 Monoid 定律，不额外满足任何其他方程**。

对比：

- **列表 `[a]`**：`[1,2] ++ [3] = [1,2,3]`，不等于 `[6]`——**不**满足交换律
    
- **`Sum Int`**：`Sum 1 <> Sum 2 = Sum 3`，满足交换律——**不是**自由 Monoid
    

**自由 Monoid 的威力在于"延迟决定"**​ ：

```
-- 把数字放入自由 Monoid（列表）
let nums = [3, 7]

-- 稍后决定用加法聚合
getSum $ mconcat $ map Sum nums  -- 10

-- 或决定用乘法聚合
getProduct $ mconcat $ map Product nums  -- 21
```

**自由 Monoid 让你"先收集、后决定聚合方式"**。这是后续 Foldable、Traversable 的核心思想——先遍历结构收集元素到列表（自由 Monoid），再用具体的 Monoid 聚合。

### 🔑 洞见八：所有自由 Monoid 都同构于列表

数学定理：**任何类型的自由 Monoid 都同构于该类型的列表**​ 。这意味着——**列表是"最通用"的收集结构**。任何 Monoid 操作都可以先在列表上做（自由 Monoid），再映射到目标 Monoid。

这一洞察是第二十二章 Foldable/Traversable 的理论基础。

### 14.1.3 逆：Monoid 与群的边界

"逆"这一节探讨的是 Monoid 与 Group（群）的区别。

### 🔑 洞见九：Monoid 不要求逆元

数学上，群（Group）要求每个元素都有逆元 `x^-1` 使得 `x <> x^-1 = mempty`。但 **Monoid 不要求逆元**。

这意味着：

|类型|有逆元吗？|
|---|---|
|`Sum Int`|✅ 有，`Sum (-x)` 是 `Sum x` 的逆|
|`Product Double`|✅ 有（非零），`Product (1/x)` 是逆|
|`[a]`（列表）|❌ 没有，无法"撤销"拼接|
|`Endo a`|⚠️ 仅当函数是双射时有逆|

### 🔑 洞见十：Dual 与"逆"的关系

标准库中的 `Dual` 新类型 ：

```
newtype Dual a = Dual { getDual :: a }

instance Monoid a => Monoid (Dual a) where
  mempty = Dual mempty
  Dual x <> Dual y = Dual (y <> x)  -- 反转结合顺序
```

`Dual` 不是逆元，而是**反转二元运算的顺序**。当 Monoid 不可交换时，`Dual` 让我们能获得"从右往左"的结合语义。

> 💡 这一节的数学意义在于：**明确 Monoid 的能力边界**。理解"Monoid 不提供逆元"，你才能理解为什么某些操作（如撤销、回滚）需要更强的代数结构（如 Group），而 Haskell 标准库选择 Monoid 作为"最小够用的抽象"。

## 14.2 当单位半群遇上应用函子：三个关键实例

这是本章**真正的华彩乐章**。三个实例分别展示了 Monoid 与 Applicative 结合后的三种威力。

### 14.2.1 Const a 的应用函子实例：累积器

Haskell 标准库源码 ：

```
newtype Const a b = Const { getConst :: a }

instance Monoid m => Applicative (Const m) where
  pure _ = Const mempty
  Const x <*> Const y = Const (x <> y)  -- 用 Monoid 的 <> 合并
```

### 🔑 洞见十一：Const 的 Applicative 实例本质上是 Monoid

GHC 文档明确说明 ：

> _"Because we ignore the second type parameter to Const, the Applicative instance, which has `(<*>) :: Monoid m => Const m (a -> b) -> Const m a -> Const m b` essentially turns into `Monoid m => m -> m -> m`, which is `(<>)`"_

**这是本章最震撼的洞见**：当 `Const m` 成为 Applicative 时，它的 `<*>` 运算**完全退化成 Monoid 的 `<>`**！

回顾第十一章和第十二章：

- `Const a b` 的 `Functor` 实例忽略映射函数
    
- `Const a b` 的 `Applicative` 实例（当 `a` 是 Monoid 时）用 `<>` 合并
    
- 第十二章透镜的 `view` 函数：`view l = getConst . l Const`——`Const` 忽略了 setter，提取了 getter 的值
    

现在加上 Monoid 约束后，`Const m` 的 `<*>` 变成：

```
Const "Hello" <*> Const " World" = Const "Hello World"  -- 字符串拼接
Const [1,2] <*> Const [3,4] = Const [1,2,3,4]  -- 列表拼接
```

### 🔑 洞见十二：Const + Monoid = 累积器

这意味着——**`Const m` 是一个"沉默的累积器"**：

- 它忽略所有"映射函数"
    
- 它把所有"上下文里的值"用 Monoid 的 `<>` 累积起来
    
- 它不关心 `b` 类型参数（幽灵类型）
    

这个特性在第二十二章 Traversable 中会爆发威力：

```
-- foldMap 的本质实现
foldMap f = getConst . traverse (Const . f)
```

`traverse` 本来用于"遍历结构并收集效果"，但当效果是 `Const m`（且 `m` 是 Monoid）时，`traverse` **退化为 `foldMap`**——遍历结构，把所有元素用 `f` 映射到 Monoid，再用 `<>` 累积。

> 💡 **第十一章的 `Const` + 本章的 Monoid 约束 = 第十二章透镜的 `view` + 第二十二章 Traversable 的 `foldMap`**。这是 Haskell 抽象"组合爆炸"威力的极致展示——一个简单的 `Const`，通过叠加不同的约束，解锁了读取、累积、折叠等多种能力。

### 14.2.2 选择应用函子（Alternative）：失败与回退

`Alternative` 类型类 ：

```
class Applicative f => Alternative f where
  empty :: f a
  (<|>) :: f a -> f a -> f a
  some :: f a -> f [a]
  many :: f a -> f [a]
```

### 🔑 洞见十三：Alternative 是"应用函子层面的 Monoid"

`empty` 和 `<|>` 与 Monoid 的 `mempty` 和 `<>` **同构**：

- `empty` 对应 `mempty`（失败/空）
    
- `<|>` 对应 `<>`（选择/回退）
    

定律也完全一致 ：

```
empty <|> x = x
x <|> empty = x
(x <|> y) <|> z = x <|> (y <|> z)
```

### 🔑 洞见十四：Alternative 的几个关键实例

**Maybe 实例**​ ：

```
instance Alternative Maybe where
  empty = Nothing
  Nothing <|> r = r
  l <|> _ = l
```

语义："尝试左边，如果失败（Nothing）则回退到右边"。

**列表实例**​ ：

```
instance Alternative [] where
  empty = []
  (<|>) = (++)
```

语义："非确定性选择"——两个列表的 `<|>` 是所有可能结果的并集。

**IO 实例**（base 4.9+）：

```
instance Alternative IO where
  empty = fail "empty"
  a <|> b = -- 尝试 a，如果抛出异常则尝试 b
```

### 🔑 洞见十五：Alternative 是解析器的命脉

这是 Alternative **最经典的应用场景**：

```
-- 解析 "bob" 或 "alice"
isAliceOrBob :: String -> Maybe String
isAliceOrBob a = isAlice a <|> isBob a <|> isCharly a
```

`<|>` 让解析器**自动回退**——尝试第一个解析器，如果失败（返回 `Nothing` 或空列表），自动尝试下一个。

> 💡 这直接为第十五章的解析器库奠定了基础。MegaParsec、Attoparsec 等库的核心机制之一就是 Alternative——它让你可以像写正则表达式一样组合解析器：`digit <|> letter`、`char 'a' *> char 'b'`。

### 14.2.3 拉链应用函子（ZipList）：位置同步

`ZipList` 的 Applicative 实例 ：

```
instance Applicative ZipList where
  pure x = ZipList (repeat x)
  ZipList fs <*> ZipList xs = ZipList (zipWith ($) fs xs)
```

### 🔑 洞见十六：ZipList vs 普通列表——两种"应用语义"

普通列表的 `<*>` 是**笛卡尔积**​ ：

```
[(+1), (*2)] <*> [10, 20] 
-- = [11, 21, 12, 40]  -- 4 个结果
```

`ZipList` 的 `<*>` 是**位置一一对应**​ ：

```
ZipList [(+1), (*2)] <*> ZipList [10, 20]
-- = ZipList [11, 40]  -- 2 个结果，一一对应
```

**为什么需要 ZipList？**​ 因为一个类型只能有一个 Applicative 实例。普通列表的 `<*>` 已经被定义为笛卡尔积（这对非确定性计算很有用），但为了支持"位置同步"的应用语义，Haskell 引入了 `ZipList` 新类型包装 。

### 🔑 洞见十七：pure 的"最小化上下文"在 ZipList 中的体现

`pure x = ZipList (repeat x)`——产生一个**无限循环**的列表，每个位置都是 `x`。

为什么是无限列表？因为 `pure f <*> xs` 必须等于 `fmap f xs`（Applicative 定律）。如果 `pure x` 只产生单元素列表 `[x]`，那么 `pure f <*> ZipList [1,2,3]` 会因为长度不匹配而被截断——**违反定律**。所以 `pure` 必须用无限重复来"填满"任意长度 。

### 🔑 洞见十八：ZipList 是"向量化运算"的抽象

`ZipList` 让你能对"并行的序列"做向量化操作：

```
-- 向量加法
ZipList [1,2,3] <*> ZipList [(+1),(+2),(+3)]  -- ZipList [2,4,6]

-- 或用 liftA2
liftA2 (+) (ZipList [1,2,3]) (ZipList [10,20,30])  -- ZipList [11,22,33]
```

这种"位置同步"的语义在信号处理、矩阵运算、并行计算等领域极其有用。

## 📝 本章核心洞见总结

> **洞见一：Monoid 是"可结合累积"的最小代数结构**。
> 
> `mempty` 是单位元，`<>` 是结合律运算。三条定律（左单位元、右单位元、结合律）保证了累积的顺序无关——这意味着并行化、增量计算、树形重组都是安全的。

> **洞见二：列表是自由单位半群**。
> 
> `[a]` 在 `++` 下以 `[]` 为单位元，且**只**满足 Monoid 定律，不额外满足交换律等其他方程。"自由"意味着"延迟决定"——你可以先把元素收集到列表，稍后再决定用 `Sum`、`Product` 或其他 Monoid 聚合。所有自由 Monoid 都同构于列表。

> **洞见三：Endo 揭示了"函数组合本身就是 Monoid"**。
> 
> `a -> a` 在 `(.)` 下以 `id` 为单位元构成 Monoid。`Endo` 新类型把这个数学事实提升为类型类实例，使"函数序列的组合"成为 `mconcat` 的自然应用。

> **洞见四：Const 的 Applicative 实例本质上是 Monoid 的 `<>`**。
> 
> 当 `a` 是 Monoid 时，`Const a` 的 `<*>` 完全退化成 `a` 的 `<>`。这意味着 `Const m` 是一个"沉默的累积器"——它忽略映射函数，把所有上下文值用 Monoid 累积。这是第十一章 `Const` 故事的延续，也是第二十二章 `foldMap` 的实现基础。

> **洞见五：Alternative 是"应用函子层面的 Monoid"**。
> 
> `empty` 对应 `mempty`，`<|>` 对应 `<>`。它为应用函子添加了"选择/失败回退"的能力——`Maybe` 的 `<|>` 是"尝试左边，失败回退右边"，列表的 `<|>` 是"非确定性选择的并集"。这是第十五章解析器库的命脉。

> **洞见六：ZipList 展示了 Applicative 的"位置同步"语义**。
> 
> 与普通列表的 `<*>` 是笛卡尔积不同，`ZipList` 的 `<*>` 是位置一一对应。这揭示了"应用函子的效果合并语义由上下文决定"——同一个 `<*>`，在不同应用函子里有完全不同的行为。

> **洞见七：Monoid 与 Applicative 的结合是 Haskell 抽象威力的化学反应**。
> 
> `Const m` 在 `m` 是 Monoid 时成为 Applicative，这让"累积"成为了应用风格编程的一等公民。第十二章的透镜 `view`、第二十二章的 `foldMap`、第二十四章的 `Traversable`——它们的底层都依赖这个组合。

> **洞见八：Monoid 不要求逆元，这明确了它的能力边界**。
> 
> 群（Group）要求逆元，Monoid 不要求。这意味着列表、Endo（非双射函数）等都不是群。理解这个边界，才能理解为什么某些操作（撤销、回滚）需要更强的代数结构。

## 🛠️ 实践建议

1. **用 Monoid 重构累积逻辑**：
    
    ```
    -- 传统方式
    sum = foldr (+) 0
    product = foldr (*) 1
    
    -- Monoid 方式
    sum = getSum . mconcat . map Sum
    product = getProduct . mconcat . map Product
    ```
    
2. **用 Endo 组合函数序列**：
    
    ```
    import Data.Monoid
    
    let transforms = [Endo (+1), Endo (*2), Endo (^2)]
    let combined = mconcat transforms
    appEndo combined 3  -- 16
    ```
    
3. **用 Const 实现累积**：
    
    ```
    -- 统计列表中满足条件的元素个数
    count :: (a -> Bool) -> [a] -> Int
    count p = getSum . mconcat . map (\x -> if p x then Sum 1 else Sum 0)
    
    -- 或用 Const
    count p = getConst . mconcat . map (\x -> Const (if p x then 1 else 0))
    ```
    
4. **用 Alternative 组合解析器（预览第十五章）**：
    
    ```
    import Control.Applicative
    
    digitOrLetter = digit <|> letter
    optionalSpace = space <|> pure ' '
    ```
    
5. **用 ZipList 做向量化运算**：
    
    ```
    import Control.Applicative
    
    -- 向量加法
    liftA2 (+) (ZipList [1,2,3]) (ZipList [10,20,30])  -- ZipList [11,22,33]
    
    -- 多列表同步
    getZipList $ (,,) <$> ZipList [1,2,3] <*> ZipList ['a','b','c'] <*> ZipList [True,False,True]
    -- ZipList [(1,'a',True), (2,'b',False), (3,'c',True)]
    ```
    
6. **验证 Monoid 定律**：
    
    ```
    monoidLaws :: (Monoid m, Eq m) => m -> m -> m -> Bool
    monoidLaws x y z =
      mempty <> x == x &&
      x <> mempty == x &&
      (x <> y) <> z == x <> (y <> z)
    ```

## 🔮 承上启下

第十五章"解析器"会直接建立在 Alternative 之上：

- **`<|>` 实现回退**：`digit <|> letter` 尝试解析数字，失败则尝试解析字母
    
- **`some` 和 `many`**：`many p` 解析零个或多个 `p`，`some p` 解析一个或多个 `p`
    
- **`empty` 实现失败**：解析失败时返回 `empty`
    

更深远的连接：

- **第十六章 Monad**：`(>>=) :: m a -> (a -> m b) -> m b` 是 Applicative 的进一步推广。Alternative 的 `empty` 和 `<|>` 会与 Monad 的 `mzero` 和 `mplus` 对应
    
- **第二十二章 Foldable/Traversable**：`foldMap f = getConst . traverse (Const . f)`——**Const 的 Monoid 实例在这里爆发威力**
    
- **第二十四章 Monad Transformers**：`Const` 和 `Endo` 在 Transformer 栈中扮演关键角色
    

**第十四章是你理解 Haskell "Monoid + Applicative 化学反应"的关键一跃**。吃透 `Const m` 在 `m` 是 Monoid 时成为 Applicative 这一事实，后面的 Traversable、Foldable、解析器就不再是"新的魔法"，而是"我们已经知道的知识的自然延伸"——你已经知道 `Const` 忽略映射函数，现在你知道它用 Monoid 累积值；你已经知道 Alternative 是应用函子层面的 Monoid，现在你知道它是解析器的命脉；你已经知道 ZipList 是"位置同步"的应用函子，现在你知道它是向量化运算的抽象。
