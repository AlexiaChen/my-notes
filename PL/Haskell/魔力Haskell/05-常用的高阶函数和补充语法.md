## 5.1 应用函数 `$` 和 `&`：消灭括号地狱

### 两个运算符的定义

```
($) :: (a -> b) -> a -> b
f $ x = f x
infixr 0 $

(&) :: a -> (a -> b) -> b
x & f = f x
infixr 1 &
```

`$` 的核心是**优先级最低（0）+ 右结合**——这意味着它可以把右边整个表达式"包"起来当作参数传给左边的函数，从而省掉大量括号。

### 🔑 洞见一：`$` 的本质是"函数应用"本身

`$` 的定义 `f $ x = f x` 看起来像废话，但它揭示了一个深刻事实：**函数应用在 Haskell 里就是一个运算符**——空格应用（`f x`）优先级最高，`$` 应用优先级最低。这让你可以在不括号的情况下控制求值顺序：

```
f (g (h x))        -- 传统写法
f $ g $ h x        -- 用 $ 改写
f . g . h $ x      -- 结合 . 使用（后面会讲）
```

### 🔑 洞见二：`&` 是 `$` 的"反向版本"

`&` 把参数放在左边、函数放在右边，形成**从左向右的数据流管道**：

```
3 & (\x -> x + 1) & (\x -> x ^ 2)   -- 16
```

这种"数据从左到右流过一系列变换"的写法，与 Unix shell 的 `cat x | grep y | wc -l` 异曲同工。**`&` 让 Haskell 代码也能拥有管道般的阅读节奏**。

> 💡 实用组合：`$` 用于"从外向内"包裹表达式，`&` 用于"从内向外"流式处理。两者互补，让代码可以根据可读性需求选择方向。

### 🔑 洞见三：`$` 不只是语法糖，它是高阶函数的"粘合剂"

当 `map` 的参数本身是一个一元函数时，`$` 让你能写出：

```
map ($ 3) [(4+), (10*), (^2), sqrt]
-- [7, 30, 9, 1.732...]
```

这里 `($ 3)` 是 `$` 部分应用——得到一个"把 3 传给某个函数"的新函数。这种写法在第六章学 `map` 时会频繁出现。

## 5.2 匿名函数：一次性函数的轻量语法

匿名函数（lambda）的语法：

```
\pattern1 pattern2 ... -> expression

3 & (\x -> x + 1) & (\x -> x ^ 2)
4 & (\x y -> x + y) & (\x -> x ^ 2)
```

### 🔑 洞见四：匿名函数是"函数作为值"的直接体现

Lambda 让你可以**就地构造一个函数值**，而不必给它起名字。这在把函数传给高阶函数时极其方便：

```
-- 需要一个"临时"的谓词函数
filter (\x -> x `mod` 7 == 0) [1..100]

-- 需要一个"临时"的转换函数  
map (\x -> x * x) [1..10]
```

### 🔑 洞见五：Lambda 不是万能的，多数时候它不该出现

这是本章**最重要的实践洞见**。很多初学者滥用 lambda，写出：

```
map (\x -> x + 1) [1..10]   -- 不必要
```

但其实可以写成：

```
map (+1) [1..10]            -- 利用柯里化，更简洁
```

判断标准：**如果 lambda 体只是把一个已知函数的参数换个名字，那就用部分应用代替 lambda**。`\x -> f x` 等价于 `f`，`\x -> x + 1` 等价于 `(+1)`。

> ⚠️ Lambda 里做模式匹配要小心：如果模式匹配失败，会引发运行时错误。所以 lambda 只适合简单的变量绑定，复杂的解构还是用 `case` 或具名函数。

## 5.3 组合函数 `.`：数学复合在代码里的落地

```
(.) :: (b -> c) -> (a -> b) -> a -> c
f . g = \x -> f (g x)
infixr 9 .
```

### 🔑 洞见六：`.` 就是数学里的函数复合 `∘`

数学上 `(g ∘ f)(x) = g(f(x))`，Haskell 里 `(g . f) x = g (f x)`。注意**顺序与数学记号相反**——Haskell 的 `g . f` 意思是"先应用 f，再应用 g"。这是编程语言的常见约定，让代码从左到右读起来像数据流的逆向。

### 🔑 洞见七：`.` 的右结合性让多函数组合无需括号

```
f . g . h  -- 等价于 f . (g . h)
```

这意味着你可以把任意长的函数管道写成一个点链，编译器会自动从右向左结合。

### 🔑 洞见八：`.` 与 `$` 是绝配

```
toEnum . (+1) . fromEnum $ 'a'  :: Char  -- 'b'
```

这里 `.` 把三个函数组合成一个新函数，`$` 把这个新函数应用到 `'a'`。**`.` 负责"纵向"组合函数，`$` 负责"横向"应用结果**——这是 Haskell 代码最经典的形态。

### 实际应用：字符转换管道

```
nextChar :: Char -> Char
nextChar = toEnum . (+1) . fromEnum

-- 等同于 point-full 写法：
nextChar c = toEnum ((+1) (fromEnum c))
```

`.` 版本读起来就像数学定义：`nextChar = toEnum ∘ (+1) ∘ fromEnum`。

## 5.4 函数的补充语法：让函数定义更声明化

### 5.4.1 `where`：本地定义的作用域

```
isListLong xs
  | l > 1000 = "This list is very long"
  | otherwise = "This list is short"
  where l = length xs
```

`where` 把辅助定义放在主函数体**之后**，形成一个本地作用域。它的好处：

- **可读性**：主逻辑在前，细节在后
    
- **作用域**：`where` 里的定义对整个函数体可见（包括所有 guard 分支）
    
- **复用**：同一个辅助定义在多个 guard 中共享
    

### 5.4.2 `guard`：基于条件的分支

Guard 用 `|` 引出条件，比 `if-then-else` 更适合多分支：

```
isListLong xs
  | l > 1000  = "very long"
  | l > 100   = "long"
  | l > 10    = "medium"
  | otherwise = "short"
  where l = length xs
```

**🔑 洞见九：Guard 是"模式匹配的布尔版本"**

模式匹配按"值的形状"分支，guard 按"条件的真假"分支。两者互补：

- 处理"数据结构的不同形态" → 模式匹配
    
- 处理"数值/属性的不同范围" → guard
    

### 5.4.3 `MultiWayIf`：多路 if 表达式

需要在 `if-then-else` 里做多分支时，可以用 `MultiWayIf` 扩展：

```
{-# LANGUAGE MultiWayIf #-}

f x = if | x > 0     -> "positive"
         | x < 0     -> "negative"
         | otherwise -> "zero"
```

它等价于 `case () of _ | x > 0 -> ...`，但更直观。

### 5.4.4 `where` 与 `let` 的区别

```
-- let 表达式：先定义，后使用
let x = y
    y = 4
in x ^ 2

-- where 子句：先使用，后定义
f xs = l ^ 2
  where l = length xs
```

**核心区别**：

- `let` 是**表达式**，可以出现在任何表达式能出现的地方
    
- `where` 是**声明**，只能附着在方程、case 分支等语法结构上
    
- `let` 里的定义**按顺序**互相可见，`where` 里的定义对整个函数体可见
    

> 📌 经验法则：简单的本地绑定用 `where`（更贴近自然语言"这个函数做什么，其中..."）；需要在表达式中局部定义时用 `let`。

## 5.5 Point-free：函数式编程的"极致美学"

Point-free（也称 tacit programming）是指**定义函数时不显式写出参数**：

```
-- Point-full
nextChar c = toEnum . (+1) . fromEnum $ c

-- Point-free  
nextChar = toEnum . (+1) . fromEnum
```

这两者是等价的，源于 **η-转换（eta-conversion）**：`g x = f x` ⟺ `g = f`。

### 🔑 洞见十：Point-free 是柯里化、组合、高阶函数的自然产物

Point-free 不是一种"风格选择"，而是 Haskell 语言特性的**必然推论**：

1. **柯里化**让每个函数都缺一个参数就返回一个新函数
    
2. **函数组合 `.`**​ 让多个函数能合并成一个函数
    
3. **高阶函数**让函数能作为参数传递
    

三者结合，你就可以不断"消去"参数，直到函数定义变成纯粹的函数组合：

```
-- 逐步 point-free 化
f x = sum (map (^2) x)          -- 原始
f x = sum . map (^2) $ x        -- 引入 .
f   = sum . map (^2)            -- η-转换消去 x
```

### 🔑 洞见十一：Point-free 的真正价值是"关注变换而非搬运数据"

Haskell wiki 上说得好：Point-free 让写代码的人和读代码的人**关注函数的组合（高层），而不是数据的搬弄（低层）**。比较：

```
-- Point-full：关注数据 x 怎么变
answer xs = sum (map cube (filter by7 xs))

-- Point-free：关注函数怎么组合
answer = sum . map cube . filter by7
```

Point-free 版本读起来像数学公式：**answer = sum ∘ map(cube) ∘ filter(by7)**。

### 🔑 洞见十二：Point-free 不是银弹

过度使用 point-free 会导致代码难以理解。Haskell wiki 明确指出：

```
-- 这种 point-free 并不改进可读性
complicated = foldr (.) id . map (.)
```

School of Haskell 教程里也有经典反例——IRC 机器人把 `\f g x y -> f (x ++ g x) (g y)` 转换成：

```
join . ((flip . ((.) .)) .) . (. ap (++)) . (.)
```

这显然"不是改进"。

> ⚠️ **使用准则**：
> 
> - 简单函数的清洁组合 → 用 point-free
>     
> - 复杂逻辑、需要中间变量 → 用 point-full
>     
> - 可读性 > 简洁性，永远
>

## 5.6 黑魔法词汇表：建立抽象思维的术语锚点

韩冬在这一节梳理了一批关键术语，它们是后续章节的词汇基础：

|术语|含义|
|---|---|
|**Saturated / Fully applied**​|函数调用时接收全部参数，进入可求值状态|
|**Arity**​|函数的参数数量，如 `+` 的 arity 是 2，`zipWith` 的是 3|
|**Nullary/Unary/Binary/Ternary**​|零元/一元/二元/三元|
|**Closure（闭包）**​|函数体里引用了外围作用域中的自由变量的函数|
|**Combinator（组合子）**​|不包含自由变量的函数|

### 🔑 洞见十三：这些术语是理解后续章节的钥匙

- **Arity**​ 概念直接服务于柯里化理解——知道 `+` 的 arity 是 2，才能理解 `(+1)` 是部分应用后 arity 为 1 的函数
    
- **Closure vs Combinator**​ 的区分，为后面学 Monad、Applicative 时的"纯函数组合"奠定词汇基础
    
- **Saturated**​ 概念与"惰性求值"直接相关——只有完全应用的函数才会真正求值

## 📝 本章核心洞见总结

> **洞见一：`$` 和 `&` 不是语法糖，是"函数应用"作为运算符的体现**。
> 
> 空格应用优先级最高，`$` 优先级最低且右结合，`&` 是反向版本。三者让你在不括号的情况下精确控制求值顺序，形成"从外向内"或"从内向外"的代码节奏。

> **洞见二：`.` 是数学复合 `∘` 的 Haskell 落地，且顺序相反**。
> 
> Haskell 的 `g . f` 表示"先 f 后 g"，这是为了契合从左到右的阅读习惯。`.` 的右结合性让多函数组合无需括号，与 `$` 搭配形成 Haskell 代码最经典的形态。

> **洞见三：匿名函数是"函数作为值"的直接体现，但不应滥用**。
> 
> 如果 lambda 体只是已知函数的参数重命名（`\x -> f x` ≡ `f`），就该用部分应用代替。Lambda 的真正价值在于构造"真正一次性"的函数。

> **洞见四：`where` 与 `let` 的本质区别是语法范畴不同**。
> 
> `let` 是表达式，`where` 是声明。`let` 先定义后使用，`where` 先使用后定义。这个区别决定了它们在不同语境下的适用性。

> **洞见五：Guard 是"布尔版的模式匹配"**。
> 
> 模式匹配按值的形状分支，guard 按条件的真假分支。两者互补，覆盖了函数分支的所有需求。

> **洞见六：Point-free 是柯里化、组合、高阶函数三者结合的必然产物**。
> 
> 它不是一种风格偏好，而是 Haskell 语言特性的推论。Point-free 的真正价值是让人关注"函数组合"而非"数据搬运"——但这不意味着它总是更好，复杂逻辑仍应用 point-full。

> **洞见七：黑魔法词汇表是后续章节的术语锚点**。
> 
> Arity、closure、combinator、saturated 这些概念，会在第七章（类型类）、第九章（惰性求值）、以及后续 Monad/Applicative 的讨论中反复出现。掌握它们，就是掌握函数式编程的"行话"。

## 🛠️ 实践建议

1. **刻意练习 `$` 与 `&` 的互换**：
    
    ```
    -- 同一个逻辑，两种写法
    f $ g $ h x
    x & h & g & f
    ```
    
    体会数据流的两种方向感。
    
2. **Lambda 使用自律**：写 lambda 前先问——"这个函数是不是某个已知函数的部分应用？"如果是，`(+1)` 优于 `\x -> x + 1`。
    
3. **组合函数管道**：遇到 `f (g (h x))` 时，尝试改写为 `f . g . h $ x`。感受代码从"嵌套"变为"管道"的阅读差异。
    
4. **Point-free 的克制**：
    
    - ✅ 用：`doubleAll = map (*2)`、`process = length . filter isAlpha`
        
    - ❌ 不用：过于复杂的组合，需要调试中间值时用 point-full + `where`
        
    
5. **Guard 优先于多层 if-then-else**：当分支超过 2 个时，guard 的可读性明显更好。
    
6. **`where` 与 `let` 的选择**：
    
    - 函数定义里的本地辅助 → `where`
        
    - 表达式内部的局部定义 → `let ... in ...`
