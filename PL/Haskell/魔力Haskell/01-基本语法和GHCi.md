
# 第一章 基本语法和 GHCi —— 读书笔记

> 💡 这一章看似在讲"怎么写 Haskell"，实则是在为整本书埋下三条主线：**一切皆表达式**、**名称只是绑定而非变量**、**函数是头等公民**。后面所有的 data、递归、高阶函数、类型类，都是在这三个支点之上生长出来的。

韩冬在这一章安排了六个小节：注释、表达式、声明、函数、GHCi、初级函数。表面是语法入门，骨子里是在训练一种**全新的编程直觉**——从"命令计算机一步步执行"切换到"描述计算本身是什么"。

六个小节的顺序并非偶然，它对应着一个程序从文本到意义的完整链路：

```
注释 → 表达式 → 声明 → 函数 → GHCi → 初级函数
  │       │        │        │       │       │
```

这条链路的**底层动机**是：Haskell 是一门**纯函数式、惰性求值、强静态类型**的语言。这三个属性决定了它的语法必然长成这样——而不是像 Java/C 那样长成另一种样子。

## 1.1 注释：`--` 与 `{- -}`

语法本身一句话就能说完：单行用 `--`，块注释用 `{- ... -}`。

**值得记取的洞见**：注释不参与求值。这听起来像废话，但对照后面的"表达式"概念会发现——Haskell 把"程序"和"关于程序的说明"切得很干净。**代码即数学陈述，注释只是旁注**。这种二分法贯穿全书：类型声明是代码的一部分（会被编译器检查），注释则完全外置。

---

## 1.2 表达式：Haskell 世界的"原子"

> ⚠️ 这是本章**最重要**的一个概念，没有之一。

书中给出的定义：表达式是有值的式子，例如 `1`、`x+3`、`True`、`sort [2,4,6,1]`。

**为什么"表达式"比"语句"更根本？**

在 C/Java/Python 里，程序是一系列**语句**（statement），执行语句会产生副作用、改变状态。但在 Haskell 里，**一切皆为表达式**——它们求值后得到一个值，且同样的输入永远得到同样的输出（引用透明性，referential transparency）。

这意味着：

- **没有"赋值语句"，只有表达式的求值**
    
- **没有"控制流语句"，`if/else` 也是表达式**（返回一个值，而非跳转）
    
- **没有"循环语句"，迭代靠递归表达式**
    

📌 **连接后续章节**：第三章的递归、第六章的 `map/filter/fold`、第四章的高阶函数——全都是"表达式的组合"。如果你在第一章没吃透"表达式优先"，后面学递归和高阶函数时会一直带着命令式思维的包袱。

**实际应用**：当你看到 `take 5 [1..]` 能正确生成前 5 个自然数而不崩溃，正是因为"表达式"配合"惰性求值"——右边的无限列表只是一个未求值的表达式，左边 `take 5` 只需要其中 5 个值，于是只有 5 个被真正计算。

## 1.3 声明：类型声明、绑定声明、模块声明、导入声明

书中把声明分成四类：

|声明类型|形式|本质|
|---|---|---|
|类型声明|`welcom :: String`|告诉编译器这个表达式的类型|
|绑定声明|`welcom = "hello world"`|给表达式起一个名字|
|模块声明|`module Main where`|划分命名空间|
|导入声明|`import Data.List`|复用其他模块的定义|

### 🔑 关键洞见：Haskell 里没有"变量"，只有"绑定"

书里这句话值得用荧光笔标出：**"Haskell中不存在变量，只存在绑定，任何时刻一个名称对应的表达都是唯一确定的"**。

博客园上的补充解释很到位：绑定一旦建立就不能改变，后面的绑定可以**遮蔽**（shadow）前面的，但不是"修改"。

**为什么这么设计？**

- **不可变性（Immutability）**​ 让引用透明性得以成立
    
- 没有可变状态 → 没有竞态条件 → **天然线程安全**
    
- 可以"等量代换"（equational reasoning）：`x = 3` 出现在任何地方，都可以直接替换成 `3` 而不改变程序含义
    

📌 **连接后续**：第二章的 `data` 声明、第七章的类型类实例声明，本质上都是"声明"这一概念的延伸——给类型起名、给类型类实例绑定实现。第一章建立的"声明"心智模型，是理解全书所有定义的钥匙。

**实际应用**：在金融系统、区块链（如 Cardano）这类对正确性要求极高的领域，不可变性带来的"推理简单性"是 Haskell 被选中的核心理由。

## 1.4 函数：最重要的元素

书中区分了两种函数调用方式：

```
print "hello world"   -- 普通函数调用
2 + 3                 -- 中缀函数调用
(+) 2 3               -- 普通函数调用（中缀转前缀）
```

**底层设计的两个关键点**：

**① 函数是一等公民（first-class citizen）**

函数可以像 `Int`、`String` 一样被传参、被返回、被绑定到名字上。这正是第四章"高阶函数"、第五章"point-free"风格的基础。

**② 所有函数本质上都是单参数的**

类型签名 `a -> b -> c` 实际是 `a -> (b -> c)`——接受一个 `a`，返回一个"接受 `b` 返回 `c` 的函数"。这种**柯里化**（currying）特性在第四章 4.3.2 会专门展开，但它的种子在第一章就已经种下。

**运算符即函数**：`+`、`&&`、`==` 这些中缀运算符，本质上就是函数——所以用括号括起来就能当普通函数用：`(+) 2 3`。反过来，普通函数用反引号括起来就能中缀调用：``3 `elem` [1,2,3]``。

📌 **连接后续**：

- 第四章的高阶函数（`map`、`filter`）→ 函数作为参数
    
- 第五章的 `$`、`&`、`.` → 本身就是（或返回）函数
    
- 第六章的折叠（`foldl`/`foldr`）→ 把函数"累积"应用到列表上
    

**实际应用**：函数作为一等公民，让 Haskell 可以用极小的词汇量表达极强的抽象。比如 `map (+1)` 就是一个"加一函数"被当作值传递给了 `map`。

## 1.5 GHCi：与 Haskell 对话的 REPL

GHCi 是 Glasgow Haskell Compiler interactive 的缩写，本质是一个 **Read-Eval-Print Loop**。常用命令：

- `:l / :load` —— 载入 `.hs` 文件
    
- `:t / :type` —— 查看表达式的类型
    
- `:i / :info` —— 查看绑定的详细信息
    
- `:q / :quit` —— 退出
    

### 为什么 GHCi 值得单独占一节？

因为 GHCi 不只是"运行代码的工具"，它是**观察 Haskell 语义的显微镜**：

**🔬 用 `:t` 观察类型推断**

Haskell 有强大的类型推断（基于 Hindley-Milner 算法），但你随时可以用 `:t` 验证编译器推导出的类型。例如 `:t (>>=)` 会揭示这个 monad 绑定运算符的签名——这是通往后续 Monad 世界的门。

**🔬 用 `:l` 动态加载模块**

GHCi 支持动态加载模块、且与 GHC 编译管线紧密集成——在 REPL 里跑的代码和编译后跑的代码行为一致。这让"探索式编程"成为可能：先在 GHCi 里试验小片段，再整合进大项目。

**🔬 在 GHCi 中 `let` 绑定**

需要注意：在 GHCi 里直接绑定名字时，要写 `let xs = [2,3,4,5]`。这是因为 GHCi 处在"连续的运算过程"中，`:{ :}` 多行模式也是为此服务。

📌 **连接后续**：

- 第七章类型类 → 用 `:t` 和 `:i` 探索类型类的约束
    
- 后续所有章节 → GHCi 是你做实验的沙盒
    

**实际应用**：GHCi 内置调试器，支持断点（`:break`）、单步（`:step`）、查看变量（`:print`）。工业级 Haskell 开发中，GHCi 是日常主力工具，而非玩具。

> 💡 学习建议：养成习惯——每学一个新函数，立刻在 GHCi 里用 `:t` 看它的类型，再用几个例子试它的行为。类型签名是 Haskell 的"说明书"，`:t` 是你的"阅读器"。

## 1.6 初级函数：站在 Prelude 的肩膀上

书中列举了一批"开箱即用"的函数：`id`、`const`、`not`、`(&&)`、`length`、`take`、`reverse`、`elem`、`(==)`、`min`、`tail`、`head` 等。

**为什么这一节很重要？**

因为这些函数大多来自 **Prelude**——Haskell 默认导入的基础模块，随编译器一起发行。它们不是语法，但**感觉上像语法**——这正是 Haskell 的设计哲学：**用库函数模拟语法糖，而非在语言层面硬编码**。

举几个有代表性的：

- `take` / `reverse` / `length` —— 列表操作的基础，第六章会用高阶函数重新"发明"它们
    
- `elem` —— 中缀调用 ``3 `elem` [1,2,3]``，展示函数与运算符的统一
    
- `id` / `const` —— 看似 trivial，却是理解"函数作为值"的最佳入门
    
- `(&&)` / `(==)` —— 中缀函数，用 `:t` 查看会看到 `(==) :: Eq a => a -> a -> Bool`——这里已经出现了**类型类约束**​ `Eq a`，第七章才会展开
    

📌 **连接后续**：

- 第三章递归 → 你会自己实现 `length`、`take` 的递归版本
    
- 第六章 `map/filter/fold` → 这些初级函数大多能用 fold 重新表达
    
- 第七章类型类 → `elem` 的 `Eq a` 约束、`min` 的 `Ord a` 约束，都是类型类的实例

## 📝 本章核心洞见总结

> **洞见一**：Haskell 不是"另一种编程语言"，而是一种**数学思维的编码方式**。表达式、绑定、函数——这三个概念合起来，让你可以像写数学公式一样写程序。

> **洞见二**：**"没有变量"是 Haskell 最反直觉也最强大的设计**。它换来了引用透明性、线程安全、等量代换的推理能力。代价是你需要用递归而非循环、用新绑定而非赋值。

> **洞见三**：GHCi 不只是运行工具，更是**学习工具**。`:t` 让你看见类型的推导，`:l` 让你动态加载模块——它把"类型驱动开发"变成了交互式的探索过程。

> **洞见四**：初级函数来自 Prelude，而 Prelude 是**用 Haskell 自身写的**。这暗示了一个重要事实——Haskell 的"标准库"和你写的代码处于同一地位，没有"内置特权"。理解这一点，你就不会把 `length`、`take` 当成魔法，而是当成"可以用递归和高阶函数自己实现"的普通函数。

## 🛠️ 实践建议

1. **装好 GHC 和 GHCi**，每学一个小节就在 REPL 里敲一遍
    
2. **刻意练习"表达式思维"**：尝试把一段 if-else 逻辑写成一个表达式，把一段循环写成递归
    
3. **用 `:t` 解剖每一个初级函数**：特别是 `id`、`const`、`($)`、`(.)`——它们的类型签名里藏着函数式编程的核心模式
    
4. **记住"绑定不是变量"**：当你本能地想写 `x = x + 1` 时，停下来，问自己——"新的 x 应该叫什么名字？"
