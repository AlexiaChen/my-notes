
# 第三十二章 序列化/反序列化与泛型编程 —— 读书笔记

> 💡 如果说第三十一章讲的是"如何扩展 Haskell 的类型系统"，那么第三十二章讲的是"**如何让 Haskell 的类型系统替你写样板代码**"——序列化（如 JSON）本质上是一种"按数据结构遍历并转换为目标格式"的操作，而泛型编程让你不必为每个数据类型手写这种遍历。表面看是 aeson 库的使用、TH 自动派生、Generic 派生、泛型编程四个主题的罗列，实则在揭示一个深层真相：**Haskell 生态中大量的"类型类实例"都是机械的、可推导的**——`ToJSON`、`FromJSON`、`Show`、`Eq`、`Arbitrary`、`Binary`……这些实例的结构完全由数据类型决定。泛型编程（GHC.Generics）和模板编程（Template Haskell）提供了两种互补的"自动派生"机制，让你只需写 `deriving (Generic, ToJSON, FromJSON)` 或 `$(deriveJSON defaultOptions ''MyType)`，编译器就能生成原本需要几十行手写的代码。

**这一章要解决的核心问题**：如何不为每个数据类型手写序列化代码？

Haskell wikiblog 对泛型编程的定义精准到位 ：

> _"Datatype-generic programming, also frequently just called generic programming or generics in Haskell, is a form of abstraction that allows defining functions that can operate on a large class of datatypes."_

而 aeson 文档则给出了具体的动机 ：

> _"Instead of manually writing your ToJSON instance, there are two options to do it automatically: Data.Aeson.TH provides Template Haskell functions which will derive an instance at compile time... The compiler can provide a default generic implementation for toJSON."_

**🔑 洞见一：序列化是"按结构遍历"的操作**

任何数据类型的 JSON 序列化都可以分解为：

1. **遍历数据结构**：递归地访问每个构造器和字段
    
2. **转换为目标格式**：将每个值映射为 JSON 的 `Value`
    
3. **组装结果**：将映射后的值组装为对象/数组
    

这个过程完全由数据类型的结构决定——这正是泛型编程的用武之地。

## 32.1 aeson 函数库：Haskell 的 JSON 标准

### 核心类型类

aeson 文档定义了两个核心类型类 ：

```
class ToJSON a where
  toJSON :: a -> Value
  toEncoding :: a -> Encoding  -- 更高效的直接编码

class FromJSON a where
  parseJSON :: Value -> Parser a
```

**`Value` 是 JSON 的 AST 表示**：

```
data Value = Object !(HashMap Text Value)
           | Array !(Vector Value)
           | String !Text
           | Number !Scientific
           | Bool !Bool
           | Null
```

### 手写实例

aeson 源码注释给出了经典的 `Person` 示例 ：

```
{-# LANGUAGE OverloadedStrings #-}

data Person = Person 
  { name :: Text
  , age :: Int 
  } deriving Show

-- 手写 ToJSON
instance ToJSON Person where
  toJSON (Person name age) = 
    object ["name" .= name, "age" .= age]
  toEncoding (Person name age) = 
    pairs ("name" .= name <> "age" .= age)

-- 手写 FromJSON
instance FromJSON Person where
  parseJSON = withObject "Person" $ \v -> Person
    <$> v .: "name"
    <*> v .: "age"
```

**关键操作符**：

- `object`：从键值对列表构造 JSON 对象
    
- `.=`：构造键值对（`"name" .= name`）
    
- `pairs`：更高效的编码方式，直接生成 `Encoding`
    
- `.:`：从 JSON 对象中提取字段
    
- `<$>` / `<*>`：Applicative 风格的解析组合
    

### 🔑 洞见二：手写实例暴露了样板代码问题

Monday Morning Haskell 指出 ：

> _"There are many useful typeclasses with a similar pattern to ToJSON and FromJSON. You need the instance to satisfy a library constraint. But the instance you'll write is very boilerplate-y."_

对于一个有 10 个字段的记录类型，手写 `ToJSON` 和 `FromJSON` 实例需要：

- 10 次 `field .= value` 的重复
    
- 10 次 `v .: "field"` 的重复
    
- 构造器和字段名的重复书写
    

**这就是泛型编程要解决的核心痛点**。

### 实际使用

```
{-# LANGUAGE OverloadedStrings #-}
import Data.Aeson
import Data.ByteString.Lazy (ByteString)
import qualified Data.ByteString.Lazy.Char8 as BS

-- 编码
encodePerson :: Person -> ByteString
encodePerson = encode

-- 解码
decodePerson :: ByteString -> Maybe Person
decodePerson = decode

-- 示例
main :: IO ()
main = do
  let p = Person "John Doe" 30
      json = encode p
  BS.putStrLn json  -- {"age":30,"name":"John Doe"}
  
  case decode json of
    Just p' -> print p'  -- Person {name = "John Doe", age = 30}
    Nothing -> putStrLn "Decode failed"
```

### 32.1.1 使用模板编程自动生成 ToJSON/FromJSON 实例

#### deriveJSON 的基本用法

Monday Morning Haskell 给出了清晰的示例 ：

```
{-# LANGUAGE TemplateHaskell #-}
import Data.Aeson.TH (deriveJSON, defaultOptions)

data Person = Person 
  { name :: String
  , age :: Int
  , occupation :: Occupation
  } deriving (Show)

data Occupation = Occupation 
  { title :: String
  , tenure :: Int
  , salary :: Int
  } deriving (Show)

-- 关键：用 TH 生成实例
deriveJSON defaultOptions ''Occupation
deriveJSON defaultOptions ''Person
```

**🔑 洞见三：TH 派生的本质是编译期代码生成**

Monday Morning Haskell 解释 ：

> _"Template Haskell is another compiler extension allowing GHC to generate code for you... Data.Aeson is one of these libraries... you can use the simple function deriveJSON on your type. This will give you some spiffy new ToJSON and FromJSON instances."_

`deriveJSON` 在编译期展开为：

```
instance ToJSON Person where
  toJSON (Person name age occupation) = 
    object [ "name" .= name
           , "age" .= age
           , "occupation" .= occupation ]

instance FromJSON Person where
  parseJSON = withObject "Person" $ \v -> Person
    <$> v .: "name"
    <*> v .: "age"
    <*> v .: "occupation"
```

#### Options 定制

Monday Morning Haskell 展示了 `Options` 的强大 ：

```
-- 字段名前缀定制
deriveJSON (defaultOptions 
  { fieldLabelModifier = ("person_" ++) }) ''Person
deriveJSON (defaultOptions 
  { fieldLabelModifier = ("occupation_" ++) }) ''Occupation

-- 生成的 JSON：
-- {"person_name":"John Doe","person_age":26,
--  "person_occupation":{"occupation_title":"teacher",
--                       "occupation_tenure":5,
--                       "occupation_salary":60000}}
```

aeson TH 文档列出了完整的 `Options` 字段 ：

|选项|类型|默认值|作用|
|---|---|---|---|
|`fieldLabelModifier`|`String -> String`|`id`|字段名转换|
|`constructorTagModifier`|`String -> String`|`id`|构造器标签转换|
|`allNullaryToStringTag`|`Bool`|`True`|空构造器编码为字符串|
|`omitNothingFields`|`Bool`|`False`|省略 `Nothing` 字段|
|`sumEncoding`|`SumEncoding`|`TaggedObject`|和类型的编码方式|
|`unwrapUnaryRecords`|`Bool`|`False`|解包单字段记录|
|`tagSingleConstructors`|`Bool`|`False`|为单构造器类型加标签|

#### 派生函数的层次

aeson TH 文档给出了完整的函数层次 ：

```
-- 生成 ToJSON 和 FromJSON 实例
deriveJSON :: Options -> Name -> Q [Dec]

-- 仅生成 ToJSON
deriveToJSON :: Options -> Name -> Q [Dec]

-- 仅生成 FromJSON
deriveFromJSON :: Options -> Name -> Q [Dec]

-- 生成 ToJSON1/FromJSON1（用于带类型参数的构造器）
deriveJSON1 :: Options -> Name -> Q [Dec]
deriveJSON2 :: Options -> Name -> Q [Dec]

-- 生成表达式而非实例
mkToJSON :: Options -> Name -> Q Exp
mkParseJSON :: Options -> Name -> Q Exp]
```

#### 🔑 洞见四：TH 派生的优势与代价

Monday Morning Haskell 客观指出 ：

> _"Template Haskell can be convenient. It reduces the amount of boilerplate code you have to write. But it will also make your code take longer to compile. There's also a price in accessibility when you use template Haskell. Most Haskell newbies will recognize deriving syntax. But if you use deriveJSON, they might be scratching their heads wondering where exactly you've defined the JSON instances."_

**优势**：

1. **生成代码针对具体类型优化**，性能通常优于 Generic 派生
    
2. **高度可定制**：通过 `Options` 完全控制 JSON 格式
    
3. **支持数据家族和元组**：`$(deriveJSON defaultOptions 'DF1)`
    

**代价**：

1. **编译时间增加**：TH 在编译期执行元程序
    
2. **可读性降低**：实例"隐形"地定义在别处
    
3. **调试困难**：展开后的代码不在源码中
    

### 实际应用

```
{-# LANGUAGE TemplateHaskell #-}
{-# LANGUAGE OverloadedStrings #-}
import Data.Aeson.TH
import Data.Aeson
import Data.ByteString.Lazy (ByteString)

-- 1. 基础 TH 派生
data User = User
  { userName :: String
  , userAge :: Int
  , userEmail :: Maybe String
  } deriving Show

deriveJSON defaultOptions ''User

-- 2. 定制 Options
data ApiResponse a = ApiResponse
  { statusCode :: Int
  , data_ :: a
  , errorMessage :: Maybe String
  } deriving Show

deriveJSON (defaultOptions 
  { fieldLabelModifier = \case
      "data_" -> "data"
      s -> s
  , omitNothingFields = True
  }) ''ApiResponse

-- 3. 和类型的定制编码
data Event 
  = UserLoggedIn String
  | UserLoggedOut String
  | ClickEvent String String
  deriving Show

deriveJSON (defaultOptions 
  { constructorTagModifier = map toLower
  , sumEncoding = TaggedObject "event_type" "event_data"
  }) ''Event

-- 生成的 JSON 示例：
-- {"event_type":"userloggedin","event_data":"alice"}
-- {"event_type":"clickevent","event_data":["button","submit"]}

-- 4. 使用派生的实例
encodeUser :: User -> ByteString
encodeUser = encode

decodeUser :: ByteString -> Maybe User
decodeUser = decode

-- 5. 在 Web 服务中使用（结合第二十七章）
-- 假设用 WAI 构建 API
apiHandler :: User -> ByteString
apiHandler user = encode $ ApiResponse 200 user Nothing
```

### 32.1.2 使用泛型提供的 ToJSON/FromJSON

#### Generic 派生的三步法

Monday Morning Haskell 给出了最简洁的路径 ：

```
{-# LANGUAGE DeriveGeneric #-}
{-# LANGUAGE DeriveAnyClass #-}

import GHC.Generics

data Person = Person
  { name :: String
  , age :: Int
  , occupation :: Occupation
  } deriving (Show, Generic, ToJSON, FromJSON)

data Occupation = Occupation
  { title :: String
  , tenure :: Int
  , salary :: Int
  } deriving (Show, Generic, ToJSON, FromJSON)
```

**🔑 洞见五：Generic 派生是"声明式"的**

仅需三步：

1. **启用扩展**：`DeriveGeneric` + `DeriveAnyClass`
    
2. **派生 Generic**：`deriving (Generic)`
    
3. **派生目标类型类**：`deriving (ToJSON, FromJSON)`
    

aeson 文档解释了背后的机制 ：

> _"The compiler can provide a default generic implementation for toJSON. To use the second, simply add a deriving Generic clause to your datatype and declare a ToJSON instance for your datatype without giving definitions for toJSON or toEncoding."_

#### 手动控制 Generic 派生

如果需要定制 `Options`，可以显式使用 `genericToJSON` 和 `genericToEncoding` ：

```
{-# LANGUAGE DeriveGeneric #-}
import GHC.Generics
import Data.Aeson

data Coord = Coord { x :: Double, y :: Double }
  deriving Generic

instance ToJSON Coord where
  toJSON = genericToJSON defaultOptions
  toEncoding = genericToEncoding defaultOptions

instance FromJSON Coord where
  parseJSON = genericParseJSON defaultOptions
```

aeson 文档特别强调了 `toEncoding` 的重要性 ：

> _"The toEncoding function is a relatively new addition to this class... Our one-liner definition of toEncoding above bypasses the intermediate Value. This provides source-level compatibility for people upgrading from older versions of this library, but obviously offers no performance advantage. To benefit from direct encoding, you must provide an implementation for this method."_

**🔑 洞见六：Generic 派生的性能特征**

aeson 文档明确指出 ：

> _"The generated instance is optimized for your type so will probably be more efficient than the following two options"_

但这里的"two options"指的是 Generic 派生的默认实现。实际上：

- **TH 派生**：针对具体类型生成特化代码，**性能最优**
    
- **Generic 派生**：通过 GHC.Generics 框架，**性能略低于 TH 但差距很小**
    
- **手写实例**：取决于手写质量
    

#### DerivingVia：更现代的语法

Haskell 文档提到了 `DerivingVia` 扩展 ：

```
{-# LANGUAGE DeriveGeneric #-}
{-# LANGUAGE DerivingVia #-}
import GHC.Generics

data Person = Person
  { name :: String
  , age :: Int
  } deriving (Show, Generic)
    deriving (ToJSON, FromJSON) via Generically Person
```

#### 🔑 洞见七：Generic 派生 vs TH 派生

|维度|Generic 派生|TH 派生|
|---|---|---|
|语法|`deriving (Generic, ToJSON, FromJSON)`|`$(deriveJSON opts ''Type)`|
|编译速度|快|慢（TH 在编译期运行）|
|运行时性能|略低于 TH|最优（针对类型特化）|
|定制能力|通过 `genericToJSON` 显式指定 Options|通过 `Options` 参数|
|可读性|高（声明式）|低（实例隐形）|
|调试难度|低|高|

Monday Morning Haskell 总结 ：

> _"There are many useful typeclasses with a similar pattern to ToJSON and FromJSON... You can get a lot of these instances by using the Generic typeclass together with DeriveAnyClass. The second route involves writing Template Haskell."_

### 实际应用

```
{-# LANGUAGE DeriveGeneric #-}
{-# LANGUAGE DeriveAnyClass #-}
{-# LANGUAGE OverloadedStrings #-}
import GHC.Generics
import Data.Aeson
import Data.Text (Text)
import Data.ByteString.Lazy (ByteString)

-- 1. 最简 Generic 派生
data User = User
  { userId :: Int
  , userName :: Text
  , userEmail :: Maybe Text
  , userAge :: Int
  } deriving (Show, Eq, Generic, ToJSON, FromJSON)

-- 2. 定制 Options 的 Generic 派生
data Product = Product
  { productName :: Text
  , productPrice :: Double
  , productTags :: [Text]
  } deriving (Show, Generic)

instance ToJSON Product where
  toJSON = genericToJSON defaultOptions 
    { fieldLabelModifier = \s -> 
        case s of
          "productName" -> "name"
          "productPrice" -> "price"
          "productTags" -> "tags"
          _ -> s
    , omitNothingFields = True
    }

instance FromJSON Product where
  parseJSON = genericParseJSON defaultOptions 
    { fieldLabelModifier = \s ->
        case s of
          "name" -> "productName"
          "price" -> "productPrice"
          "tags" -> "productTags"
          _ -> s
    }

-- 3. 嵌套类型的 Generic 派生
data Order = Order
  { orderId :: Int
  , orderUser :: User
  , orderProducts :: [Product]
  , orderTotal :: Double
  } deriving (Show, Generic, ToJSON, FromJSON)

-- 4. 和类型的 Generic 派生
data Notification 
  = EmailNotification Text Text  -- 收件人, 内容
  | SMSNotification Text Text    -- 手机号, 内容
  | PushNotification Text Text Text  -- 设备ID, 标题, 内容
  deriving (Show, Generic, ToJSON, FromJSON)

-- 默认编码为：{"EmailNotification":["alice@example.com","Hello"]}
-- 可以通过 sumEncoding 定制

instance ToJSON Notification where
  toJSON = genericToJSON defaultOptions
    { constructorTagModifier = \s -> 
        case s of
          "EmailNotification" -> "email"
          "SMSNotification" -> "sms"
          "PushNotification" -> "push"
          _ -> s
    , sumEncoding = TaggedObject "type" "data"
    }

-- 5. 使用
encodeUser :: User -> ByteString
encodeUser = encode

decodeOrder :: ByteString -> Maybe Order
decodeOrder = decode

main :: IO ()
main = do
  let user = User 1 "Alice" (Just "alice@example.com") 30
      product = Product "Haskell Book" 49.99 ["book", "programming"]
      order = Order 1001 user [product] 49.99
  
  let json = encode order
  BS.putStrLn json
  
  case decode json of
    Just order' -> print order'
    Nothing -> putStrLn "Failed to decode"
```

## 32.2 泛型：按结构遍历的抽象机制

### 泛型编程的本质

Haskell wikiblog 的定义 ：

> _"Datatype-generic programming... is a form of abstraction that allows defining functions that can operate on a large class of datatypes."_

**关键洞察**：`length` 函数可以同时用于列表和树 ：

```
-- 列表的长度
length :: List a -> Int
length Nil = 0
length (Cons _ t) = 1 + length t

-- 树的大小（同样是"长度"的概念）
size :: Tree a -> Int
size Leaf = 0
size (Bin _ l r) = 1 + size l + size r
```

**泛型编程允许定义一个统一的 `length`**，可以操作列表、树以及许多其他数据类型 。

### GHC.Generics 的核心机制

GHC 用户指南揭示了泛型的核心 ：

> _"Generic programming support in GHC allows defining classes with methods that do not need a user specification when instantiating: the method body is automatically derived by GHC."_

#### 表示类型（Representation Types）

GHC.Generics 定义了几个原始类型来表示 Haskell 数据类型 ：

```
-- 单元：用于无参数的构造器
data U1 p = U1

-- 常量、附加参数和递归
newtype K1 i c p = K1 { unK1 :: c }

-- 元信息（构造器名等）
newtype M1 i c f p = M1 { unM1 :: f p }

-- 和：编码构造器之间的选择
infixr 5 :+:
data (:+:) f g p = L1 (f p) | R1 (g p)

-- 积：编码构造器的多个参数
infixr 6 :*:
data (::) f g p = f p :*: g p
```

#### Generic 类型类

GHC 用户指南 ：

```
class Generic a where
  type Rep a :: Type -> Type
  from :: a -> (Rep a) x
  to :: (Rep a) x -> a
```

**🔑 洞见八：Generic 类型类是用户类型与表示类型的桥梁**

`from` 将用户数据类型转换为其泛型表示，`to` 反之。GHC 用户指南给出了 `UserTree` 的示例 ：

```
data UserTree a = Node a (UserTree a) (UserTree a) | Leaf

-- GHC 自动生成的表示
type Rep (UserTree a) = 
  M1 D ('MetaData "UserTree" "Main" "package-name" 'False) (
    M1 C ('MetaCons "Node" 'PrefixI 'False) (
      M1 S ('MetaSel 'Nothing ...) (K1 R a) 
      :*: M1 S ('MetaSel 'Nothing ...) (K1 R (UserTree a))
      :*: M1 S ('MetaSel 'Nothing ...) (K1 R (UserTree a))
    ) 
    :+: M1 C ('MetaCons "Leaf" 'PrefixI 'False) U1
  )
```

#### 编写泛型函数

GHC 用户指南 ：

> _"A generic function is defined by creating a class and giving instances for each of the representation types of GHC.Generics."_

以 `Serialise` 类为例 ：

```
class Serialise a where
  put :: a -> [Bit]

-- 为表示类型编写实例
class GSerialise f where
  gput :: f a -> [Bit]

-- U1: 无参数的构造器
instance GSerialise U1 where
  gput U1 = []

-- K1: 常量（递归到底层类型）
instance (Serialise c) => GSerialise (K1 i c) where
  gput (K1 x) = put x

-- M1: 元信息，直接穿透
instance (GSerialise f) => GSerialise (M1 i c f) where
  gput (M1 x) = gput x

-- (:+:): 和类型（多个构造器）
instance (GSerialise f, GSerialise g) => GSerialise (f :+: g) where
  gput (L1 x) = O : gput x
  gput (R1 x) = I : gput x

-- (:*:): 积类型（多个参数）
instance (GSerialise f, GSerialise g) => GSerialise (f :*: g) where
  gput (x :*: y) = gput x ++ gput y

-- 最终的用户接口
instance (Generic a, GSerialise (Rep a)) => Serialise a where
  put = gput . from
```

### 🔑 洞见九：泛型编程的三个步骤

1. **定义表示类型类**（`GSerialise f`）：为 `U1`、`K1`、`M1`、`:+:`、`:*:` 编写实例
    
2. **定义用户接口类型类**（`Serialise a`）：使用 `DefaultSignatures` 或空实例 + `Generic` 约束
    
3. **用户数据类型派生 `Generic`**：`data MyType = ... deriving (Generic)`
    

这样，当用户写 `data UserTree a = ... deriving (Generic)` 时，GHC 自动生成 `Rep UserTree`，而 `put` 函数通过 `gput . from` 自动工作。

### DefaultSignatures：连接泛型与用户接口

GHC 用户指南 ：

> _"Using a combination of DeriveGeneric, DefaultSignatures, and DeriveAnyClass, you can easily do datatype-generic programming using the GHC.Generics framework."_

```
class Serialise a where
  put :: a -> [Bit]
  default put :: (Generic a, GSerialise (Rep a)) => a -> [Bit]
  put = gput . from
```

**`default` 签名**让 GHC 在有 `Generic` 实例时自动使用泛型实现。

### 🔑 洞见十：aeson 的 Generic 派生正是这一机制的应用

aeson 的 `ToJSON` 类型类内部使用了 `DefaultSignatures`：

```
class ToJSON a where
  toJSON :: a -> Value
  default toJSON :: (Generic a, GToJSON (Rep a)) => a -> Value
  toJSON = genericToJSON defaultOptions
```

当用户写 `deriving (ToJSON)`（配合 `DeriveAnyClass`）或 `instance ToJSON MyType`，GHC 自动使用 `genericToJSON`。

### 泛型编程的广泛应用

Haskell 文档总结了泛型编程的典型应用 ：

> _"Generic programming is a way of automatically deriving useful typeclass instances for custom datatypes... Haskell can automatically work out how to do things like: serialize data, parse it (from JSON, from command line args), memoize functions, sort and group, write lenses, generate examples for property tests."_

具体场景：

1. **序列化/反序列化**：aeson 的 ToJSON/FromJSON、binary 的 Binary
    
2. **命令行参数解析**：`options-generic` 库
    
3. **快速排序/分组**：`discrimination` 库
    
4. **Lens 生成**：`generic-lens` 库
    
5. **测试数据生成**：QuickCheck 的 `Arbitrary` via `Generic`
    
6. **记忆化**：`memotrie` 库
    

### 实际应用：编写自己的泛型函数

```
{-# LANGUAGE DeriveGeneric #-}
{-# LANGUAGE DefaultSignatures #-}
{-# LANGUAGE TypeOperators #-}
{-# LANGUAGE FlexibleContexts #-}
import GHC.Generics

-- 1. 统计构造器中字段的数量
class CountFields a where
  countFields :: a -> Int
  default countFields :: (Generic a, GCountFields (Rep a)) => a -> Int
  countFields = gCountFields . from

class GCountFields f where
  gCountFields :: f a -> Int

-- U1: 无字段
instance GCountFields U1 where
  gCountFields _ = 0

-- K1: 一个字段
instance GCountFields (K1 i c) where
  gCountFields _ = 1

-- M1: 穿透
instance (GCountFields f) => GCountFields (M1 i c f) where
  gCountFields (M1 x) = gCountFields x

-- (:+:): 和类型，取最大
instance (GCountFields f, GCountFields g) => GCountFields (f :+: g) where
  gCountFields (L1 x) = gCountFields x
  gCountFields (R1 x) = gCountFields x

-- (:*:): 积类型，求和
instance (GCountFields f, GCountFields g) => GCountFields (f :*: g) where
  gCountFields (x :*: y) = gCountFields x + gCountFields y

-- 使用
data Person = Person
  { name :: String
  , age :: Int
  , email :: String
  } deriving (Generic, Show)

data Pair a b = Pair a b deriving (Generic, Show)

main :: IO ()
main = do
  let p = Person "Alice" 30 "alice@example.com"
  print $ countFields p  -- 3
  
  let pair = Pair 42 "answer"
  print $ countFields pair  -- 2

-- 2. 提取所有字段名
class FieldNames a where
  fieldNames :: a -> [String]
  default fieldNames :: (Generic a, GFieldNames (Rep a)) => a -> [String]
  fieldNames = gFieldNames . from

class GFieldNames f where
  gFieldNames :: f a -> [String]

instance GFieldNames U1 where
  gFieldNames _ = []

instance (GFieldNames f, GFieldNames g) => GFieldNames (f :+: g) where
  gFieldNames (L1 x) = gFieldNames x
  gFieldNames (R1 x) = gFieldNames x

instance (GFieldNames f, GFieldNames g) => GFieldNames (f :*: g) where
  gFieldNames (x :*: y) = gFieldNames x ++ gFieldNames y

instance (GFieldNames f) => GFieldNames (M1 i c f) where
  gFieldNames (M1 x) = gFieldNames x

-- 对于含字段名的 M1 S (MetaSel (Just name) ...) (K1 ...)
instance (KnownSymbol name) => GFieldNames (M1 S ('MetaSel ('Just name) ...) (K1 i c)) where
  gFieldNames _ = [symbolToString (Proxy :: Proxy name)]
  where
    symbolToString :: KnownSymbol s => Proxy s -> String
    symbolToString _ = symbolVal (Proxy :: Proxy s)

-- 3. 泛型 JSON 定制（简化版）
class GToJSON' f where
  gToJSON' :: f a -> [(Text, Value)]

instance GToJSON' U1 where
  gToJSON' _ = []

instance (ToJSON c) => GToJSON' (K1 i c) where
  gToJSON' (K1 x) = [("value", toJSON x)]

-- 4. 结合 aeson 的完整泛型派生

import GHC.Generics
import Data.Aeson

data Config = Config
  { configHost :: String
  , configPort :: Int
  , configDebug :: Bool
  } deriving (Show, Generic)

-- 最简派生
instance ToJSON Config where

    { fieldLabelModifier = drop 6 }  -- 去掉 "config" 前缀
  toEncoding = genericToEncoding defaultOptions 
    { fieldLabelModifier = drop 6 }

  parseJSON = genericParseJSON defaultOptions 
    { fieldLabelModifier = ("config" ++) }  -- 添加 "config" 前缀

## 📝 本章核心洞见总结

> **洞见一：序列化是"按结构遍历"的操作**。
> 
> 任何数据类型的 JSON 序列化都可以分解为：遍历数据结构、转换为目标格式、组装结果——这个过程完全由数据类型的结构决定 。**这正是泛型编程的用武之地**。

> **洞见二：aeson 提供两种自动派生路径**。
> 
> aeson 文档："Instead of manually writing your ToJSON instance, there are two options to do it automatically: Data.Aeson.TH provides Template Haskell functions... The compiler can provide a default generic implementation" 。**TH 派生 vs Generic 派生，各有优劣**。

> **洞见三：TH 派生的本质是编译期代码生成**。
> 
> Monday Morning Haskell："Template Haskell is another compiler extension allowing GHC to generate code for you... you can use the simple function deriveJSON on your type" 。**`deriveJSON defaultOptions ''Person` 在编译期展开为完整的实例定义**。

> **洞见四：TH 派生高度可定制但代价明显**。
> 
> Monday Morning Haskell："Template Haskell can be convenient... But it will also make your code take longer to compile. There's also a price in accessibility" 。**优势**：性能最优、定制能力强；**代价**：编译慢、可读性低、调试难 。

> **洞见五：Generic 派生是声明式的**。
> 
> Monday Morning Haskell："You can get a lot of these instances by using the Generic typeclass together with DeriveAnyClass" 。**三步法**：启用 `DeriveGeneric` + `DeriveAnyClass`、派生 `Generic`、派生目标类型类 。

> **洞见六：Generic 派生通过 DefaultSignatures 工作**。
> 
> aeson 文档："The compiler can provide a default generic implementation for toJSON. To use the second, simply add a deriving Generic clause to your datatype and declare a ToJSON instance... without giving definitions for toJSON or toEncoding" 。**`genericToJSON` 和 `genericToEncoding` 是默认实现**。

> **洞见七：toEncoding 关乎性能**。
> 
> aeson 文档："The toEncoding function is a relatively new addition... Our one-liner definition of toEncoding above bypasses the intermediate Value" 。**直接实现 `toEncoding` 可避免中间 `Value` 转换，提升性能**。

> **洞见八：泛型编程定义"对一大类数据类型操作的函数"**。
> 
> Haskell wikiblog："Datatype-generic programming... is a form of abstraction that allows defining functions that can operate on a large class of datatypes" 。**一个 `length` 函数可以同时用于列表和树**​ 。

> **洞见九：GHC.Generics 用表示类型编码数据结构**。
> 
> GHC 用户指南："data U1 p = U1... newtype K1 i c p = K1... data (:+:) f g p = L1 (f p) | R1 (g p)... data (::) f g p = f p :_: g p" 。__和类型用 `:+:` 表示构造器选择，积类型用 `:*:` 表示构造器参数_*。

> **洞见十：Generic 类型类是用户类型与表示类型的桥梁**。
> 
> GHC 用户指南："class Generic a where type Rep a :: Type -> Type; from :: a -> (Rep a) x; to :: (Rep a) x -> a" 。**`from` 转换用户类型到表示类型，`to` 反向转换**。

> **洞见十一：泛型函数分三层**。
> 
> GHC 用户指南："A generic function is defined by creating a class and giving instances for each of the representation types" 。**①为表示类型编写泛型函数类 ②定义用户接口类型类并用 `default` 签名 ③用户数据类型 `deriving (Generic)`**。

> **洞见十二：DefaultSignatures 连接泛型与用户接口**。
> 
> GHC 用户指南："Using a combination of DeriveGeneric, DefaultSignatures, and DeriveAnyClass, you can easily do datatype-generic programming" 。**`default put :: (Generic a, GSerialise (Rep a)) => a -> [Bit]; put = gput . from`**​ 。

> **洞见十三：aeson 的 Generic 派生正是泛型机制的应用**。
> 
> aeson 内部使用 `DefaultSignatures`：`class ToJSON a where toJSON :: a -> Value; default toJSON :: (Generic a, GToJSON (Rep a)) => a -> Value; toJSON = genericToJSON defaultOptions` 。**用户写 `deriving (ToJSON)`，GHC 自动使用 `genericToJSON`**。

> **洞见十四：泛型编程应用广泛**。
> 
> Haskell 文档："Generic programming is a way of automatically deriving useful typeclass instances... serialize data, parse it, memoize functions, sort and group, write lenses, generate examples for property tests" 。**aeson、binary、options-generic、QuickCheck、generic-lens 等都基于泛型**。

> **洞见十五：TH 派生与 Generic 派生的选择**。
> 
> **简单场景用 Generic 派生**（简洁、编译快）；**需要精细定制或追求极致性能用 TH 派生**（针对类型特化、Options 灵活）。两者都远优于手写实例。

## 🛠️ 实践建议

1. **日常开发首选 Generic 派生**：
    
    ```
    {-# LANGUAGE DeriveGeneric #-}
    {-# LANGUAGE DeriveAnyClass #-}
    
    import GHC.Generics
    import Data.Aeson
    
    data User = User
      { userId :: Int
      , userName :: Text
      , userEmail :: Maybe Text
      } deriving (Show, Eq, Generic, ToJSON, FromJSON)
    ```
    
2. **需要定制 JSON 格式时用 Generic + 显式 Options**：
    
    ```
    {-# LANGUAGE DeriveGeneric #-}
    {-# LANGUAGE OverloadedStrings #-}
    
    import GHC.Generics
    import Data.Aeson
    
    data Config = Config
      { host :: String
      , port :: Int
      , debug :: Bool
      } deriving (Show, Generic)
    
    instance ToJSON Config where
      toJSON = genericToJSON defaultOptions 
        { fieldLabelModifier = \s -> 
            if s == "debug" then "debug_mode" else s
        , omitNothingFields = True
        }
      toEncoding = genericToEncoding defaultOptions 
        { fieldLabelModifier = \s -> 
            if s == "debug" then "debug_mode" else s
        , omitNothingFields = True
      }
    
    instance FromJSON Config where
      parseJSON = genericParseJSON defaultOptions 
        { fieldLabelModifier = \s -> 
            if s == "debug_mode" then "debug" else s
        }
    ```
    
3. **需要极致性能或复杂定制时用 TH 派生**：
    
    ```
    {-# LANGUAGE TemplateHaskell #-}
    
    import Data.Aeson.TH
    
    data Event 
      = UserLogin String
      | UserLogout String
      | PageView String String
      deriving Show
    
    deriveJSON (defaultOptions 
      { constructorTagModifier = \s ->
          case s of
            "UserLogin" -> "user_login"
            "UserLogout" -> "user_logout"
            "PageView" -> "page_view"
            _ -> s
      , sumEncoding = TaggedObject "event" "params"
      , fieldLabelModifier = const "value"
      }) ''Event
    ```
    
4. **在 Web 服务中集成 aeson**（结合第二十七章）：
    
    ```
    {-# LANGUAGE DeriveGeneric #-}
    {-# LANGUAGE OverloadedStrings #-}
    
    import Network.Wai
    import Network.Wai.Handler.Warp
    import Data.Aeson
    import GHC.Generics
    import Data.ByteString.Lazy (toStrict, fromStrict)
    
    data ApiRequest = ApiRequest
      { requestAction :: String
      , requestData :: Value
      } deriving (Generic, ToJSON, FromJSON)
    
    data ApiResponse = ApiResponse
      { responseStatus :: Int
      , responseData :: Value
      } deriving (Generic, ToJSON, FromJSON)
    
    app :: Application
    app req respond = do
      body <- strictRequestBody req
      case decode (fromStrict body) of
        Just (ApiRequest action data_) -> do
          let result = processAction action data_
              resp = ApiResponse 200 (toJSON result)
          respond $ responseLBS status200 
            [("Content-Type", "application/json")]
            (toStrict $ encode resp)
        Nothing -> 
          respond $ responseLBS status400 
            [("Content-Type", "application/json")]
            (toStrict $ encode $ ApiResponse 400 (toJSON ("Invalid request" :: String)))
    
    main :: IO ()
    main = run 8080 app
    ```
