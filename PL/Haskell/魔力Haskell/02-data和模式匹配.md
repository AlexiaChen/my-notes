
# 第二章 data 和模式匹配 —— 读书笔记

> 💡 如果说第一章教你用 Haskell 提供的"词汇"说话，那么第二章就是教你**创造词汇**——用 `data` 定义属于自己的世界，再用模式匹配在这个世界里做结构化的推理。这一章之后，你将不再受限于 `Int`、`Bool`、`String`，而是能把任何领域的概念直接"刻"进类型系统里。

韩冬在这一章安排了四个小节：数据声明 `data`、模式匹配（含"无处不在的模式匹配"与 `@pattern`）、各式各样的数据类型（多构造函数 / 完备性检查 / 无参构造函数 / 类型变量 / 记录语法）、排版规则。表面看是语法教学，实则在铺两条底层主线：**代数数据类型（ADT）是 Haskell 表达力的源泉**，**模式匹配是函数式编程"按结构思考"的核心方法**。

## 2.1 数据声明 `data`：把领域"刻"进类型

最基础的形态：

```
data Bool = False | True
```

这一行做了三件事：

1. 声明了一个**类型**​ `Bool`
    
2. 声明了两个**构造函数**（data constructor）：`False` 和 `True`
    
3. 规定了 `Bool` 类型的值**只能是**这两个构造函数之一
    

### 🔑 洞见一：ADT 是"和类型"与"积类型"的代数组合

这是本章**最值得深挖**的底层设计。Haskell 从 Miranda 继承了一个核心思想：把代数数据类型定义为"**乘积之和**"（sum of products）。

- **和类型（Sum Type / 二选一）**：`False | True` —— 对应集合论的**并集**。一个值要么是这个、要么是那个。
    
- **积类型（Product Type / 同时有）**：构造函数带多个参数，`data Point = Pt Float Float` —— 对应集合论的**笛卡尔积**。一个值同时包含多个字段。
    

两者组合，就能表达任意复杂的结构。比如二叉树：

```
data Tree a = Leaf a | Branch (Tree a) (Tree a)
```

代数地看，这就是方程 **T = A + T × T**​ 的最小解：一个树要么是一片叶子（包含一个值），要么是一个分支（包含两个子树）。**这种"代数视角"不是数学家的玩具，而是 Haskell 编译器做优化的理论基础**——基于代数的 fold/unfold 变换定律，编译器可以做"deforestation"（消除中间数据结构）。

### 🔑 洞见二：用 `data` 消灭"空指针异常"

这是 Haskell 设计中极具革命性的一点。在其他语言里，"可能没有值"通常用 `null` 表示，运行时一不小心就 `NullPointerException`。Haskell 的做法是——**把"可能为空"这件事直接编码进类型**：

```
data Maybe a = Nothing | Just a
```

数学上，`Maybe A ≅ A ∪ {⊥}`——所有 `A` 的值，加上一个特殊的"无值"标记。

为什么这么设计？看一个除法函数：

```
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv x y = Just (x `div` y)
```

**"可能失败"这件事现在写在类型签名里了**。调用者拿到 `Maybe Int`，编译器**强制**他处理 `Nothing` 的情况——这就从源头消灭了一整类运行时错误。

> 💡 ADT 填补了静态类型语言的一个重大安全漏洞：没有向下转型、没有 `NullPointerException`。一个值"可能是 A、可能是 B、也可能是 C"这种结构在编程中无处不在，而 ADT 用一行代码就能简洁地表达它。

### 🔑 洞见三：`data` 与"声明"的呼应

回到第一章学的"声明"概念——`data` 声明其实是类型声明的一种进化：它不仅给类型起了名字，还**定义了这个类型的值空间**。这与第一章"表达式有类型、声明给表达式命名"一脉相承，但更进一步：**你不再是类型系统的使用者，而是类型系统的创造者**。

## 2.2 模式匹配：按结构思考的"手术刀"

光有 `data` 还不够，你得能**拆解**构造出来的值。这就是模式匹配。

### 匹配机制的本质

Haskell 报告中明确规定：模式匹配**自顶向下、从左到右**进行，结果有三种——成功（绑定变量）、失败（尝试下一个方程）、发散（遇到 `_|_` 即错误）。

更深刻的一点：**函数定义里的模式匹配，本质上都是 case 表达式的语法糖**。比如：

```
take 0 _      = []
take _ []     = []
take n (x:xs) = x : take (n-1) xs
```

语义上等价于：

```
take m ys = case (m, ys) of
              (0, _)      -> []
              (_, [])     -> []
              (n, x:xs)   -> x : take (n-1) xs
```

**这意味着"模式匹配"不是特殊语法，而是 case 分析的语法糖**——理解这一点，你对 Haskell 的"一致性"会有更深体会：语言的核心机制很少，但它们组合起来威力巨大。

### 2.2.1 无处不在的模式匹配

模式匹配不只在函数定义里用，它**无处不在**：

- **`let` / `where` 绑定**：`let (x, y) = point in ...`
    
- **`case` 表达式**：显式分发
    
- **``\` lambda 模式**：``(x:_) -> x`（注意：lambda 里用模式匹配要谨慎，失败会运行时报错）
    
- **列表推导**：`[x | (x, _) <- pairs]`
    
- **`do` 记号法**（后面学 Monad 时）：`do (x, y) <- ...`
    

> 📌 **连接第一章**：第一章我们强调"一切皆表达式"。模式匹配让"解构"也成为一个表达式级别的操——它不是语句，而是表达式的一部分。这种统一性正是 Haskell 优雅的根源。

### 2.2.2 `@pattern`：as-pattern

`@` 模式让你**既能匹配整体，又能拿到局部**：

```
f s@(x:xs) = x : s
```

这里 `s` 绑定到整个列表 `x:xs`，`x` 绑定到头部，`xs` 绑定到尾部。as-pattern 有两个好处：

1. **可读性**：避免在右侧重复写 `x:xs`
    
2. **性能**：naive 的实现可能会重建 `x:xs`，而 as-pattern 直接复用被匹配的值
    

StackBuilders 的文章里举了标准库 `span` 的例子，完美展示了 `@` 模式的实际应用：

```
span _ xs@[] = (xs, xs)
span p xs@(x:xs')
  | p x = let (ys, zs) = span p xs' in (x:ys, zs)
  | otherwise = ([], xs)
```

## 2.3 各式各样的数据类型：ADT 的全频谱

这一节是 `data` 的"全家福"，每一子节都在回答一个问题："ADT 还能怎么用？"

### 2.3.1 多构造函数：和类型的威力

```
data Shape = Circle Float Float Float
           | Rectangle Float Float Float Float
           | Triangle Float Float Float Float Float
```

一个 `Shape` 可以是圆、矩形或三角形。处理时**必须**通过模式匹配穷举所有构造子——编译器借此保证你不会漏掉任何一种情况。

**实际应用**：JSON 值的建模、抽象语法树（AST）、状态机的状态、网络协议的报文类型——任何"二选一或多选一"的场景都是和类型的天然领地。

### 2.3.2 完备性检查：编译器的"安全网"

这是 Haskell 一个**极其重要**的特性。当你写模式匹配时，如果遗漏了某些构造子，编译器（开启 `-Wall` 时）会警告：

```
Warning: Pattern match(es) are non-exhaustive
         In an equation for `f`: Patterns not matched: Nothing
```

**为什么这个特性如此关键？**

因为它把"运行时错误"提前到了"编译时错误"。在 Java/C++ 里，忘记处理某个 enum 值是运行时才暴露的 bug；在 Haskell 里，**编译器在编译期就强迫你想清楚每一种可能性**。

> ⚠️ 这是 Haskell "make illegal states unrepresentable"（让非法状态无法表示）设计哲学的基石。结合 2.3.1 的多构造函数，你得到一个强大的组合：**类型系统枚举所有可能 + 编译器检查是否穷举**。

### 2.3.3 无参数构造函数：枚举的优雅写法

```
data Direction = North | South | East | West
data Color = Red | Green | Blue
```

这些构造函数不带参数，本质上就是类型安全的枚举。对比 C/C++ 的 `enum` 或 Java 的 `enum`，Haskell 的版本更彻底——它们不是底层整数的别名，而是**独立的值**，参与类型检查。

### 2.3.4 `data` 与类型变量：参数化类型

```
data Maybe a = Nothing | Just a
data Tree a = Leaf a | Branch (Tree a) (Tree a)
data Either a b = Left a | Right b
```

类型变量 `a`、`b` 让数据类型**参数化**。`Maybe Int`、`Maybe String`、`Tree Bool` 共享同一个定义，却拥有完全不同的类型。

**`Either` 是一个特别值得展开的洞见**：

```
data Either a b = Left a | Right b
```

数学上是 **A ⊔ B**（不相交并集）。约定俗成：`Left` 放错误信息，`Right` 放成功结果。所以：

```
safeDiv :: Int -> Int -> Either String Int
safeDiv _ 0 = Left "Division by zero is not allowed."
safeDiv x y = Right (x `div` y)
```

对比 `Maybe`，`Either` 不仅能表达"失败"，还能**携带失败的原因**。这是错误处理从"哑失败"进化到"智能失败"的关键一步——后面学 Monad 时，`Either String` 就是 `Except` Monad 的核心。

### 2.3.5 记录语法：为真实项目而生

当构造函数的字段多了，位置参数就很难记：

```
-- 难记：哪个 Float 是哪个？
data Person = Person String Int String String

-- 记录语法：字段有名
data Person = Person
  { personName   :: String
  , personAge    :: Int
  , personEmail  :: String
  , personPhone  :: String
  }
```

记录语法自动生成：

- **构造器**：`Person { personName = "Alice", personAge = 30, ... }`
    
- **访问器函数**：`personName`、`personAge` 等，类型 `Person -> String`、`Person -> Int`
    
- **更新语法**：`alice { personAge = 31 }`（注意：返回新值，原值不变——呼应第一章"绑定而非变量"）
    

> 💡 记录语法是 Haskell 在工业级项目中可维护性的关键。真实项目的数据结构往往有十几个字段，位置参数会让代码变成噩梦，记录语法让代码自文档化。

## 2.4 排版规则：用缩进表达结构

Haskell 用**缩进**来表达代码的层次结构（类似 Python，但有自己的规则）。这一节韩冬讲解了 Haskell 的"layout rule"——什么时候必须缩进、如何避免歧义。

**为什么 Haskell 要这么做？**

因为 Haskell 程序大量使用 `let`、`where`、`do`、`case` 等需要多行块的构造。如果用花括号和分号（如 C/Java），代码会非常嘈杂。**Haskell 选择让编译器通过缩进来推断块边界**，让代码更清爽。

底层逻辑：**代码的结构应该由它的视觉结构反映出来**。当你在 GHCi 或 `.hs` 文件里写多行定义时，缩进不是风格问题，而是语法问题。

> 📌 实用建议：养成统一用空格（不用 Tab）、块内统一缩进 2 或 4 格的习惯。遇到"parse error (possibly incorrect indentation)"时，先检查缩进。

## 📝 本章核心洞见总结

> **洞见一：ADT 是 Haskell 表达力的终极源头**。
> 
> 一个 `data` 声明同时定义了类型、构造函数、值空间——这是"和类型"与"积类型"的代数组合。理解了这个，你就理解了为什么 Haskell 能用如此少的语法特性表达如此丰富的概念。

> **洞见二：模式匹配不是语法糖，是思维方式**。
> 
> 它强迫你**按数据结构本身来思考**——"这个值可能是 A 或 B，如果是 A 它里面有什么，如果是 B 它里面有什么"。这种"结构化的穷举"是函数式编程区别于命令式编程的核心。

> **洞见三：完备性检查把 bug 消灭在编译期**。
> 
> 多构造函数 + 穷举匹配 + 编译器警告 = 不可能漏掉任何一种情况。这是 Haskell "make illegal states unrepresentable" 哲学的具体落地。

> **洞见四：`Maybe` 和 `Either` 是 ADT 的"杀手级应用'"**。
> 
> 它们用一行 `data` 声明解决了"空指针"这个困扰业界几十年的问题——不是用特殊的 `null` 值，而是**把"可能为空"编码进类型**。这是后面学 Monad 时 `Maybe` 和 `ExceptT` 的基础。

> **洞见五：类型变量让数据"参数化"**。
> 
> `data Maybe a = ...` 中的 `a` 是类型层面的变量，它让一个定义能实例化为无数种具体类型。这是 Haskell 多态的基础，也是后面 Functor/Applicative/Monad 能泛化到所有容器的前提。

## 🛠️ 实践建议

1. **刻意练习 ADT 建模**：拿你熟悉的领域（比如"订单状态"、"游戏角色"、"HTTP 响应"）试着用 `data` 定义出来。目标是——**让非法状态无法用类型表示**。
    
2. **用 `:t` 和 `:i` 解剖标准库的 ADT**：在 GHCi 里输入 `:i Maybe`、`:i Either`、`:i []`，看它们的真实定义。你会发现 `[]`（列表）本身就是一个 ADT：`data [] a = [] | a : [a]`。
    
3. **永远开启 `-Wall`**：`ghci -Wall` 或编译时加 `-Wall`，让编译器提醒你模式匹配是否完备。这是工业级 Haskell 开发的标配。
    
4. **对比"命令式怎么做"**：遇到一个"可能为 null"的场景，先想 Java/C++ 怎么写（返回 null / 抛异常），再写 Haskell 版本（返回 `Maybe` / `Either`）。体会类型系统如何替你记住"这里可能失败"。
    
5. **记录语法用于真实结构**：任何超过 3 个字段的数据类型，都用记录语法。这是为未来的自己好。
