## 6.1 映射：保结构的"一一变换"

### 定义与类型

```
map :: (a -> b) -> [a] -> [b]
map _ [] = []
map f (x:xs) = f x : map f xs
```

### 🔑 洞见一：map 抽象的是"遍历 + 变换"这个递归模板

回忆你在第三章可能写过的代码：

```
doubleAll [] = []
doubleAll (x:xs) = x * 2 : doubleAll xs

squareAll [] = []
squareAll (x:xs) = x ^ 2 : squareAll xs
```

这两个函数的**递归骨架完全相同**——空列表返回空列表，非空列表对头部应用一个函数、与尾部的递归结果用 `:` 连接。区别只在"应用哪个函数"。`map` 把这个模板抽象出来：**把"应用哪个函数"作为参数传入**。

### 🔑 洞见二：map 的"保结构"特性是并行化的基础

`map` 有三个关键性质：

1. **输出长度 = 输入长度**（一一对应）
    
2. **元素顺序保持不变**
    
3. **每个元素的变换独立于邻居**
    

第三点至关重要——因为 `f x` 的计算不依赖 `f (x-1)` 或 `f (x+1)`，**map 天然可以并行化**。这就是为什么在 Haskell 的并行编程库（如 `parallel`）里，`parMap` 几乎是免费的——`map` 的结构保证了无数据共享、无竞态条件。

### 🔑 洞见三：map 可以改变元素类型

注意类型签名 `map :: (a -> b) -> [a] -> [b]` 里 **a 和 b 是两个独立的类型变量**：

```
map show [1, 2, 3]              -- ["1", "2", "3"] :: [String]
map length ["hi", "hello"]      -- [2, 5] :: [Int]
```

**列表的类型参数在 map 过程中可以改变**——这是 `map` 比"foreach 循环"强大得多的根本原因。命令式语言的 foreach 通常只能原地修改元素（类型不变），而 `map` 可以把 `[Int]` 映射成 `[String]`、把 `[User]` 映射成 `[UserId]`。

> 📌 **连接第十一章 Functor**：`map` 的本质是"在容器内做变换，保持容器结构不变"。第十一章会告诉你——任何满足这个性质的容器（Maybe、Tree、IO）都可以是 Functor，`fmap` 就是推广版的 `map`。

### 实际应用

```
-- 把所有用户转为其 ID
map userId users

-- 把字符串列表转为长度列表  
map length ["hello", "world"]  -- [5, 5]

-- 配合部分应用，极简
map (*2) [1..10]        -- 翻倍
map (^2) [1..10]        -- 平方
```

## 6.2 过滤：不改变元素，只决定去留

### 定义与类型

```
filter :: (a -> Bool) -> [a] -> [a]
filter _ [] = []
filter p (x:xs)
  | p x       = x : filter p xs
  | otherwise = filter p xs
```

### 🔑 洞见四：filter 与 map 的本质区别

`map` 是"变换"，`filter` 是"选择"。两者的类型签名揭示了根本差异：

- `map :: (a -> b) -> [a] -> [b]` —— **a 和 b 可以不同**，元素可以被改成别的类型
    
- `filter :: (a -> Bool) -> [a] -> [a]` —— **输入输出都是 `[a]`**，元素类型永远不变
    

`filter` 永远不改变元素本身，它只决定"留下还是丢弃"。这就是为什么 `filter` 的结果列表长度 ≤ 输入长度。

### 🔑 洞见五：filter 的谓词是"纯函数"，这至关重要

谓词 `p :: a -> Bool` 必须是纯函数（无副作用、引用透明）。这保证了：

- 过滤的顺序不影响结果
    
- 可以并行过滤（每个元素独立判断）
    
- 可以惰性过滤（只计算需要的元素）
    

```
-- 复合谓词
filter (\x -> even x && x > 5) [1..12]  -- [6, 8, 10, 12]
```

### 🔑 洞见六：map + filter 的组合律

`map` 和 `filter` 可以任意组合，且有一些有趣的代数律：

```
-- 分配律
map f . filter p = filter (p . f) . map f  -- 当 f 单调时
```

更深层的洞见是：**`map` 和 `filter` 的组合可以融合成一个遍历**（fusion law）。编译器或手工重写时：

```
-- 低效：两次遍历
filter isEven (map (*2) [1..10])

-- 高效：融合为一次遍历
map (*2) (filter (\x -> even (x*2)) [1..10])
```

> 💡 **这条融合律是 Haskell 性能优化的核心技巧之一**。GHC 的"deforestation"优化就是基于这类代数律，自动消除中间列表的创建。

### 实际应用

```
evens = filter even [1..10]              -- [2,4,6,8,10]
big = filter (>5) [1..10]                -- [6,7,8,9,10]
lowers = filter isLower "Hello World"    -- "elloorld"
```

## 6.3 折叠：递归遍历的"终极抽象"

### 定义与类型

```
foldr :: (a -> b -> b) -> b -> [a] -> b
foldr _ acc [] = acc
foldr f acc (x:xs) = f x (foldr f acc xs)

foldl :: (b -> a -> b) -> b -> [a] -> b
foldl _ acc [] = acc
foldl f acc (x:xs) = foldl f (f acc x) xs
```

### 🔑 洞见七：fold 抽象的是"带累积变量的循环"

Haskell 维基教材里有一段精彩分析：命令式语言里你写：

```
y = 0
for i in range(1, 6):
    y = y + x[i]
```

用数学符号写出来是：`((((0 + x1) + x2) + x3) + x4) + x5`。这个模式——**"从初始值开始，对列表每个元素应用一个二元函数，累积结果"**——就是 `foldl`。而反过来分组：`x1 + (x2 + (x3 + (x4 + (x5 + 0))))` 就是 `foldr`。

**这意味着：任何"遍历列表并聚合为单个值"的操作，本质都是 fold 的特例**：

```
sum     = foldr (+) 0
product = foldr (*) 1
concat  = foldr (++) []
length  = foldr (\_ acc -> 1 + acc) 0
and     = foldr (&&) True
or      = foldr (||) False
```

### 🔑 洞见八：foldr 与 foldl 的本质区别不只是方向

很多人以为 `foldr` 和 `foldl` 只是"从右往左"和"从左往右"的区别。实际上，**它们的区别深得多**：

|维度|foldr|foldl|
|---|---|---|
|结合顺序|`f x1 (f x2 (f x3 acc))`|``(((acc \`f\` x1) \`f\` x2) \`f\` x3)``|
|递归结构|**递归发生在"累积"参数里**​|**递归发生在"列表"参数里**​|
|惰性友好度|✅ 友好（可处理无限列表）|❌ 不友好（必须先到列表末尾）|
|栈使用|常量栈（尾递归）|需要先到末尾才能计算，可能栈溢出|

Haskell 维基教材明确建议：**"Prefer foldr, for it uses less stack space. foldl must reach the end of the list then work its way back."**

为什么 `foldr` 能处理无限列表？看 `foldr` 的定义：

```
foldr f acc (x:xs) = f x (foldr f acc xs)
```

如果 `f x` 的结果**不强制求值第二个参数**，那么 `foldr` 可以立即停止。例如：

```
take 5 $ foldr (:) [] [1..]  -- 可以工作！
```

因为 `(:)` 是惰性的——`x : rest` 只在需要 `rest` 时才计算 `rest`。而 `foldl` 不行：

```
foldl (+) 0 [1..]  -- 永远停不下来——必须到达列表末尾
```

### 🔑 洞见九：foldr 是"正确的"折叠

GHCi 里试试：

```
foldr (&&) True (False : repeat True)  -- False（立即返回）
foldl (&&) True (False : repeat True)  -- 死循环
```

`foldr` 利用了 `&&` 的短路特性——遇到 `False` 立即返回，不再求值后面的 `repeat True`。而 `foldl` 必须把整个 `repeat True` 累加完才知道结果——但它是无限的。

> ⚠️ **实践准则**：默认用 `foldr`，除非你有明确的左结合需求且列表有限。 Haskell 的 `Data.List` 还提供了 `foldl'`（严格版 `foldl`），避免 thunk 堆积导致的空间泄漏。

### 🔑 洞见十：fold 是 map 和 filter 的"母体"

你可能没意识到——`map` 和 `filter` 都可以用 `foldr` 定义：

```
map f    = foldr ((:) . f) []
filter p = foldr (\x xs -> if p x then x : xs else xs) []
```

**这意味着：foldr 是列表递归模式的"终极抽象"**。所有"遍历列表"的操作，最终都能归结为 `foldr`。

> 📌 **连接第二十二章 Foldable**：当 Haskell 后来引入 `Foldable` 类型类时，`foldr` 就是其核心方法。任何可遍历的数据结构（树、Map、Set）都可以定义自己的 `foldr`——第十一章 Functor 推广 `map`，第二十二章 Foldable 推广 `foldr`，两者共同构成了 Haskell 抽象的巅峰。

### 实际应用

```
-- 求和
foldr (+) 0 [1..10]              -- 55

-- 反转列表
foldr (\x acc -> acc ++ [x]) [] [1,2,3]  -- [3,2,1]

-- 拼接字符串列表
foldr (++) "" ["hello", " ", "world"]    -- "hello world"

-- 查找最大值
foldr max 0 [3, 1, 4, 1, 5]             -- 5
```

## 6.4 扫描：折叠的"轨迹记录"

### 定义与类型

```
scanl :: (b -> a -> b) -> b -> [a] -> [b]
scanl f z [x1, x2, ...] == [z, z `f` x1, (z `f` x1) `f` x2, ...]
```

### 🔑 洞见十一：scan 是 fold 的"轨迹"

`scanl` 做的事情与 `foldl` 完全一样，但**它把每一步的累积值都记录下来，生成一个列表**：

```
scanl (+) 0 [1..5]  -- [0, 1, 3, 6, 10, 15]
--        ^  ^  ^  ^   ^   ^
--        0  0+1 0+1+2 ... 最终结果
```

两个关键恒等式：

```
last (scanl f z xs) == foldl f z xs
head (scanr f z xs) == foldr f z xs
```

**这意味着：fold 是 scan 的"最后一帧"**。 scan 记录了整个过程，fold 只取最终结果。

### 🔑 洞见十二：scan 揭示了"折叠的本质是状态机"

`scanl` 输出的列表，本质上是一个**状态机的轨迹**——初始状态 `z`，每遇到一个输入元素，状态按照 `f` 转移一次。这种"状态转移序列"在现实中无处不在：

- **金融**：账户余额的变化轨迹
    
- **物理**：物体位置随时间的变化
    
- **算法**：动态规划的状态数组
    
- **监控**：系统指标的时间序列
    

```
-- 计算股票价格的累计收益
scanl (+) 0 [0.01, -0.02, 0.015, 0.03]  -- [0.0, 0.01, -0.01, 0.005, 0.035]

-- 计算前缀和
scanl (+) 0 [1,2,3,4,5]  -- [0,1,3,6,10,15]
```

### 🔑 洞见十三：scan 与惰性求值的完美结合

因为 Haskell 是惰性的，`scanl` 可以处理无限列表：

```
take 10 $ scanl (+) 0 [1..]  -- [0,1,3,6,10,15,21,28,36,45]
```

**这在命令式语言里是不可能直接表达的**——你必须用循环 + 数组手动模拟。而在 Haskell 里，它就是一个表达式。

### 实际应用

```
-- 阶乘序列
scanl (*) 1 [1..10]  -- [1,1,2,6,24,120,720,5040,40320,362880,3628800]

-- 移动平均（简化版）
movingAvg = scanl (\acc x -> (acc + x) / 2) 0 [1..10]
```

## 6.5 方向是相对的：用 foldr 实现 foldl

这是本章**最具哲学意味**的一节。韩冬提出了一个深刻的问题：**能否用 foldr 实现 foldl？**

答案是肯定的：

```
foldl f acc xs = foldr (\x g -> \acc' -> g (f acc' x)) id xs acc
```

或者更直观的版本：

```
foldl f z xs = foldr (\x g -> g . flip f x) id xs z
```

### 🔑 洞见十四：方向不是固定的，而是视角问题

这个实现揭示了一个深层真相：**左折叠和右折叠不是本质不同的两种操作，而是同一种递归结构的两种视角**。

Haskell 维基教材给出了一个简洁的等价关系：

```
foldl f z xs = foldr (\x y -> f y x) z (reverse xs)
```

**这意味着**：如果你愿意先反转列表，右折叠就能模拟左折叠。或者，如果你愿意让累积函数返回一个"等待下一个参数的函数"（即 continuation），左折叠就能模拟右折叠。

### 🔑 洞见十五：方向的相对性反映了"结合性"的本质

考虑 `(+)` 这个操作——它是**结合的**：`(a + b) + c == a + (b + c)`。所以对于求和，`foldl (+) 0` 和 `foldr (+) 0` 给出相同结果。

但对于**非结合**操作，方向就至关重要：

```
foldl (-) 0 [1,2,3]  -- ((0 - 1) - 2) - 3 = -6
foldr (-) 0 [1,2,3]  -- 1 - (2 - (3 - 0)) = 2
```

**方向决定了结合方式，结合方式决定了结果**。这不是语法细节，而是数学本质。

### 🔑 洞见十六：在实践中如何选择

基于本章所有讨论，给出明确的实践准则：

1. **默认用 `foldr`**——惰性友好、可处理无限列表、栈空间常量
    
2. **需要严格左折叠时用 `foldl'`**（来自 `Data.List`）——避免 thunk 堆积
    
3. **需要轨迹记录时用 `scanl` 或 `scanr`**
    
4. **`map` 和 `filter` 优先于手工 `foldr`**——语义更清晰
    
5. **组合使用**：`foldr f z . map g` 可以融合为 `foldr (f . g) z`（fusion law）

## 📝 本章核心洞见总结

> **洞见一：map / filter / fold / scan 不是"四个列表函数"，而是"四种递归模式"**。
> 
> 它们分别对应：一一变换、条件选择、累积聚合、轨迹记录。这四种模式覆盖了几乎所有列表操作。

> **洞见二：map 的"保结构"特性是它的灵魂**。
> 
> 输出长度 = 输入长度、顺序不变、元素变换独立——这三性质让 map 天然可并行，也让 map 成为 Functor 的原型。

> **洞见三：filter 永远不改变元素类型，只决定去留**。
> 
> 这与 map 形成鲜明对比。map + filter 的组合律是 Haskell 优化（fusion）的数学基础。

> **洞见四：foldr 是"正确的"折叠**。
> 
> 它惰性友好、可处理无限列表、栈空间常量。foldl 必须到达列表末尾才能开始计算——这在无限列表上是致命的。

> **洞见五：fold 是 map 和 filter 的母体**。
> 
> `map f = foldr ((:) . f) []`，`filter p = foldr (\x xs -> if p x then x:xs else xs) []`。这意味着 foldr 是列表递归的"终极抽象"。

> **洞见六：scan 是 fold 的轨迹记录**。
> 
> `last (scanl f z xs) == foldl f z xs`。scan 揭示了 fold 的本质是状态机——而状态机是现实世界动态系统的通用模型。

> **洞见七：方向是相对的**。
> 
> foldl 可以用 foldr 实现，反之亦然。选择哪个取决于：操作是否结合、是否需要惰性、是否处理无限列表。

> **洞见八：这四个组合子是后续所有抽象的具体原型**。
> 
> Functor 推广 map，Foldable 推广 fold，Traversable 推广"同时 map 和 fold"。第十一章到第二十二章的抽象大厦，都奠基在第六章这四个函数上。

## 🛠️ 实践建议

1. **刻意练习"用 fold 实现一切"**：
    
    ```
    length = foldr (\_ acc -> 1 + acc) 0
    reverse = foldr (\x acc -> acc ++ [x]) []
    sum = foldr (+) 0
    product = foldr (*) 1
    ```
    
    这种练习会让你彻底理解 fold 的抽象能力。
    
2. **map + filter 融合**：
    
    ```
    -- 低效
    filter isEven (map (*2) [1..100])
    
    -- 高效
    map (*2) (filter (\x -> even (x*2)) [1..100])
    ```
    
    或者更简洁——用 list comprehension：`[x*2 | x <- [1..100], even (x*2)]`
    
3. **优先 foldr，严格场景用 foldl'**：
    
    ```
    import Data.List (foldl')
    sum' = foldl' (+) 0  -- 严格左折叠，避免 thunk 堆积
    ```
    
4. **scan 用于"状态轨迹"**：
    
    ```
    -- 计算股票收益的累计曲线
    cumulativeReturns = scanl (+) 0 dailyReturns
    ```
    
5. **组合子链式调用（point-free）**：
    
    ```
    -- 求列表中所有偶数的平方和
    answer = sum . map (^2) . filter even
    ```
    
    这一行完美结合了第五章的语法工具和第六章的组合子。

## 🔮 承上启下

下一章"类型类"会在本章基础上往前推一步：

- **`map` 推广为 `Functor`**：任何容器都能 `fmap`，不限于列表
    
- **`fold` 推广为 `Foldable`**：任何可遍历结构都能 `foldr`
    
- **类型类 `Eq`、`Ord`、`Show`**：为 `data` 追加能力，让 `map`/`filter`/`fold` 能作用于自定义类型
    

**第六章是你理解 Haskell "抽象金字塔"的基石**。吃透 map/filter/fold/scan，第十一章的 Functor、第十三章的 Applicative、第十六章的 Monad、第二十二章的 Foldable/Traversable 就都不是"新的魔法"，而是"我们已经知道的知识的自然延伸"——你已经知道 `map` 是怎么工作的，Functor 只是告诉你"这个模式适用于所有容器"；你已经知道 `foldr` 是怎么工作的，Foldable 只是告诉你"这个模式适用于所有可遍历结构"。
