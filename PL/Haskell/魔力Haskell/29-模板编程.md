
# 第二十九章 模板编程 —— 读书笔记

> 💡 如果说前面章节讲的是"用 Haskell 写程序"，那么第二十九章讲的是"**用 Haskell 写能写 Haskell 的程序**"——模板编程（Template Haskell，TH）让你在**编译期**运行 Haskell 代码，生成 Haskell 代码并嵌入到最终程序中。表面看是 Q 单子、拼接、reify 几个概念的介绍，实则在揭示一个深层真相：**Haskell 的"代码即数据"理念在编译期达到了顶峰**——表达式、声明、类型、模式都可以被表示为 AST（抽象语法树）数据类型，你可以在 Q 单子里构造这棵树，用 `$(...)` 把它"拼接"回真实代码。这一章让你亲眼看见：第二十八章 persistent 的 `share [mkPersist ...] [persistLowerCase| ... |]` 那个神秘的 quasiquote，背后就是 TH 在起作用；`deriveJSON`、`lens` 的自动生成、Aeson 的类型推导——整个 Haskell 生产生态的"魔法"都建立在 TH 之上。

韩冬在这一章安排了四个小节：**29.1 什么是模板**、**29.2 Q 单子**、**29.3 拼接**、**29.4 reify**。表面是从"元编程概念"到"Q 单子"到"拼接语法"再到"编译期反射"的递进，实则在铺设一条主线：**TH 让"代码生成"成为类型安全的、可组合的、编译期执行的头等公民**——AST 是数据，Q 是构造数据的单子，拼接是数据与代码的转换点，reify 是查询编译器符号表的窗口。

## 🎯 全局脉络：为什么需要模板编程？

```
前二十八章: 用 Haskell 写程序
   ↓
第二十九章: 模板编程（TH）  ← 你在这里
   ↓
用 Haskell 写"生成 Haskell 代码"的程序
```

**这一章要解决的核心问题**：如何消除重复的样板代码？

TH 资料开宗明义 ：

> _"Template Haskell (TH) allows us to write 'macros' -> Haskell code that runs during compile time (so called 'meta code') and generates Haskell code that becomes part of our Haskell program (so called 'object code')."_

**🔑 洞见一：TH 的双层代码世界**

TH 中存在两个世界：

- **Meta code（元代码）**：运行在**编译期**的 Haskell 代码，操纵 TH AST
    
- **Object code（目标代码）**：元代码**生成**的 Haskell 代码，成为最终程序的一部分
    

GHC 用户指南给出了权威定义 ：

> _"Template Haskell allows you to do compile-time meta-programming in Haskell."_

**经典应用场景**（TH 资料 ）：

- 自动派生类型类实例（`deriveJSON`、`deriveShow`、`Arbitrary` 等）
    
- 自动生成 lenses（lens 库、`makeLenses`）
    
- 数据库实体定义（persistent 的 `share`/`mkPersist`）
    
- 编译期计算（将运行时计算提前到编译期）
    
- 自定义准引号（嵌入式 DSL 解析）

## 29.1 什么是模板：AST 即数据

### TH 的核心三角

TH 资料精准地概括了 TH 的三大支柱 ：

> _"TH AST: `Exp`, `Decl`, ... . We use these in the meta code to describe the object code we are generating... `Q`: Quotation monad, we write meta code inside it. Splicing: `$( )`. Transforms meta code into object code."_

**这三个概念形成 TH 的基础**：

1. **TH AST**：用 `Language.Haskell.TH` 模块中的数据类型（`Exp`、`Decl`、`Type`、`Pat` 等）描述要生成的代码
    
2. **Q 单子**：编写元代码的"引述单子"（quotation monad），提供构造 AST 所需的能力（生成新名字、查询环境、报告错误等）
    
3. **拼接（`$(...)`）**：把元代码转换成目标代码——运行给定的 Q 单子计算，获得 TH AST，然后在调用处生成代码
    

### AST 数据类型：代码即数据

TH 把 Haskell 代码的每个语法类别都表示为递归数据类型 ：

|AST 类型|表示的代码|示例构造器|
|---|---|---|
|`Exp`|表达式|`VarE`、`AppE`、`LamE`、`LitE`|
|`Pat`|模式|`VarP`、`ConP`、`LitP`|
|`Decl`|顶层声明|`FunD`、`DataD`、`InstanceD`|
|`Type`|类型|`ConT`、`AppT`、`ArrowT`|
|`Lit`|字面量|`IntegerL`、`StringL`|

**🔑 洞见二：手动构造 AST vs 引号语法**

你可以直接用手动构造 AST（繁琐但显式）：

```
-- 手动构造 AST：表示 "1 + 2"
plusE :: Q Exp
plusE = return (AppE (AppE (VarE '(+)) (LitE (IntegerL 1))) (LitE (IntegerL 2)))
```

或者用**引号语法**（简洁且类型安全）：

```
-- 用引号语法：同上但更直观
plusE :: Q Exp
plusE = [| 1 + 2 |]
```

TH 资料明确指出 ：

> _"Usually we will write functions that take some args and return Q a where a is part of TH AST, and then we splice those with $( ) where we need to generate the code."_

### 引号的类型

GHC 用户指南 给出了完整的引号体系：

|引号语法|类型|表示|
|---|---|---|
|`[e\\| ... \\|]` 或 `[|...|]`|
|`[d\\| ... \\|]`|`Quote m => m [Dec]`|声明引号|
|`[t\\| ... \\|]`|`Quote m => m Type`|类型引号|
|`[p\\| ... \\|]`|`Quote m => m Pat`|模式引号|

**🔑 洞见三：引号与拼接是互逆操作**

TH 资料精准描述 ：

> _"Inverse operation of splicing -> splicing transforms TH AST (meta code) into object code, quotation brackets transform object code into TH AST (meta code)."_

- **拼接（`$(...)`）**：TH AST → 目标代码（object code）
    
- **引号（`[|...|]`）**：目标代码 → TH AST（meta code）
    

这构成了一个漂亮的对称：

```
目标代码 --引号--> TH AST --拼接--> 目标代码
```

### 名字引号：获取 Name

GHC 用户指南 ：

> _"A name can be quoted with either one or two prefix single quotes: 'f has type Name, and names the function f. Similarly 'C has type Name and names the data constructor C."_

```
'f    -- 单引号：获取函数/值构造器的 Name（类型为 Name）
''T   -- 双引号：获取类型构造器的 Name（类型为 Name）
```

**🔑 洞见四：单引号与双引号的语义区别**

- `'f`：在**表达式上下文**中解释 `f`——获取函数/变量的名字
    
- `''T`：获取**类型构造器**的名字
    
- 如果标识符第二个字符是单引号（如 `f'7`），需要加空格避免歧义：`' f'7`
    

### 实际应用：deriveShow 简化版

```
{-# LANGUAGE TemplateHaskell #-}
import Language.Haskell.TH

-- 生成一个恒等 lambda 函数：\x -> x
genId :: Q Exp
genId = [| \x -> x |]

-- 使用拼接
identityInt :: Int -> Int
identityInt = $(genId)  -- 展开为：\x -> x
```

## 29.2 Q 单子：元代码的执行上下文

### Q 单子的本质

GHC 用户指南 ：

> _"The Q monad is a monad defined in Language.Haskell.TH.Syntax which supports several useful operations during code generation such as reporting errors or looking up identifiers in the environment."_

**🔑 洞见五：Q 单子是"编译期的 IO"**

TH 资料给出了精准类比 ：

> _"Think of Q like IO, but instead of side effects, it builds syntax trees during compilation."_

Q 单子提供的关键能力（Hackage 文档 ）：

|操作|类型|作用|
|---|---|---|
|`newName`|`String -> Q Name`|生成**保证新鲜**的名字（解决命名冲突）|
|`report`|`Bool -> String -> Q ()`|报告错误或警告|
|`reportError`|`String -> Q ()`|报告错误|
|`reportWarning`|`String -> Q ()`|报告警告|
|`fail`|`String -> Q a`|中止计算|
|`location`|`Q Loc`|获取拼接处的源代码位置|
|`runIO`|`IO a -> Q a`|在 Q 单子中运行任意 IO（强大但危险）|
|`reify`|`Name -> Q Info`|查询编译器符号表（见 29.4）|
|`lookupTypeName`|`String -> Q (Maybe Name)`|在当前作用域查找类型名|
|`lookupValueName`|`String -> Q (Maybe Name)`|在当前作用域查找值名|

### newName： hygienic 宏的关键

CIS 194 讲义给出了一个经典例子 ：

```
-- 生成 liftM 实现的主体
liftMBody' :: Int -> Q Exp
liftMBody' n = do
  m_names <- replicateM n (newName "x")  -- 生成 n 个新鲜名字
  let mk_bind m_name name = BindS (VarP name) (VarE m_name)
  let binds = zipWith mk_bind m_names m_names
  let ret = NoBindS (foldl AppE (VarE (mkName "f")) (map VarE m_names))
  return $ LamE (map VarP m_names) (DoE (binds ++ [ret]))
```

CIS 194 讲义明确指出 ：

> _"The string passed in is just a suggestion for the name. You could always pass the same string in but get different names each time."_

**🔑 洞见六：hygiene（卫生性）是宏系统的核心难题**

CIS 194 讲义通过一个失败案例说明了问题 ：

```
-- 错误示例：使用单一字母名字导致命名冲突
liftMBody :: Int -> Q Exp
liftMBody n = do
  let names = replicate n "x"  -- 每次都是 "x"
  -- 如果拼接处有 "x" 已经在使用中，就会冲突！
```

**解决方案**：用 `newName` 生成**保证新鲜**的名字——这是 TH 宏系统卫生性的基础。

### runIO：Q 单子中的 IO

Hackage 文档 ：

> _"The runIO function lets you run an I/O computation in the Q monad. Take care: you are guaranteed the ordering of calls to runIO within a single Q computation, but not about the order in which splices are run."_

**🔑 洞见七：runIO 强大但有陷阱**

CIS 194 讲义指出 ：

> _"TH exports the function runIO :: IO a -> Q a, which allows any IO operation in the Q monad. This is indeed very powerful..."_

**典型用途**：

```
-- 在元代码中打印调试信息
debugTH :: String -> Q ()
debugTH msg = runIO $ putStrLn $ "[TH Debug] " ++ msg

-- 读取文件并在编译期嵌入内容
embedFile :: FilePath -> Q Exp
embedFile path = do
  content <- runIO $ readFile path
  [| content |]
```

**陷阱**：拼接的执行顺序不被保证——不能在多个拼接之间依赖 IO 的副作用顺序。

### 实际应用：自动生成 Show 实例

基于 Basic Tutorial of TH ：

```
{-# LANGUAGE TemplateHaskell #-}
import Language.Haskell.TH

-- 为记录类型自动生成 Show 实例
emptyShow :: Name -> Q [Dec]
emptyShow name = do
  -- 1. 用 reify 查询类型的信息（详见 29.4）
  TyConI (DataD _ _ _ [RecC _ fields] _) <- reify name
  
  -- 2. 提取字段名
  let fieldNames = map (\(name, _, _) -> name) fields
  
  -- 3. 为每个字段生成显示函数
  let showField n = [| \x -> nameBase n ++ " = " ++ show ($(varE n) x) |]
  let showFields = listE $ map showField fieldNames
  
  -- 4. 生成 Show 实例声明
  [d| instance Show $(conT name) where
        show x = intercalate ", " (map ($ x) $showFields) |]
```

## 29.3 拼接：元代码与目标代码的桥梁

### 拼接语法

GHC 用户指南 ：

> _"A splice is written x,wherexisanarbitraryexpression.Theremustbenospacebetweenthe′' and the expression."_

**拼接可以出现在四个上下文**：

|上下文|拼接类型|示例|
|---|---|---|
|表达式|`Q Exp`|`$(genExpr)`|
|模式|`Q Pat`|`f $(genPat) = ...`（罕见）|
|类型|`Q Type`|`f :: $(genType)`|
|顶层声明|`Q [Dec]`|`$(genDecls)`|

**🔑 洞见八：$ 符号的双重身份**

GHC 用户指南明确指出 ：

> _"This use of $ overrides its meaning as an infix operator, just as M.x overrides the meaning of . as an infix operator. If you want the infix operator, put spaces around it."_

```
-- 拼接：$ 后面紧跟表达式，无空格
$(generateCode)

-- 函数应用：$ 两边有空格，是普通的中缀运算符
map ($ x) fs

-- 嵌套拼接：在引号内部使用拼接
plusC = [| $oneC + $twoC |]  -- oneC 和 twoC 都是 Q Exp
```

### 拼接的执行时机

GHC 用户指南 ：

> _"What splicing operator does is run given Q monad, obtain the result which is AST representing the code, and then turn it into Haskell code and embed it at the place where splicing was called."_

**🔑 洞见九：拼接的编译期执行**

拼接在**编译期**执行：

1. 编译器遇到 `$(metaExpr)`
    
2. 运行 `metaExpr`（一个 Q 单子计算）获得 TH AST
    
3. 把 AST 转换为 Haskell 代码
    
4. 把生成的代码嵌入到拼接调用的位置
    
5. 继续编译嵌入后的代码
    

**这意味着**：拼接生成的代码与手写代码在类型检查、优化等方面完全等价。

### 顶层拼接的限制

GHC 用户指南 ：

> _"Note that declaration splices are not allowed anywhere except at top level (outside any other declarations)."_

**🔑 洞见十：声明拼接必须在顶层**

```
-- ✅ 正确：顶层声明拼接
$(makeShowInstance ''MyType)
$(makeLenses ''MyRecord)

-- ❌ 错误：在函数内部使用声明拼接
myFunction = do
  $(declareSomething)  -- 不允许！
  return ()
```

**原因**（Template Meta-programming 论文 ）：

> _"Since declaration splices introduce unspecified new bindings, it may not be clear where a variable that occurs in the original program is bound."_

把声明拼接限制在顶层，保证了"给定变量 x 的出现，如果能看到词法上包围它的绑定，那确实是 x 的绑定"——避免了命名作用域的混乱。

### 类型化拼接（Typed Splices）

GHC 7.8+ 引入了类型化拼接 ：

```
-- 类型化表达式引号
[|| 1 + 2 ||]  :: Quote m => Code m Int

-- 类型化拼接
$$typedCode  -- 类型安全的拼接
```

**类型化拼接的优势**：编译器在拼接处就能验证生成代码的类型，提供更好的类型安全。

### 实际应用：编译期计算

```
{-# LANGUAGE TemplateHaskell #-}
import Language.Haskell.TH

-- 编译期计算斐波那契数
fib :: Int -> Integer
fib 0 = 0
fib 1 = 1
fib n = fib (n-1) + fib (n-2)

-- 在编译期计算 fib 20 并嵌入结果
fib20 :: Integer
fib20 = $(pure $ LitE $ IntegerL $ fib 20)  -- 6765

-- 更复杂的示例：编译期生成查找表
generateLookupTable :: Int -> Q Exp
generateLookupTable n = do
  let table = [ (i, fib i) | i <- [0..n] ]
  [| \x -> case x of
      $(listE [ match i v | (i, v) <- table ])
      _ -> error "Out of range"
  |]
  where
    match i v = do
      let pat = LitP (IntegerL i)
      let body = NormalB (LitE (IntegerL v))
      return $ Match pat body []

-- 使用
fibLookup :: Int -> Integer
fibLookup = $(generateLookupTable 10)
-- 展开为高效的 case 表达式
```

## 29.4 reify：编译期反射

### reify 的类型与能力

Hackage 文档 ：

> _"reify :: Name -> Q Info -- reify looks up information about the Name."_

**🔑 洞见十一：reify 是编译器的"自省"API**

CIS 194 讲义精辟描述 ：

> _"The Q monad provides another very important facility: the ability to inspect predefined types and functions and see their definitions, not unlike the :info command in GHCi."_

**Info 数据类型**（Hackage 文档 ）：

```
data Info
  = ClassI Dec [InstanceDec]           -- 类定义
  | ClassOpI Name Type ParentName Fixity  -- 类方法
  | TyConI Dec                         -- 类型构造器
  | FamilyI Dec [InstanceDec]          -- 类型族
  | PrimTyConI Name Arity Unlifted     -- 原始类型构造器
  | DataConI Name Type ParentName Fixity  -- 数据构造器
  | VarI Name Type (Maybe Dec) Fixity    -- 值变量
  | TyVarI Name Type                   -- 类型变量
```

### reify 能查询什么？

Hackage 文档 列出了 reify 系列函数：

|函数|作用|
|---|---|
|`reify`|查询名称的完整信息（返回 `Info`）|
|`reifyType`|查询名称的类型|
|`reifyFixity`|查询运算符的优先级|
|`reifyInstances`|查询类/类型族的实例|
|`reifyRoles`|查询类型参数的 role|
|`lookupTypeName`|在类型命名空间查找名字|
|`lookupValueName`|在值命名空间查找名字|

### 🔑 洞见十二：命名空间的重要性

Hackage 文档 给出了一个重要警告：

> _"It is sometimes useful to construct the argument name using lookupTypeName or lookupValueName to ensure that we are reifying from the right namespace. For instance, in this context: `data D = D` which D does `reify (mkName "D")` return information about?"_

**解决方案**：用 `lookupTypeName` 和 `lookupValueName` 明确指定命名空间：

```
do
  Just typeName <- lookupTypeName "D"   -- D 作为类型
  Just valName <- lookupValueName "D"   -- D 作为值
  typeInfo <- reify typeName
  valInfo <- reify valName
```

### reify 的可见性边界

GHC 用户指南 ：

> _"The type environment seen by reify includes all the top-level declaration up to the end of the immediately preceding declaration group, but no more."_

**🔑 洞见十三：reify 只能看到"拼接点之前"的声明**

```
module M where

f x = x          -- 声明组 1
$(th1 4)         -- 拼接点 1：reify 能看到 f，看不到 h

h y = k y y      -- 声明组 2
$(blah1)         -- 拼接点 2：reify 能看到 f 和 h，看不到 w

$(th2 10)        -- 拼接点 3：reify 能看到 f、$(th1) 生成的绑定、h

w z = $(blah2)   -- 声明组 3
```

**这意味着**：reify 是"向前看"的——只能看到当前拼接点之前已定义的声明。

### reify 的局限性

Haskell Wiki 指出了 reify 的几个坑 ：

1. **导入的内容可能不完整**：如果用 `-O0` 编译模块，接口文件可能不包含数据构造器的信息
    
    > _"However, if you compiled M without optimisation (ie -O0, the default), and without -XTemplateHaskell, GHC tries to put as little info in the interface file as possible."_
    > 
    > **解决方案**：用 `-O` 或 `-fno-omit-interface-pragmas` 编译
    
2. **函数定义不可用**：`VarI` 的 `Maybe Dec` 字段始终是 `Nothing`
    
    > _"At present, this value is always Nothing: returning the RHS has not yet been implemented"_
    
3. **运行时不能 reify**：`runQ (reify ''Bool)` 在运行时崩溃
    
    > _"Reason: reify consults the type environment, and that is not available at run-time."_
    

### 实际应用：自动派生类型类

基于 Basic Tutorial of TH 的完整示例：

```
{-# LANGUAGE TemplateHaskell #-}
import Language.Haskell.TH
import Data.List (intercalate)

-- 为记录类型自动生成 Show 实例
deriveShow :: Name -> Q [Dec]
deriveShow typeName = do
  -- 1. reify 查询类型信息
  info <- reify typeName
  
  -- 2. 模式匹配提取记录字段
  case info of
    TyConI (DataD _ _ _ [RecC _ fields] _) -> do
      -- fields: [(fieldName, strictness, fieldType)]
      let fieldNames = [name | (name, _, _) <- fields]
      
      -- 3. 为每个字段生成显示函数
      let showField :: Name -> Q Exp
          showField fname = [| \x -> nameBase fname ++ " = " 
                                  ++ show ($(varE fname) x) |]
      
      let showFieldsExp = listE $ map showField fieldNames
      
      -- 4. 生成 Show 实例
      [d| instance Show $(conT typeName) where
            show x = intercalate ", " (map ($ x) $showFieldsExp) |]
    
    _ -> error $ "deriveShow: expected a record type, got: " ++ show info

-- 使用
data Person = Person
  { personName :: String
  , personAge :: Int
  } deriving (Show)  -- 这行可以去掉，用下面的 TH 替代

$(deriveShow ''Person)

-- 展开后等价于：
-- instance Show Person where
--   show x = intercalate ", " 
--     [ (\x -> "personName = " ++ show (personName x)) x
--     , (\x -> "personAge = " ++ show (personAge x)) x
--     ]
```

```
前二十八章: 用 Haskell 写程序

第二十九章: 模板编程（TH）  ← 你在这里

┌──────────────────────────────────────────┐
│ reify: 编译期自省（查询编译器符号表）     │
│   ↑                                      │
│ 拼接 ($(...)): 元代码 → 目标代码         │
│   ↑                                      │
│ Q 单子: 元代码的执行上下文               │
│   ↑                                      │
│ TH AST: Exp/Decl/Type/Pat（代码即数据）  │
└──────────────────────────────────────────┘
```

**本章给你四件行李**：

1. **模板编程的本质是"编译期代码生成"**：元代码（运行在编译期的 Haskell）生成目标代码（成为最终程序的 Haskell）
    
2. **Q 单子是"编译期的 IO"**：提供 `newName`（生成新鲜名字）、`runIO`（运行 IO）、`reify`（查询符号表）、`report`（报告错误）等关键操作
    
3. **拼接（`$(...)`）是元代码与目标代码的桥梁**：在表达式、模式、类型、顶层声明四个上下文都能使用；拼接在编译期执行，生成的代码与手写代码完全等价
    
4. **reify 是编译期的"自省"API**：查询类型、类、数据构造器的定义，类似 GHCi 的 `:info`，但有命名空间和时间边界的限制

## 📝 本章核心洞见总结

> **洞见一：TH 让"代码即数据"在编译期达到顶峰**。
> 
> TH 资料："Template Haskell allows us to write 'macros' -> Haskell code that runs during compile time and generates Haskell code that becomes part of our Haskell program" 。**元代码（meta code）运行在编译期，生成目标代码（object code）**。

> **洞见二：TH 的三大支柱——AST、Q、拼接**。
> 
> TH 资料："TH AST: `Exp`, `Decl`, ... Q: Quotation monad, we write meta code inside it. Splicing: `$( )`. Transforms meta code into object code" 。**三者形成 TH 的基础，且相互交织**。

> **洞见三：AST 数据类型是递归的树结构**。
> 
> `Exp`、`Decl`、`Type`、`Pat`、`Lit` 等类型递归地表示 Haskell 代码的每个语法类别 。**你可以手动构造 AST（繁琐），或用引号语法（简洁）**。

> **洞见四：引号与拼接是互逆操作**。
> 
> TH 资料："splicing transforms TH AST into object code, quotation brackets transform object code into TH AST" 。**引号：`object code → TH AST`；拼接：`TH AST → object code`**。

> **洞见五：Q 单子是"编译期的 IO"**。
> 
> TH 资料："Think of Q like IO, but instead of side effects, it builds syntax trees during compilation" 。**Q 提供 newName、reify、runIO、report 等操作**​ 。

> **洞见六：newName 解决宏系统的卫生性问题**。
> 
> CIS 194 讲义："The string passed in is just a suggestion for the name. You could always pass the same string in but get different names each time" 。**hygiene（卫生性）是宏系统的核心难题，newName 保证生成新鲜名字**。

> **洞见七：runIO 强大但有陷阱**。
> 
> Hackage 文档："you are guaranteed the ordering of calls to runIO within a single Q computation, but not about the order in which splices are run" 。**典型用途：调试输出、编译期文件读取**。

> **洞见八：拼接在编译期执行**。
> 
> GHC 用户指南："What splicing operator does is run given Q monad, obtain the result which is AST representing the code, and then turn it into Haskell code and embed it at the place where splicing was called" 。**生成的代码与手写代码在类型检查、优化方面完全等价**。

> **洞见九：$ 符号的双重身份**。
> 
> GHC 用户指南："This use of overridesitsmeaningasaninfixoperator...Ifyouwanttheinfixoperator,putspacesaroundit"。∗∗‘(expr)`是拼接；`map ($ x)` 是函数应用**。

> **洞见十：声明拼接必须在顶层**。
> 
> GHC 用户指南："declaration splices are not allowed anywhere except at top level" 。**原因（Template Meta-programming 论文）：声明拼接引入不确定的新绑定，限制在顶层可避免作用域混乱**​ 。

> **洞见十一：reify 是编译器的"自省"API**。
> 
> CIS 194 讲义："The Q monad provides another very important facility: the ability to inspect predefined types and functions and see their definitions, not unlike the :info command in GHCi" 。**reify :: Name -> Q Info 查询名称的完整信息**。

> **洞见十二：reify 的可见性边界**。
> 
> GHC 用户指南："The type environment seen by reify includes all the top-level declaration up to the end of the immediately preceding declaration group, but no more" 。**reify 只能看到"拼接点之前"的声明**。

> **洞见十三：reify 的局限性**。
> 
> Haskell Wiki 指出三个坑：①导入的内容可能不完整（用 `-O` 编译解决）；②函数定义的 RHS 不可用（`VarI` 的 `Maybe Dec` 始终是 `Nothing`）；③运行时不能 reify（`reify` 依赖编译期类型环境） 。

> **洞见十四：命名空间至关重要**。
> 
> Hackage 文档："It is sometimes useful to construct the argument name using lookupTypeName or lookupValueName to ensure that we are reifying from the right namespace" 。**`'f` 和 `''T` 分别对应值和类型命名空间**。

> **洞见十五：TH 是 Haskell 生产生态的基石**。
> 
> TH 资料："This is the backbone of systems like Plutus, Aeson's deriveJSON, and lens auto-generation" 。**第二十八章 persistent 的 `share [mkPersist ...] [persistLowerCase| ... |]` 就是 TH 的典型应用**。

## 🛠️ 实践建议

1. **用 TH 自动派生类型类**：
    
    ```
    {-# LANGUAGE TemplateHaskell #-}
    import Language.Haskell.TH
    
    -- 为记录类型自动生成 Show 实例
    deriveShow :: Name -> Q [Dec]
    deriveShow typeName = do
      TyConI (DataD _ _ _ [RecC _ fields] _) <- reify typeName
      let fieldNames = [name | (name, _, _) <- fields]
      let showField n = [| \x -> nameBase n ++ " = " 
                                ++ show ($(varE n) x) |]
      let showFieldsExp = listE $ map showField fieldNames
      [d| instance Show $(conT typeName) where
            show x = intercalate ", " (map ($ x) $showFieldsExp) |]
    ```
    
2. **用 newName 生成卫生的宏**：
    
    ```
    -- 生成 liftM 实现
    liftMBody' :: Int -> Q Exp
    liftMBody' n = do
      m_names <- replicateM n (newName "x")  -- 新鲜名字
      let binds = [BindS (VarP name) (VarE m_name) 
                   | (m_name, name) <- zip m_names m_names]
      let ret = NoBindS (foldl AppE (VarE (mkName "f")) 
                         (map VarE m_names))
      return $ LamE (map VarP m_names) (DoE (binds ++ [ret]))
    ```
    
3. **用 reify 查询类型信息**：
    
    ```
    -- 查询类型的构造器
    inspectType :: Name -> Q ()
    inspectType typeName = do
      info <- reify typeName
      case info of
        TyConI (DataD _ _ _ constructors _) -> do
          runIO $ putStrLn $ "Data type with constructors: " 
                   ++ show constructors
        _ -> runIO $ putStrLn "Not a data type"
    ```
    
4. **用引号语法简化 AST 构造**：
    
    ```
    -- 手动构造（繁琐）
    manualAST :: Q Exp
    manualAST = return $ AppE (AppE (VarE '(+)) 
                            (LitE (IntegerL 1))) 
                            (LitE (IntegerL 2))
    
    -- 引号语法（简洁）
    quoteAST :: Q Exp
    quoteAST = [| 1 + 2 |]
    
    -- 嵌套拼接
    plusC :: Quote m => m Exp
    plusC = [| $oneC + $twoC |]
      where
        oneC = [| 1 |]
        twoC = [| 2 |]
    ```
    
5. **编译期计算与嵌入**：
    
    ```
    {-# LANGUAGE TemplateHaskell #-}
    import Language.Haskell.TH
    
    -- 编译期计算斐波那契数
    fib :: Int -> Integer
    fib 0 = 0
    fib 1 = 1
    fib n = fib (n-1) + fib (n-2)
    
    -- 编译期嵌入结果
    fib10 :: Integer
    fib10 = $(pure $ LitE $ IntegerL $ fib 10)  -- 55
    
    -- 编译期读取文件并嵌入
    embedFile :: FilePath -> Q Exp
    embedFile path = do
      content <- runIO $ readFile path
      [| content |]
    ```
    
6. **声明拼接必须在顶层**：
    
    ```
    -- ✅ 正确
    module MyModule where
    
    $(deriveShow ''Person)
    $(deriveJSON ''User)
    $(makeLenses ''Config)
    
    -- ❌ 错误：函数内部的声明拼接
    myFunc = do
      $(deriveShow ''Foo)  -- 不允许！
      return ()
    ```
    
7. **用 lookupTypeName/lookupValueName 明确命名空间**：
    
    ```
    -- 避免命名空间歧义
    reifySafely :: String -> Q Info
    reifySafely str = do
      Just typeName <- lookupTypeName str
      reify typeName
    
    -- 或者用单引号/双引号
    reifyType' = reify ''MyType      -- 类型命名空间
    reifyValue' = reify 'myFunction  -- 值命名空间
    ```
    
8. **调试 TH 代码**：
    
    ```
    -- 用 -ddump-splices 查看展开的拼接
    -- ghc -ddump-splices MyModule.hs
    
    -- 在 Q 单子中打印调试信息
    debugTH :: String -> Q ()
    debugTH msg = runIO $ putStrLn $ "[TH] " ++ msg
    
    -- 用 runQ 在 GHCi 中测试
    -- runQ [| 1 + 2 |] >>= print
    ```
