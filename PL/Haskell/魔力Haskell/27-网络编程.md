
# 第二十七章 网络编程 —— 读书笔记

> 💡 如果说第二十六章让你掌握了"高效字符串"这个最常被误用的数据类型，那么第二十七章就是把这把利器用到网络这个最真实的战场——**Haskell 的网络编程生态是分层清晰的**：最底层是 `network` 包的 Socket（裸 TCP/UDP），往上是 `wai`/`warp` 定义的 Web 应用接口与高性能服务器，再往上是 `wai-extra` 的中间件，最上层是用 `Monad` 变换器对 HTTP 能力做抽象以便测试，而 WebSocket 则是 HTTP 升级到全双工通信的桥梁。表面看是 5 个小节的库介绍，实则在揭示一个深层真相：**Haskell 的网络编程范式与第二十四、二十五章学的"单子变换器栈"完美契合**——`ReaderT Config (StateT AppState (WriterT Log IO)) a` 这样的栈，正是真实 Web 服务的标准形态。这一章让你亲眼看见：第二十六章学的 `ByteString` 和 `Builder`，如何在 WAI 的 `Application` 类型中贯穿始终——请求体是 `ByteString`、响应体是 `ByteString`、WebSocket 收发的是 `ByteString`、Socket 读写还是 `ByteString`。

```
│ 27.1 WAI/Warp: Web 应用接口 + 服务器        │
│ 27.5 network:Sockets: 裸 TCP/UDP            │
└─────────────────────────────────────────────┘
```

**这一章要解决的核心问题**：用什么抽象来处理网络？

Yesod 官方文档对 WAI 的设计哲学给出了精准描述 ：

> _"WAI is also built on top of the http-types package... Since we don't care about the specific request parameters, we ignore the first argument to the function, which contains the request value. The second argument is our 'send a response' function, which we immediately use."_

**🔑 洞见一：WAI 的核心是"Application 类型"**

```
type Application = Request -> (Response -> IO ResponseReceived) -> IO ResponseReceived
```

- **输入**：`Request`（HTTP 请求）
    
- **​ continuation**：`Response -> IO ResponseReceived`（一个"发送响应"的回调函数）
    
- **输出**：`IO ResponseReceived`（IO 动作）
    

这种"回调式"接口让 WAI 既支持简单的"一次性响应"，也支持流式响应、文件发送、WebSocket 升级等高级场景 。

## 27.1 wai/warp：Web 应用接口与高性能服务器

### WAI：Web 应用接口

Yesod 文档给出了最简的 Hello World ：

```
{-# LANGUAGE OverloadedStrings #-}
import Network.Wai
import Network.HTTP.Types (status200)
import Network.Wai.Handler.Warp (run)

application :: Application
application _ respond = 
  respond $ responseLBS status200 [("Content-Type", "text/plain")] "Hello World"

main :: IO ()
main = run 3000 application
```

**🔑 洞见二：WAI 的四种响应构造器**

Yesod 文档揭示了 WAI 响应的四种形态 ：

1. **`ResponseFile`**：直接发送文件（利用操作系统的 `sendfile` 系统调用，绕过内存拷贝）
    
2. **`ResponseBuilder`**：用 Builder 构造响应体（第二十六章学的 ByteString Builder）
    
3. **`ResponseStream`**：流式响应（"yield data" + "flush buffer" 交替）
    
4. **`ResponseRaw`**：跳出 HTTP 模式（用于 WebSocket 升级、HTTPS 代理等）
    

**这意味着**：WAI 不仅仅是"返回字符串"——它是完整的、可优化的、可升级的 HTTP 抽象。

### Warp：WAI 的高性能服务器

Hackage 文档明确描述 ：

> _"warp: A fast, light-weight web server for WAI applications. HTTP/1.0, HTTP/1.1 and HTTP/2 are supported."_

**🔑 洞见三：Warp 是 Haskell Web 服务的生产标准**

- **高性能**：Warp 是 Haskell 生态中最常用的 WAI 后端，以"快、轻"著称
    
- **HTTP/2 支持**：支持 direct 和 ALPN（在 TLS 中）两种方式，但不支持 upgrade
    
- **Slowloris 防护**：在请求接收和响应发送的各个环节都有超时控制
    

### 🔑 洞见四：请求体的流式处理

Yesod 文档描述了 WAI 请求体的设计 ：

> _"the request body is represented with a IO ByteString action (ByteString here being a strict ByteString)... Once you've consumed the entire request body, further calls to this action will return an empty ByteString."_

**关键点**：

- 请求体不是一次性加载到内存的惰性 ByteString（避免惰性 I/O 的问题）
    
- 而是"每次调用返回一个 chunk"的 `IO ByteString` 动作
    
- 消费完整个请求体后，再次调用返回空 ByteString
    
- 这与第二十六章学的严格 ByteString 理念完全一致
    

### 实际应用

```
{-# LANGUAGE OverloadedStrings #-}
import Network.Wai
import Network.Wai.Handler.Warp (run)
import Network.HTTP.Types (status200, status404)
import qualified Data.ByteString.Lazy as BL

-- 路由分发
router :: Application
router req respond = do
  case pathInfo req of
    ["health"] -> respond $ responseLBS status200 
      [("Content-Type", "application/json")] "{\"status\":\"ok\"}"
    ["echo"] -> do
      body <- strictRequestBody req
      respond $ responseLBS status200 
        [("Content-Type", "text/plain")] (BL.fromStrict body)
    _ -> respond $ responseLBS status404 
      [("Content-Type", "text/plain")] "Not Found"

-- 运行服务器
main :: IO ()
main = do
  putStrLn "Server running on http://localhost:3000"
  run 3000 router
```

## 27.2 wai-extra：中间件与扩展功能

### 中间件的概念

Hackage 文档列出 wai-extra 提供的核心功能 ：

> _"Provides basic WAI handler and middleware functionality: WAI Testing Framework... Event Source... Accept Override... Add Headers... Clean Path... GZip Compression... HTTP Basic Authentication... JSONP... Method Override... Request Logging... Request Rewrite... Stream Files... Virtual Host..."_

### 🔑 洞见五：中间件是"Application -> Application"的函数

```
type Middleware = Application -> Application
```

**wai-extra 提供的核心中间件**（Hackage 文档 ）：

|中间件|作用|
|---|---|
|`RequestLogger`|请求日志（开发和生产环境）|
|`Gzip`|协商 HTTP gzip 压缩|
|`HttpAuth`|HTTP Basic 认证|
|`AddHeaders`|添加任意 HTTP 头|
|`CleanPath`|规范化请求路径|
|`MethodOverride`|通过 `_method` 查询参数覆盖 HTTP 方法|
|`Jsonp`|JSONP 包装|
|`RequestSizeLimit`|请求体大小限制|
|`Rewrite`|基于自定义规则重写请求路径|
|`Vhost`|虚拟主机重定向|
|`Timeout`|超时控制|
|`StreamFile`|将 `ResponseFile` 转换为 `ResponseStream`|
|`ForceSSL`|强制 SSL|

### 🔑 洞见六：中间件的组合就是"洋葱模型"

```
import Network.Wai.Middleware.RequestLogger (logStdoutDev)
import Network.Wai.Middleware.Gzip (gzip)
import Network.Wai.Middleware.AddHeaders (addHeaders)

-- 中间件的组合
app :: Application
app = logStdoutDev          -- 外层：请求日志
    $ gzip def              -- 中层：Gzip 压缩
    $ addHeaders [("X-Frame-Options", "DENY")]  -- 内层：添加安全头
    $ myApp                 -- 核心应用
```

**执行顺序**：请求从外到内穿过中间件，响应从内到外返回——这就是经典的"洋葱模型"。

### 实际应用

```
{-# LANGUAGE OverloadedStrings #-}
import Network.Wai
import Network.Wai.Handler.Warp (run)
import Network.Wai.Middleware.RequestLogger (logStdoutDev)
import Network.Wai.Middleware.Gzip (gzip)
import Network.Wai.Middleware.HttpAuth (basicAuth)
import Network.HTTP.Types (status200)

-- 认证校验函数
checkCreds :: Data.ByteString.ByteString 
           -> Data.ByteString.ByteString 
           -> IO Bool
checkCreds user pass = 
  return $ user == "admin" && pass == "secret"

-- 受保护的应用
protectedApp :: Application
protectedApp _ respond = 
  respond $ responseLBS status200 
    [("Content-Type", "text/plain")] "Secret content"

-- 完整应用栈
app :: Application
app = logStdoutDev                          -- 1. 请求日志
    $ gzip def                              -- 2. Gzip 压缩
    $ basicAuth checkCreds "My Realm"       -- 3. Basic 认证
    $ protectedApp                          -- 4. 核心应用

main :: IO ()
main = run 3000 app
```

## 27.3 HTTP 的单子抽象：让 HTTP 客户端可测试

### 问题：IO 让测试困难

传统的 HTTP 客户端代码直接返回 `IO`：

```
import Network.HTTP.Client (httpLbs, Request, Manager, Response)
import Data.ByteString.Lazy (ByteString)

fetchUser :: Request -> Manager -> IO (Response ByteString)
fetchUser = httpLbs
```

**问题**：这种代码无法在纯环境中测试——`IO` 把"HTTP 请求"和"副作用"紧紧绑定。

### 🔑 洞见七：用类型类抽象 HTTP 能力

Pusher 的技术博客给出了优雅的解决方案 ：

```
class Monad m => MonadHTTP m where
  httpLbs :: Request -> Manager -> m (Response ByteString)

-- IO 实例：真实的 HTTP 请求
instance MonadHTTP IO where
  httpLbs = Network.HTTP.Client.httpLbs

-- Mock 实例：返回预设响应
instance Monad m => MonadHTTP (MockServer m) where
  httpLbs _ _ = ask  -- 从 Reader 中获取预设响应
```

**优势**（Pusher 博客 ）：

> _"Using these typeclasses has a benefit beyond testing: It splits the IO type up into types that specifically reflects the action to be performed... It is easier to refactor because new concrete implementations can be swapped in by implementing the typeclass."_

### 🔑 洞见八：Free Monad 提供更彻底的抽象

`free-http` 库用 Free Monad 表达 HTTP 动词 ：

```
-- Free Monad 表达 HTTP 操作
data HttpF client a = HttpF StdMethod 
                            (RequestType client) 
                            (ResponseType client -> a) 
                    deriving Functor

type FreeHttp client m a = FreeT (HttpF client) m a

-- 不同后端解释器
runHttp :: FreeHttp MyClient IO String -> IO String  -- 真实 IO
runPure :: FreeHttp MyClient Identity a -> a          -- 纯测试
runRandom :: FreeHttp MyClient IO a -> IO a           -- 随机测试
```

**这意味着**：HTTP 程序可以用 Free Monad 表达，然后用不同的解释器运行——生产环境用真实 HTTP 客户端，测试环境用纯函数或随机生成器 。

### 🔑 洞见九：MonadHTTP 与单子变换器栈的结合

这正是第二十四、二十五章学的知识的实战应用：

```
{-# LANGUAGE FlexibleContexts #-}
import Control.Monad.Reader
import Control.Monad.State
import Control.Monad.IO.Class (MonadIO)

-- 用具体的 IO
type App a = ReaderT Config (StateT AppState IO) a

-- 用具体的 IO
doHttpRequest :: (MonadReader Config m, MonadState AppState m, MonadIO m)
              => Request -> m (Response ByteString)
doHttpRequest req = do
  config <- ask
  liftIO $ httpLbs req (cfgManager config)
```

**关键洞察**：通过 `MonadIO` 约束，`doHttpRequest` 可以在任何包含 IO 的变换器栈中使用——完全解耦！

### 实际应用

```
{-# LANGUAGE FlexibleContexts #-}
import Control.Monad.Reader
import Control.Monad.State
import Network.HTTP.Client
import Data.ByteString.Lazy (ByteString)

-- 应用配置
data AppConfig = AppConfig
  { cfgManager :: Manager
  , cfgBaseUrl :: String
  }

-- 应用状态
data AppState = AppState
  { apiCallCount :: Int
  }

-- 应用单子
type App a = ReaderT AppConfig (StateT AppState IO) a

-- 抽象的 HTTP 请求函数
fetchUrl :: (MonadReader AppConfig m, MonadState AppState m, MonadIO m)
         => String -> m (Response ByteString)
fetchUrl url = do
  -- 读取配置
  config <- ask
  -- 更新状态：API 调用计数 +1
  modify $ \s -> s { apiCallCount = apiCallCount s + 1 }
  -- 发起请求
  let req = parseRequest_ (cfgBaseUrl config ++ url)
  liftIO $ httpLbs req (cfgManager config)

-- 业务函数
fetchUserProfile :: (MonadReader AppConfig m, MonadState AppState m, MonadIO m)
                 => Int -> m (Maybe UserProfile)
fetchUserProfile userId = do
  response <- fetchUrl $ "/users/" ++ show userId
  case responseStatus response of
    status200 -> return $ decode (responseBody response)
    _ -> return Nothing

-- 测试版本（使用 Mock）
data MockApp m a = MockApp (ReaderT AppConfig (StateT AppState m) a)
  deriving (Functor, Applicative, Monad)

-- 在测试中，可以用 Mock 替换 httpLbs 的行为
```

## 27.4 WebSocket 编程：全双工实时通信

### WebSocket 与 WAI 的桥接

wai-websockets 的 Hackage 文档给出了关键函数 ：

```
websocketsOr :: ConnectionOptions -> ServerApp -> Application -> Application
```

**🔑 洞见十：WebSocket 是 HTTP 的"升级"**

`websocketsOr` 的工作机制 ：

1. 检查请求是否是 WebSocket 握手请求
    
2. 如果是 → 升级到 WebSocket 连接，调用 `ServerApp`
    
3. 如果不是 → 降级到普通的 WAI `Application`
    

wai-websockets 的 Hackage 文档 ：

> _"Upgrade a websockets ServerApp to a wai Application. Uses the given backup Application to handle Requests that are not WebSocket requests."_

### 🔑 洞见十一：WebSocket 的核心是 PendingConnection

```
type ServerApp = PendingConnection -> IO ()

handleConnection :: PendingConnection -> IO ()
handleConnection pending = do
  conn <- acceptRequest pending
  -- 现在 conn 是全双工的 WebSocket 连接
  forever $ do
    msg <- receiveData conn
    sendTextData conn $ "Echo: " <> msg
```

**WebSocket 连接的特性**：

- **全双工**：客户端和服务器可以同时发送
    
- **消息导向**：以消息为单位，而非字节流
    
- **支持文本和二进制**：`sendTextData` / `sendBinaryData`
    

### 多客户端广播：共享状态管理

初学者指南给出了用 `TVar` 和 `Map` 管理客户端的模式 ：

```
import Control.Concurrent.STM
import qualified Data.Map as Map

type ClientId = Int
type ServerState = TVar (Map ClientId Connection)

-- 广播消息到所有客户端
broadcast :: ServerState -> T.Text -> STM ()
broadcast state msg = do
  clients <- readTVar state
  forM_ (Map.elems clients) $ \conn ->
    sendTextData conn msg
```

**🔑 洞见十二：WebSocket 并发处理的关键**

初学者指南警告 ：

> _"A common pitfall is using an infinite loop (forever) to process messages without considering concurrency. If this loop blocks indefinitely, it can prevent your server from accepting new connections."_

**最佳实践**：

1. **每个连接一个线程**：用 `forkFinally` 处理并发
    
2. **共享状态用 STM**：避免竞态条件
    
3. **优雅关闭**：客户端断开时清理状态
    

### 实际应用

```
{-# LANGUAGE OverloadedStrings #-}
import Control.Concurrent.STM
import Control.Concurrent (forkFinally)
import Control.Exception (finally)
import Control.Monad (forever, forM_)
import qualified Data.Text as T
import qualified Network.WebSockets as WS
import qualified Network.Wai.Handler.WebSockets as WaiWS
import Network.Wai.Handler.Warp (run)

-- 客户端表示
type Client = (T.Text, WS.Connection)

-- 服务器状态
type ServerState = [Client]

-- 广播消息
broadcast :: T.Text -> ServerState -> IO ()
broadcast message clients = do
  T.putStrLn message
  forM_ clients $ \(_, conn) -> WS.sendTextData conn message

-- 应用状态用 MVar 管理
main :: IO ()
main = do
  state <- newMVar []
  putStrLn "WebSocket server on ws://localhost:3000"
  run 3000 $ WaiWS.websocketsOr WS.defaultConnectionOptions (app state) backupApp
  where
    app :: MVar ServerState -> WS.ServerApp
    app state pending = do
      conn <- WS.acceptRequest pending
      WS.forkPingThread conn 30  -- 保活
      
      -- 读取用户名
      msg <- WS.receiveData conn
      let client = (msg, conn)
      
      -- 添加客户端
      modifyMVar_ state $ \clients -> do
        broadcast (msg <> " joined") clients
        return (client : clients)
      
      -- 消息循环
      `finally` do
        -- 清理：移除客户端
        modifyMVar_ state $ \clients ->
          return $ filter ((/= msg) . fst) clients
        broadcast (msg <> " left") =<< readMVar state
    
    -- 备份 HTTP 应用
    backupApp :: Network.Wai.Application
    backupApp _ respond = 
      respond $ responseLBS status200 
        [("Content-Type", "text/plain")] "Not a WebSocket request"
```

## 27.5 Socket 编程：裸 TCP/UDP 的掌控力

### network 包的核心 API

Hackage 文档给出了 TCP 回声服务器的标准模板 ：

```
import Network.Socket
import Network.Socket.ByteString (recv, sendAll)

-- TCP 服务器
runTCPServer :: Maybe HostName -> ServiceName -> (Socket -> IO a) -> IO a
runTCPServer mhost port server = withSocketsDo $ do
  addr <- resolve
  E.bracketOnError (open addr) close $ \sock -> do
    setSocketOption sock ReuseAddr 1
    bind sock $ addrAddress addr
    listen sock 1024
    loop sock
  where
    loop sock = forever $ E.bracketOnError (accept sock) (close . fst) $ 
      \(conn, _peer) -> void $ forkFinally (server conn) (const $ gracefulClose conn 5000)
```

### 🔑 洞见十三：Socket 编程的"生命周期"

Hackage 文档描述了完整流程 ：

1. **resolve**：`getAddrInfo` 解析地址（协议无关，支持 IPv4 和 IPv6）
    
2. **open**：`openSocket` 创建套接字
    
3. **bind**：绑定到地址
    
4. **listen**：开始监听（指定队列长度）
    
5. **accept**：接受连接
    
6. **communicate**：通过 `recv`/`sendAll` 通信
    
7. **close**：`gracefulClose` 优雅关闭
    

### 🔑 洞见十四：Socket 的并发模型

Hackage 文档明确指出 ：

> _"The proper programming model is that one Socket is handled by a single thread... There is one exception for multiple threads vs a single Socket: one thread reads data from a Socket only and the other thread writes data to the Socket only."_

**这意味着**：

- **每个连接一个线程**：`forkFinally` 处理并发
    
- **资源清理**：`bracketOnError` 确保异常时关闭 socket
    
- **优雅关闭**：`gracefulClose conn 5000` 等待 5 秒让数据发送完毕
    

### 🔑 洞见十五：withSocketsDo 的兼容性

Hackage 文档 ：

> _"With older versions of the network library... on Windows operating systems, the networking subsystem must be initialised using withSocketsDo... withSocketsDo is not necessary for the current network library. However, for compatibility with older versions on Windows, it is good practice to always call withSocketsDo (it's very cheap)."_

**最佳实践**：总是用 `withSocketsDo` 包裹网络初始化代码。

### 实际应用

```
{-# LANGUAGE OverloadedStrings #-}
import Control.Concurrent (forkFinally)
import Control.Exception (bracketOnError)
import Control.Monad (forever, void)
import qualified Data.ByteString as S
import Network.Socket
import Network.Socket.ByteString (recv, sendAll)

-- 聊天室服务器
main :: IO ()
main = do
  -- 广播通道
  chan <- newChan :: IO (Chan S.ByteString)
  
  -- 启动广播线程
  _ <- forkIO $ forever $ do
    msg <- readChan chan
    -- 广播给所有客户端（简化版：此处应维护客户端列表）
    putStrLn $ "Broadcast: " ++ show msg
  
  -- 运行 TCP 服务器
  runTCPServer Nothing "4242" $ \conn -> do
    -- 每个连接一个线程
    let broadcast msg = writeChan chan msg
    
    -- 读取客户端名称
    nameMsg <- recv conn 1024
    let clientName = S.takeWhile (/= 0) nameMsg
    
    -- 通知其他客户端
    broadcast $ "User " <> clientName <> " joined"
    
    -- 消息循环
    let loop = do
          msg <- recv conn 1024
          if S.null msg
            then broadcast $ "User " <> clientName <> " left"
            else do
              broadcast $ clientName <> ": " <> msg
              loop
    
    loop `finally` do
      broadcast $ "User " <> clientName <> " disconnected"
      close conn

-- TCP 服务器模板
runTCPServer :: Maybe HostName -> ServiceName -> (Socket -> IO a) -> IO a
runTCPServer mhost port server = withSocketsDo $ do
  addr <- resolve
  bracketOnError (open addr) close $ \sock -> do
    setSocketOption sock ReuseAddr 1
    bind sock $ addrAddress addr
    listen sock 1024
    loop sock
  where
    resolve = do
      let hints = defaultHints 
            { addrFlags = [AI_PASSIVE]
            , addrSocketType = Stream
            }
      head <$> getAddrInfo (Just hints) mhost (Just port)
    
    open addr = do
      sock <- socket (addrFamily addr) (addrSocketType addr) (addrProtocol addr)
      bind sock (addrAddress addr)
      listen sock 1024
      return sock
    
    loop sock = forever $ bracketOnError (accept sock) (close . fst) $ 
      \(conn, _peer) -> void $ forkFinally (server conn) (const $ gracefulClose conn 5000)
```

## 📝 本章核心洞见总结

> **洞见一：WAI 的核心是 Application 类型**。
> 
> `type Application = Request -> (Response -> IO ResponseReceived) -> IO ResponseReceived` ——回调式接口支持简单响应、流式响应、文件发送、WebSocket 升级等所有场景 。

> **洞见二：WAI 响应有四种构造器**。
> 
> `ResponseFile`（sendfile 零拷贝）、`ResponseBuilder`（Builder 构造）、`ResponseStream`（流式）、`ResponseRaw`（跳出 HTTP 模式） 。**这与第二十六章学的 ByteString/Builder 完美契合**。

> **洞见三：Warp 是 Haskell Web 服务的生产标准**。
> 
> Hackage 文档："A fast, light-weight web server for WAI applications. HTTP/1.0, HTTP/1.1 and HTTP/2 are supported" 。**Slowloris 防护通过各环节超时实现**​ 。

> **洞见四：wai-extra 提供"Application -> Application"的中间件**。
> 
> Hackage 文档列出的核心中间件：RequestLogger、Gzip、HttpAuth、AddHeaders、CleanPath、MethodOverride、Jsonp、RequestSizeLimit、Vhost、Timeout 等 。**中间件组合形成"洋葱模型"**。

> **洞见五：HTTP 单子抽象让客户端可测试**。
> 
> Pusher 博客："Using these typeclasses has a benefit beyond testing: It splits the IO type up into types that specifically reflects the action to be performed" 。`MonadHTTP` 类型类 + 具体实例（IO/Reader/Mock）实现依赖倒置。

> **洞见六：Free Monad 提供更彻底的 HTTP 抽象**。
> 
> `free-http` 库用 `HttpF` functor 表达 HTTP 动词，用不同解释器运行：真实 IO、纯函数、随机生成 。**这是第二十五章"Monad 变换的升格操作"思想在 HTTP 客户端的延伸**。

> **洞见七：WebSocket 是 HTTP 的协议升级**。
> 
> wai-websockets 的 `websocketsOr`："Upgrade a websockets ServerApp to a wai Application" 。**非 WebSocket 请求降级到普通 WAI Application**。

> **洞见八：WebSocket 并发处理的关键**。
> 
> 初学者指南警告："A common pitfall is using an infinite loop (forever) to process messages without considering concurrency" 。**最佳实践**：每连接一线程 + STM 管理共享状态 + 优雅关闭。

> **洞见九：Socket 编程的生命周期**。
> 
> Hackage 文档：`getAddrInfo` → `openSocket` → `bind` → `listen` → `accept` → `recv`/`sendAll` → `gracefulClose` 。**协议无关**：支持 IPv4 和 IPv6 。

> **洞见十：Socket 的并发模型是"一连接一线程"**。
> 
> Hackage 文档："The proper programming model is that one Socket is handled by a single thread" 。**例外**：一个线程只读、另一个线程只写，可以共享一个 Socket 。

> **洞见十一：withSocketsDo 的兼容性实践**。
> 
> Hackage 文档："withSocketsDo is not necessary for the current network library. However, for compatibility with older versions on Windows, it is good practice to always call withSocketsDo" 。**代价很低，但兼容性很好**。

> **洞见十二：ByteString 贯穿整个网络栈**。
> 
> WAI 请求体是 `IO ByteString` 、WebSocket 收发 `ByteString` 、Socket 读写 `ByteString` ——**第二十六章学的严格 ByteString 是网络编程的内存基础**。

## 🛠️ 实践建议

1. **Web 服务标准栈**：
    
    ```
    {-# LANGUAGE OverloadedStrings #-}
    import Network.Wai
    import Network.Wai.Handler.Warp (run)
    import Network.Wai.Middleware.RequestLogger (logStdoutDev)
    import Network.Wai.Middleware.Gzip (gzip)
    
    -- 生产级 Web 服务栈
    app :: Application
    app = logStdoutDev $ gzip def $ router
    
    router :: Application
    router req respond = case pathInfo req of
      ["health"] -> respond healthCheck
      ["api", "users"] -> respond $ handleUsers req
      _ -> respond notFound
    
    main :: IO ()
    main = run 3000 app
    ```
    
2. **WebSocket 聊天服务器**：
    
    ```
    import Control.Concurrent.STM
    import qualified Network.WebSockets as WS
    import qualified Network.Wai.Handler.WebSockets as WaiWS
    import Network.Wai.Handler.Warp (run)
    
    -- 用 TVar 管理客户端
    type ServerState = TVar (Map T.Text WS.Connection)
    
    chatServer :: ServerState -> WS.ServerApp
    chatServer state pending = do
      conn <- WS.acceptRequest pending
      WS.forkPingThread conn 30
      userName <- WS.receiveData conn
    
      atomically $ modifyTVar state (Map.insert userName conn)
      broadcast state $ userName <> " joined"
    
      `finally` do
        atomically $ modifyTVar state (Map.delete userName)
        broadcast state $ userName <> " left"
    ```
    
3. **HTTP 客户端的 Monad 抽象**：
    
    ```
    {-# LANGUAGE FlexibleContexts #-}
    import Network.HTTP.Client
    import Control.Monad.Reader
    import Control.Monad.State
    
    class Monad m => MonadHTTP m where
      httpLbs' :: Request -> Manager -> m (Response ByteString)
    
    instance MonadHTTP IO where
      httpLbs' = httpLbs
    
    -- 在变换器栈中使用
    fetchData :: (MonadReader Config m, MonadHTTP m) => String -> m ByteString
    fetchData url = do
      config <- ask
      let req = parseRequest_ url
      response <- httpLbs' req (cfgManager config)
      return $ responseBody response
    ```
    
4. **TCP Socket 服务器**：
    
    ```
    import Network.Socket
    import Network.Socket.ByteString (recv, sendAll)
    
    echoServer :: IO ()
    echoServer = runTCPServer Nothing "3000" $ \conn -> do
      msg <- recv conn 1024
      unless (S.null msg) $ do
        sendAll conn msg
        echoServer' conn
    
    runTCPServer :: Maybe HostName -> ServiceName -> (Socket -> IO a) -> IO a
    runTCPServer mhost port server = withSocketsDo $ do
      addr <- resolve
      bracketOnError (open addr) close $ \sock -> do
        setSocketOption sock ReuseAddr 1
        bind sock $ addrAddress addr
        listen sock 1024
        loop sock
      where
        loop sock = forever $ 
          bracketOnError (accept sock) (close . fst) $ 
            \(conn, _) -> void $ forkFinally (server conn) 
              (const $ gracefulClose conn 5000)
    ```
    
5. **完整的 Web 应用栈**：
    
    ```
    {-# LANGUAGE GeneralizedNewtypeDeriving #-}
    
    -- 结合第二十四、二十五章的单子变换器
    newtype App a = App 
      { runApp :: ReaderT Config (StateT AppState (WriterT (Seq.Seq LogMsg) IO)) a }
      deriving (Functor, Applicative, Monad)
    
    -- 自动获得 MonadReader/MonadState/MonadWriter/MonadIO
    -- 业务代码完全解耦，可在测试中用纯函数替换 IO
    
    serveRequest :: (MonadReader Config m, MonadState AppState m, 
                    MonadWriter (Seq.Seq LogMsg) m, MonadIO m)
                 => Request -> m Response
    serveRequest req = do
      tell $ Seq.singleton $ "Handling " <> pathInfo req
      config <- ask
      modify $ \s -> s { requestCount = requestCount s + 1 }
      liftIO $ putStrLn "Processing request..."
      return successResponse
    ```
