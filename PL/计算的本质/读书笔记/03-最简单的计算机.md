
# 第3章　最简单的计算机 —— 读书笔记

## 本章在全书的位置：从"程序语义"走向"计算模型"

第2章回答了"程序的含义如何被精确定义"（小步/大步/指称语义）；第3章则把视角抬高一格：**什么样的问题能被"最简单的一类机器"解决？**​ 答案就是**有限自动机（FA）**——一类记忆能力被严格限制（只有有限个状态）的计算模型。Tom Stuart 用 Ruby 亲手实现 DFA/NFA，并把它与**正则表达式**在语义上打通，最后证明它们的**等价性**。这一章是全书的"计算模型第一课"，也是后面下推自动机（PDA，第4章）、图灵机（第5章）的能力层级阶梯的第一级。

> 💡 一句话洞见：本章真正想建立的直觉是——**"计算能力"可以用"记忆的组织方式"来分级**。有限状态 = 常数级记忆 = 正则语言；下推栈 = 无限栈记忆 = 上下文无关语言；图灵机 = 任意读写带 = 可递归枚举语言。第3章站在这个阶梯的最底端，却也因此最清晰、最"可完全判定"。

## 3.1 确定性有限自动机（DFA）

### 3.1.1 状态、规则和输入

一个 DFA 由五元组定义：**状态集 Q、字母表 Σ、转移函数 δ、起始状态 q₀、接受状态集 F**​ 。规则极其简单：在任一状态读到某个输入字符，就**唯一确定**地转移到下一个状态。Stuart 用 Ruby 把"规则"建模为对象（`FARule`），把"规则集"封装成 `DFARulebook`，把整个自动机封装成 `DFA` 类——这种"规则即数据、机器即对象"的建模，正是第1章"对象+方法"特性的第一次实战。

### 3.1.2 输出

DFA 的"输出"不是打印数字，而是**接受/拒绝**：读完整个输入串后，若停在某个**接受状态**，则接受该串；否则拒绝。这定义了一个**语言**（被接受的字符串集合）。DFA 识别的语言恰是**正则语言**​ 。

### 3.1.3 确定性

"确定性"有两层含义 ：

- **无 ε-转移**：不能"不看输入"就跳转；
    
- **转移唯一**：对每个状态+字符，至多一条适用规则（确定的下一状态）。
    

确定性带来一个巨大好处：**模拟 DFA 只需 O(n) 时间和 O(1) 空间**（n 为输入长度）——每一步状态唯一确定，无需回溯、无需存储候选。这是工业界为什么大量用 DFA 做**词法分析/模式匹配**的根本原因。

### 3.1.4 模拟

Stuart 实现的核心是一个 `DFA` 类：持有当前状态，提供 `#read_character(c)`（按规则转移）、`#read_string(s)`（逐字符读取）、`#accepting?`（是否在接受状态）。你可以在 irb 里亲手构造一个"识别偶数个 0"的 DFA，逐字符喂入，观察状态迁移——这正是**小步语义"按规则重写"的第一次具象化**：当前状态就是"当前配置"，规则就是"规约规则"，一步步把输入串"消费"掉。

> 💡 洞见：DFA 的模拟和第2章小步语义是**同一个思维模式**——都是"当前配置 + 规约规则 → 下一步配置"的迭代。区别只在于：第2章规约的是 AST 节点，这里规约的是"(状态, 剩余输入)"对。这暗示了一个深层统一：**一切计算模型都是"配置+重写规则"**，后面图灵机、tag system 都不会跳出这个框架。

## 3.2 非确定性有限自动机（NFA）

### 3.2.1 非确定性

NFA 放宽了确定性的两条限制 ：

- 一个状态读一个字符，可以有多条可选转移（"分叉"）；
    
- 允许 **ε-转移**（free move，见 3.2.2），即不消费输入也能跳转。
    

关键理解：**NFA 并非"掷骰子随机选一条路"**，而是**并行地/同时地处于多条可能路径上**——只要存在**至少一条**路径能到达接受状态，就接受该串 。用集合语言说：NFA 的"当前配置"是一个**状态集合**（所有"当前可能所在"的状态），每读一个字符，就把这个集合按规则"推进"一步。

Stuart 的实现非常漂亮：用 `#read_character(c)` 把"当前状态集合"映射为"下一步状态集合"（对所有当前状态求并集），这就是**子集构造（subset construction）**​ 的雏形。NFA 的模拟本质是**BFS/状态集合的迭代**。

> 💡 洞见：NFA 的"状态集合"视角，是理解**幂集构造**（把 NFA 转成等价 DFA）的关键。DFA 的每一个状态，其实就是 NFA 的一个"状态子集"。这揭示了一个更普遍的工程思想：**用"集合/幂集"把"非确定性"提升为"确定性"**——后面在并发理论里，"非确定性"常被建模为"分支的可能世界集合"，思路如出一辙。

### 3.2.2 自由移动（free move / ε-转移）

ε-转移（epsilon transition）指**不消费任何输入字符**的状态跳转 。它让 NFA 的表达更简洁（比如正则的 `a*` 可以用一个 ε-环路表达），但也让模拟稍复杂：每次"真正读字符"前后，都要把"通过 ε-转移可达的所有状态"一并纳入当前集合——即计算 **ε-闭包（epsilon-closure）**。

Stuart 在 Ruby 里用 `#follow_free_moves(state)` 递归/迭代地求出从某状态出发、只经 ε-转移能到达的全部状态。这是 NFA 模拟不可或缺的一步：**当前配置 = 当前真实状态 ∪ 其 ε-闭包**。

工业联系：ε-闭包是 **Thompson 构造法**（把正则表达式编译成 NFA）的核心操作 ；而现代正则引擎（如 RE2、Rust 的 `regex` crate）在做 NFA 模拟/DFA 转换时，都要高效计算 ε-闭包。ε-转移让"正则 → NFA"的构造极其自然，也为 3.4 的等价性证明提供了桥梁。

## 3.3 正则表达式

### 3.3.1 语法

Stuart 用 Ruby 为**正则语言的一个小子集**定义了 AST 节点：`Empty`（空串）、`Literal`（单字符）、`Concatenate`（拼接）、`Choose`（选择 `|`）、`Repeat`（Kleene 星 `*`）。这恰是**正则语言的归纳定义**：从原子（空串、单字符）出发，经拼接、并集、闭包三种运算构造出所有正则语言 。

> 补充（英文权威）：正则表达式的严格代数定义正是——`∅` 和 `ε` 是正则表达式；若 r、s 是正则式，则 `rs`（拼接）、`r|s`（选择）、`r*`（Kleene 星）也是正则式 ；其语义是"描述正则语言"的字符串集合。Stuart 的 mini 正则语法完整覆盖了这三类构造。

### 3.3.2 语义

"正则式的含义"是什么？就是**它被接受的语言（字符串集合）**。Stuart 给出两种语义视角：

- **操作语义（NFA 视角）**：用 **Thompson 构造**，把每个正则 AST 节点递归地翻译成一个 NFA 片段（原子→两状态+一条字符边；拼接→串联两个 NFA；选择→ε-分支到两个 NFA；`*`→ε-环路）。这正是 Thompson 在 1968 年提出的方法 ：把正则式编译成 NFA，再用 3.2 的 NFA 模拟去"运行"。
    
- **指称语义（集合视角）**：每个正则式节点直接映射到"被接受的语言集合"——`Literal(c)` → `{c}`，`Concatenate(r,s)` → `L(r)·L(s)`，`Choose(r,s)` → `L(r)∪L(s)`，`Repeat(r)` → `L(r)*`（Kleene 闭包）。这完美呼应第2章指称语义的"组合性"原则：复合短语的含义是其子短语含义的数学组合。
    

> 💡 洞见：这一节是全章**最精彩的对偶**——同一个正则式，既有"如何执行"（NFA/Thompson 构造，操作语义），又有"是什么"（语言集合，指称语义）。这正是第2章两种语义观的**第一次真正落地**。理解这一点，你会恍然大悟：正则引擎不是在"解释字符串"，而是在"把一个代数表达式翻译成一台小机器，再让这台小机器跑输入"。

### 3.3.3 解析

有了 AST 结构和语义，还差一步：**把正则式的文本（如 `(a|b)*c`）解析成 AST**。Stuart 在 3.3.3 手写一个**递归下降解析器**（recursive descent parser），把字符流转成正则 AST——这直接复用第2章 2.6"实现语法解析器"的技术。解析正则式需要处理运算符优先级（`*` > 拼接 > `|`）和括号分组，是一个极好的**解析器实战练习**。

工业联系：所有正则引擎（PCRE、RE2、Onigmo/Ruby 内置正则）的第一步都是**把模式字符串解析成内部 AST/NFA**，再编译/优化。Ruby 3.4 引入的 `Regexp::Timeout` 正是为了让正则匹配可中断、避免 ReDoS（正则拒绝服务）攻击 ——而 ReDoS 的根源，恰恰是**某些病态正则会让回溯型引擎（NFA 模拟）指数级爆炸**。理解 3.3 的 NFA 视角，你就能从"计算模型"层面理解为什么 ReDoS 会发生、为什么工业界越来越倾向**基于 DFA/Thompson NFA 的非回溯引擎**（如 RE2、Rust `regex`）。

## 3.4 等价性

这是本章的"理论高潮"，Stuart 要证明三件事在表达能力上**等价**：

1. **DFA ≃ NFA**：任何 NFA 都可通过**幂集构造（subset construction）**​ 转换为等价 DFA（状态数可能指数级膨胀，但语言相同）；
    
2. **NFA ≃ 正则表达式**：Kleene 定理 —— 正则语言恰是能被 NFA（从而 DFA）识别的语言 ；
    
3. 闭环：**DFA ↔ NFA ↔ 正则表达式**，三者描述同一类语言——**正则语言**。
    

> 补充（英文权威）：Kleene 定理是自动机理论的基石 ：正则表达式是"描述"正则语言的表达式；FA（DFA/NFA）是"识别"正则语言的机器；两者能力等价。证明路径通常是：正则式 → NFA（Thompson 构造，3.3.2 已做）→ NFA → DFA（幂集构造）→ DFA → 正则式（状态消去法）。Stuart 在 Ruby 里通过"都能被同一套 NFA/DFA 模拟接受"来**实验性地**验证这一等价，而非给出严格数学证明——这正是本书"用可运行代码代替形式证明"的一贯风格。

工业联系（等价性的真正价值）：

- **词法分析器生成器（Lex/Flex/JFlex）**：用正则式描述 token 模式 → 内部转成 DFA → 生成高效词法分析器代码（O(n) 时间、O(1) 空间） ；
    
- **正则表达式引擎**：用户输入的正则 → NFA（Thompson）→ 可选 DFA 转换 → 匹配 ；
    
- **文本编辑器/IDE 的语法高亮**：底层就是正则 → DFA 的匹配；
    
- **网络入侵检测（Snort/Suricata）**：用正则/DFA 做高速模式匹配。
    

> 💡 洞见（本章最重要的工程启示）：**"等价"不等于"等价地高效"**。NFA → DFA 的幂集构造可能让状态数指数爆炸（最坏 2ⁿ），所以实际正则引擎要在"NFA 模拟（可能回溯爆炸）"和"DFA（可能状态爆炸）"之间做权衡。RE2 选择 DFA+有限状态缓存，Rust `regex` 选择 Thompson NFA 解释器+有限回溯保护，PCRE 选择回溯+NFA——**不同引擎的取舍，本质是对"等价性代价"的不同回答**。读懂第3章，你就能理解为什么 Ruby/Java/Python 的回溯型正则会出 ReDoS，而 RE2/Rust `regex` 不会。

## 全章脉络与"第一性原理"总结

把第3章的逻辑主线抽出来：

1. **DFA**（3.1）：有限状态 + 确定转移 → O(n) 模拟 → 识别正则语言；
    
2. **NFA**（3.2）：放宽到非确定/ε-转移 → 用"状态集合/ε-闭包"模拟 → 与 DFA 等价但表达更简洁；
    
3. **正则表达式**（3.3）：用 AST + Thompson 构造/NFA 编译 + 递归下降解析 → 三种正则运算恰描述正则语言；
    
4. **等价性**（3.4）：DFA ≃ NFA ≃ 正则表达式（Kleene 定理）→ 三者同描述正则语言。
    

**一条贯穿全书的洞见**：第3章在悄悄建立"语言/自动机/代数"的三位一体——**同一种计算能力，可以从三个角度理解**：机器角度（DFA/NFA 如何跑）、代数角度（正则式如何组合）、集合角度（被接受的语言是什么）。这种"一题三解"的思维方式，是理论计算机科学最核心的武器：当你后面遇到图灵机（第5章）、λ 演算（第6章）时，都会反复看到"机器 vs 代数 vs 语义"的三重奏。

**与第2章的深层呼应**：DFA/NFA 的"按规则逐步迁移"，正是第2章小步语义"按规则重写"的最简单实例；正则式的"操作语义（NFA）+ 指称语义（语言集合）"对偶，正是第2章两种语义观的第一次完整落地。**第3章不是孤立的"自动机入门"，而是第2章语义学思想的"计算模型化"延续**——它把"程序含义"具体成了"机器能/不能识别哪类语言"，从而引出了全书最核心的问题之一：**计算的边界在哪里？**（这个问题要到第8章停机问题才真正爆发，但第3章的正则语言边界，是那座冰山露出海面的第一角。）
