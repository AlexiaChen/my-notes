
# 第6章　从零开始编程 —— 读书笔记

## 本章在全书的位置：从"机器模型"切换到"函数模型"

前五章走的是 **Church–Turing 论题**​ 的一条腿——**图灵机**（机器模型）：用"状态+纸带+重写规则"刻画全部可计算函数。第6章切换到另一条腿——**λ 演算（Lambda Calculus）**，由 Alonzo Church 在 1930s 提出 ，是**函数式编程的理论基石**，也是另一个"等价刻画可计算性"的终极模型。

> 💡 一句话洞见：本章标题"从零开始编程（Programming with Nothing）"字面意思极其激进——**在纯 λ 演算里，没有数字、没有布尔、没有列表、没有字符串、甚至没有赋值语句，唯一存在的"东西"是"函数"和"函数调用"**。Tom Stuart 要做的，是只用 Ruby 的 `Proc`（闭包）这一个特性，从零把数字、布尔、谓词、序对、列表、字符串**全部用函数模拟出来**。这既是对"λ 演算图灵完备"的实证，也是对"计算本质"最纯粹的一次逼近：**计算 = 函数抽象 + 应用**，仅此而已。

## 6.1 模拟 lambda 演算（用 Ruby Proc 从零构造一切）

### 6.1.1 使用 proc 工作

这一节是全书技术含量最高、也最"烧脑"的起点。Stuart 用 Ruby 的 `Proc`（闭包）来模拟 λ 演算的 λ 抽象（λx.M）和应用（M N）。关键：λ 演算里**一切都是函数**——函数接受函数、返回函数、函数体内再构造新函数。

> 补充（英文权威）：λ 演算的语法极简 ：`e ::= x | λx.e | e₁ e₂`（变量、抽象、应用）。计算规则只有一条——**β-归约**：`(λx.M) N → M[x:=N]`（把函数体 M 中所有的 x 替换为 N）。Ruby 的 `Proc` 正是对"代码块+闭包"的封装，能记住创建时的上下文 ，天然适合模拟 λ 抽象。

### 6.1.2 问题

如果"只有 Proc"，我们怎么表达 `if/then/else`、数字加减、列表遍历？这些高级构造在 λ 演算里**都必须被编码成高阶函数**。这就是"从零编程"要解决的核心问题——**用最少的原语（函数抽象+应用+β归约）表达一切计算**。

### 6.1.3 数字（Church 编码）

Stuart 用 **Church 编码（Church encoding）**​ 把自然数表示为"高阶函数" ：数字 n 被编码为"接受一个函数 f 和一个初值 x，把 f 应用到 x 上 n 次"的函数，即 `n = λf.λx. fⁿ(x)`。

- `ZERO = lambda { |f| lambda { |x| x } }` （0 次应用 f）
    
- `ONE = lambda { |f| lambda { |x| f[x] } }` （1 次）
    
- `TWO = lambda { |f| lambda { |x| f[f[x]] } }` （2 次）
    
- 构造 `successor = lambda { |n| lambda { |f| lambda { |x| f[n[f][x]] } } }`
    

> 补充（英文权威）：Church 数是 Alonzo Church 发明的自然数编码 ：`0 ≡ λf.λx. x`；`1 ≡ λf.λx. f x`；`2 ≡ λf.λx. f (f x)`；`n ≡ λf.λx. fⁿ x`。其本质是"数的迭代/重复结构"本身——**数字 = "重复多少次"的指令"**，而非"符号 1/2/3"。

> 💡 洞见：Church 数的美妙在于——**它把"是什么（数值）"转化成了"做什么（重复 f 多少次）"**。这是"指称语义"思想的极致：一个数字的含义，就是"把它当作重复次数去使用"这个行为。后面 `add`/`multiply` 都会从这个"重复"直觉自然涌现。

### 6.1.4 布尔值（Church 布尔）

布尔值同样用函数编码 ：`TRUE = λx.λy. x`（两个参数中选第一个）；`FALSE = λx.λy. y`（选第二个）。这个编码精妙地让"选择"本身成为函数。

- `TRUE = lambda { |x| lambda { |y| x } }`
    
- `FALSE = lambda { |x| lambda { |y| y } }`
    

> 补充（英文权威）：Church 布尔的定义正是 ：`true ≡ λx.λy. x`；`false ≡ λx.λy. y`。利用它，`if-then-else` 可直接定义为 `λc.λt.λe. c t e`——把条件 c（一个 Church 布尔）应用到"真分支 t"和"假分支 e"上，c 会自动选出正确分支。

### 6.1.5 谓词

有了布尔和数字，就能构造**谓词（返回布尔的函数）**：`IS_ZERO` 判断一个 Church 数是否为 0——利用 Church 数的"重复"结构，把"是否零次应用"编码为"是否选第二个分支"。Stuart 构造 `IS_ZERO`、`LESS_THAN_OR_EQUAL` 等谓词，全部用函数组合实现。

> 💡 洞见：谓词的构造揭示了 λ 演算的一个通用技法——**用"把某函数应用到数据上，观察它选哪个分支/产生什么结果"来提取信息**。这是函数式编程"无副作用地做决策"的核心：没有 if 语句，只有"把条件当作函数去应用，让它自己选分支"。

### 6.1.6 有序对（Church 序对）

序对 `(a,b)` 编码为 `PAIR = λa.λb.λf. f a b`——一个接受"投影函数 f"的函数，f 决定返回 a 还是 b。`FIRST = λp. p (λa.λb. a)`，`SEST = λp. p (λa.λb. b)` 分别提取左右元素。

> 补充（英文权威）：Church 编码可将有序对编码为 ：`pair ≡ λa.λb.λf. f a b`；`first ≡ λp. p (λa.λb. a)`；`second ≡ λp. p (λa.λb. b)`。这与布尔共用同一个"选择"机制——**对/错/第一/第二，本质都是"从若干选项中选一个"的函数**。

### 6.1.7 数值运算

基于 Church 数和序对，Stuart 构造全套算术：

- **加法 `ADD`**：`λm.λn.λf.λx. m f (n f x)`——对 x 先应用 n 次 f，再应用 m 次 f，共 m+n 次。
    
- **乘法 `MULT`**：`λm.λn.λf. m (n f)`——m 次"每次做 n 次 f"，共 m×n 次。
    
- **指数 `POW`**：`λm.λn. n m`（妙用——n 次应用"取 m 次方"的函子）。
    
- **前驱 `PRED`**、**减法 `SUB`**：构造较复杂，通常用"序对技巧"（pair = (当前值, 当前值-1) 的滑动窗口）实现。
    

> 补充（英文权威）：Church 数的算术运算定义 ：`plus ≡ λm.λn.λf.λx. m f (n f x)`；`mult ≡ λm.λn.λf. m (n f)`；`pow ≡ λm.λn. n m`。这些定义全部**只用了函数抽象和应用**——印证了"纯 λ 演算足以表达算术"。

> 💡 洞见：看 `ADD`/`MULT`/`POW` 的定义，你会惊叹——**算术运算被还原成了"函数复合/重复次数的代数"**。`plus m n` 就是"先做 n 次、再做 m 次"；`mult m n` 就是"m 次‘做 n 次’"。**加法=串联重复，乘法=嵌套重复，指数=重复重复**——这个层级关系本身就是对"运算本质"的深刻洞见。

### 6.1.8 列表（Church 列表）

列表用 **Church 编码的链表**​ 表示：空表 `NIL` 和一个"cons"操作 `CONS = λh.λt.λf. f h t`——列表被编码为"接受一个‘折叠/匹配函数 f’的函数"，f 决定如何消费(头, 尾)。`MAP`、`FILTER`、`FOLD`（fold/reduce）都可纯函数式定义。

> 补充（英文权威）：Church 编码可将链表编码为 ：`nil ≡ λc.λn. n`；`cons ≡ λh.λt.λc.λn. c h t`。右折叠 `foldr` 可定义为 `λf.λz.λl. l f z`——**列表 = "把自己折叠成某个值"的函数**，这正是函数式编程 `fold`/`reduce` 的哲学源头。

工业联系（函数式编程的核心武器）：

- **Ruby 的 `Enumerable#inject`/`reduce`**：`[1,2,3].inject(0, &:+)` 正是 Church/Bohem 列表 `fold` 思想的 OO 化 ；
    
- **`map`/`filter`/`reduce`**：JavaScript/Python/Ruby 的高阶函数，本质是 λ 演算"把函数作为参数传递、返回函数"的工程化 ；
    
- **Haskell/Lisp/Scheme/Elixir**：这些语言的底层语义直接建立在 λ 演算上——Haskell 的"一切皆函数应用"、Lisp 的 S-表达式+λ 演算，都是 Church 思想的直系后代；
    
- **React/Redux 的 reducer**：`(state, action) => newState` 正是"用函数描述状态变迁"，可追溯到 λ 演算的状态编码。
    

### 6.1.9 字符串

字符串被编码为**字符的列表**——每个字符又用 Church 数编码（如 ASCII/Unicode 码点对应的 Church 数）。于是"字符串"= "Church 数列表"。Stuart 用前面构造的列表操作（`CONS`/`FOLD`）来操作字符串：`STRING_TO_LIST`、`LIST_TO_STRING`、字符串拼接（列表拼接）、字符映射（列表 map）。

> 💡 洞见：字符串=字符列表=Church 数 列表——**这一层层编码揭示了一个震撼事实：现代计算机里"数字/布尔/字符/字符串/列表"的所有数据类型，在 λ 演算里都可被"统一还原为函数"**。你每天写的 `String`、`Array`、`Integer`，在理论上不过是"函数的不同编码方式"。这是"从零编程"最深刻的启示：**数据 = 行为（对数据的操作方式）**——这就是"面向对象 + 函数式"殊途同归的地方。

### 6.1.10 解决方案（递归与 Y 组合子）

到这里有个致命问题：**λ 演算没有"命名/赋值"，如何实现递归？**​ 比如求阶乘 `fact(n)`，函数体内要"调用自己"。答案是 **Y 组合子（Y combinator）**——一个高阶函数，能"喂给自己"从而实现匿名递归 。

- Y 组合子定义：`Y = λf. (λx. f (x x)) (λx. f (x x))`（无类型 λ 演算的不动点组合子）。
    
- 用法：`FACT = Y (λf. λn. IS_ZERO n ONE (MULT n (f (PRED n))))`——`Y` 把"期望递归的函数 f"包装成"能自我调用的版本"。
    

> 补充（英文权威）：Y 组合子由 Haskell Curry 发现 ，定义为 `Y ≡ λf. (λx. f (x x)) (λx. f (x x))`，满足 `Y F = F (Y F)`（不动点方程）。它让"匿名 λ 表达式"获得递归能力——**这是 λ 演算图灵完备的关键一环**：没有 Y 组合子，纯 λ 演算只能表达"原始递归"；有了 Y，就能表达"一般递归/任意可计算函数"。

> 💡 洞见（本章最反直觉也最重要）：**Y 组合子揭示了"递归"的本质——它不是语言关键字，而是一种"函数自我引用"的数学结构**。任何支持"函数作为参数+函数返回函数+函数应用"的语言，都能用 Y 组合子从零实现递归——无需语言内置 `def`/`rec`。这是"计算通用性"在函数世界的对应物：**图灵机靠"纸带+状态"实现通用，λ 演算靠"Y 组合子+β归约"实现通用**，二者殊途同归（Church–Turing 论题）。

### 6.1.11 高级编程技术

有了 Y 组合子+Church 编码，Stuart 展示如何用"纯函数+Proc"实现更工程的构造：**条件分支、循环（用递归代替）、列表处理、字符串处理、甚至简单的"面向对象"**（用闭包封装状态，模拟"对象=带私有状态+方法分发的闭包"）。

> 补充（英文权威）：这一节呼应了函数式编程的核心主张 ——**程序 = 函数组合 + 数据 = 函数编码**。Ruby 作为"混合范式语言"，其 `Proc`/闭包/代码块机制让它能自然地桥接 OO 与函数式 ：你可以用闭包模拟对象（如 `Object.new` 的闭包版），也可以用对象承载函数。

工业联系（λ 演算思想的工程落地）：

- **闭包/高阶函数**：JavaScript 的 callback/Promise 链、Ruby 的 `Proc`/代码块、`Enumerable` 的 `map`/`reduce`，都是 λ 演算"函数作为参数/返回值"的工程化 。
    
- **React Hooks/函数式 UI**：UI = `(state, action) → state` 的纯函数，状态用 reducer（Y 组合子式的递归/折叠）管理。
    
- **DSL 构造**：Ruby 的 RSpec（`describe/it`）、Rake（`task` 块）、Rails 路由块，本质都是"把代码块/Proc 作为参数传递，构造迷你语言"——这正是 λ 演算"函数抽象+应用"的 OO 包装 。
    
- **Serverless / FaaS**：AWS Lambda/云函数——函数成为一等公民、可被传递/组合/远程调用，是 λ 演算思想在云原生时代的回响（AWS 甚至以"Lambda"命名其 FaaS 产品，致敬 Church）。
    
- **Lisp/Scheme 方言**：Clojure（JVM 上的 Lisp）、Racket，直接以 λ 演算为语义基础，宏系统让"代码即数据"（同像性）成为可能。
    

## 6.2 实现 lambda 演算（写一个 λ 演算的解释器）

前半章"用 Ruby Proc 模拟 λ 演算"（把 λ 演算当 Ruby 程序跑）；后半章则反过来——**用 Ruby 写一个 λ 演算的解释器/求值器**（把 λ 演算当"被解释的语言"跑）。这是第2章"操作语义/指称语义"思想的又一次实战。

### 6.2.1 语法

为 λ 演算定义 AST 节点：`Variable`（变量）、`Abstraction`（抽象 λx.M）、`Application`（应用 M N）。用 Ruby 类建模这些节点——延续第2章"语法→AST"的思路。

> 补充（英文权威）：λ 演算的抽象语法正是 ：`e ::= x | λx.e | e₁ e₂`。Stuart 的 AST 类直接对应这三个构造子。

### 6.2.2 语义

为 λ 演算 AST 定义**操作语义（小步/大步）**——核心是 **β-归约**​ 的 Ruby 实现：`(λx.M) N → M[x:=N]`（替换）。Stuart 实现：

- **变量捕获与 α-转换**：为避免"自由变量被错误绑定"，需要做 α-转换（重命名绑定变量）保证替换安全——这是 λ 演算实现的关键技术细节。
    
- **小步语义**：`#reduce` 对 AST 做一步 β-归约（找到最左最外可归约项/normal-order），迭代直到成"范式（normal form）"。
    
- **大步语义**：`#evaluate` 递归求值，直接给出最终结果（若终止）。
    

> 补充（英文权威）：β-归约是 λ 演算唯一的计算规则 ：`(λx.M) N →β M[x:=N]`。实现时必须处理**变量捕获问题**——Naïve 替换会导致"自由变量被绑定"，需用 α-转换（λx.M → λy.M[x:=y]，y 不在 M 中自由出现）规避 。这正是对第2章"操作语义"的深化：λ 演算的"小步"就是反复做 β-归约。

> 💡 洞见：6.2 把第2章的"程序含义"思想用到了极致——**λ 演算的解释器，就是"对 AST 反复做 β-归约"的小步语义机器**。你写的每一个 `#reduce`，都是第2章小步语义在"函数世界"的对应物。而"变量替换+α转换"的复杂性，恰恰揭示了**"名字/作用域/绑定"是编程语言语义里最微妙的部分**——这也是为什么第2章要花力气讲"环境/作用域"。

### 6.2.3 语法分析

最后，为 λ 演算写一个**递归下降解析器**，把 λ 演算的文本（如 `λx. λy. x y`）解析成 6.2.1 的 AST——直接复用第2章 2.6"实现语法解析器"的技术。解析需处理：变量名、λ 抽象（λx. 体）、应用（空格/括号分组）、运算符优先级（应用左结合、抽象体向右延伸）。

工业联系（解释器/编译器的核心）：

- **Ruby 自身的 parser**：Ruby 源码 → AST（由 Bison 生成的 `parse.c` 构建），再经编译器/解释器执行——你写的 `SyntaxTree`/`Ripper` 能看到这个 AST 。
    
- **Lisp/Scheme 解释器**：经典 SICP 练习"用 Lisp 写 Lisp 解释器"（`eval`/`apply` 互递归），正是 6.2 的直系祖先——λ 演算解释器是"写解释器"这件事的 Minimal 版本。
    
- **JetBrains MPS/ANTLR**：用 CFG/DSL 定义语言语法并生成解析器/解释器，本质是把 6.2.3"手写递归下降"工程化、通用化 。
    
- **TypeScript/Babel**：把源码解析为 AST（@babel/parser）→ 遍历/变换 AST（@babel/traverse）→ 重新生成代码——这正是"AST → 语义操作 → 输出"管线在工业界的日常。
    

## 全章脉络与"第一性原理"总结

把第6章的逻辑主线抽出来：

1. **模拟 λ 演算**（6.1）：用 Ruby Proc 从零构造——数字（Church 数）→ 布尔（Church 布尔）→ 谓词 → 序对 → 数值运算 → 列表 → 字符串 → **Y 组合子实现递归**​ → 高级函数式技术；
    
2. **实现 λ 演算**（6.2）：反过来用 Ruby 写 λ 演算解释器——语法（AST）→ 语义（β-归约/小步+大步）→ 解析器（递归下降）。
    

**一条贯穿全书的洞见**：第6章与第5章是**同一枚硬币的两面**——第5章用"机器模型（图灵机）"刻画可计算性的顶点，第6章用"函数模型（λ 演算）"**以另一种方式抵达同一个顶点**。二者等价（Church–Turing 论题），共同证明：**"可计算"= "能被图灵机算" = "能被 λ 演算表达"**。而第6章的震撼在于——**λ 演算只用"函数抽象+应用"两个构造，就能从零长出全部数据类型和控制结构**。这让你重新理解"编程"：所谓程序，不过是对"函数如何组合、如何自我引用（Y 组合子）"的精确描述。

**与前面章节的深层呼应**：

- 第2章"操作语义/指称语义"在 6.2 被用到极致——λ 演算解释器就是"对 AST 做 β-归约"的小步语义机器；
    
- 第5章 UTM 的"程序即数据"思想，在 λ 演算里以更纯粹的方式重现——**λ 演算里"程序（函数）就是数据（可被函数操作/返回/应用）"**，这正是 Lisp"代码即数据（同像性）"、Ruby `Proc`/元编程的哲学源头；
    
- 第1章"Proc/闭包"特性，到第6章终于揭示其理论深度——**Ruby 的 `Proc` 不只是一个语法糖，它是 λ 演算"函数抽象"的工程化身**；
    
- "配置+重写规则"的统一视角，在 λ 演算里升格为**"AST+β-归约"**——图灵机靠"纸带配置+状态规则"计算，λ 演算靠"AST 配置+β规则"计算，二者同构。
