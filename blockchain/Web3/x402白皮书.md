## 摘要

x402 是一个开放支付标准，使 AI 智能体和 Web 服务能够自主支付 API 访问、数据和数字服务的费用。通过利用长期保留的 HTTP 402"需要付款"状态码，x402 消除了对 API 密钥、订阅和手动支付处理的需求，允许使用 USDC 等稳定币进行实时、机器原生交易。

只需一行代码，开发者就可以集成按需付费变现，为 AI 驱动应用程序的上下文检索和第三方 API 解锁无摩擦支付。x402 提供即时结算、接近零的费用以及与链无关的灵活性，使其成为 AI 优先商业和机器对机器支付的理想解决方案。

## 1. 动机

AI 和自主系统的快速增长正在重塑互联网经济，但实现完全自主 AI 系统的主要障碍之一是缺乏一个能够使 AI 智能体在没有人类干预的情况下运作的支付系统。

传统支付系统主要为人机交互而设计。因此，Web 服务存在以下问题：
- 无法被 AI 智能体自主使用
- 被困在低效的商业模式中（如订阅制）
- 受到运营复杂性的阻碍，如结算延迟时间长、交易费用高、手动开单以及容易受到欺诈和拒付的影响

这些挑战为 AI 驱动的应用程序和机器对机器（M2M）交易制造了重大摩擦，阻止了自主数字经济的完全实现。AI 智能体需要即时、无摩擦地访问实时上下文数据、API 服务和分布式计算资源才能独立运作。它们需要动态且自主地执行微交易的能力，而无需人工干预或传统支付设置的延迟。

浏览器使用 API 试图解决智能体支付的某些需求，但它们继续利用最初为人类用户而非机器设计的系统。因此，它们仍然受到手动用户体验（UX）导航、对信用卡的依赖、账户验证过程以及阻碍智能体交互真正自动化的整体面向人类摩擦的负担。

最终，x402 背后的动机是释放自主 AI 系统和智能体商业的全部潜力，培育一个更高效、无摩擦和可扩展的数字经济，以用于工具使用。通过实现机器原生支付，x402 使 AI 智能体能够自主发现和获取第三方云资源、上下文数据和 API 工具——使它们更容易在没有人工干预的情况下实现目标优化目标。这赋能开发者、企业和消费者自由创新，无需支付摩擦，加速 AI 驱动商业的采用和演变。

## 2. 链上支付：自主数字经济的基础

### 2.1 传统支付方式的缺陷

传统支付系统产生高成本、结算时间长、拒付风险，并需要多层手动设置和授权，使其对于 AI 驱动的商业来说不切实际。

例如，ACH 银行转账需要 1-3 天才能结算，而信用卡支付——尽管即时授权——也可能需要几天才能完成，并且在数月内仍可被撤销。此外，传统系统在金融普惠方面存在重大障碍，全球约有 14 亿人没有银行账户且无法获得服务（来源）。

x402 弥合了这一差距，使 AI 智能体和 API 提供商能够通过实时、无信任的支付无缝交互——消除了传统计费系统的摩擦，并解锁了新的按需付费收入模式。

### 2.2 通过区块链和数字资产扩展支付

与传统支付方式相比，通过 x402 进行的链上交易在约 200 毫秒内结算，为 API 提供商提供即时支付最终性。没有滚动拒付窗口，没有结算延迟——只有实时访问和收入收集。x402 建立在无需许可的区块链基础设施之上，全球可用，无需昂贵的转换或访问传统金融渠道。关于链上支付如何变革数字商业的更广泛讨论（Base.org，2025）。

x402 通过利用稳定币和 Layer-2 扩展来消除这些低效率，实现低成本、即时和自动化的交易。下表将 x402 与传统支付方式进行比较，展示了为什么它是 AI 优先、按需付费模型的最佳选择。

| 支付渠道                  | 典型费用         | 结算最终性     | 拒付风险       | 可扩展性            |
| --------------------- | ------------ | --------- | ---------- | --------------- |
| **信用卡**               | $0.30 + 2.9% | 数天（批量）    | 是，最多 120 天 | 65k TPS*（理论最大值） |
| **PayPal**            | 约 3% + 加价    | 即时授权，数天结算 | 是          | 未知              |
| **Stripe (使用加密货币支付)** | 1.5%+        | 取决于区块链    | 否 - 不可撤销   | 取决于区块链          |
| **以太坊 L1**            | $1–$5 + gas  | 1-2 分钟确认  | 否 - 不可撤销   | 15-20 TPS       |
| **x402 (在 Base 上)**   | 免费*          | 200 毫秒    | 否 - 不可撤销   | 数百到数千 TPS       |

*名义 gas < $0.0001

## 3. x402 的工作原理

x402 是由 Coinbase 开发的开放支付协议，使 AI 智能体能够自主完成交易。它由链上技术和数字货币（主要是 USDC 等稳定币）提供支持，提供了一个轻量级、安全和即时的支付系统，我们希望它能帮助加速 M2M 支付和智能体商业的采用。

x402 协议利用长期保留的 HTTP 402"需要付款"状态码来要求付款以完成 API 请求或加载网页。如果 API 请求缺少付款，x402 会以 HTTP 402 需要付款状态响应，提示客户端付款并重试。

通过这个简单的协议，x402 消除了对 API 密钥、账户和订阅的需求。x402 使任何 API 或内容提供商都能够通过无缝集成到现有基础设施中的轻量级中间件接受按需付费支付。

### 3.1 集成示例

只需一行代码，公司就可以将 API、内容和服务变现：

```javascript
paymentMiddleware(amount: "0.10", address: "0x...")
```

### 3.2 核心支付流程

1. **客户端请求** – AI 智能体或应用程序请求访问 API 或数字资源。
2. **需要付款 (402)** – 如果没有附加有效付款，服务器会以 HTTP 402 响应，提供定价和付款详细信息。
3. **智能体使用签名的付款重试请求** – 智能体在重试请求中提交签名的付款授权。
4. **Web 服务验证并广播付款** – 服务器验证付款，广播它，并向 API 请求返回响应。

## 5. 为智能体商业创建支付层

今天的传统支付系统是为人类构建的——需要信用卡、订阅和手动开单——使它们与自主 AI 智能体、API 和机器对机器交易不兼容。

随着 AI 系统承担更多自动化、决策制定角色，它们需要无缝且无摩擦的支付基础设施，使自主智能体能够快速访问上下文、检索实时数据并在第三方系统上执行操作，而无需延迟或人工干预。

### 5.1 赋能智能体自主交易

AI 模型现在可以自主运作——但支付仍然是一个瓶颈。如果没有机器原生解决方案，语言模型仍然在很大程度上依赖人工干预来访问智能体模型外部的上下文和操作。

x402 消除了对人工干预的需求，提供了一个加密原生支付标准，允许 AI 系统：
- 为每个 API 请求、数据查询或 AI 模型推理付费，而无需预先注册账户。
- 动态获取实时信息（例如，金融市场数据、云资源）。
- 与链上和链下服务无缝交互，自主触发付款。

这实现了完全自主的、AI 驱动的商业——允许面向目标的智能体在按需、无需许可的经济中独立运作。

## 6. 启用新的商业模式

### 6.1 实用的微支付

传统支付方式基于账户模型运作，通常需要交易对手方之间一定程度的信任/信用风险。这些方式是为人类设计的，不适用于像 API 请求这样小型、高频率的交易服务。每笔交易费用高达 0.30 美元，微支付变得不切实际——迫使企业依赖订阅和捆绑定价，导致许多潜在消费者放弃使用。

作为一种支付协议，x402 使按请求、按服务或按使用秒数收费成为可能，具有以下特点：
- 接近零的交易成本，使每次请求低至 0.001 美分的付款成为可能。
- API、AI 推理和按需内容的真正按需付费定价。
- 机器对机器交易，允许 IoT 设备和 AI 智能体自主为资源付费。

首次，企业可以有利可图地大规模支持微支付，为 AI 驱动的平台创造新的变现机会。这之所以成为可能，是因为 Base 等 rollup 上的交易成本低、速度快，以及 USDC 等与美元挂钩的可信稳定币。

### 6.2 无缝的按需付费变现

在线接受付款传统上意味着强迫用户创建账户、管理 API 密钥和处理手动计费周期。x402 通过提供以下功能消除了这些障碍：
- 无缝的按请求付款——无需订阅，无需预付款，无锁定。
- 即时、最终交易——无拒付，无欺诈风险，无中介。
- AI 原生变现——让 AI 智能体和人类用户动态付款，无需预先批准或 API 密钥。

对于开发者和企业来说，这意味着更高的收入、更低的成本和无缝的支付体验。

## 7. 简化支付运营

### 7.1 减轻欺诈、拒付和合规开销

除了交易费用外，传统支付系统还使企业面临拒付、欺诈、运营损失和合规开销的风险。使用 x402：
- 付款在链上即时结算，消除拒付和争议。
- 开发者不需要 PCI 合规，除非促进者选择直接接受卡付款
- 不依赖银行或第三方批准，确保全球、无需许可的访问

通过消除这些障碍，x402 使企业能够专注于增长，而不是支付复杂性。

### 7.2 面向未来、与链和代币无关的支付

x402 旨在支持任何稳定币、数字资产或区块链——解锁超越传统支付提供商的灵活性。
- 虽然 USDC 是首批支持资产之一，但 x402 旨在支持稳定币、数字资产和多个区块链网络。
- 企业和开发者可以选择最适合其用例的加密货币，确保最大的灵活性。

这种面向未来的设计确保 x402 将随着 AI 驱动商业的扩展而继续发展。

## 8. x402 规范：灵活的 HTTP 支付标准

x402 中间件是一个轻量级集成，实现了按请求付费的 API 支付。以下部分详细介绍了开发者如何配置 x402 以及 AI 智能体如何实时处理需要付款的响应。

### 8.1 中间件配置

```javascript
paymentMiddleware(amount: "0.10", address: "0x...")
```

| 参数 | 描述 |
|------|------|
| **amount** | 每次请求的成本（例如，"$0.10"） |
| **address** | 接收付款的钱包地址 |

### 8.2 处理无支付请求

如果提交的请求没有付款，服务器会以 HTTP 402（需要付款）响应。响应为 AI 智能体和人类提供结构化反馈，包括：

```json
{
  "maxAmountRequired": "0.10",
  "resource": "/api/market-data",
  "description": "Access to real-time market data requires payment.",
  "payTo": "0xABCDEF1234567890ABCDEF1234567890ABCDEF12",
  "asset": "0xA0b86991C6218b36c1d19D4a2e9Eb0cE3606EB48",
  "network": "ethereum-mainnet"
}
```

| 字段 | 描述 |
|------|------|
| **maxAmountRequired** | 访问所需的付款金额（例如，$0.10） |
| **resource** | 请求的 API 端点或服务 |
| **description**（可选） | 描述付款详细信息的自定义消息 |
| **payTo** | 开发者的钱包地址（接收付款） |
| **asset** | 交易的合约地址 |
| **network** | 区块链网络标识符 |

## 9. 技术规范

x402 实现了标准化的 HTTP 402 响应方法，对支付请求和验证有精确的规范。

### 9.1 支付请求格式

当 API 返回 402 响应时，它包含一个具有以下字段的结构化 JSON 负载：

| 字段 | 描述 |
|------|------|
| **maxAmountRequired** | 所需的最大付款金额（例如，"0.10"） |
| **assetType** | 代币标准（例如，"ERC20"） |
| **assetAddress** | 付款代币的合约地址 |
| **paymentAddress** | 接收方的钱包地址 |
| **network** | 区块链网络标识符（例如，"base-mainnet"） |
| **expiresAt** | 此付款请求不再有效的时间戳 |
| **nonce** | 防止重放攻击的唯一标识符 |
| **paymentId** | 此付款请求的唯一标识符 |

### 9.2 支付授权

提交付款时，客户端包含一个加密签名的消息，其中包含：
- 支付请求中的所有字段
- 实际付款金额（必须 ≤ maxAmountRequired）
- 授权的时间戳
- 来自付款钱包的加密签名

签名遵循 EIP-712 标准，使用户在授权交易时能够在钱包界面中清晰安全地查看。

### 9.3 交易结算

x402 实现可以通过各种方法处理结算：
- **链上结算**：直接区块链交易
- **Layer-2 结算**：使用乐观或 ZK rollups 降低费用
- **支付通道**：用于可信各方之间的高频微支付
- **批量结算**：将多个微支付合并为单笔交易

这种灵活性允许开发者为其特定用例和交易量选择最有效的结算机制。

## 10. 集成示例

x402 旨在在各种编程语言和框架中轻松集成。

### 10.1 服务端实现

对于使用 Express 的 NodeJS 应用程序：

```javascript
// 安装：npm install @x402/express-middleware
const express = require('express');
const { x402PaymentRequired } = require('@x402/express-middleware');
const app = express();

app.get('/premium-data', x402PaymentRequired({
  amount: "0.10",
  address: "0x1234...",
  assetAddress: "0x2345...", // USDC 合约
  network: "base-mainnet"
}), (req, res) => {
  // 此代码仅在有效付款后运行
  res.json({ premiumData: "Valuable information" });
});

app.listen(3000);
```

### 10.2 客户端实现

对于使用 x402 客户端库的 Web 应用程序：

```javascript
// 安装：npm install @x402/client
import { x402Client } from '@x402/client';
import { connectWallet } from 'your-wallet-connector';

const client = new x402Client();
const wallet = await connectWallet();

// 使用用户的钱包配置客户端
client.setWallet(wallet);

// 使用自动付款处理进行 API 请求
try {
  const data = await client.fetch('https://api.example.com/premium-data');
  console.log(data); // 高级数据
} catch (error) {
  console.error('Payment failed:', error);
}
```

### 10.3 钱包集成

x402 旨在与任何支持标准签名方法的加密货币钱包配合使用。当需要付款时，钱包界面显示一个确认屏幕，显示：
- 请求域（例如，api.example.com）
- 请求的付款金额
- 付款代币（例如，USDC）
- 正在访问的特定资源

这种透明性确保用户始终确切知道他们支付的 内容，维持服务提供商和用户之间的信任。

这些工具使开发者能够在不连接到生产区块链或花费真实代币的情况下构建和测试 x402 集成。
