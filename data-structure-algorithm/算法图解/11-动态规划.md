
第11章是整本书算法设计思想的"集大成者"——上一章你看到贪婪算法在 0-1 背包上失败了，因为"局部最优阻塞全局最优"。动态规划（Dynamic Programming, DP）就是为了解决这个问题而生的：它用**空间换时间**，把每个子问题的解存起来，避免重复计算，从而在面对"选择之间有组合效应"的问题时，依然能在多项式时间内找到全局最优解。Bhargava 在书中用"网格"作为核心隐喻——这是本书最直观、也最深刻的算法可视化 。下面按你的目录结构逐节展开。

## 11.1 再谈背包问题

### 11.1.1 简单算法

**书中原意**：

Bhargava 首先给出暴力解法 ：列出所有物品组合（每个物品选或不选 → 2ⁿ 种组合），计算每种组合的总重量和总价值，过滤掉超重组合，取价值最大的。

对于 n 个物品，暴力解法的时间复杂度是 **O(2ⁿ)**——这是指数级的灾难。当 n=30 时，2³⁰ ≈ 10 亿次计算，已经不可行；n=60 时，2⁶⁰ ≈ 10¹⁸ 次计算，宇宙年龄都不够用。

**第一性原理洞见**：

暴力解法的问题不在于"思路错"，而在于"重复计算太多"。考虑物品集合 {A, B, C, D}，暴力会分别计算：

- 选 {A, B} 的最大价值
    
- 选 {A, B, C} 的最大价值
    
- 选 {A, B, D} 的最大价值
    

但这些计算都重复求解了"前 2 个物品在容量 X 下的最大价值"这个子问题。**子问题的解被反复计算，这就是指数复杂度的根源**。

> 💡 **动态规划的第一性原理**：**如果问题具有"重叠子问题（Overlapping Subproblems）+ 最优子结构（Optimal Substructure）"，就可以用一张表把子问题的解存起来，每个子问题只算一次。**

### 11.1.2 动态规划

**书中原意**：

Bhargava 的核心洞见——**用一个网格来求解**​ ：

- **行**​ = 商品（每行增加一个商品）
    
- **列**​ = 不同容量的背包（从 0 到最大容量）
    
- **单元格**​ = 在当前商品集合和当前容量约束下，背包能装的最大价值
    

网格填充规则（状态转移方程）：

```
dp[i][v] = max(
    dp[i-1][v],                    // 不放第 i 个商品
    dp[i-1][v-w[i]] + v[i]         // 放第 i 个商品（如果容量允许）
)
```

这个公式的含义 ："将前 i 件物品放入容量为 v 的背包中"这个子问题，若只考虑第 i 件物品的策略（放或不放），那么就可以转化为一个只牵扯前 i-1 件物品的问题。

**走查示例（书中数据）**：

- 背包容量 35 磅
    
- 吉他（G）：15 磅，$1500
    
- 音响（A）：30 磅，$3000
    
- 笔记本电脑（L）：20 磅，$2000
    

填充网格后，右下角单元格的值 = **$3500**（笔记本 + 吉他），正是全局最优解 。

**第一性原理洞见**：

动态规划的本质是用**"状态"和"转移"**来刻画问题：

- **状态**：dp[i][v] = "前 i 个商品，容量 v 下的最大价值"
    
- **转移**：每个状态由两个更小的状态推导而来（放 or 不放）
    
- **边界**：dp[0][v] = 0，dp[i][0] = 0
    

这个网格为什么能工作？因为它巧妙地利用了两个性质：

1. **最优子结构**：全局最优解包含了子问题的最优解。如果"笔记本+吉他"是最优解，那么"在前 2 个商品（笔记本、吉他）中，容量 35 磅下的最优解"必然是"笔记本+吉他"。
    
2. **无后效性**：当前状态只与之前的状态有关，一旦 dp[i][v] 确定，它就不会再改变，后续计算只读取它的值。
    

**空间优化（滚动数组）**：

搜狗百科明确指出 ："可以压缩空间，f[v]=max{f[v], f[v-w[i]]+v[i]}"。这意味着我们可以用一维数组代替二维网格，空间复杂度从 O(nW) 降到 O(W)。

但 Bhargava 在书中强调的是**二维网格的直观性**——它让你"看见"动态规划的工作原理。这是本书教学法的高明之处：**先建立直观，再优化空间**。

**复杂度分析**：

- **时间**：O(nW)，其中 n 是商品数，W 是背包容量
    
- **空间**：O(nW)（二维）/ O(W)（一维压缩）
    

> ⚠️ **关键认知**：O(nW) 看起来是多项式的，但 W 是"数值"而非"输入规模"——如果 W 用二进制表示，输入长度是 log W，那么 O(nW) 实际上是**伪多项式时间（Pseudo-polynomial）**。这意味着当 W 很大时（如 W=10⁹），DP 仍然不可行。这是 0-1 背包问题的固有局限——它是 NP-hard 的。

**工业映射：动态规划求解背包问题**

|工业场景|对应问题|解法|
|---|---|---|
|资源分配|0-1 背包|DP O(nW)|
|投资组合优化|0-1 背包|DP + 分支定界|
|云计算资源调度|0-1 背包变种|DP + 启发式|
|广告投放预算分配|0-1 背包|DP|
|切割库存问题|0-1 背包变种|DP|
|编译器指令调度|0-1 背包|DP|

> 💡 **工程智慧**：工业界处理大规模 0-1 背包时，如果 W 太大导致 O(nW) 不可行，会切换到**分支定界（Branch and Bound）**或**整数线性规划（ILP）求解器**如 CPLEX、Gurobi。DP 是理论基准，ILP 是工业标准。

## 11.2 背包问题 FAQ

Bhargava 在这一节用一系列"如果...会怎样"的问题，深挖动态规划的机理 。这些问题看似简单，实则触及 DP 的本质。

### 11.2.1 再增加一件商品将如何呢

**书中答案**：只需在网格中增加一行，重新计算该行 。新商品的加入不会改变之前的计算结果，只需要基于已有的上一行来计算新行。

**洞见**：这正是 DP 的**增量性**——每增加一个商品，只需 O(W) 时间更新一行。这个性质让 DP 在处理"流式数据"时有独特优势：商品可以一个个到来，每到一个就更新一行。

📌 **工业映射**：实时竞价（RTB）系统中，广告候选一个个到来，每到一个就用 DP 更新"当前预算下的最大收益"。这种**在线 DP**​ 是程序化广告的核心技术。

### 11.2.2 行的排列顺序发生变化时结果将如何

**书中答案**：结果不变 。因为 DP 网格的每一行只依赖于上一行，而与行的顺序无关。你可以按任意顺序处理商品，最终右下角的值都是相同的。

**洞见**：这揭示了 DP 的一个重要性质——**只要状态转移方程正确，计算顺序不影响最终结果**（在 0-1 背包这种特定结构下）。但这不是所有 DP 问题的通用性质，有些 DP 问题对计算顺序敏感（如最长递增子序列的某些变种）。

### 11.2.3 可以逐列而不是逐行填充网格吗

**书中答案**：可以 。因为计算每个单元格时，只需要其正上方和左上方的单元格值。只要保证这两个依赖项已计算，按列填充完全可行。

**洞见**：这引出了一个重要的工程优化——**缓存友好性**。按行填充时，访问 dp[i-1][v] 和 dp[i-1][v-w[i]] 是**跳跃访问**（间隔 w[i] 个元素）；按列填充时，访问模式更连续。在大规模 DP 中，按列填充可能获得更好的 CPU 缓存命中率。

### 11.2.4 增加一件更小的商品将如何呢

**书中答案**：网格需要增加相应的列以适应更小的容量粒度 。如果新商品重量是 5 磅（而不是 15、20、30），你需要把容量刻度细化到 5 磅一隔，否则无法准确表示该商品。

**洞见**：这揭示了 DP 的一个**根本性约束**——状态空间的离散化程度决定了 DP 的可行性。如果商品重量不是整数，或者容量粒度太细，状态空间会爆炸。

📌 **工业映射**：在金融领域的投资组合优化中，如果资产价格是连续值，工程师会用**离散化（Quantization）**把连续空间映射到有限网格。这是"用精度换可行性"的典型工程权衡。

### 11.2.5 可以拿商品的一部分吗

**书中答案**：这就变成了**分数背包问题**，可以用贪婪算法解决（按价值密度降序） 。

**洞见**：这是本章与上一章的精彩呼应——**分数背包用贪婪 O(n log n) 得最优；0-1 背包用 DP O(nW) 得最优**。两种"背包"对应两种算法范式，根源在于"商品是否可分割"。

### 11.2.6 旅游行程最优化

**书中场景**：Bhargava 用"旅游行程规划"作为背包问题的现实映射——有限时间内选择哪些景点参观，使总满意度最大 。

**洞见**：这是 DP 的**建模能力**展示。任何具有以下结构的问题都可以转化为背包：

- 有限资源（时间/预算/容量）
    
- 多个选项，每个选项消耗资源并产生价值
    
- 每个选项最多选一次（0-1）或可选多次（完全背包）
    

📌 **工业映射**：

- **AWS Spot Instance 调度**：有限预算下选择哪些实例类型，最大化算力
    
- **Netflix 带宽分配**：有限带宽下选择哪些视频质量，最大化用户体验
    
- **基因测序资源分配**：有限计算资源下选择哪些基因片段优先分析
    

### 11.2.7 处理相互依赖的情况

**书中答案**：如果商品之间存在依赖（如选了 A 才能选 B），标准的 0-1 背包 DP 不再直接适用，需要修改状态或建模方式 。

**洞见**：这触及了 DP 的**适用边界**。DP 擅长处理"选项独立"的问题；当选项之间有依赖时，需要：

1. **扩展状态**：把依赖关系编码进状态（如 dp[i][mask] 表示已选集合）
    
2. **重新定义子问题**：使子问题重新具有最优子结构
    
3. **或使用其他范式**：如拓扑排序 + DP、树形 DP
    

📌 **工业映射**：软件包依赖解析（如 apt、npm）本质上是带依赖的背包问题。现代包管理器用 SAT 求解器或拓扑排序 + DP 的混合方法。

### 11.2.8 计算最终的解时会涉及两个以上的子背包吗

**书中答案**：不会 。每个单元格的值只来自**至多两个**子问题：dp[i-1][v]（不放）和 dp[i-1][v-w[i]]（放）。这就是状态转移方程的二元性。

**洞见**：0-1 背包的 DP 之所以高效，正是因为每个状态只有**常数个**依赖项。如果依赖项是 O(n) 个，复杂度就会飙升至 O(n²W)。

### 11.2.9 最优解可能导致背包没装满吗

**书中答案**：**是的，可能没装满**​ 。DP 最大化的是"总价值"，而不是"装满程度"。如果剩余容量无法被任何剩余商品有效利用，最优解就是"不满"。

**洞见**：这揭示了 DP 的目标函数与直觉的差异。**DP 严格优化你定义的目标函数**——如果你定义的是"最大化价值"，它可能不满；如果你定义的是"在价值最大化的前提下最小化剩余容量"，就需要修改状态或后处理。

📌 **工业映射**：集装箱装船问题中，航运公司关心的不只是"总价值最大"，还有"空间利用率"。这时候需要在 DP 后加一层筛选，或者在状态中加入"剩余空间"维度。

## 11.3 最长公共子串

### 11.3.1 绘制网格

**书中原意**：Bhargava 用两个字符串 "blue" 和 "clues" 演示 。构建一个网格：

- **行**​ = 第一个字符串的字符
    
- **列**​ = 第二个字符串的字符
    
- **单元格**​ = 以对应字符结尾的最长公共子串长度
    

### 11.3.2 填充网格

**填充规则**：

```
if s1[i] == s2[j]:
    dp[i][j] = dp[i-1][j-1] + 1   // 对角线 +1
else:
    dp[i][j] = 0                   // 子串必须连续
```

**走查**："blue" vs "clues"，最长公共子串是 "lue"，长度为 3。

### 11.3.3 揭晓答案

**书中答案**：网格中最大的值就是最长公共子串的长度。通过回溯最大值所在的对角线，可以重建子串本身。

**第一性原理洞见**：

子串（Substring）要求**连续**，所以状态转移只能在"字符匹配时延续对角线"。这与子序列（Subsequence）形成鲜明对比——子序列不要求连续，状态转移更复杂。

> 💡 **关键区分**：
> 
> - **子串**：连续 → dp[i][j] = dp[i-1][j-1] + 1（匹配时）
>     
> - **子序列**：不连续 → dp[i][j] = max(dp[i-1][j], dp[i][j-1])（不匹配时）
>     

### 11.3.4 最长公共子序列

**书中原意**：Bhargava 将问题升级为"最长公共子序列（LCS）"——不要求字符连续 。

**状态转移方程**：

```
if s1[i] == s2[j]:
    dp[i][j] = dp[i-1][j-1] + 1
else:
    dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

搜狗百科给出了权威定义 ："最长公共子序列（LCS）是一个在一个序列集合中（通常为两个序列）用来查找所有序列中最长子序列的问题。这与查找最长公共子串的问题不同的地方是：子序列不需要在原序列中占用连续的位置。"

**复杂度**：时间 O(mn)，空间 O(mn)（可优化到 O(min(m,n))）。

### 11.3.5 最长公共子序列之解决方案

**书中走查**：以 "blue" 和 "clues" 为例，LCS 是 "lue"（长度 3）。注意在这个例子中子串和子序列的结果相同，但它们是本质不同的问题。

**第一性原理洞见**：

LCS 之所以重要，是因为它具有**两个关键性质**​ ：

1. **最优子结构**：LCS 问题可以分解成更小、更简单的子问题
    
2. **重叠子问题**：高级子问题通常会重用低级子问题的解
    

这两个性质正是动态规划的适用条件。

📌 **工业映射：LCS 在真实系统中的应用**

|应用场景|具体例子|
|---|---|
|**代码版本控制**​|Git 的 diff 算法（Myers diff）基于 LCS 思想|
|**DNA 序列比对**​|BLAST 算法用 LCS 变种做生物序列比对|
|**自然语言处理**​|句子相似度计算、抄袭检测|
|**文件同步**​|rsync 用 rolling checksum + LCS 思想|
|**拼写检查**​|编辑距离（Levenshtein Distance）是 LCS 的推广|
|**Plagiarism Detection**​|Turnitin 等学术不端检测系统的核心算法|

> 💡 **工程智慧**：Git 的 `diff` 命令展示两个文件的变化，底层正是 LCS 算法。当你 `git diff file_v1 file_v2` 时，Git 在 O(mn) 时间内计算出最长公共子序列，然后展示"非公共部分"作为差异。这是每个程序员每天都在用的 DP 应用，却很少有人意识到它的数学之美。

## 11.4 小结

Bhargava 在本章通过具体的动态规划案例引出了动态规划的核心思想，并明确了：动态规划用于在问题可分解为重叠子问题且具有最优子结构时，通过在网格中存储子问题的解来节省计算时间；对于 0-1 背包问题，可以使用动态规划得到精确解，其时间复杂度为 O(nW)；最长公共子串/子序列问题也可以通过动态规划在 O(mn) 时间内求解。

**我的整体洞见**：

第11章真正教给你的，是一个**关于"时空权衡"的第一性原理**——

> 💡 **当问题具有"重叠子问题 + 最优子结构"时，动态规划用 O(状态空间) 的空间换取 O(状态空间) 的时间，把指数级复杂度压到多项式级。**

从这个第一性原理出发，你能看懂整个动态规划家族的工程分布：

### 动态规划的"适用光谱"

|问题|是否具有最优子结构|是否具有重叠子问题|DP 是否适用|
|---|---|---|---|
|0-1 背包|✅|✅|✅ O(nW)|
|最长公共子序列|✅|✅|✅ O(mn)|
|最长公共子串|✅|✅|✅ O(mn)|
|最长递增子序列|✅|✅|✅ O(n²) 或 O(n log n)|
|编辑距离|✅|✅|✅ O(mn)|
|矩阵链乘法|✅|✅|✅ O(n³)|
|最短路径（Dijkstra）|✅|❌|贪婪更高效|
|区间调度|✅|❌|贪婪 O(n log n)|
|0-1 背包（W 极大）|✅|✅|DP 不可行，需 ILP|

### 识别 DP 问题的工程决策树

SpaceComplexity 的文章给出了清晰的判断框架：

```
问题能否分解？
├─ 否 → DP 不适用，考虑其他范式
└─ 是 → 具有最优子结构？
        ├─ 否 → DP 不适用
        └─ 是 → 子问题是否重叠？
                ├─ 否 → 分治（如快排、归并排序）
                └─ 是 → DP 适用！
                        ↓
                选择计算方向：
                ├─ 自底向上（递推）→ 通常更快，无递归开销
                └─ 自顶向下（备忘录）→ 代码直观，只算所需子问题
```

### 本章的三大核心洞见

**洞见一：DP 是"贪婪失败"后的救赎**

上一章你看到贪婪算法在 0-1 背包上失败了——因为"局部最优阻塞全局最优"。DP 通过**穷举所有子问题的最优解并组合起来**，规避了贪婪的短视。代价是 O(nW) 的时间和空间，但换来的是**全局最优的保证**。

这是算法设计的一个普遍真理：**贪婪和 DP 不是竞争对手，而是互补工具**。贪婪能解的问题，DP 也能解（但通常更慢）；DP 能解的问题，贪婪不一定能解。工程上先试贪婪（简单快速），贪婪失效再用 DP（保证最优）。

**洞见二：网格是 DP 的可视化灵魂**

Bhargava 用"网格"作为 DP 的统一隐喻，这是本书最深刻的教学创新。无论是背包的"商品 × 容量"网格，还是 LCS 的"字符 × 字符"网格，**每个 DP 问题都对应一张填字游戏般的网格**。

理解这张网格，你就理解了 DP 的本质：

- **行/列**​ = 状态维度
    
- **单元格**​ = 子问题的解
    
- **填充顺序**​ = 拓扑排序（依赖关系）
    
- **状态转移**​ = 单元格间的计算公式
    
- **右下角**​ = 原问题的解
    

> 💡 **工程技巧**：调试 DP 时，手画小网格走查是最有效的方法。如果你无法在 3×3 的网格上手算出正确答案，你的状态转移方程就一定有问题。

**洞见三：DP 的"伪多项式"陷阱**

0-1 背包的 O(nW) 看起来是多项式的，但 W 是数值而非输入规模。如果 W 用二进制表示，输入长度是 log W，那么 O(nW) 实际上是**指数级**（相对于输入长度）。这就是"伪多项式时间"——它对于 W 较小的实际问题是实用的，但理论上仍然是 NP-hard 的。

这个认知至关重要：**DP 不是银弹。当状态空间爆炸时，DP 也会失效**。这时候工业界切换到：

- **整数线性规划（ILP）**：CPLEX、Gurobi
    
- **分支定界**：智能剪枝搜索空间
    
- **近似算法**：牺牲最优性换取可行性
    
- **启发式算法**：遗传算法、模拟退火
    

> ⚠️ **一个反直觉的工程事实**：很多工程师误以为"DP = 最优解"。但 DP 的"最优"是有条件的——**必须在伪多项式时间内可行**。当 W=10⁹ 时，O(nW) 的 DP 比指数级 brute-force 好不了多少。这时候"用 ILP 求解器在几秒内得到最优解"反而是更务实的选择。理解 DP 的边界，比掌握 DP 本身更重要。

---

**带走这一章的三句话**：

1. **DP = 网格 + 状态转移 + 记忆化。它用 O(状态空间) 的空间换取多项式时间，把指数级复杂度压到 O(nW) 或 O(mn)**——这是"时空权衡"第一性原理的极致体现
    
2. **DP 是贪婪失败后的救赎：0-1 背包贪婪失败 → DP 成功；分数背包贪婪成功 → 不需要 DP**——两个背包问题揭示了算法选择的本质
    
3. **DP 的"伪多项式"陷阱：O(nW) 在 W 极大时仍然不可行**——工业界在大规模问题上切换到 ILP 或分支定界，DP 是理论基准而非工程终点
