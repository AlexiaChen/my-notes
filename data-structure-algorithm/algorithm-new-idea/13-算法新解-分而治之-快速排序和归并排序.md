## 二、13.1 快速排序：划分的艺术

### 13.1.1 基本形式：分治思想的经典演绎

快速排序的核心思想极为优雅 ：

**分治三步曲**：

1. **分解（Divide）**：选择基准元素（pivot），将数组划分为两部分——左部分 ≤ pivot ≤ 右部分
2. **解决（Conquer）**：递归地对左右两部分分别快速排序
3. **合并（Combine）**：无需显式合并——划分操作已经让数组"原地"趋于有序
    
**伪代码**：

```
quicksort(A, lo, hi):
    if lo < hi:
        p = partition(A, lo, hi)  # 划分，返回 pivot 的最终位置
        quicksort(A, lo, p - 1)   # 递归左部分
        quicksort(A, p + 1, hi)   # 递归右部分
```

**为什么快排"快"？**​

- **原地排序**：partition 操作在原数组上完成，仅需 O(log n) 递归栈空间
- **缓存友好**：顺序访问数组，CPU 缓存命中率高
- **常数因子小**：平均比较次数约 1.39 n log n，是 O(n log n) 算法中常数最小的
- **平均 O(n log n)**：在随机输入下表现优异

> 💡 快排与 BST 的深刻同构：partition 操作本质上是在构建一棵"二叉搜索树"——pivot 是根节点，左部分是左子树，右部分是右子树。快排的递归过程，就是一棵 BST 的构建过程。如果输入有序，这棵 BST 退化为链表（最坏 O(n²)）——这正是第1章 BST 退化问题的重演！

### 13.1.2 严格弱序：泛型编程的基石

**严格弱序（Strict Weak Ordering）**​ 是 C++ STL 等泛型库的核心概念 ：

**定义**：一个二元关系 `<` 满足严格弱序，当且仅当：

- **非自反性**：!(x < x)
- **非对称性**：若 x < y，则 !(y < x)
- **传递性**：若 x < y 且 y < z，则 x < z
- **不可比关系的传递性**：若 x 与 y 不可比，y 与 z 不可比，则 x 与 z 不可比
    
**为什么快排需要严格弱序？**​

- 快排的 partition 操作依赖于"比较"操作
- 如果使用自定义比较函数，必须满足严格弱序，否则 partition 可能陷入死循环或产生错误结果
- 这是快排能够泛型化的理论基础
    
> 📌 13.1.2 节的核心洞见：**严格弱序是泛型排序算法的数学基础**。Java 的 `Comparator`、C++ 的 `std::less`、Python 的 `key` 函数，背后都是严格弱序。理解这一概念，才能正确实现泛型快排。

### 13.1.3 划分：快排的灵魂

**划分（Partition）**​ 是快排最核心的操作 ：

**经典 Lomuto 划分**：

```
partition(A, lo, hi):
    pivot = A[hi]  # 选择最后一个元素作为 pivot
    i = lo
    for j = lo to hi-1:
        if A[j] <= pivot:
            swap(A[i], A[j])
            i += 1
    swap(A[i], A[hi])
    return i
```

**Hoare 划分**（更高效）：

```
partition(A, lo, hi):
    pivot = A[(lo + hi) / 2]
    i = lo - 1, j = hi + 1
    while True:
        do i += 1 while A[i] < pivot
        do j -= 1 while A[j] > pivot
        if i >= j: return j
        swap(A[i], A[j])
```

**两种划分的对比**：

- **Lomuto**：实现简单，但缓存不友好（单向扫描）
- **Hoare**：交换次数更少，缓存友好，但实现微妙
    
**划分的本质**：**通过一次线性扫描，将数组分为"≤ pivot"和"≥ pivot"两部分**。这是 O(n) 的操作，是快排能达到 O(n log n) 的关键。

> 💡 划分与 BST 插入的深刻联系：划分操作等价于 BST 的插入——pivot 是根，左部分是左子树，右部分是右子树。但划分是**批量**的 BST 插入——一次操作就完成了 n 个元素的"分类"。这是快排比"逐个 BST 插入"快的根本原因（第2章 BST 排序需要 O(n log n) 期望时间，而快排平均也是 O(n log n) 时间，但常数更小）。

### 13.1.4 函数式划分算法的小改进

这一节探讨函数式编程中的划分实现 ：

**命令式划分的困境**：

- 命令式划分需要原地交换，破坏不可变性
- 函数式编程要求不可变数据结构
    
**函数式划分的核心思想**：**累积划分（Accumulated Partition）**

**累积式快速排序**：

- 不原地交换，而是"累积"地构建左、右两个列表
- 遍历数组，将 < pivot 的元素累积到左列表，> pivot 的元素累积到右列表
- 递归排序两个列表，最后拼接
    
**伪代码**：

```
qsort([]) = []
qsort(x:xs) = qsort([y | y <- xs, y <= x]) ++ [x] ++ qsort([y | y <- xs, y > x])
```

**为什么这是"小改进"？**​

- 保持了函数式的不可变性
- 但空间复杂度 O(n)（需要构建新列表）
- 实践中常数较大，不如命令式快排快
    
> 💡 函数式快排与命令式快排的本质区别：**命令式用"交换"在原数组上分类，函数式用"过滤"构建新列表**。前者空间 O(log n)，后者空间 O(n)。这是函数式编程"用空间换不可变性"的典型案例。

## 三、13.2 快速排序的性能分析：平均 O(n log n) 的数学之美

这一节是全书最精美的数学分析之一 ：

**平均情况分析**：

设 T(n) 为对 n 个元素快排的平均比较次数。假设 pivot 等可能地为第 k 小元素（k = 1, 2, ..., n）：

T(n)=n1​k=1∑n​[(n−1)+T(k−1)+T(n−k)]

通过求解递归式，可得：

T(n)=2nlnn≈1.39nlog2​n

**为什么是 1.39 n log n？**​

- 系数 2 来自划分操作的比较
- ln n 是自然对数（以 e 为底）
- 转换为以 2 为底：2n ln n = 2n (ln 2)(log₂ n) ≈ 1.39 n log₂ n
    
**最坏情况分析**：

- 当 pivot 总是最小或最大元素时（如已排序数组 + 选末位 pivot），递归树退化为链表
- 时间复杂度 O(n²)
- 这是快排的阿喀琉斯之踵
    
**为什么平均情况如此优秀？**​

- 随机选择的 pivot 大概率接近中位数
- 即使 pivot 是 10% 分位点或 90% 分位点，递归深度仍是对数级的
- 只有极端情况下（pivot 总是极端值）才会退化
    
> 📌 13.2 节的核心洞见：**快排的平均性能之所以优秀，是因为"随机性"的引入**。pivot 的随机选择使得退化情况的概率趋近于 0。这是"随机化算法"思想的经典案例——用随机性换取平均性能。

## 四、13.3 工程实践中的改进：处理重复元素

这是快排从"理论算法"走向"工程算法"的关键一步 ：

### 13.3.1 处理重复元素的工程方法

**问题**：当数组中存在大量重复元素时，经典划分（Lomuto/Hoare）效率低下：

- 所有等于 pivot 的元素都被分到同一侧
- 递归树严重不平衡
- 时间复杂度退化为 O(n²)

**解决方案：三路划分（3-way Partition）**​ ：

将数组划分为三部分：

- **< pivot**：左部分
- **= pivot**：中间部分（已就位）
- **> pivot**：右部分
    
**伪代码（Dutch National Flag 算法）**：

```
three_way_partition(A, lo, hi):
    pivot = A[lo]
    lt = lo        # < pivot 区域的结束位置
    gt = hi        # > pivot 区域的开始位置
    i = lo
    while i <= gt:
        if A[i] < pivot:
            swap(A[lt], A[i])
            lt++, i++
        elif A[i] > pivot:
            swap(A[gt], A[i])
            gt--
        else:
            i++
    # 现在 A[lo..lt-1] < pivot, A[lt..gt] = pivot, A[gt+1..hi] > pivot
    return lt, gt
```

**为什么三路划分如此重要？**​

- 对于包含大量重复元素的数组，三路划分将时间复杂度从 O(n²) 降到 O(n log n)
- 中间部分"= pivot"的元素无需递归，直接就位
- 这是 Java 的 `Arrays.sort()`（对基本类型）采用的策略
    
### 13.3.2 双向划分（2-way Partition）

**经典 Hoare 划分的优化**：从两端向中间扫描，交换逆序对。

**优势**：

- 交换次数少于 Lomuto 划分
- 缓存友好（两端扫描）
- 实际运行更快
    
## 五、13.4 针对最差情况的工程实践：让快排"永不退化"

这是快排工程化最关键的防线 ：

**最差情况防护策略**：

**1. 三数取中法（Median-of-Three）**：

- 选择 lo、mid、hi 三个位置的中位数作为 pivot
- 对于部分有序的数组，能显著降低退化概率
    
**2. 随机化 pivot**：

- 随机选择 pivot 位置
- 期望情况下避免退化
    
**3. 小数组切换到插入排序**：

- 当子数组大小 < 10（或某个阈值）时，切换到插入排序
- 原因：插入排序在小规模数据上常数更小，且对基本有序数据极快
    
**4. Introsort（内省排序）**：

- C++ STL `std::sort` 采用的策略
- 监控递归深度，若超过 2 log₂ n，切换到堆排序
- **保证最坏情况 O(n log n)**

> 💡 Introsort 的哲学：**取各家之长**——快排的平均性能 + 堆排序的最坏保证 + 插入排序的小规模优势。这是工程算法设计的典范。

## 六、13.5-13.6 其他工程实践

这两节探讨快排的其他工程优化 ：

**1. 尾递归优化**：

- 对较小的子数组递归，对较大的子数组迭代
- 将递归深度从 O(n) 降到 O(log n)
    
**2. 并行化快排**：

- 左右子数组的排序相互独立，可并行执行
- 现代多核 CPU 上的重要优化
    
**3. 缓存感知的快排**：

- 根据 CPU 缓存大小调整 pivot 选择和子数组阈值
    
## 七、13.7 归并排序：合并的艺术

### 基本形式：与快排对称的分治

归并排序的核心思想 ：

**分治三步曲**：

1. **分解（Divide）**：将数组从中间分为两半
2. **解决（Conquer）**：递归地对两半分别归并排序
3. **合并（Combine）**：将两个有序数组合并为一个有序数组
    
**伪代码**：

```
mergesort(A, lo, hi):
    if lo < hi:
        mid = (lo + hi) / 2
        mergesort(A, lo, mid)
        mergesort(A, mid+1, hi)
        merge(A, lo, mid, hi)  # 合并两个有序子数组
```

**合并操作（Merge）**：

```
merge(A, lo, mid, hi):
    left = A[lo..mid], right = A[mid+1..hi]
    i = j = 0, k = lo
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            A[k++] = left[i++]
        else:
            A[k++] = right[j++]
    # 复制剩余元素
    while i < len(left): A[k++] = left[i++]
    while j < len(right): A[k++] = right[j++]
```

**为什么归并排序稳定 O(n log n)？**​

- 每次划分都是精确的 n/2，递归树完美平衡
- 合并操作 O(n)，递归深度 O(log n)
- 总复杂度 O(n log n)，与输入数据无关
    
**归并排序 vs 快速排序的核心差异**：

|维度|快速排序|归并排序|
|---|---|---|
|核心操作|划分（partition）|合并（merge）|
|操作时机|递归前划分|递归后合并|
|最坏情况|O(n²)|O(n log n)|
|空间复杂度|O(log n) 递归栈|O(n) 额外空间|
|稳定性|不稳定|**稳定**​|
|缓存友好性|极好|中等|
|实际速度|更快（常数小）|较慢（常数大）|
|适合场景|内存排序、数据随机|外部排序、需要稳定性|

> 💡 归并排序与手指树的深刻同构：归并排序的"分"对应手指树的 split（O(log n) 摊还），"合"对应手指树的 concat（O(log n) 摊还）。如果用数学归纳法证明，归并排序的过程就是在手指树上执行 split 和 concat 的过程。这是第12章手指树与第13章归并排序的隐形纽带。

## 八、13.8 原地归并排序：克服空间瓶颈

归并排序的最大缺点是 O(n) 额外空间。这一节探讨如何在原地实现归并 ：

### 13.8.1 死板原地归并

**核心思想**：利用原数组的空闲空间进行合并。

**挑战**：合并两个有序子数组需要额外的临时空间——如果没有额外空间，合并会变得复杂。

**死板方法**：每次合并时，将左半部分复制到临时数组，然后与右半部分合并回原数组。这本质上还是需要 O(n) 空间，只是"看起来"原地。

### 13.8.2 原地工作区

**核心思想**：利用数组本身的未使用部分作为工作区。

**关键技术**：

- **旋转合并**：通过数组旋转实现原地合并
- **插入排序思想**：将右半部分的元素逐个插入左半部分
    
**伪代码（旋转合并）**：

```
inplace_merge(A, lo, mid, hi):
    # 通过旋转，将 A[mid] 插入到正确位置
    while lo <= mid and mid+1 <= hi:
        if A[lo] <= A[mid+1]:
            lo++
        else:
            # 旋转 A[lo..mid+1]，将 A[mid+1] 移到 lo 位置
            rotate(A, lo, mid, mid+1)
            lo++, mid++
```

**复杂度分析**：原地归并的时间复杂度仍是 O(n log n)，但常数较大。

### 13.8.3 原地归并排序与链表归并排序

**链表归并排序的优势**：

- 链表的合并操作可以 O(1) 空间完成（只需修改指针）
- 这是链表排序的首选算法
    
**对比**：

|维度|数组原地归并|链表归并|
|---|---|---|
|空间复杂度|O(1) 但常数大|O(1) 且高效|
|时间复杂度|O(n log n)|O(n log n)|
|缓存友好性|差|差|
|实际速度|较慢|中等|

> 📌 13.8.3 节的核心洞见：**链表归并排序是归并排序最自然的形态**。因为链表的合并操作天然是 O(1) 空间的——这正是许多函数式编程语言（如 Haskell、Lisp）选择归并排序作为默认排序算法的原因。

## 九、13.9 自然归并排序：利用输入的有序性

**核心思想**：利用输入数组中已有的有序片段（run），减少不必要的划分 。

**算法流程**：

1. 扫描数组，识别自然有序的片段（run）
2. 将这些 run 放入队列
3. 反复合并队列中最小的两个 run，直到只剩一个
    
**为什么这是改进？**​

- 对于部分有序的数组，自然归并排序接近 O(n)
- 这是 TimSort（Python、Java 的默认排序算法）的核心思想
    
> 💡 自然归并排序与插入排序的呼应：第2章插入排序在基本有序数据上 O(n)；自然归并排序将这一思想推广到分治框架中。

## 十、13.10 自底向上归并排序：消除递归

**核心思想**：去掉递归，从长度为 1 的子数组开始，反复合并 。

**算法流程**：

```
bottom_up_mergesort(A):
    n = len(A)
    width = 1
    while width < n:
        for i = 0 to n step 2*width:
            merge(A, i, min(i+width, n-1), min(i+2*width-1, n-1))
        width *= 2
```

**优势**：

- 无递归栈开销
- 缓存友好（顺序访问）
- 易于并行化

**为什么需要自底向上？**​

- 递归版本有 O(log n) 的栈空间开销
- 自底向上版本是真正的 O(1) 空间（不考虑合并的工作区）
- 现代工程实现常用自底向上 + 小数组插入排序的组合
    
## 十一、13.11 并行处理：多核时代的归并排序

**核心思想**：归并排序的分治特性天然适合并行化 ：

**并行策略**：

1. **任务并行**：不同子数组的排序可并行执行
2. **数据并行**：合并操作可并行化（如双路并行合并）
    
**为什么归并排序比快排更适合并行？**​

- 归并排序的划分是确定的（总是 n/2），子任务完全独立
- 快排的划分依赖 pivot，子任务规模不确定，负载均衡困难

> 💡 现代多核 CPU 上，并行归并排序可以达到接近线性的加速比。这是大数据处理框架（如 Hadoop MapReduce）选择归并排序作为核心算法的根本原因 。

## 十二、13.12 小结：O(n log n) 排序算法的完整图景

作者在 13.12 节将快排与归并排序并排对比 ：

|维度|快速排序|归并排序|
|---|---|---|
|平均时间|O(n log n)|O(n log n)|
|最坏时间|O(n²)（可防护到 O(n log n)）|O(n log n)|
|空间复杂度|O(log n) 递归栈|O(n) 额外空间|
|稳定性|不稳定|**稳定**​|
|缓存友好性|极好|中等|
|并行化|困难（负载不均衡）|**容易（任务独立）**​|
|原地性|是|否（除非原地归并）|
|小数组优化|切换到插入排序|切换到插入排序|
|适合场景|内存排序、通用排序|外部排序、稳定排序、并行排序|

**两种算法的哲学对比**：

- **快速排序**："划分派"——先分类，后递归。信任随机性，追求平均性能
- **归并排序**："合并派"——先递归，后合并。追求最坏保证，牺牲空间换稳定性
    
**工程实践中的真实选择**：

- **C 标准库 `qsort`**：快速排序（历史原因 + 平均性能最优）
- **C++ STL `std::sort`**：Introsort（快排 + 堆排序 + 插入排序的混合）
- **Java `Arrays.sort()`（基本类型）**：双轴快排（Dual-Pivot Quicksort）
- **Java `Arrays.sort()`（对象类型）**：TimSort（归并排序的改进版）
- **Python `sorted()`**：TimSort
- **Go `sort.Sort()`**：Introsort 变体
- **Hadoop MapReduce**：归并排序（外部排序 + 并行）
    
## 十三、"为什么"与"实际应用"重点提炼

### 为什么需要两种 O(n log n) 排序算法？一种不够吗？

这是理解本章的关键。快排和归并排序各有其不可替代的优势：

**选择快速排序的场景**​ ：

- 内存排序，数据完全在 RAM 中
- 数据随机性好，不要求稳定性
- 对平均性能要求高
- 缓存友好性至关重要
- 典型应用：游戏排行榜更新、内存数据库排序
    
**选择归并排序的场景**​ ：

- 要求排序稳定性（如电商订单：先按金额排序，再按时间排序）
- 链表排序（归并是链表排序的首选）
- 外部排序（数据超出内存容量）
- 并行处理（多核/分布式环境）
- 对最坏时间复杂度有严格要求
- 典型应用：数据库排序、日志分析、Hadoop MapReduce
    
### 工业界的真实应用

**1. 快速排序的工程演化**：

- **C 标准库 `qsort`**：经典快排
- **C++ STL `std::sort`**：Introsort（快排为主，递归深度超限时切换堆排序，小数组切换插入排序）
- **Java 双轴快排**：Yaroslavskiy 在 2009 年提出，用两个 pivot 划分三部分，在大数据集上比经典快排快 ~10%
- **实时系统**：快排的平均性能使其成为通用排序的首选
    
**2. 归并排序的工程演化**：

- **TimSort**（Python、Java 对象排序、Android）：归并排序 + 插入排序 + 自然归并，利用数据中的有序片段
- **Hadoop MapReduce**：归并排序是 Shuffle 阶段的核心算法——Map 端局部排序，Reduce 端全局归并
- **数据库外部排序**：数据分块读入内存排序，写入临时文件，最后多路归并
- **PostgreSQL、MySQL**：外部排序使用归并排序


**3. 混合排序策略**​ ：

- 现代排序算法几乎没有"纯"快排或"纯"归并
- 都是混合策略：小数组用插入排序，中等数组用快排，大规模/外部数据用归并
- 这是工程算法设计的通用范式
    
### 一个深层洞察：分治思想是贯穿全书的隐形主线

回顾全书，分治思想反复出现：

|章节|分治的应用|
|---|---|
|第1章 BST|递归定义：左子树、右子树、根|
|第3章 红黑树|旋转操作：局部调整，保持全局性质|
|第6章 后缀树|Ukkonen 算法：增量构建，分治思想|
|第7章 B树|多路分支：本质上是"多路分治"|
|第9章 堆排序|分治思想在"选择"维度的应用|
|第10章 斐波那契堆|势分析：将昂贵操作分摊到多个廉价操作|
|第12章 手指树|树脊递归：深层结构递归下降|
|**第13章 快排/归并**​|**分治思想的经典演绎**​|
|第14章 二分查找|分治思想在搜索中的应用|

> 💡 分治思想是《算法新解》全书的"隐形主线"——从 BST 的递归定义，到红黑树的旋转修复，到 B树的多路分支，到手指树的树脊递归，再到第13章快排/归并的经典分治——**所有复杂的算法和数据结构，本质上都是在用分治思想"分而治之"**。第13章将这一思想提升到了"算法策略"的高度，为第14章的搜索算法奠定基础。

## 十四、全局总结：这一章到底在讲什么

如果要用一句话概括第13章：**它展示了"分而治之"思想如何将排序算法从 O(n²) 提升到 O(n log n)——快速排序用"划分"在递归前分类数据，归并排序用"合并"在递归后整合数据，两种互补的形态构成了基于比较的排序算法的完整图景**。

更宏观地看，第13章在全书中的位置极为关键：

- **它是第四部分"排序和搜索"的开篇**：从数据结构转向算法策略，分治思想是这一转变的核心
- **它完成了 O(n log n) 排序算法的"三驾马车"**：堆排序（第9章）、快速排序（13.1-13.6）、归并排序（13.7-13.11）。三种算法分别从"选择"、"划分"、"合并"三个角度达到基于比较的排序算法的理论下限
- **它回收了全书的多个伏笔**：
    
    - 第1章 BST 的"左小右大" ↔ 快排的划分
    - 第2章插入排序的"基本有序 O(n)" ↔ 归并的自然归并
    - 第9章堆排序的 O(n log n) ↔ 快排/归并的 O(n log n)
    - 第12章手指树的 split/concat ↔ 归并的分与合
        
- **它为第14章搜索埋下伏笔**：14.1.1 节"分而治之的搜索"直接延伸本章思想——二分查找、k-选择问题都是分治在搜索领域的应用
- **它展示了"算法策略驱动"的思维方式**：数据结构是"名词"，算法是"动词"；分治是连接名词和动词的"语法"

> 📌 读书笔记的核心收获：**快排与归并排序的并排学习，揭示了算法设计的一个根本真理——同一个问题（排序）可以有多种互补的解决方案，每种方案都有其独特的优势场景**。快排用"划分"换取平均性能和原地性，归并用"合并"换取最坏保证和稳定性。工程实践中的智慧不是"选择最好的算法"，而是"为不同场景选择最合适的算法"——这正是 Introsort、TimSort 等混合排序算法成功的根本原因。而分治思想作为贯穿全书的隐形主线，在第13章达到了"算法策略"的高度——它不仅是排序算法的核心，更是第14章搜索算法、乃至整个算法领域的通用范式。
