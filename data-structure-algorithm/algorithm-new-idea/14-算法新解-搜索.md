## 二、14.1 序列搜索：在有序中定位

### 14.1.1 分而治之的搜索：二分思想的淋漓尽致

**核心思想**：如果序列是有序的（或可比较的），每次比较可以排除一半候选。

**经典二分查找**：

```
binary_search(A, target):
    lo, hi = 0, n-1
    while lo <= hi:
        mid = (lo + hi) // 2
        if A[mid] == target: return mid
        elif A[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1
```

**时间复杂度**：O(log n)——每次迭代排除一半元素。

**为什么二分查找是"分而治之"的搜索范式？**​

回顾第13章的分治思想：

- **快速排序**：划分在递归前——"分"是主动的
- **归并排序**：合并在递归后——"合"是主动的
- **二分查找**：划分在递归前，且**只需要递归一个分支**——"分"后立即丢弃另一半
    
二分查找是分治思想最纯粹的形态——**它不合并，不处理两个分支，而是每次只选择相关的那一半**。这是"分而治之"在搜索领域的极致应用。

**二分查找与 BST 查找的深刻同构**：

|维度|BST 查找|二分查找|
|---|---|---|
|数据结构|二叉搜索树|有序数组|
|决策依据|当前节点值与目标的比较|中点值与目标的比较|
|下一步|走向左/右子节点|调整 lo/hi 指针|
|排除比例|约一半子树|恰好一半|
|时间复杂度|O(log n) 平均，O(n) 最坏|O(log n) 稳定|

> 💡 BST 查找与二分查找是同构的——**BST 就是"把二分查找的决策树显式存储起来"**。第1章的 BST 查找，本质上是"预先构建好的二分查找"；而二分查找，本质上是"隐式的、每次临时构建的 BST 查找"。这一同构揭示了全书"树"部分与"搜索"部分的隐形纽带。

**k-选择问题（Selection Problem）**：

查找无序数组中第 k 小的元素。

**算法思想**：基于快速排序的 partition 操作——

- 随机选择一个 pivot，进行 partition
- 若 pivot 的位置 == k，则找到
- 若 pivot 的位置 > k，递归左半部分
- 若 pivot 的位置 < k，递归右半部分
    
**时间复杂度**：平均 O(n)——每次划分排除一部分元素，期望递归深度 O(log n)，每层的 partition 代价递减。

**为什么 k-选择只需要 O(n)？**​ 这是分治思想的又一个精妙应用——**我们不需要完全排序，只需要"部分排序"到目标位置**。快速排序的 partition 操作恰好提供了这种"部分排序"能力。这是第13章快排思想在搜索领域的直接延伸。

**中位数查找**：k-选择的特例（k = n/2），O(n) 时间找到中位数。这是统计学、机器学习中的基础操作。

### 14.1.2 信息复用：字符串匹配的智能跳跃

**核心问题**：在文本 T 中查找模式 P 的所有出现位置。

**朴素算法**：

```
naive_search(T, P):
    for i = 0 to n-m:
        match = True
        for j = 0 to m-1:
            if T[i+j] != P[j]:
                match = False
                break
        if match: yield i
```

**时间复杂度**：O(n·m)——最坏情况下每个位置都要比较 m 次。

**为什么朴素算法低效**​ 因为它**不复用信息**——每次对齐都从头比较，之前比较的结果完全丢弃。

**信息复用的两种核心策略**：

#### 策略一：KMP 算法（Knuth-Morris-Pratt）

**核心思想**：**利用模式串自身的前缀信息，避免文本指针的回溯**。

**部分匹配表（Prefix Function）**：

- 对于模式串 P，计算 `π[i]` = P[0..i] 的最长真前缀，同时是 P[0..i] 的真后缀的长度
- 例：P = "ABABAC"，π = [0, 0, 1, 2, 3, 0]

**匹配算法**：

```
KMP_search(T, P):
    π = compute_prefix_function(P)  # O(m)
    i = j = 0
    while i < n:
        if T[i] == P[j]:
            i++, j++
            if j == m: yield i - m, j = π[j-1]
        else if j > 0:
            j = π[j-1]  # 关键：利用 π 表跳跃，不回溯 i
        else:
            i++
```

**时间复杂度**：O(n + m)——预处理 O(m)，匹配 O(n)。

**为什么 KMP 是"信息复用"的典范？**​

- 它复用了**模式串的前缀结构信息**（π 表）
- 当匹配失败时，文本指针 i **不回溯**，只调整模式指针 j
- 这是"空间换时间"的经典——用 O(m) 的预处理空间，换得 O(n) 的匹配时间
    
> 💡 KMP 与第5章 Trie 的深刻联系：π 表的本质就是模式串的**前缀自动机**——每个状态对应一个前缀，转移表示下一个字符。KMP 匹配过程就是在这个自动机上行走。而前缀自动机，本质上是 Trie 的一种压缩形式。这是全书"字符串数据结构"思想在搜索算法中的回响。

#### 策略二：Boyer-Moore 算法

**核心思想**：**从模式串尾部开始匹配，利用"坏字符"和"好后缀"规则实现跳跃式移动**。

**坏字符规则**：

- 当 T[i+j] ≠ P[j] 时，检查 T[i+j] 在 P 中最后出现的位置
- 若存在，移动模式使该字符对齐
- 若不存在，移动模式越过该字符
    
**好后缀规则**：

- 当匹配了一段后缀后失败，寻找模式中与已匹配后缀相同的最长片段
- 移动模式使该片段对齐
    
**时间复杂度**：最坏 O(n·m)，但**实践中常优于 KMP**——因为 Boyer-Moore 可以一次跳过多个字符。

**为什么 Boyer-Moore 实践中更快？**​

- KMP 每次至少前进 1 个字符
- Boyer-Moore 利用坏字符规则可以**一次跳过整个模式长度**
- 在随机文本中，Boyer-Moore 的平均比较次数约为 n/m——几乎每个字符只比较一次
    
> 📌 14.1.2 节的核心洞见：**"信息复用"是字符串匹配的灵魂**。KMP 复用模式串的前缀信息，Boyer-Moore 复用文本中的字符分布信息和模式串的后缀信息。两种算法从不同角度回答了同一个问题——"如何从已匹配的信息中提取最大价值，避免重复比较"。这与第6章后缀树的思想一脉相承：**利用字符串的内在结构，避免重复工作**。

**其他字符串匹配算法**（14.1.2 节可能涉及的）：

- **Rabin-Karp**：利用哈希指纹，O(n+m) 平均，适合多模式匹配
- **有限自动机方法**：构建模式串的 DFA，O(n) 匹配
- **Horspool 算法**：Boyer-Moore 的简化版，实践中极快
    
## 三、14.2 解的搜索：在状态空间中探索

### 14.2.1 深度优先搜索和广度优先搜索：盲目搜索的两大范式

**核心问题**：在一个状态空间中，从初始状态出发，找到目标状态（或所有可达状态）。

**状态空间的数学表述**：

- **状态**：问题在某个时刻的快照
- **转移规则**：从一个状态到另一个状态的合法操作
- **状态空间图**：节点是状态，边是转移规则
    
**两种基本的图遍历策略**：

#### 广度优先搜索（BFS）

**核心思想**：**逐层扩展**——先访问所有距离为 1 的状态，再访问距离为 2 的状态……

**数据结构**：队列（这正是第11章队列的用武之地）

**算法**：

```
BFS(start, target):
    queue = [start]
    visited = {start}
    while queue not empty:
        node = queue.dequeue()
        if node == target: return path(node)
        for neighbor in neighbors(node):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.enqueue(neighbor)
```

**时间复杂度**：O(V + E)——每个节点和边访问一次。

**空间复杂度**：O(V)——队列中可能存储所有节点。

**BFS 的核心性质**：**首次访问到目标节点时，路径长度是最短的**（在边权相等的图中）。

**为什么 BFS 用队列？**​ 队列的 FIFO 性质保证了"先发现的节点先扩展"——这正是"逐层扩展"的数学本质。这是第11章队列思想在图算法中的直接应用。

**典型应用**：

- **最短路径**（边权相等）：社交网络中两人之间的最短连接、迷宫最短出口
- **连通分量**：找出图中所有连通的区域
- **拓扑排序的辅助**：Kahn 算法用 BFS 思想
- **网络广播**：数据包在网络中的传播
    
#### 深度优先搜索（DFS）

**核心思想**：**沿一条路径深入到底，遇到死胡同才回溯**。

**数据结构**：栈（递归调用栈或显式栈）

**算法（递归版）**：

```
DFS(node, target):
    if node == target: return path(node)
    for neighbor in neighbors(node):
        if neighbor not visited:
            mark visited
            result = DFS(neighbor, target)
            if result: return result
    return None
```

**时间复杂度**：O(V + E)。

**空间复杂度**：O(h)——递归深度，h 是图的最大深度。

**DFS 的核心性质**：**空间效率高**（相比 BFS），适合深度大的图；但**不保证最短路径**。

**为什么 DFS 用栈？**​ 栈的 LIFO 性质保证了"最后发现的节点先扩展"——这正是"深入到底"的数学本质。递归调用栈是函数式编程中 DFS 的自然表达。

**典型应用**：

- **拓扑排序**：DFS 的后序遍历逆序即为拓扑序
- **连通性分析**：找出图中所有连通分量、强连通分量（Tarjan 算法）
- **环检测**：判断有向图是否有环
- **路径搜索**：迷宫求解、棋盘游戏（如 N 皇后、数独）
- **回溯算法的基础**：N 皇后、组合总和、全排列
    
**DFS vs BFS 的本质对比**：

|维度|DFS|BFS|
|---|---|---|
|数据结构|栈|队列|
|探索策略|深入到底|逐层扩展|
|空间复杂度|O(h)，h 为深度|O(w)，w 为宽度|
|最短路径|不保证|**保证**（边权相等）|
|适合场景|深度大、解在深处|解在浅处、需要最短路径|
|全书对应|递归（函数式）|第11章队列（命令式/函数式）|

> 💡 DFS 与 BFS 的对比，本质上是**栈与队列的对比**——而栈与队列的对比，正是第11章"并不简单的队列"的核心议题。第11章告诉我们：在不可变约束下，队列需要精巧设计才能达到 O(1) 摊还；而栈（链表）天然就是 O(1) 的。这解释了为什么函数式编程中 DFS 比 BFS 更自然——因为栈的不可变实现极简，队列的不可变实现复杂。这是 14.2.1 节与第11章的隐形纽带。

**盲目搜索的局限**：

- DFS/BFS 都是"盲目"的——它们不利用任何关于目标的启发式信息
- 在大规模状态空间中，盲目搜索不可行
- 这就需要 14.2.2 节的"启发式搜索"
    
### 14.2.2 搜索最优解：启发式与优化的艺术

**核心问题**：在状态空间中，不仅要找到目标，还要找到**最优**目标（最短路径、最小代价、最大价值）。

**三类核心算法范式**：

#### 范式一：贪心算法

**核心思想**：**每一步都选择当前看起来最优的决策，期望最终结果全局最优**。

**适用条件**：问题满足**贪心选择性质**和**最优子结构**。

**典型算法**：

**1. Dijkstra 最短路径算法**：

- **贪心策略**：每次从未处理的节点中选择距离最小的节点，将其距离确定为最终值
- **数据结构**：优先队列（第8章堆、第10章斐波那契堆）
- **时间复杂度**：O((V + E) log V)（二叉堆）或 O(V log V + E)（斐波那契堆）
- **为什么用堆**​ 因为需要反复提取最小距离节点——这正是堆的看家本领
- **与第10章的深刻联系**：斐波那契堆的 O(1) 摊还 decrease-key，正是为 Dijkstra 量身定做
    
**2. 最小生成树（Prim/Kruskal）**：

- **Prim**：贪心选择连接已覆盖节点与未覆盖节点的最小边，用堆维护
- **Kruskal**：所有边按权重排序，用并查集维护连通性，贪心地选择不形成环的最小边
- **与第13章的联系**：Kruskal 需要 O(E log E) 的排序——这正是第13章归并排序/快排的用武之地
    
**3. 霍夫曼编码**：

- 贪心地合并频率最小的两个节点
- 与第10章的堆排序思想同源
    
**贪心算法的哲学**：**局部最优 → 全局最优**。这不是总能成立，但在满足贪心选择性质的问题上，贪心是最优雅、最高效的解决方案。

#### 范式二：动态规划（Dynamic Programming）

**核心思想**：**将复杂问题分解为重叠子问题，通过记忆化避免重复计算**。

**适用条件**：问题满足**最优子结构**和**重叠子问题**。

**典型算法**：

**1. 最长公共子序列（LCS）**：

- 状态：`dp[i][j]` = 序列 A[0..i] 和 B[0..j] 的 LCS 长度
- 转移：`dp[i][j] = dp[i-1][j-1] + 1`（若 A[i]==B[j]）或 `max(dp[i-1][j], dp[i][j-1])`
- 时间复杂度：O(n·m)
    
**2. 0-1 背包问题**：

- 状态：`dp[i][j]` = 前 i 个物品在容量 j 下的最大价值
- 转移：`dp[i][j] = max(dp[i-1][j], dp[i-1][j-w[i]] + v[i])`
- 时间复杂度：O(n·W)

**3. 最短路径（Floyd-Warshall）**：

- 状态：`dp[k][i][j]` = 允许经过前 k 个节点时，i 到 j 的最短路径
- 转移：`dp[k][i][j] = min(dp[k-1][i][j], dp[k-1][i][k] + dp[k-1][k][j])`
- 时间复杂度：O(V³)
    
**动态规划与 DFS 的深刻联系**：

- 朴素 DFS 求解这些问题的时间复杂度是指数级的
- 动态规划 = DFS + 记忆化——通过缓存子问题结果，将指数级降到多项式级
- 这是"空间换时间"的极致
    
**动态规划与第6章后缀树的联系**：

- LCS 问题可以用后缀树在 O(n + m) 时间内解决
- 这体现了"数据结构驱动"与"算法驱动"的两种范式——后缀树用空间换得极致时间，动态规划用时间换得通用性
    
#### 范式三：A* 搜索

**核心思想**：**在 Dijkstra 的基础上，引入启发式函数 h(n)，引导搜索朝向目标方向**。

**优先级**：f(n) = g(n) + h(n)，其中 g(n) 是实际代价，h(n) 是启发式估计

**与 Dijkstra 的关系**：当 h(n) = 0 时，A* 退化为 Dijkstra

__为什么 A_ 更高效？__​ 因为它__利用启发式信息_*，避免探索无关的方向

## 四、14.3 小结：搜索算法的完整图景

作者在 14.3 节将全章的搜索范式并排对比 ：

|搜索范式|适用场景|核心数据结构|时间复杂度|
|---|---|---|---|
|二分查找|有序序列中找目标|数组|O(log n)|
|k-选择|无序序列中找第 k 小|数组 + partition|O(n) 平均|
|KMP|文本中找模式|π 表（前缀自动机）|O(n + m)|
|Boyer-Moore|文本中找模式|坏字符/好后缀表|O(n·m) 最坏，实践 O(n/m)|
|BFS|无权图最短路径|队列|O(V + E)|
|DFS|连通性/拓扑/回溯|栈|O(V + E)|
|Dijkstra|带权图最短路径|优先队列（堆）|O((V+E) log V)|
|动态规划|重叠子问题|DP 表|问题相关|
|贪心|满足贪心选择性质|问题相关|问题相关|
|A*|有启发式信息的最短路径|优先队列 + 启发式|介于 Dijkstra 和最佳情况之间|

**搜索算法的进化本质**：

```
盲目搜索（DFS/BFS）
    ↓ 引入"有序性"
分而治之的搜索（二分查找、k-选择）
    ↓ 引入"信息复用"
字符串匹配（KMP、Boyer-Moore）
    ↓ 引入"优先级"
最优解搜索（Dijkstra、A*）
    ↓ 引入"记忆化"
动态规划
```

每一层进化，都是在"盲目搜索"的基础上，利用更多的**问题结构信息**，从而获得更高的效率。

## 五、"为什么"与"实际应用"重点提炼

### 为什么搜索是《算法新解》的终章？

这是理解本章定位的关键。全书四部分：

1. **树**：如何组织数据以支持全序/偏序/前缀访问
2. **堆**：如何维护最值
3. **队列和序列**：如何表示顺序数据
4. **排序和搜索**：如何预处理数据 + 如何找到答案
    
**搜索是全书知识的最终交付**——前 13 章的所有数据结构与算法，最终都要服务于"搜索"这一根本需求。用户不在乎数据是如何组织的，他们只在乎"我的答案在哪里"。

### 搜索算法的真实应用

**1. 二分查找的应用**：

- **数据库索引查找**：B+ 树的查找本质上是二分查找的多路推广
- **数学求根**：二分法求函数零点
- **资源分配**：在约束条件下二分查找最大/最小值（如最大化最小值问题）
- **现代 CPU 的分支预测**：本质上是二分决策

**2. KMP/Boyer-Moore 的应用**：

- **文本编辑器查找/替换**：Ctrl+F 的核心算法
- **病毒特征码匹配**：防病毒软件在文件中搜索已知病毒特征
- **DNA 序列匹配**：生物信息学中在基因组中搜索特定序列
- **入侵检测系统（IDS）**：在网络流量中匹配攻击特征
- **编译器/解释器**：词法分析阶段的标识符匹配
    
**3. BFS/DFS 的应用**：

- **社交网络**：六度空间理论验证、好友推荐
- **网络爬虫**：网页抓取的顺序策略
- **拓扑排序**：编译器依赖分析、包管理器依赖解析
- **迷宫/谜题求解**：AI 游戏玩家、数独求解器
- **版本控制系统**：Git 的历史追溯（DAG 的 DFS）
    
__4. Dijkstra/A_ 的应用_*：

- **GPS 导航**：Google Maps、高德地图的路径规划
- **网络路由**：OSPF 协议用 Dijkstra 计算最短路径
- **机器人路径规划**：自动驾驶、仓储机器人
- **游戏 AI**：NPC 寻路
    
**5. 动态规划的应用**：

- **生物信息学**：序列比对（LCS 的延伸）
- **金融**：期权定价（Bellman 方程）
- **自然语言处理**：词性标注、机器翻译（Viterbi 算法）
- **运筹学**：资源分配、调度优化
    
### 一个深层洞察：搜索是"问题结构信息"的竞技场

回顾全书，我们发现一个深刻的规律——**搜索算法的效率上限，取决于我们能从问题中提取多少结构信息**：

|信息量|搜索策略|复杂度|
|---|---|---|
|无结构信息|盲目 DFS/BFS|O(b^d)，b 是分支因子，d 是深度|
|序列有序|二分查找|O(log n)|
|模式串前缀结构|KMP|O(n + m)|
|字符分布信息|Boyer-Moore|实践 O(n/m)|
|边权非负|Dijkstra（贪心）|O((V+E) log V)|
|重叠子问题|动态规划|多项式级|
|启发式信息|A*|介于 Dijkstra 和最佳之间|

> 💡 这一规律与全书的方法论完全吻合：**数据结构设计的本质，就是"提取并利用数据的结构信息"**。第1章 BST 利用"键的可比较性"，第5章 Trie 利用"键的字符结构"，第6章后缀树利用"后缀间的包含关系"，第7章 B树利用"磁盘块的批量存取"——而第14章告诉我们：**搜索算法的本质，也是"提取并利用问题的结构信息"**。

**没有"最好的搜索算法"，只有"最适合问题结构的搜索算法"**——这正是《算法新解》通过 14 章反复传递的核心信息。
