# 《算法》（Sedgewick & Wayne）第2章 · 排序 —— 读书笔记

> **开篇先立一个"第一性原理"的锚点**：排序的本质是一个"逆序对消除"问题。一个完全逆序的数组有 ~N²/2 对逆序，任何**基于比较**的排序每一步最多消除一个逆序，因此必然至少做 ~N²/2 次比较——这就是所有 O(N²) 初级排序的天花板，也是 O(N log N) 算法存在的意义（每次比较不是只消除 1 个逆序，而是成倍削减"剩余不确定性"）。本章的全部故事，就是**人类如何一步步发明越来越会"批量消除逆序"的方法**。

---

## 一、2.1 初级排序算法 —— 在"相邻交换"里摸到天花板

### 1.1 游戏规则（2.1.1）：统一的骨架

所有排序共享同一套骨架：操作 `Comparable[]` 数组的 `sort()` 方法，配两个工具函数 `less()`（比较）与 `exch()`（交换），并通过 `Comparable` 接口的 `compareTo()` 定义**全序关系**（自反、反对称、传递，不允许出现矛盾）。**洞见 ①**：这套统一骨架的意义，是让不同算法能在**同一基准（SortCompare 客户端 + 倍率实验）**下公平比拼——这正是第1章 1.4 节"科学方法"的第一次实战应用。

### 1.2 选择排序（2.1.2）

- **做法**：反复扫描剩余部分找最小元素，与当前位置交换。
    
- **不变式**：当前下标左侧的元素已排好序，且是全局最小的那些。
    
- **代价**：~N²/2 次比较、**恰好 N 次交换**（每个元素最多移动一次）。
    
- **关键性质**：**运行时间与输入顺序无关**——对已经有序的数组，它和随机数组一样慢。这既是"可预测"的优点，也是"不会白嫖有序性"的缺点。不稳定，原地排序。
    

**洞见 ②：选择排序是"数据移动最小化"的极端——它用最多的比较，换最少的交换。**​ 当"比较便宜、交换极贵"（例如元素是超大记录、交换要拷贝整条记录）时，这个"怪脾气"反而让它有一席之地。这提醒我们：**没有绝对最差的算法，只有不匹配场景的算法。**

### 1.3 插入排序（2.1.3）—— 本章第一个"小而美"的赢家

- **做法**：像整理手牌一样，把当前元素向左滑入已排序前缀中的正确位置，较大元素逐个右移。
    
- **核心等式（极重要）**：**交换次数 = 逆序对数；比较次数 = 逆序对数 + (N−1)**。算法的"工作量"正是在**度量数组有多乱**。
    
- **代价**：平均 ~N²/4 比较与交换；最坏（逆序）~N²/2；**最好（已排序）仅需 N−1 次比较、0 次交换，线性时间**。
    
- **性质**：**稳定**（只交换相邻元素，不会跨过相等的元素），原地排序。
    

**洞见 ③：插入排序是"自适应（adaptive）"的鼻祖——它对"部分有序"数组天然友好。**​ 这正是它后来被当作归并排序、快速排序**小数组 cutoff（切换到插入排序，子数组长度 ≤15 左右）**的根本原因：递归到足够小的子数组时，递归开销反而大于"近乎有序"的插入排序，一切换能提速约 10%~15%。**一条经验法则：任何高级排序，最后几层都该"退化"成插入排序。**

### 1.4 希尔排序（2.1.6）—— 插入排序"隔空交换"的武器化

希尔排序是插入排序的"酷哥哥"：不再只比较相邻元素，而是比较**相隔 h 个位置**的元素，对各个交错的子序列分别做插入排序，然后逐步缩小 h 至 1。**当 h=1 时退化为普通插入排序，但此时数组已经"基本有序"，插入排序一路狂飙。**

- **增量序列**：书里用 **3h+1 序列**（1, 4, 13, 40, 121, 364…），从小于 N/3 的最大 h 起步，每次整除 3。Sedgewick 自己还发现了一组更优但更复杂的序列（1, 5, 19, 41, 109…）。
    
- **代价**：3h+1 序列最坏比较次数为 **O(N^(3/2))**，实践中远小于此；**不稳定，原地排序，代码量极小**。
    

**洞见 ④（本章最值得玩味的一点）：希尔排序的"最优增量序列"至今仍是开放研究问题——我们研究排序 70+ 年，仍不知道希尔排序的最好步长该怎么取！**​ Sedgewick 在 Coursera 课上直言："我花了一年找到一组不错的序列，但没人知道它是不是最优的。" 这给读者的启示是双重的：

1. **好的算法仍有待发现**——不要迷信"经典即终极"；
    
2. **一个简单想法（让元素远距离跳跃）就能带来质的性能飞跃**——从 O(N²) 量级跃迁到亚二次。这正是"创新往往来自对默认假设的质疑"（为什么只能和邻居比？）。
    

### 1.5 比较两种算法（2.1.5）与可视化（2.1.4）

本节用 `SortCompare` 客户端把两种算法在随机数组上跑分，结合第1章的**倍率实验（doubling ratio）**验证理论：N 翻倍时，O(N²) 算法耗时约翻 4 倍，O(N log N) 算法仅略超翻倍。**洞见 ⑤：可视化 + 倍率实验，是把"直觉"锻造成"可证伪命题"的工程习惯**——看见柱状图里插入排序在小数据领先、大数数据断崖式落后，比任何公式都直观。

## 二、2.2 归并排序 —— "分治"的教科书范例

### 2.1 第一性原理：排序如何"批量消逆序"？

归并排序的核心操作是 **merge**：把两个**已排序**的子数组合并成一个更大的有序数组（双指针像拉链一样依次取较小者）。由此自然导出**分治递归**：把数组对半分 → 递归排好两半 → 合并结果。**洞见 ⑥：归并的精髓在于——两个各自内部已无逆序的子数组合并时，一次 merge 就能把横跨两半的逆序对全部归位，效率远高于"逐个元素"消除。**

### 2.2 自顶向下（2.2.2）

- **做法**：递归二分，回溯时合并。工作在"从递归回来的路上"完成。
    
- **代价**：比较次数介于 ½N log N 与 N log N 之间；数组访问最多 6N log N。**这是基于比较的排序的渐进最优界**。
    

### 2.3 自底向上（2.2.3）

- **做法**：不递归。先两两合并大小为 1 的子数组，再合并大小为 2 的、4 的、8 的……循环翻倍子数组大小，直到覆盖全数组。
    
- **代价**：与自顶向下同阶（½N log N ~ N log N 比较，≤6N log N 数组访问）。
    

**洞见 ⑦：自底向上归并是"链表排序"的自然选择**——链表无法 O(1) 随机访问，但合并两个有序链表天然只需指针重排、可原地完成。这解释了为什么许多链表排序实现（如 Java 旧版对象数组的 TimSort 前身、外部排序的多路归并）都扎根于归并思想。

### 2.4 三个工程改进（2.2.2 末尾）

|改进|做法|效果|
|---|---|---|
|**小数组切到插入排序**​|子数组长度 ≤15 时改用手牌插入排序|提速约 10%~15%|
|**已排序则跳过 merge**​|若 `a[mid] ≤ a[mid+1]`，跳过本次合并|对有序数组**整体线性时间**​|
|**消除辅助数组的拷贝**​|递归两层间交替扮演"输入/辅助"角色|省掉拷贝开销（仍占用 O(N) 空间）|

**洞见 ⑧：这三个改进共同揭示一个工程真理——"理论最优"不等于"实际最快"。**​ 常数项、缓存友好性、递归开销，都会让"同样 O(N log N)"的两种实现差出数倍。归并排序的"可改进空间"恰恰是它生命力的来源。

### 2.5 排序算法的复杂度（2.2.4）—— 决策树与下界

**这是全章的理论制高点。**​ 任何基于比较的排序可建模为一棵**决策树**：内部节点是一次比较 `a[i]:a[j]`，叶节点对应一种排列。排序 N 个不同元素必须能区分全部 N! 种排列 ⇒ 决策树至少有 N! 个叶子 ⇒ 树高（最坏比较次数）至少 `lg(N!)`。由 Stirling 公式 `lg(N!) ~ N lg N`。

> **结论：任何基于比较的排序，最坏情况下至少做 Ω(N log N) 次比较。归并排序与堆排序达到 O(N log N)，因此是基于比较的渐进最优排序算法。**

**洞见 ⑨：这个下界是"比较模型"的下界，不是"排序问题"的绝对下界。**​ 一旦允许非比较操作（计数排序、基数排序利用键值分布），就能突破到线性时间 O(N)。**理解"模型假设"比记住结论更重要**——它教你判断：何时该用比较排序（通用、键值任意），何时该换非比较排序（键值范围有限、可分解）。

## 三、2.3 快速排序 —— 分治的另一副面孔

### 3.1 与归并的对称美（第一性原理视角）

归并排序：**先递归、后合并**（"先分后治"，工作在后）。

快速排序：**先切分、后递归**（"先治后分"，工作在前）。切分选一个切分元素 v，把数组重排为"≤v / v已就位 / ≥v"三段，再递归排左右两段。

**洞见 ⑩：快排与归并是分治的"镜像"。**​ 归并的切分是机械的对半分（不依赖数据），合并要花力气；快排的切分依赖数据（选好 pivot 才能均分），递归则水到渠成。这个对称关系，是理解"为什么快排平均更快"的钥匙——**快排的内循环（左右指针扫描）极紧凑、缓存命中率高**，且数据移动次数少于归并。

### 3.2 性能特点（2.3.2）

- **平均**：~2N ln N 次比较；**最坏**：~N²/2 次比较（当数组已排序且 pivot 总取端点时）。
    
- **关键**：**必须先打乱数组（shuffle）**！这是把"最坏情况"从"输入决定"变成"概率极低事件"的工程关键——Sedgewick 名言："你电脑上的快排对大数组做二次比较的概率，远小于你的电脑被雷劈中的概率"。
    

### 3.3 算法改进（2.3.3）

|改进|做法|效果|
|---|---|---|
|**小数组切到插入排序**​|子数组 ≤5~15 切换|提速一个数量级（快排常数因子大幅下降）|
|**三取样切分（median-of-3）**​|取 3 个元素的中位数作 pivot|切分更均衡，代价仅一次中位数计算|
|**三向切分（Dijkstra 3-way）**​|把数组分成 `<v` / `=v` / `>v` 三段，等于 pivot 的不再递归|**对含大量重复键的数组，从 O(N log N) 降到线性 O(N)**，且是"熵最优"的|

**洞见 ⑪（Sedgewick 本人的研究结晶，含金量极高）：三向切分的真正威力在"重复键"上。**​ Sedgewick 在 1977 年的论文就指出：当数组含大量相等键时，普通单 pivot 快排会退化到 O(N²)（每一层只减少一个元素）；而三向切分把"等于 pivot"的一段一次性归位，直接避免无谓递归。2016 年 Sebastian Wild 最终证明了 Bentley-Sedgewick 猜想：**三向切分在任意键值分布下渐进最优（常数因子为 1）**。**这告诉我们：一个改进的价值，往往在"最坏的输入"面前才真正显现。**

## 四、2.4 优先队列与堆排序 —— 用"堆"这棵完全二叉树重塑选择排序

### 4.1 优先队列 ADT（2.4.1）

优先队列 = 支持 `insert`（插入）与 `delMax/delMin`（删除最大/最小）的抽象数据类型。**洞见 ⑫：为什么不直接排序、再按顺序取？**​ Sedgewick 的回答切中要害——**在许多场景（如 TopM、多路归并 Multiway）数据量大到无法全装入内存，甚至数据根本不会同时存在**。优先队列让你"边到边处理、始终只保留当前最优的几个"，这是排序做不到的。

### 4.2 初级实现（2.4.2）与堆的定义（2.4.3）

- 无序数组：insert O(1)，delMax O(N)（类选择排序内循环）。
    
- 有序数组：delMax O(1)，insert O(N)。
    
- **二叉堆**：用**完全二叉树**按层序存入数组（下标 1 起，`k` 的左孩子 `2k`、右孩子 `2k+1`、父节点 `⌊k/2⌋`），且满足**堆有序**（每个节点 ≥ 其两个子节点，最大堆）。
    

### 4.3 堆的算法（2.4.4）：swim 与 sink

- **swim(k)**：新元素从底部上浮，与父节点比较、必要时交换，直到恢复堆有序。insert = 尾部加入 + swim，代价 ≤1+lg N 次比较。
    
- **sink(k)**：根（或某节点）变小后下沉，与较大的子节点交换，直到恢复堆有序。delMax = 交换根与末尾 + sink(1)。
    

### 4.4 堆排序（2.4.5）

堆排序分两阶段，**直接在待排序数组内部维护堆，无需额外空间（原地）**：

1. **堆构造**：从 `k=N/2` downto 1 依次 `sink(k, N)`。利用"左右子树已是堆"的不变式，自右向左把整棵无序数组重排为堆。**巧妙结论：基于 sink 的堆构造是线性时间 O(N)**。
    
2. **下沉排序（sortdown）**：反复把堆顶（当前最大）与堆末尾交换，`N--`，再 `sink(1, N)`。最多做 2N lg N 次比较与交换。
    

**性质**：O(N log N) 时间、**原地（O(1) 额外空间）**、非稳定。它是"时间-空间同时最优"的排序——但**内循环比快排长、缓存局部性差**，实践中通常慢于快排。

**洞见 ⑬：堆排序是"选择排序的树形升级"**——普通选择排序每轮线性扫描找最大（O(N)），堆排序用堆把"找最大"加速到 O(log N)。**同一个问题（反复取最大），换一种数据结构，就从 O(N²) 降到 O(N log N)。**​ 这是数据结构力量的经典示范。

**洞见 ⑭：堆排序"理论完美、实践稍逊"的矛盾，揭示了缓存（cache）在现代算法性能中的决定性地位。**​ 快排扫描是顺序访问、缓存友好；堆排序父子节点在数组中跳跃访问、缓存命中率低。当你疑惑"为什么渐近相同、快慢却不同"时，答案往往在内存层次，而非大 O。

## 五、2.5 应用 —— 排序的真正威力：归约（Reduction）

### 5.1 将各种数据排序（2.5.1）

只要对象实现 `Comparable`（定义 `compareTo`）或提供 `Comparator`，同一套排序框架就能排序任意数据类型——这是"面向接口"的工程回报。

### 5.2 我应该使用哪种排序算法（2.5.2）

综合官方速查表，给出**第一性原理的选型决策**：

|算法|原地|稳定|最好|平均|最坏|适用场景|
|---|---|---|---|---|---|---|
|选择排序|✓|✗|N²|N²|N²|交换极贵、比较便宜|
|插入排序|✓|✓|**N**​|N²|N²|**小数据 / 基本有序**（用作 cutoff）|
|希尔排序|✓|✗|N|N^(3/2)|—|中等规模、代码空间受限（嵌入式）|
|归并排序|✗(需 N 辅助)|✓|N log N|N log N|N log N|**需要稳定性 / 链表排序**​|
|快速排序|✓|✗|N log N|2N ln N|N²(概率极低)|**通用大规模数据，实践中最快**​|
|堆排序|✓|✗|N|2N log N|2N log N|空间极度受限、需最坏 O(N log N) 保证|

**洞见 ⑮（选型第一性原理）：没有"最好的排序"，只有"最匹配问题约束的排序"。**​ 决策依次看：①数据规模（小→插入）；②是否要求稳定（是→归并）；③是否容忍最坏情况（否→快排+随机化）；④空间是否紧张（是→堆排序）；⑤键值是否有分布可利用（是→非比较排序）。**把约束列清楚，算法自己会"跳出来"。**

### 5.3 问题的归约（2.5.3）—— 本章思想天花板

**归约（Reduction）**：若能用问题 Y 的算法来帮助解决问题 X，则称 **X 归约到 Y**。代价 = 调用 Y 的代价 + 归约（预处理/后处理）代价。

经典例子：

- **找中位数 ≤ 排序**：排序 N 个元素 → 取中间那个。代价 N log N + 1。
    
- **元素互异性 ≤ 排序**：排序 → 检查相邻元素是否相等。代价 N log N + N。
    

由此引出一个"归约链"：**中位数、元素互异性、二维最近点对、二维凸包、Delaunay 三角剖分……都可归约到排序**，从而都是 O(N log N)。

**洞见 ⑯（本章最具"元认知"价值的一条）：排序是一种"通用计算原语"。**​ 很多问题表面不是排序，但一旦把数据排好序，答案就唾手可得。这教会我们一种解题思路——**面对一个陌生问题，先问："如果数据有序，这题会不会变简单？"**​ 会，就先排序（归约到排序）；这正是"归约"思维的威力，也是 Sedgewick 把这一节放在章末的深意。

### 5.4 排序应用一览（2.5.4）

系统排序（如 Java 8+ `Arrays.sort`）：对对象用 TimSort（归并的优化变体，稳定），对基本类型用**双 pivot 快速排序**（Dual-Pivot Quicksort，快排的进一步工程优化）。**洞见 ⑰：你日常调用的"系统排序"，正是本章算法在工程上几十年迭代的结晶。**​ 理解本章，就等于理解了你每天都在"免费使用"的那段代码的灵魂。

## 六、全章脉络图（章节间的"第一性原理"联系）

```
2.1 初级排序 (选择/插入/希尔)
   │  • 选择: 最少交换, 与输入无关
   │  • 插入: 自适应, 小数组/部分有序最快 → 成为后续所有高级排序的"小数组 cutoff"
   │  • 希尔: 质疑"只能比邻居" → 隔空插入 → 亚二次 O(N^(3/2))
   ▼
2.2 归并排序 (分治: 先分后治, 工作在后)
   │  • merge 抽象 + 自顶向下/自底向上
   │  • 决策树下界 Ω(N log N) → 归并是"基于比较"的渐进最优之一
   │  • 改进: cutoff/跳过已排序/消除拷贝 → "理论最优≠实际最快"
   ▼
2.3 快速排序 (分治的镜像: 先治(切分)后分, 工作在前)
   │  • 与归并对称: 切分靠数据, 内循环紧凑 → 实践中最快
   │  • 改进: 打乱+三取样+三向切分(重复键线性, 熵最优)
   ▼
2.4 优先队列 & 堆排序
   │  • 堆 = 完全二叉树 + 堆有序; swim/sink 两个原语
   │  • 堆排序 = 选择排序的树形升级: O(N log N) 且原地(时间-空间双优)
   │  • 揭示: 缓存局部性常比大 O 更影响实际性能
   ▼
2.5 应用: 归约 (Reduction)
      • "如果数据有序, 问题会变简单吗?" → 能, 就归约到排序
      • 中位数/元素互异/几何问题 均可归约到排序 → 排序是通用计算原语
```

**一句话总结全章**：排序算法的演进史，是一部 **"如何更聪明地批量消除逆序对"** 的历史——从逐个消除（O(N²)），到一次比较成倍削减不确定性（O(N log N)），再到利用键值分布突破比较模型（非比较排序）。而**归并/快排/堆排序三兄弟**，分别用"分治后置、分治前置、堆结构"三种思路，共同抵达了比较排序的渐进最优，并各自在不同约束（稳定/空间/实际速度/缓存）下成为最优解。**读懂这一层，你就拥有了"面对任何排序需求都能理性选型"的能力。**
