
# 《算法》（Sedgewick & Wayne）第5章 · 字符串 —— 读书笔记

> **开篇锚点（第一性原理）**：字符串不是"普通的键"，它是**由字符序列构成的、自带内部结构**的键。普通排序/查找把键当作"原子"（只问 `compareTo` 谁大谁小）；而字符串算法把键"拆开"——逐字符利用它的内部结构。本章的全部故事，正是围绕字符串的这一特殊性展开：**排序**利用字符的分布做基数排序（突破比较排序 O(N log N) 的下界）；**查找**把字符串自身结构化为搜索路径（Trie）或模式匹配（KMP/Boyer-Moore/Rabin-Karp）；**正则**把模式编译成自动机；**压缩**把字符出现的频率与重复模式编码为更短的位流。一句话——**字符串算法的本质，是"把键拆成字符序列来利用"。**

## 一、5.1 字符串排序 —— 突破比较排序的下界

### 1.1 键索引计数法（5.1.1）：所有非比较字符串排序的原子操作

键索引计数法的核心步骤：

1. **频率统计**：`count[key+1]++`（count[0]=0）；
    
2. **频率转起始索引**：`count[i] += count[i-1]`；
    
3. **分类**：按 `count[key]++` 把元素填入辅助数组 `aux[]`；
    
4. **回写**。
    

**命题**：键索引计数法是**稳定**的，时间 O(N+R)，空间 O(N+R)（R 为字母表大小）。

**洞见 ①：键索引计数法是"用键本身的值作为索引直接定位"——它完全绕开了 `compareTo`，是"非比较排序"思想的原型。**​ 第2章我们证明过基于比较的排序有 Ω(N log N) 下界；而键索引计数法告诉我们：**只要键能直接映射到小范围整数索引，就能 O(N) 排序**。这正是字符串排序能突破下界的根源。

### 1.2 低位优先 LSD（5.1.2）：从右到左的"多趟稳定计数排序"

LSD 从字符串**最右侧字符**开始，对每个位置做一次键索引计数排序，直到最左。**由于计数排序是稳定的，后一趟排序不会打乱前一趟已经排好的相对顺序**——这是 LSD 正确性的关键。

**命题**：LSD 排序是稳定的，对长度为 W 的 N 个定长字符串，时间 O(W(N+R))，空间 O(N+R)。

**洞见 ②：LSD 是"以空间（辅助数组）和稳定性为代价，把 O(N log N) 压到 O(N)"的典范。**​ 它最适合**定长字符串**（如电话号码、身份证号、日期、IP 地址）——长度一致，从低位到高位逐趟即可。

### 1.3 高位优先 MSD（5.1.3）：从左到右的"递归多路划分"

MSD 从**最左侧字符**开始，用键索引计数法将字符串分到 R 个桶（每个桶对应一个字符），然后**对每个桶递归地在下一个字符位置上做 MSD**。

**关键性质**：

- **不一定检查所有输入**：一旦某个桶内的字符串首字符已能区分，就不再继续检查后续字符 ；
    
- **随机字符串**：平均检查字符数亚线性，**平均时间 O(N log_R N)**​ ；
    
- **最坏情况**：N 个完全相同的字符串需检查全部 W 个字符，时间 O(W(N+R))；
    
- **小数组陷阱**：MSD 对小的子数组极其缓慢（每次递归都要新建 count[R+1] 数组，当 R=256、N=2 时比直接复制慢约 100 倍；R=65536 时慢约 32000 倍）。
    

**工程改进**：对长度 ≤ M（通常 15）的小数组切换为**从位置 d 开始的插入排序**。

**洞见 ③：MSD 揭示了"递归 + 多路划分"的威力与代价——它能早期剪枝（不必检查所有字符），但递归开销在小数组时灾难性。**​ 这再次印证了前面章节反复出现的主题：**没有"最好"的算法，只有"匹配数据特征"的算法**。MSD 对"随机字符串"极佳，但对"大量长公共前缀"的字符串（如 URL、文件路径）表现糟糕——因为每个递归层级都要为每个字符创建 count 数组。

### 1.4 三向字符串快速排序（5.1.4）：MSD 与快排的"混血儿"

三向字符串快排：在位置 d 取一个字符作 pivot，将字符串分为**小于 / 等于 / 大于**​ pivot 的三组；对"等于"组在 d+1 位置递归，对"小于/大于"组在 d 位置递归。

**命题**：

- 平均 ~2N ln N 次字符比较（随机字符串）；
    
- **避免了长公共前缀的重复比较**——这是它相对 MSD 的关键优势 ；
    
- 原地排序（不需辅助数组），缓存友好；
    
- 不稳定的。
    

**洞见 ④（Bentley-Sedgewick 1997 年论文的核心结论）：三向字符串快排是"一般字符串排序的方法之选（method of choice）"。**​ 相较 MSD：

- MSD 缓存不友好、内存开销大（每层递归都新建 count[]）、在小数组时开销灾难性；
    
- 三向字符串快排缓存友好、原地、内循环短、且**对长公共前缀不敏感**。
    

**洞见 ⑤：三向字符串快排是"三向切分（第2章 Dijkstra 3-way 快排）+ 基数（按字符位置递归）"的完美融合。**​ 理解这一层，你看到的不再是"又一个排序算法"，而是"前面章节思想在字符串上的自然组合"——这正是 Sedgewick 写作此书的方法论：**高级算法 = 基础思想的新组合**。

### 1.5 字符串排序算法的选择（5.1.5）

|算法|稳定|原地|时间（保障/随机）|额外空间|适用场景|
|---|---|---|---|---|---|
|字符串插入排序|是|是|N~N² / —|1|小数组、基本有序|
|归并排序|是|否|N log N|N|稳定通用|
|三向字符串快排|否|是|1.39WN log R* / 1.39N log N|log N + W|**一般字符串的首选**​|
|LSD|是|否|2W(N+R)|N+R|较短的**定长**字符串|
|MSD|是|否|2W(N+R)* / N log_R N|N+DR|随机字符串|

* MSD 的"保障"时间是考虑最坏情况（所有字符串相同）

**洞见 ⑥（选型第一性原理）**：

- 字符串**定长**​ → **LSD**（稳定 + 线性）；
    
- 字符串**随机、长度不一**​ → **MSD**（亚线性检查字符数）；
    
- **含有较长公共前缀**的字符串 → **三向字符串快排**（避免重复比较）；
    
- **通用首选**​ → **三向字符串快排**。
    

**核心判据是"字符串的特征"而非"算法本身的优劣"——这正是字符串排序选型的第一性原理。**

## 二、5.2 单词查找树 —— 把"字符串"本身变成搜索路径

### 2.1 Trie（单词查找树）（5.2.1–5.2.2）

Trie 的每个结点代表一个字符，从根到某结点的路径构成一个前缀；在结点中标记"是否为某个键的结尾"，即可存储一组字符串。

**核心性质**：

- 查找/插入/删除：O(L)，L 为键长（**与键总数 N 无关**！）；
    
- 前缀匹配、前缀计数、按字典序遍历：极自然；
    
- 空间：每个键一个结点，但**所有键共享前缀的字符只存一次**。
    

**命题**：Trie 的查找/插入时间与键的总数无关，仅与键的长度成正比。

**洞见 ⑦：Trie 的深刻之处在于——它把"字符串集合"的空间结构显式地建模成一棵树。**​ 在 BST/红黑树中，键的比较结果决定走向；而在 Trie 中，**键的字符本身就是路径**——你不需要"比较"，你只需要"沿着字符走"。这是"数据结构映射问题结构"的极致体现。

**洞见 ⑧：Trie 是"空间换时间"的极致。**​ 当字符串集合的前缀重复度高（如路由表、自动补全词典、IP 前缀），Trie 的空间开销被共享前缀抵消，查询又达到 O(L)——此时它比任何基于比较的符号表都快。但当字符串几乎没有公共前缀时，Trie 退化为"每字符一个结点"的稀疏树，空间开销巨大——**这就是它的阿喀琉斯之踵**。

### 2.2 三向单词查找树 TST（5.2.3–5.2.4）

TST 是 Trie 与 BST 的混血：每个结点含一个字符、三个子链接（**小于 / 等于 / 大于**​ 当前字符），以及值字段。

- 沿"等于"链接继续匹配下一个字符；
    
- "小于/大于"链接构成 BST 结构，在该字符位置上二分查找。
    

**命题**：TST 的查找/插入平均为 O(L log R)（R 为字母表大小），最坏 O(L·R)；空间开销远小于 Trie。

**洞见 ⑨：TST 是"Trie 的空间浪费"与"BST 的时间开销"之间的优雅折中。**​ Trie 用 R 路分支换取 O(L) 查找但空间爆炸；BST 用 O(log R) 深度换取紧凑空间但要比较。TST 把二者融合——**字符匹配时走中间链接（等于），不匹配时在左右子树中 BST 式查找**。**这是"两种数据结构的杂交产生更好性质"的典范**，也是 Bentley-Sedgewick 对字符串符号表的标志性贡献。

### 2.3 字符串符号表的实现选择（5.2.5）

|实现|查找（平均）|额外空间|适用场景|
|---|---|---|---|
|红黑树 BST|c log N|N|通用、需有序性|
|散列表 Hash|1|N|快速、无需有序|
|Trie|L|R^N（最坏）|前缀密集、需前缀操作|
|TST|L log R|N|**一般字符串的首选**​|

**洞见 ⑩：对字符串键，TST 通常是"最佳实践"——它兼具 Trie 的 O(L) 特性与 BST 的空间效率，又天然支持前缀匹配。**​ 这也是为什么现代自动补全、拼写检查、IP 路由表大量采用 TST 或其变体（Radix Tree/Patricia Trie）。

## 三、5.3 子字符串查找 —— 从暴力到"预处理换线性"

### 3.1 暴力算法（5.3.2）

双重循环，文本指针 i、模式指针 j，失配时 i 回退到 i-j+1、j 归零。**最坏 O(N·M)**。

**洞见 ⑪：暴力算法的根本低效在于——文本指针 i 反复"回退"。**​ 每一次失配，之前匹配的信息全部丢弃。所有高效算法都在回答同一个问题：**"失配时，如何利用已匹配的信息，让 i 不回退（或尽量少回退）？"**

### 3.2 KMP 算法（5.3.3）：利用"已匹配前缀的最长真后缀"

KMP 预处理模式串，构建 **DFA 状态机**（或 next/failure 数组）：`dfa[j][c]` 表示"在状态 j 遇到字符 c 时转移到状态 dfa[j][c]"。匹配过程中文本指针 i **只进不退**。

**命题**：KMP 最坏时间 O(N+M)，且不需要文本回退。

**核心思想**：利用"已匹配的模式前缀 pat[0..j-1]"的**最长真后缀同时也是模式的前缀**这一性质，决定失配时模式应该滑到哪个位置——相当于把"暴力算法中 i 的回退"转化为"j 在 DFA 中的状态转移"。

**洞见 ⑫：KMP 的本质是用模式的"自相似结构"（前缀-后缀重合）指导跳跃。**​ 它强烈依赖模式自身的重复性——若模式几乎没有自相似（如随机字符），KMP 的 next 数组几乎全是 0，退化为接近暴力；若模式高度重复（如 "AAAAAB"），KMP 发挥巨大威力。**这告诉我们：KMP 不是" universally 最优"的，它是"为具有自相似性的模式量身定做"的。**

**洞见 ⑬：KMP 的 DFA 视角极其优美——它把"模式匹配"转化为"在自动机上跑文本"。**​ 这个视角直接通向 5.4 节的正则表达式 NFA：KMP 是"确定性有限自动机（DFA）"；正则匹配是"非确定有限自动机（NFA）"。**理解 KMP 的 DFA 本质，5.4 节的正则引擎就水到渠成。**

### 3.3 Boyer-Moore 算法（5.3.4）：从右往左 + 大幅跳跃

Boyer-Moore 反向思维——**从模式的末尾开始匹配**。预处理模式，构建 `right[]` 数组：记录每个字符在模式中最右出现的位置。

匹配时：

- 若文本字符 c 不在模式中 → 模式直接右移 M 位（整个模式滑过 c）；
    
- 若 c 在模式中 → 右移模式使模式中 c 的最右出现与文本 c 对齐；
    
- 若 c 与模式对应位置字符匹配 → 继续向左匹配。
    

**命题**：Boyer-Moore（仅用坏字符启发式）**平均约 N/M 次字符比较**，但最坏仍可能 O(N·M)；若加入类似 KMP 的规则防止重复模式，最坏可降至 ~3N 次比较 。

**洞见 ⑭：Boyer-Moore 的平均性能是"亚线性"的——它常常跳过多达 M 个字符。**​ 这是所有单模式匹配算法中平均最快的，也是 `grep` 等工具的默认选择。但**它的"平均极快"建立在"字母表较大、模式较长"的假设上**；对于小字母表（如二进制串）或短模式，跳跃幅度受限，性能下降。**这就是工程选型的关键：Boyer-Moore 适合"真实文本 + 较长模式"，KMP 适合"保证线性 + 模式自相似"。**

### 3.4 Rabin-Karp 指纹算法（5.3.5）：把字符串比较转化为"整数比较"

Rabin-Karp 用**模散列（滚动哈希）**：计算模式 pat[0..M-1] 的哈希值；对文本每个位置 i，计算 txt[i..i+M-1] 的哈希值；若相等再做逐一字符验证（防哈希冲突）。

**关键技巧——滚动哈希**：

```
hash(txt[i+1..i+M]) = (hash(txt[i..i+M-1]) * R - txt[i] * R^M + txt[i+M]) mod Q
```

每次只需常数时间计算下一个窗口的哈希值。

**命题**：

- **蒙特卡洛版本**：总是线性时间，但可能返回错误结果（哈希碰撞）；
    
- **拉斯维加斯版本**：总是正确，但最坏 O(N·M)（需逐一验证）；
    
- 实践上选大质数 Q ≈ M·N²，碰撞概率约 1/N 甚至 1/Q 。
    

**洞见 ⑮：Rabin-Karp 的独门绝技是"自然扩展到多模式匹配和二维模式"。**​ 因为它本质上是"哈希比较"，你可以：

- 同时查找 K 个模式：计算所有模式的哈希值，文本每个窗口的哈希值与这 K 个值比较（O(N+K) 而非 O(N·K)）；
    
- 二维模式匹配（如图像模板）：用二维滚动哈希。
    

**这正是"算法思想决定扩展能力"的范例——KMP/Boyer-Moore 是为单模式定制的；Rabin-Karp 的"哈希思维"让它能轻松扩展到单算法多模式。**

### 3.5 子字符串查找算法总结

|算法|预处理|最坏时间|平均/典型|关键优势|关键劣势|
|---|---|---|---|---|---|
|暴力|—|NM|NM|实现极简|文本指针回退|
|KMP|O(M)|O(N+M)|O(N+M)，i 不回退|**最坏线性、i 不回退**​|依赖模式自相似性、额外空间|
|Boyer-Moore|O(R+M)|O(NM)（仅坏字符）|**~N/M 次比较**​|**平均速度最快**​|小字母表/短模式时退化|
|Rabin-Karp|O(M)|O(NM)（拉斯维加斯）|O(N+M)（蒙特卡洛）|**多模式/二维扩展**​|算术运算较慢、最坏保证弱|

**洞见 ⑯（选型第一性原理）**：

- 需要**最坏保证线性**​ → KMP；
    
- 追求**平均速度最快**（真实文本、长模式） → Boyer-Moore（或 grep 使用的变种）；
    
- 需要**多模式 / 二维匹配**​ → Rabin-Karp；
    
- 短模式、小字母表、或"最坏情况可能出现" → KMP 或 Boyer-Moore 的完整版（加好后缀规则）。

## 四、5.4 正则表达式 —— 把模式编译成 NFA

### 4.1 正则与 NFA 的对应（5.4.4–5.4.6）

Sedgewick 的处理极其优美：**正则表达式可以编译为一个非确定有限状态自动机（NFA）**。基本构造规则：

- **字符 c**​ → 状态 i 到 i+1 的 ε-转换（匹配 c 后）；
    
- **连接 AB**​ → A 的接受状态 ε-连接到 B 的起始状态；
    
- **或 A|B**​ → 从新起始状态 ε 到 A、B 的起始状态，A、B 的接受状态 ε 到新接受状态；
    
- **闭包 A*** → 从新起始状态 ε 到 A 起始状态和新接受状态，A 的接受状态 ε 到 A 起始状态和新接受状态；
    
- **括号 (A)**​ → 仅改变优先级。
    

**洞见 ⑰：正则→NFA 的编译规则，本质是"语法的组合性"——每个正则操作符对应一段 NFA 片段，组合正则就是拼接 NFA 片段。**​ 这正是编译器前端"正则→NFA→DFA→词法分析器"的标准流程。理解这一点，你就明白了所有编程语言词法分析器的底层原理。

### 4.2 模拟 NFA 运行（5.4.5）

用两个栈（或结合 DFS）模拟 NFA：

1. 维护"当前可能所在的状态集合"；
    
2. 读入一个字符 → 先沿 ε-转换扩展状态集合，再沿匹配字符的转换移动到下一状态集合；
    
3. 若最终状态集合含接受状态 → 匹配成功。
    

**命题**：模拟 NFA 匹配文本的时间复杂度 O(N·M)（N 为文本长，M 为正则编译后的 NFA 状态数）。

**洞见 ⑱：KMP 是 DFA（确定性），正则是 NFA（非确定性）。**​ DFA 在每个状态读一个字符后**唯一确定**下一个状态；NFA 可能有多个下一个状态（ε-转换），需要"同时追踪所有可能"。**从 KMP 到正则 NFA，你看到的是"确定 vs 不确定"这一计算理论核心概念的算法实现**——而这正是 5.3 与 5.4 两节的内在联系。

**洞见 ⑲：正则匹配的本质是"图搜索"——NFA 就是一个有向图，状态是顶点，转换是边，匹配是"从起始状态到接受状态是否存在一条路径，其上的字符标签拼接等于文本"。**​ 这直接呼应了第4章的图算法——**你学到的图遍历（DFS/BFS），在这里以 NFA 模拟的形式再次出现**。

## 五、5.5 数据压缩 —— 把"冗余"编码为"短位流"

### 5.1 游戏规则与二进制 I/O（5.5.1–5.5.3）

压缩的本质：**利用数据中字符出现的频率差异和重复模式，用较短的位编码高频/重复内容，用较长位编码低频内容，使总体位数小于原始表示**。

**局限**：并非所有数据都可压缩——随机数据的信息熵已经达到上限，无法进一步压缩（这由香农信息论保证）。

### 5.2 游程编码 RLE（5.5.5）：最直观的压缩

RLE 适用于"连续重复字符多"的数据（如基因组序列、简单图像、传真）。**做法**：不存"AAAABBB"而存"4A3B"。

**命题**：RLE 对"游程长"的数据压缩比高；对随机数据可能反而膨胀（需额外存储计数值）。

**洞见 ⑳：RLE 是"利用重复模式"的最朴素形式——它只捕捉"空间局部性"（相邻重复）。**​ 这是所有压缩算法的起点思想：**冗余 = 可预测性 = 可压缩性**。

### 5.3 霍夫曼压缩（5.5.6）：用"变长编码"匹配频率

霍夫曼编码的核心：

1. **统计频率**：扫描输入，统计每个字符的出现次数；
    
2. **建霍夫曼树**：把每个字符看作一个叶子结点（权值=频率），每次取权值最小的两个结点合并为新结点，新结点权值为两者之和，重复直到只剩一个根；
    
3. **生成编码**：从根到叶子的路径，左走记 0、右走记 1，得到每个字符的变长编码；
    
4. **编码输出**：用生成的编码替换原文每个字符。
    

**命题**：霍夫曼编码是**最优前缀码**——在"每个字符独立编码"的模型下，没有任何前缀码的平均码长比霍夫曼码更短。

**洞见 ㉑：霍夫曼编码是"贪心算法"的又一经典应用——每次合并最小的两个结点，局部最优（让低频字符尽早获得更长编码）导致全局最优（总体码长最短）。**​ 这与第4章 MST 的 Kruskal 算法（每次选最小权边）共享同一贪心哲学。

**洞见 ㉒（霍夫曼与 BST 的深刻对称）**：霍夫曼树与第3章的最优 BST 是"对偶"的——

- 最优 BST：已知每个键被查找的概率，建一棵 BST 使**期望查找代价**最小（内部路径长度加权）；
    
- 霍夫曼树：已知每个字符的出现频率，建一棵树使**期望编码长度**最小（外部路径长度加权）。
    

**二者都是"用贪心合并最小权值结点"——区别仅在于一个用于"查找"、一个用于"编码"。**​ 理解这一对称，你就掌握了"最优二叉树"这一算法族的精髓。

**洞见 ㉓：霍夫曼编码是"信息论与算法"的交汇点**​ 香农信息论告诉我们：字符 c 的理论最优编码长度是 -log₂(p(c)) 位（p(c) 是其出现概率）；霍夫曼码的平均长度 ≤ H + 1（H 为信息熵）。**这意味着：压缩的极限由数据的信息熵决定，霍夫曼编码以"最多 1 位"的差距逼近这个极限**​ 这是"理论下界"与"实际算法"完美对接的范例。

## 六、全章脉络图（章节间的"第一性原理"联系）

```
5.1 字符串排序
   │  键索引计数法(非比较排序原型, 稳定 O(N+R))
   │  → LSD: 定长字符串, 稳定线性
   │  → MSD: 递归多路划分, 随机字符串亚线性, 但小数组灾难
   │  → 三向字符串快排: MSD + 三向切分, 缓存友好/原地/长前缀友好
   │  核心: 利用字符分布突破比较排序 O(N log N) 下界
   ▼
5.2 单词查找树 (Trie / TST)
   │  Trie: 字符即路径, O(L) 查找但与 N 无关, 空间换时间
   │  TST: Trie × BST 的混血, 兼顾时间与空间 → 字符串符号表首选
   │  核心: 把"字符串的字符序列"本身结构化为搜索路径
   ▼
5.3 子字符串查找
   │  暴力: 文本指针回退, O(NM)
   │  KMP: DFA + 利用模式自相似性, 线性且 i 不回退
   │  Boyer-Moore: 从右往左 + 坏字符规则, 平均 ~N/M (亚线性)
   │  Rabin-Karp: 滚动哈希, 线性期望, 易扩展多模式/二维
   │  核心: 预处理模式 → 失配时不回退/大幅跳跃
   ▼
5.4 正则表达式
   │  正则 → NFA 编译 (语法的组合性)
   │  NFA 模拟 = 图搜索 (呼应第4章 DFS/BFS)
   │  KMP(DFA) vs 正则(NFA): "确定性 vs 非确定性"的计算理论体现
   ▼
5.5 数据压缩
      • 游程编码 RLE: 利用空间局部性(重复模式)
      • 霍夫曼编码: 贪心建最优前缀码, 平均码长 ≤ 信息熵+1
      • 与最优 BST 对偶: 一个用于查找, 一个用于编码
      • 核心: 冗余 = 可预测性 = 可压缩性
```

**一条贯穿全章的暗线——"字符串的特殊性"**：

- 5.1 排序：字符串的字符可**直接作为计数索引**​ → 非比较排序突破下界；
    
- 5.2 查找树：字符串的字符序列可**自身构成搜索路径**​ → Trie/TST；
    
- 5.3 子串匹配：模式的**内部结构（自相似性/字符分布）可被预处理利用**​ → KMP/Boyer-Moore/Rabin-Karp；
    
- 5.4 正则：正则的**语法结构可编译为状态机**​ → NFA；
    
- 5.5 压缩：字符的**频率差异与重复模式可被变长编码利用**​ → 霍夫曼/RLE。
    

**一句话总结全章**：第5章是一部 **"利用字符串内部结构"的算法全景**——排序利用字符分布突破比较下界（LSD/MSD/三向字符串快排）；查找把字符串自身结构化为搜索路径（Trie/TST）；子串匹配通过预处理模式实现线性/亚线性（KMP/Boyer-Moore/Rabin-Karp）；正则编译为 NFA 用图搜索模拟；压缩用变长编码逼近信息熵（霍夫曼）。贯穿始终的第一性原理是：**字符串不是原子键，它的字符序列本身就是可利用的结构——谁能更好地利用这种结构，谁就能突破"把字符串当作黑盒"的算法性能上限。**
