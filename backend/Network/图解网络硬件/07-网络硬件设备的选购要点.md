## 07.01 选择产品的类别

这一节是选购的"第一问"——**我的网络里到底需要哪些类别的设备？**

```
网络产品类别全景

  边界层:
    路由器 ──── 连接 ISP, 做 NAT/出口路由
    防火墙 ──── 安全边界, 状态检测+VPN+NAT
    
  核心/汇聚层:
    L3 交换机 ── VLAN 间高速路由
    
  接入层:
    L2 交换机 ── 终端接入
    PoE 交换机 ─ L2 + 给 AP/摄像头供电
    
  无线:
    无线 AP ──── 把有线变无线
    无线控制器 ─ 管理多台 AP (大型企业)
    
  其他:
    负载均衡器、带宽控制器、代理服务器等
```

> 💡 **选型的第一性原则**：先把网络拓扑画出来，标出每一层需要什么功能的设备，再决定类别。**小型网络可能一台"All-in-One"路由器就够；中大型网络才需要分层组网**。

**与前六章的映射**：

|网络层次|需要的设备类别|对应章节|
|---|---|---|
|边界|路由器 + 防火墙|第3章 + 第5章|
|核心/汇聚|L3 交换机|第4章|
|接入|L2/PoE 交换机|第2章|
|无线覆盖|无线 AP/控制器|第6章|

## 07.02 基于功能需求汇总备选设备型号

这一节讲**如何从"类别"细化到"具体型号"**——把功能需求逐项列出来，再去厂商产品手册里找匹配的型号。

**功能需求清单（选型核对表）**：

```
功能维度检查:
  ├─ 网络接口
  │   ├─ 接口数量 (WAN/LAN 口够不够?)
  │   ├─ 接口类型 (RJ45 10/100/1000BASE-T? SFP 光口?)
  │   ├─ 接口速率 (千兆? 万兆? 40G? 100G?)
  │   └─ 逻辑接口 (VLAN 子接口数量? 汇聚接口带宽?)
  │
  ├─ 性能表现
  │   ├─ 吞吐率 (bit/s + pps)
  │   ├─ 硬件加速范围 (ASIC 处理什么? CPU 处理什么?)
  │   └─ 多任务负载 (同时开多个功能时 CPU/内存够不够?)
  │
  ├─ 软件功能
  │   ├─ 协议支持 (TCP/IP, UDP, OSPF, BGP, IPv6...)
  │   ├─ 独立功能 (NAT, ACL, QoS, VPN, DPI...)
  │   ├─ 管理功能 (CLI, Web, SNMP, Syslog...)
  │   └─ 报告功能 (流量统计, 审计日志...)
  │
  └─ 迁移便捷性
      └─ 替换旧设备时, 同厂商同 OS 更易迁移
```

> 📌 **这一节是"需求工程"**：把业务需求翻译成设备规格要求。前面六章学的每一个技术概念（VLAN、OSPF、NAT、状态检测、PoE...），在这里都变成了一张核对表上的勾选项。

## 07.03 网络硬件的采购流程

这一节讲**企业采购的标准流程**——RFI → RFP → RFQ。

```
采购流程三阶段（07.03）

  RFI (Request for Information) 07.03.01
       │  "信息征询"——广泛了解市场上有什么产品
       │  非正式, 用于摸底
       ▼
  RFP (Request for Proposal) 07.03.01
       │  "方案征求"——向厂商要具体方案
       │  包含: 需求规格书 + 技术要求 + 商务要求
       │  厂商回应: 推荐型号 + 拓扑设计 + 报价草拟
       ▼
  RFQ (Request for Quotation) 07.03.02
           "报价征求"——向入围厂商要正式报价
           包含: 确切型号 + 数量 + 单价 + 总价
           厂商回应: 正式报价单 + 交货期 + 保修条款
```

> 💡 **RFI/RFP/RFQ 的区别**：RFI 是"我想了解"，RFP 是"请给我方案"，RFQ 是"请给我价格"。三步递进，从广到窄，从模糊到精确。

## 07.04 根据性能选择产品的型号 ← 本章技术核心

这一节是**性能选型的硬核部分**，分六个维度展开 ：

### 07.04.01 收集同网络延迟相关的信息

```
网络延迟的组成:

  总延迟 = 处理延迟 + 队列延迟 + 串行延迟 + 传播延迟
           ───────   ───────   ───────   ───────
           设备转发    拥塞排队   数据串行   物理传输
           (μs级)     (ms级)    (μs级)    (ms级, 与距离相关)

  实时业务(语音/视频)对延迟敏感:
    端到端延迟 < 150 ms (ITU-T G.114 建议)
    抖动 < 30 ms
    丢包率 < 1%
```

> 📌 **选型含义**：语音/视频网络必须选**低延迟设备**（交换机 < 5 μs，路由器 < 100 μs，防火墙 < 200 μs）。

### 07.04.02 网络设备产品性能的测量方法

**线速转发的关键指标**：

```
包转发率 (pps) 计算:
  千兆以太网线速 = 1.488 Mpps (64 字节小包)
  公式: 端口速率 ÷ (最小帧长 + 帧间隙 + 前导码)
       = 1 Gbps ÷ (672 bit) = 1.488 Mpps

  选型硬指标:
  - 千兆交换机必须 ≥ 1.488 Mpps (64 字节小包线速)
  - 全双工线速: 端口数 × 端口速率 × 2
  - 设备的背板带宽必须 ≥ 上述值, 否则全端口同跑会拥塞
```

> ⚠️ **"小包性能"是关键陷阱**：很多厂商标称"线速"是指大包（1518 字节）；但 64 字节小包才是压力测试。VoIP、游戏、交易网络对小包性能极其敏感。

### 07.04.03 交换机性能的考量方法

```
交换机性能考量:
  ├─ 吞吐量 (bit/s): 端口数 × 端口速率 × 2 (全双工)
  ├─ 包转发率 (pps): 千兆≥1.488Mpps, 万兆≥14.88Mpps
  ├─ 背板带宽: ≥ 全端口线速总和
  ├─ MAC 表容量: 8K 起步, 企业级 32K~256K
  ├─ 缓冲容量: 大缓冲抗突发, 小缓冲低延迟
  └─ 功能开启后的性能衰减: ACL/QoS/镜像 开启后是否仍线速?
```

**三层组网的性能规划**：

```
接入层: 千兆下行, 2×1G 或 2×10G 上行
          → 48 口千兆 PoE 交换机
  汇聚层: 万兆下行, 2×40G 上行
          → 12×10G + 2×40G 汇聚交换机
  核心层: 40G/100G, 冗余链路
          → 模块化机框式核心交换机
```

### 07.04.04 路由器性能的考量方法

```
路由器性能考量:
  ├─ 吞吐量 (bit/s + pps): 关注小包性能
  ├─ 路由表容量: 数万~数百万条 (企业~运营商)
  ├─ 转发延迟: < 100 μs
  ├─ 功能性能衰减: NAT/VPN/QoS 全开后的实测算力
  └─ 接口类型和密度: WAN 口支持什么链路? GPON? LTE? MPLS?
```

### 07.04.05 防火墙性能的考量方法

```
防火墙性能三要素 (呼应第5章 05.08):
  ├─ 并发会话数: 10 万级起步, 企业级百万~千万级
  ├─ 每秒新建会话数 (CPS): DoS 抗压能力的关键
  └─ NAT 表容量: 决定并发转换能力

  ⚠️ 全功能性能衰减:
     仅包过滤: 10 Gbps
     开启 DPI: 可能降到 5 Gbps
     开启 IPS: 可能降到 3 Gbps
     开启 VPN: 可能降到 2 Gbps
     
  选型铁律: VPN 吞吐最好 ≥ 实际带宽的 1.5 倍
          防止开启加密后掉速
```

### 07.04.06 无线 LAN 性能的考量方法

```
无线 LAN 性能考量 (呼应第6章):
  ├─ 无线标准: Wi-Fi 6 (802.11ax) 起步, Wi-Fi 6E/7 前瞻
  ├─ MU-MIMO: 多用户多入多出, 提升并发
  ├─ OFDMA: 正交频分多址, 降低小包延迟
  ├─ 单 AP 并发终端数: 20~50 台 (办公), 50~100 台 (高密度)
  ├─ 覆盖范围: 与发射功率、天线、环境遮挡相关
  └─ 漫游性能: 跨 AP 切换时延 < 50 ms (语音不掉线)
```

## 07.05 根据物理需求选择产品

这一节把视角拉回物理层——**设备能不能放进你的机房？**

### 07.05.01 交换机的选择

```
交换机物理选型:
  ├─ 外形: 桌面式 / 机架式 (19") / 机框式
  ├─ 高度: 1U / 2U / 4U... (1U = 4.45 cm)
  ├─ 端口密度: 24 口 / 48 口 / 96 口
  ├─ 电源: 单电源 / 双电源冗余
  ├─ PoE 预算: 总供电功率 (W) 要覆盖所有 AP/摄像头
  └─ 散热: 前置后出风 / 左右风道 (与机房空调匹配)
```

### 07.05.02 路由器的选择

```
路由器物理选型:
  ├─ 外形: 盒式 / 机框式
  ├─ 接口模块: 模块化插槽数, 支持什么 WAN 接口?
  ├─ 电源冗余: 双电源 1+1
  └─ 性能档位: 与出口带宽匹配 (不要小马拉大车)
```

### 07.05.03 防火墙产品的选择

```
防火墙物理选型:
  ├─ 吞吐量档位: 与出口带宽匹配
  ├─ 接口: 电口/光口配比, 是否够用?
  ├─ 电源冗余: 双电源 1+1
  ├─ 热插拔: 风扇/电源/线卡能否在线更换
  └─ 加密加速: 是否有专用加密芯片 (影响 VPN 吞吐)
```

> 📌 **物理选型的核心教训**：**端口预留 20%~30% 冗余**。50 台 PC 别买 48 口交换机，买 48 口也要预留上行和扩展。

## 07.06 确认网络设备的互操作性

```
互操作性验证:

  为什么重要?
  - 多厂商混合组网时, 协议实现可能有差异
  - 标准遵循度不同, 可能导致互通问题

  验证要点:
  ├─ 标准协议一致性: STP/RSTP/MSTP, OSPF, BGP, 802.1Q...
  ├─ 厂商私有协议兼容性: EIGRP, CDP, VTP (Cisco 私有)
  ├─ 管理协议: SNMP v2/v3, Syslog, NETCONF
  ├─ 时间同步: NTP
  └─ 认证互通: 802.1X, RADIUS

  ✅ 最佳实践: 核心层统一厂商, 接入层可多厂商
             关键协议用标准协议, 避免绑定私有协议
```

> 💡 **互操作性 = 避免厂商锁定**：接入层用便宜的国产交换机，核心层用 Cisco/华为/Juniper，中间靠标准协议互通——这是企业网常见的"分层多厂商"策略。

## 07.07 高可用性的考量方法

```
高可用性设计:

  设备级冗余:
  ├─ 电源: 1+1 或 N+N 冗余
  ├─ 风扇: N+1 可热插拔
  ├─ 主控板: 1:1 备份 (机框式设备)
  ├─ 交换矩阵: 双交换网板
  └─ 线卡: 关键链路跨线卡分布

  链路级冗余:
  ├─ LACP 链路聚合 (交换机间)
  ├─ STP/RSTP/MSTP (防环路)
  └─ 多路径路由 (ECMP)

  协议级冗余:
  ├─ VRRP/HSRP (网关冗余)
  ├─ 路由协议快速收敛 (OSPF/BGP)
  └─ 防火墙集群 (Active-Standby / Active-Active)

  架构级冗余:
  ├─ 双机热备
  ├─ 多出口 (多 ISP)
  └─ 异地灾备
```

> 📌 **可用性指标**：99.9% (年停机 8.76 小时) / 99.99% (52.6 分钟) / 99.999% (5.26 分钟)。每多一个 9，成本和复杂度指数级上升。

## 07.08 价格相关的考量方法

这一节讲**总拥有成本 (TCO)**，分四个维度 ：

```
价格考量四维度（07.08）

  ① 端口单价 (07.08.01)
       │  每台设备的价格 ÷ 端口数
       │  横向对比同档次设备的端口成本
       ▼
  ② 比特单价 (07.08.02)
       │  设备价格 ÷ 总吞吐量
       │  对比"每 Gbps 多少钱"
       │  高性能设备的比特单价通常更低
       ▼
  ③ 学习成本 (07.08.03)
       │  工程师掌握该设备的学习时间
       │  稀有操作系统 = 高学习成本
       │  主流厂商 (Cisco/Huawei) = 人才市场充裕
       ▼
  ④ 支持的费用 (07.08.04)
          厂商技术支持费用
          保修延期费用
          现场服务费用
          软件授权费用 (防火墙的安全功能授权等)
```

> 💡 **TCO 视角**：采购价只是冰山一角。5 年 TCO = 采购价 + 授权费 + 支持费 + 能耗费 + 运维人力成本。有时候"贵的设备"反而 TCO 更低（可靠性高、运维省力）。

## 07.09 达到采购条件

这一节讲**采购合规**​ ：

```
采购合规三要素（07.09）

  ① 绿色采购 (07.09.01)
       │  能耗标准, 环保要求
       │  低功耗设备 = 长期电费节省
       ▼
  ② 符合 RoHS 要求 (07.09.02)
       │  限制有害物质指令 (铅/汞/镉等)
       │  欧盟强制, 全球通行
       ▼
  ③ 加密出口管理相关 (07.09.03)
          强加密功能可能涉及出口管制
          跨国企业采购需合规审查
```

> 📌 政府、金融、运营商行业采购，合规是**一票否决项**——不满足 RoHS 或加密出口管制的设备，再好也不能买。

## 07.10 售后支持相关的基础知识

这一节是选购的"最后一公里" ：

```
售后支持考量（07.10）

  维护方式 (07.10.01)
       ├─ 现场维护: 厂商工程师上门
       └─ 返厂维修: 设备寄回原厂
  
  厂商保修 (07.10.02)
       ├─ 标准保修: 通常 1 年
       ├─ 延保: 3 年 / 5 年
       ├─ SLA 响应时间: 4 小时响应 / 24 小时上门
       ├─ 备件供应: 本地是否有备件库?
       └─ 软件支持: 免费升级? 安全补丁?
```

> ⚠️ **售后是隐形的"第二次采购"**：设备坏了没人修，再便宜也是浪费。核心设备务必买延保+SLA 现场服务。

             这条决策链逐级筛选, 找到最优解

**读这一章的六条连结意识**（写进笔记的价值点）：

1. **与前六章的"知识映射"**：前三章的每一个技术概念（VLAN、OSPF、NAT、状态检测、PoE、Wi-Fi 6...）在第7章都变成了选型核对表上的勾选项。**前六章是"懂"，第7章是"用"**。
2. **性能选型的"全功能视角"**：厂商标的"线速"往往是理想值。开启 DPI/IPS/VPN/ACL/QoS 后性能会衰减 30%~70%。**必须看"全功能模式下的性能"**——这是 07.04 反复强调的选型铁律。
3. **"小包性能"是试金石**：64 字节小包线速转发能力，是区分"真线速"和"假线速"的关键。千兆交换机 ≥ 1.488 Mpps 是硬指标。
4. **TCO 而非采购价**：07.08 的四个维度（端口单价/比特单价/学习成本/支持费用）揭示了**总拥有成本**思维。便宜的设备可能因为高功耗、高学习成本、昂贵支持费而变得不便宜。
5. **高可用是架构问题**：07.07 的高可用性不仅是"买两台"，更是设备级+链路级+协议级+架构级的立体冗余。VRRP、LACP、STP、双电源、双上行——这些前面章节学的协议，在高可用设计里全部派上用场。
6. **合规与售后是"一票否决项"**：07.09 的 RoHS/绿色采购、07.10 的 SLA/保修，对政府/金融行业是硬门槛。**技术再好，不合规范，不能买**。
