## 06.01 无线 LAN 简介

这一节是"开场白"——把无线 LAN 的定位讲清楚。

**无线 LAN 的本质**：

```
无线 LAN (WLAN) = 用无线电波替代网线,
                 在有限区域内让设备无线连接和通信的网络
```

**为什么需要无线 LAN**：

```
有线 LAN 的局限                    无线 LAN 的优势
──────────────────                ──────────────────
  终端被网线拴住                    终端自由移动
  布线工程成本高                    部署快捷、成本低
  物理端口数量受限                  多设备并发接入
  历史建筑/古建筑难布线              突破物理束缚
```

> 📌 **关键认知**：无线 LAN 不是要"取代"有线网络，而是**在终端到接入交换机这一段用无线电波替代网线**。AP 收到无线信号后，还是要转换成有线以太网帧，通过网线回传到交换机 。换句话说，无线 LAN 是有线 LAN 的"无线延伸"。

## 06.02 理解无线 LAN 所需的基础知识 ← 本章技术核心

### 06.02.01 CSMA/CA — 无线 LAN 的"交通规则"

这是理解无线 LAN 最关键的一节。**有线以太网用的是 CSMA/CD（冲突检测），无线 LAN 用的是 CSMA/CA（冲突避免）**——为什么不一样？

```
有线以太网: CSMA/CD (冲突检测)
  站点 A ──── 同轴电缆/双绞线 ──── 站点 B
       │
       │ ① 听信道: 空闲? → 发送
       │ ② 发送的同时持续监听
       │ ③ 检测到冲突? → 立即停止 + 发阻塞信号 + 随机退避
       │
       ▼
  为什么能 CD? 因为有线介质上"边发边听"能听到冲突

无线 LAN: CSMA/CA (冲突避免)
  站点 A )))))) 空气 )))))) 站点 B
       │
       │ ① 听信道: 空闲? → 等一个 IFS 帧间隔
       │ ② 随机退避一段时间
       │ ③ 再听: 还空闲? → 发送
       │ ④ 发送完成后等待 ACK
       │ ⑤ 没收到 ACK? → 认为冲突/丢失 → 重传
       ▼
  为什么必须 CA? 因为无线介质上"边发边听"做不到:
       - 发送方自己的信号太强, 掩盖了冲突
       - 隐藏节点问题: A 和 C 都能听到 AP, 但互相听不到对方
```

**CSMA/CA 的核心思想**：

```
Carrier Sense (载波监听): 发送前先听信道忙不忙
  Multiple Access (多路访问): 多个站点共享同一无线信道
  Collision Avoidance (冲突避免): 通过"随机退避 + ACK 确认"尽量避免冲突
```

> 💡 **隐藏节点问题**（Hidden Node Problem）是无线 LAN 特有的：
> 
> ```
> A )))     ))) C
>        \      /
>         \    /
>          AP
>     A 和 C 都能与 AP 通信, 但 A 听不到 C, C 也听不到 A
>     如果 A 和 C 同时向 AP 发送 → AP 处冲突 → 但 A/C 各自不知道
>     解决方案: RTS/CTS 机制 (Request To Send / Clear To Send)
> ```

### 06.02.02 无线 LAN 的架构

这一节讲无线 LAN 的组件模型：

```
无线 LAN 基本架构

  ┌─────────────────────────────────────────────────────────┐
  │                                                         │
  │   站点 STA (Station)                                    │
  │   ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐          │
  │   │ 笔记本 │ │ 手机   │ │ 平板   │ │ IoT    │          │
  │   └────────┘ └────────┘ └────────┘ └────────┘          │
  │        │            │            │            │         │
  │        │  )))))) 无线电波 ))))))))))))))))))))))))         │
  │        │            │            │            │         │
  │        ▼            ▼            ▼            ▼         │
  │   ┌──────────────────────────────────────────────┐     │
  │   │           接入点 AP (Access Point)            │     │
  │   │   无线 ↔ 有线的桥梁                           │     │
  │   │   把 802.11 帧 ⇄ 以太网帧                     │     │
  │   └───────────────────┬──────────────────────────┘     │
  │                       │ 以太网线                         │
  │                       ▼                                 │
  │   ┌──────────────────────────────────────────────┐     │
  │   │            PoE 交换机 (接入层)                  │     │
  │   │   给 AP 供电 + 把数据回传到核心                │     │
  │   └───────────────────┬──────────────────────────┘     │
  │                       │                                 │
  │                       ▼                                 │
  │              核心交换机 / 路由器 / 防火墙                │
  │                                                         │
  └─────────────────────────────────────────────────────────┘
```

**关键概念**：

|术语|含义|
|---|---|
|**STA**​ (Station)|无线客户端设备（笔记本/手机/平板/IoT）|
|**AP**​ (Access Point)|接入点，无线与有线网络的桥梁|
|**BSS**​ (Basic Service Set)|一个 AP 覆盖的基本服务集，最小工作单元|
|**BSSID**​|AP 的 MAC 地址，唯一标识一个 BSS|
|**ESS**​ (Extended Service Set)|多个 BSS 通过分布式系统互联，提供大范围覆盖|
|**SSID**​|无线网络名称，用户看到的"Wi-Fi 名"|
|**ESSID**​|扩展服务集标识符，通常说的 SSID 即指 ESSID|

**BSS vs ESS 的关系**：

```
BSS (一个 AP 的覆盖)
  ┌────────────────────┐
  │     AP-1           │
  │   )))) ))) )))     │
  │      STA A             
  │      STA B             
  └────────────────────┘
              │
              │ 分布式系统 (DS, 通常指太网有线骨干)
              ▼
  ┌────────────────────┐
  │     AP-2           │
  │   )))) ))) )))     │
  │      STA C             
  │      STA D             
  └────────────────────┘
  ───────────────────────────────────────────
  多个 BSS + 同一个 SSID = ESS (扩展服务集)
  终端在 AP-1 和 AP-2 之间移动 = 漫游 (Roaming)
```

### 06.02.03 无线 LAN 的拓扑结构

```
两种基本拓扑：

  ① 基础设施模式 (Infrastructure Mode) ← 主流
     STA ──无线──► AP ──有线──► 网络
     - AP 集中控制通信
     - 支持认证、关联、帧转发
     - 支持漫游
     - 家庭/办公室/校园/公共场所都用这种

  ② 自组织模式 (Ad-hoc Mode)
     STA ──无线──► STA ──无线──► STA
     - 设备之间直接通信, 无 AP
     - 对等网络 (Peer-to-Peer)
     - 适合临时/应急/小规模网络
     - 不支持接入有线网络
```

> 📌 企业网络 99% 用基础设施模式。Ad-hoc 模式多见于临时组网或特定 IoT 场景。

## 06.03 各种各样的无线 LAN 标准 ← 速率演进史

这一节按时间线把 802.11 家族标准捋一遍。**核心规律：频段从 2.4GHz → 5GHz → 6GHz 扩展，调制从 DSSS → OFDM → 256-QAM → 4096-QAM 演进，天线从 SISO → MIMO → MU-MIMO → Beamforming**。

```
IEEE 802.11 标准演进（06.03.01–06.03.07 + Wi-Fi 命名）

  年份    标准            频段         最大速率    关键技术         Wi-Fi 品牌
  ──────────────────────────────────────────────────────────────────────────
  1997    802.11        2.4 GHz       2 Mbps      DSSS/FHSS       Wi-Fi 0
  1999    802.11b       2.4 GHz       11 Mbps     CCK             Wi-Fi 1
  1999    802.11a       5 GHz         54 Mbps     OFDM            Wi-Fi 2
  2003    802.11g       2.4 GHz       54 Mbps     OFDM/DSSS       Wi-Fi 3
  2009    802.11n       2.4/5 GHz     600 Mbps    MIMO, 40MHz     Wi-Fi 4
  2014    802.11ac      5 GHz         6.9 Gbps    MU-MIMO, 80/160MHz  Wi-Fi 5
  2019    802.11ax      2.4/5 GHz     9.6 Gbps    OFDMA, BSS着色   Wi-Fi 6
  (2021)  802.11ax-6E   6 GHz        9.6 Gbps    6 GHz 频段扩展   Wi-Fi 6E
  2024    802.11be      2.4/5/6 GHz   46 Gbps     MLO, 320MHz     Wi-Fi 7
       │
       │ 06.03.07 IEEE 802.11ad
       │   60 GHz 毫米波, 最高 7 Gbps, 极短距离(房间内)
       │   主打"无线替代 HDMI/USB"的短距超高吞吐场景
       ▼
  06.03.08 Wi-Fi
       Wi-Fi 是 Wi-Fi Alliance 对 IEEE 802.11 标准的认证品牌
       有了 Wi-Fi 认证, 不同厂商设备才能互通
```

**2.4GHz vs 5GHz vs 6GHz 频段对比**：

```
频段        2.4 GHz              5 GHz              6 GHz
  ──────────────────────────────────────────────────────────
  覆盖范围    远(绕射好)           中(绕射差)          近(直线传播)
  穿墙能力    强                   弱                  更弱
  干扰情况    拥挤(蓝牙/微波炉/        较干净            最干净
             ZigBee/邻居Wi-Fi)
  信道数量    3 个非重叠信道        24+ 个非重叠信道   更多信道
  适用场景    覆盖优先             速度优先            高密度/低延迟
```

> 💡 **工程经验**：2.4GHz 用于"覆盖补盲"（走廊、角落），5GHz 用于"高吞吐主用"（办公区、会议室），6GHz 用于"Wi-Fi 6E/7 高密度场景"。现代 AP 都是双频或三频并发。

## 06.04 无线 LAN 搭载的各种功能 ← 本章工程核心

### 06.04.01 关联 (Association)

```
终端接入无线网络的完整流程：

  STA                        AP
   │                          │
   │── ① 被动/主动扫描 ──────►│  (STA 发现 AP 的 SSID)
   │◄── ② Beacon/Probe Response─│
   │                          │
   │── ③ Authentication ─────►│  (开放系统/共享密钥认证)
   │◄── ④ Auth Response ─────│
   │                          │
   │── ⑤ Association Request ►│  (STA 请求关联到 AP)
   │◄── ⑥ Assocoation Response│  (AP 分配 AID, 关联建立)
   │                          │
   │── ⑦ 802.1X/EAP 认证 ────►│  (可选, 企业网络)
   │◄── ⑧ 认证成功 ──────────│
   │                          │
   │── ⑨ DHCP Discover ─────►│  (获取 IP 地址)
   │◄── ⑩ DHCP Offer ────────│
   │                          │
   ▼                          
  关联完成, 数据通信开始
```

### 06.04.02 接入点的接入控制

```
接入控制方式：

  MAC 地址过滤
      白名单: 只有列表中的 MAC 才能关联
      黑名单: 列表中的 MAC 被拒绝
      局限: MAC 可伪造, 安全性较弱

  SSID 隐藏
      不广播 SSID, 终端必须手动输入
      局限: 可被 sniffer 抓包破解, 仅"安全通过 obscurity"

  VLAN 分配
      不同 SSID → 不同 VLAN
      员工 SSID → 员工 VLAN → 内网
      访客 SSID → 访客 VLAN → 仅互联网
```

### 06.04.03 接入点的认证

```
认证机制演进：

  WEP (已淘汰)
      静态密钥, RC4 加密, 易被破解
      
  WPA (过渡)
      动态密钥, TKIP 加密, 仍不够安全
      
  WPA2 (当前主流)
      AES-CCMP 加密, 802.1X 认证
      个人模式 (WPA2-PSK): 预共享密钥, 家庭/小办公室
      企业模式 (WPA2-Enterprise): 802.1X + RADIUS, 大企业
      
  WPA3 (新一代)
      SAE (Simultaneous Authentication of Equals) 替代 PSK
      防暴力破解, 前向保密
      192-bit 加密套件 (WPA3-Enterprise)
```

### 06.04.04 无线 LAN 通信的加密

```
加密协议对比：

  WEP       RC4, 40/104-bit    ← 已破解, 禁用
  TKIP      RC4, 128-bit      ← WPA 用, 已不安全
  CCMP      AES, 128-bit      ← WPA2 用, 安全
  GCMP      AES, 256-bit      ← WPA3 用, 更强
```

> 📌 **企业无线安全最佳实践**：WPA2/3-Enterprise + 802.1X + RADIUS 服务器 + PEAP/EAP-TLS 认证 。每个员工用个人域账号登录无线，既安全又便于审计。

### 06.04.05 自治型接入点 (Autonomous AP / Fat AP)

```
自治型 AP (Fat AP):
  ┌─────────────────────────┐
  │  AP 独立完成所有功能      │
  │  - 射频管理               │
  │  - 认证/加密              │
  │  - VLAN 划分              │
  │  - 客户端管理             │
  └─────────────────────────┘
  
  优点: 独立工作, 不依赖外部控制器
  缺点: 每台 AP 单独配置, 规模大了运维灾难
  适用: 家庭/SOHO/小办公室 (几台 AP 以内)
```

### 06.04.06 集中管理型接入点 (Centralized AP / Fit AP) ← 企业主流

```
集中管理架构 (AC + Fit AP):

  ┌──────────────────────────────────────────────┐
  │               无线控制器 AC                    │
  │  (Access Controller)                          │
  │  ┌────────────────────────────────────────┐  │
  │  │ 集中管理所有 AP:                        │  │
  │  │ - 配置下发                               │  │
  │  │ - 射频资源管理 (自动信道/功率调优)         │  │
  │  │ - 客户端认证 (对接 RADIUS)               │  │
  │  │ - 漫游管理                               │  │
  │  │ - 漫游数据库                             │  │
  │  │ - 策略下发                               │  │
  │  └────────────────────────────────────────┘  │
  │         │ CAPWAP 隧道                         │
  │         │ (Control And Provisioning           │
  │         │  of Wireless Access Points)         │
  │         ▼                                     │
  │  ┌──────────┐ ┌──────────┐ ┌──────────┐      │
  │  │  Fit AP  │ │  Fit AP  │ │  Fit AP  │ ...  │
  │  │ (瘦AP)   │ │ (瘦AP)   │ │ (瘦AP)   │      │
  │  │ 只管射频 │ │ 只管射频 │ │ 只管射频 │      │
  │  │ + 数据   │ │ + 数据   │ │ + 数据   │      │
  │  └────┬─────┘ └────┬─────┘ └────┬─────┘      │
  │       │            │            │            │
  │       └────────────┴────────────┘            │
  │                    │                         │
  │                    ▼                         │
  │              PoE 交换机 (接入层)               │
  └──────────────────────────────────────────────┘
```

> 💡 **Fat AP vs Fit AP 的本质区别**：Fat AP 是"全能型选手"（自己干所有活），Fit AP 是"哑终端"（只管收发无线信号，智能决策全在 AC）。企业网络必须用 AC + Fit AP 架构 ，否则几十台 AP 的配置管理会让人崩溃。

**CAPWAP 协议**：AC 和 Fit AP 之间的通信协议，负责配置下发、状态上报、客户端数据隧道封装 。

### 06.04.08 中继器连接

```
无线中继 (Repeater):
  STA )))) AP1 )))) AP2 )))) AP3
         (中继)    (中继)
  
  扩展覆盖范围, 但:
  - 每中继一次, 带宽减半 (因为同一信道重复传输)
  - 延迟增加
  - 仅适合家庭/小办公室扩展覆盖
  
  企业网络更常用"AP 分布 + 有线回传"而非中继
```

## 06.05 无线 LAN 通信速率与覆盖范围的要点 ← 工程权衡

这一节是**无线部署的工程核心**——速率、覆盖、干扰、信道四个因素的平衡。

### 06.05.01 最大通信速率

```
理论速率 vs 实际速率:

  802.11ac 理论: 6.9 Gbps
  实际单终端: 通常 300-800 Mbps
  实际多终端共享: 进一步下降
  
  影响因素:
  - 调制方式 (离 AP 越远, 调制越保守, 速率越低)
  - 信道宽度 (20/40/80/160 MHz)
  - MIMO 流数 (1x1, 2x2, 3x3, 4x4)
  - 客户端能力 (木桶效应: 取 AP 和终端的较低能力)
```

### 06.05.02 覆盖范围

```
覆盖范围的决定因素：

  发射功率 (TX Power)        天线增益 (Antenna Gain)
       │                          │
       ▼                          ▼
  覆盖半径 ←────────────────── 覆盖形状
       │
       ▼
  接收灵敏度 (RX Sensitivity)
  终端的接收能力往往比 AP 弱 → "上行受限"
  
  典型室内覆盖:
  - 2.4GHz: 单 AP 覆盖 20-30 米半径
  - 5GHz: 单 AP 覆盖 10-15 米半径
  - 6GHz: 单 AP 覆盖 5-10 米半径
```

### 06.05.03 干涉 (干扰)

```
干扰源分类：

  同频干扰 (Co-channel Interference)
      邻居 Wi-Fi 用相同信道 → 互相干扰
      缓解: 自动信道选择 (RRM)
      
  邻频干扰 (Adjacent-channel Interference)
      信道重叠 → 互相干扰
      缓解: 只用非重叠信道 (2.4GHz: 1/6/11)
      
  非 Wi-Fi 干扰
      微波炉 (2.45 GHz)
      蓝牙设备
      无线摄像头
      无绳电话
      ZigBee
      缓解: 优先用 5GHz/6GHz
```

### 06.05.04 无线 LAN 信道

```
2.4GHz 信道规划 (最经典的三信道复用):

  Channel:  1       6       11
  ├────────┼────────┼────────┤
  │████████│        │        │
  │████████│████████│        │  ← 信道1
  │        │████████│████████│  ← 信道6
  │        │        │████████│  ← 信道11
  └────────┴────────┴────────┘
  
  原则: 相邻 AP 用 1/6/11 错开, 避免重叠
  
5GHz 信道规划:
  信道多 (36, 40, 44, 48, 149, 153, 157, 161...)
  可用 80MHz/160MHz 宽信道
  干扰少, 是高速主用频段
```

### 06.05.05 接入点的最大通信范围

```
AP 部署的"小功率多点位"原则:

  错误做法: 少量 AP, 大功率, 追求单 AP 大覆盖
      问题: 边缘速率极低, 同频干扰严重, 容量不足
  
  正确做法: 多 AP, 中等功率, 蜂窝式覆盖
      优点: 单 AP 负载低, 容量高, 漫游体验好
      
  典型企业部署:
  - 开放式办公区: 每 15-25 米一台 AP
  - 会议室/高密度: 每 10-15 米一台 AP
  - 安装高度: 2.5-3.5 米
  - 吸顶安装, 利用走廊波导效应
```

## 06.06 无线 LAN 的接入点产品

### 06.06.01 产品规格书的阅读方法

```
AP 规格书关键参数解读：

  物理层:
  - 无线标准: 802.11ax (Wi-Fi 6) 起步, ax+be 前瞻
  - 频段: 双频(2.4+5)/三频(2.4+5+6)

  - 上行口: 1x/2x/5Gbps/10Gbps 以太网

  性能:
  - 最大带机量: 普通商用 30-40 台, 企业级 60-100+ 台
  - 并发能力: OFDMA 资源单元数
  
  功能:
  - 工作模式: Fat / Fit (需配套 AC)
  - 安全: WPA2/WPA3, 802.1X
  - 管理: 云管理 / AC 管理 / 独立管理

**读这一章的六条连结意识**（写进笔记的价值点）：

1. **与第2章 L2 交换机的承接**：AP 本质上是**无线侧的 L2 桥接设备**——它把 802.11 帧转换成以太网帧，然后交给上游的 L2 交换机。所以 AP 下游的无线客户端，在上游交换机看来就是普通的 MAC 地址。VLAN、STP、LACP 等 L2 概念在无线侧一样适用（通过 SSID↔VLAN 映射）。
2. **与第4章 L3 交换机的承接**：企业无线网络中，客户端的网关通常是 L3 交换机的 SVI（每个 SSID 对应一个 VLAN，每个 VLAN 有一个 SVI 作为网关）。无线客户端拿到的 IP 从 L3 交换机上的 DHCP 服务或独立的 DHCP 服务器获取。跨 VLAN 通信由 L3 交换机做 VLAN 间路由。
3. **与第5章防火墙的承接**：无线客户端访问互联网或跨安全区域访问时，流量经过防火墙。访客无线网络的隔离、无线用户的身份认证与审计，都需要防火墙/安全策略配合。**无线不等于"无防"**——企业无线安全风险比有线高得多，因为信号在空中传播。
4. **CSMA/CA 是无线 LAN 的灵魂**：理解了这个机制，就理解了为什么无线网络"带宽共享"、为什么高密度场景下性能会急剧下降、为什么需要 OFDMA/MU-MIMO 等技术来改进 。这是区分有线思维和无线思维的关键。
5. **自治型 AP vs 集中管理型 AP 是架构分水岭**：家庭/SOHO 用 Fat AP（自治型），企业用 AC + Fit AP（集中管理型）。**企业无线网络绝不能让 AP 独立工作**——集中管理是稳定性、漫游体验、运维效率的基石 。
6. **为第7章选购做铺垫**：06.06 的产品规格书阅读方法，直接对接第7章的"无线 LAN 性能考量"（07.04.06）。选购 AP 时要看的不只是"速率数字"——带机量、PoE 预算、AC 管理能力、Wi-Fi 标准代次、安全特性，这些都要纳入第7章的 TCO 计算框架。
