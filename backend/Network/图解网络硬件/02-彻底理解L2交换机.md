## 02.01 中继器和网桥的不同点

这一节是"家族溯源"，把交换机的前辈们挨个点一遍，才能理解交换机"新在哪里"。

```
L2 转发设备的演进谱系

  中继器 (Repeater, L1)
       │  放大电信号，不懂帧
       ▼
  共享式集线器 (Hub)
       │  多端口中继器，所有端口在同一冲突域
       ▼
  网桥 (Bridge, 早期 L2)
       │  开始"学习 MAC 地址"，按帧转发
       ▼
  交换式集线器 = 交换机 (Switch)
          多端口网桥，每端口独立冲突域，
          硬件级（ASIC）线速转发
```

**核心对比**（这一节最重要的两张"表")

|设备|工作层|冲突域|转发依据|关键局限|
|---|---|---|---|---|
|中继器|L1|不分隔|电信号放大|不懂帧|
|集线器 (Hub)|L1|所有端口共享一个冲突域|广播到所有端口|冲突多、带宽浪费|
|网桥 (Bridge)|L2|每端口一个冲突域|MAC 地址|软件转发，慢|
|**交换机 (Switch)**​|**L2**​|**每端口一个冲突域**​|**MAC 地址表**​|**默认不隔离广播域**​|

> 💡 **读书要点**：交换机本质上是"多端口网桥"，但因为用了 **ASIC 硬件芯片**（呼应第1章 01.04.07），所以能做到线速转发。这就是它取代 Hub 和网桥的根本原因。

**交换机学习 MAC 地址的过程**（02.01.05 是整章的技术基石）：

```
PC-A (MAC: AA)         交换机          PC-B (MAC: BB)
       │                     │                │
       │ ① 发送帧给 B        │                │
       │─── 源MAC=AA ───────►│                │
       │                     │ ② 记录: AA ⇢ 端口1
       │                     │   (MAC表写入)
       │                     │ ③ 查 BB? 没有 → 泛洪
       │                     │── 泛洪 ────────►│
       │                     │                │ ④ 收到, 回应给 A
       │◄── 源MAC=BB ───────│                │
       │                     │ ⑤ 记录: BB ⇢ 端口2
       │                     │   (MAC表补全)
       │                     │                │
   此后 A↔B 单向单播, 不再泛洪
```

MAC 表（也叫 CAM 表）的结构是 **(MAC 地址, 出口端口, VLAN ID)**​ 三元组。表里没有的条目就"泛洪"，表里有的就"精确转发"，出入口相同的就"过滤丢弃"。

## 02.02 交换机是如何诞生的

历史脉络小节，关键是把"以太网从总线型走向交换式"这条主线抓出来：

```
以太网拓扑演进

  总线型 (Bus)               星型 + 交换机 (Switched)
  ─────────              ─────────────────────────────
  所有主机抢一条线          每主机独享一条点到点链路
  冲突域 = 整个网段         每端口 = 独立冲突域
  带宽被共享                带宽被独占
       │                          │
       │      交换式以太网兴起       │
       └──────────────────────────►│
                            现代 LAN 的标准形态
```

> 📌 **与第1章 01.02 的连结**：第1章讲过"以太网为何胜出"，这一节接着讲"以太网胜出之后，拓扑如何从共享式演进到交换式"——这正是交换机诞生的历史动因。

## 02.03 交换机中使用的数据帧及其传输方式

这一节讲交换机"怎么传帧"，三种传输方式对比：

```
交换机传输方式（02.03.02）

  直通转发 (Cut-Through)
       │  收到目的 MAC 就开始转发
       │  延迟低，但不校验 CRC
       ▼
  存储转发 (Store-and-Forward)
       │  收完整帧 + CRC 校验通过才转发
       │  延迟高，但无错帧不转发
       ▼
  自适应交换 (Adaptive / Fragment-Free)
       │  收到帧头前 64 字节就开始转发
       │  兼顾速度与可靠性（02.03.03）
```

> 💡 **记忆锚点**：**存储转发**最常见，因为它能丢弃错误帧；**直通转发**延迟最低，用在低延迟交易网络；**自适应**是折中。

## 02.04 全双工和半双工

```
半双工 (Half-Duplex)             全双工 (Full-Duplex)
──────────────────              ──────────────────
  同一时刻只能发或收              同时收发
  需要 CSMA/CD 防冲突             不需要 CSMA/CD
  Hub 时代的主流                  交换机时代的主流
  效率 ≤ 50%                      效率 ≈ 100%
```

> 📌 现代交换机端口基本都是全双工，这也是交换机性能远超 Hub 的关键之一。

## 02.05 如何描述交换机的处理能力

这一节给的是"选型语言"，几个核心指标：

```
交换机性能指标（02.05）

  吞吐量 (Throughput)         ── 单位时间内能转发的比特数
  包转发率 (pps)              ── 单位时间内能转发的包数
  背板带宽 (Backplane)        ── 交换矩阵的总带宽
  线速 (Wire Speed)           ── 端口带宽跑满时的转发能力
```

> 💡 **线速是金标准**：一款 24 口千兆交换机要做到"线速"，意味着背板带宽至少要 24 × 1 Gbps × 2（全双工）= 48 Gbps。

## 02.08 交换机搭载的其他功能（本章的重头戏之一）

这一节信息密度极大，几乎涵盖了现代 L2 交换机所有"进阶技能"。我们挑核心的四个展开：

### 🌲 生成树功能 (02.08.03) — STP

```
为什么需要 STP？

  SW1 ──── SW2
   │        │
   └── SW3 ─┘      物理冗余链路 → 逻辑环路
                  广播帧在环路里无限循环 → 广播风暴

  STP 的做法：临时阻塞某些端口，打破环路

        ┌───►[阻塞]──┐
  SW1 ──SW2         SW3
        ◄── 唯一通路 ─┘

  根桥 (Root Bridge) 选举 → 计算到根的最短路径
  → 非最短路径的端口进入 Blocking 状态
  链路故障 → 原阻塞端口自动切换为 Forwarding
```

> 📌 **IEEE 802.1D 标准**。STP 是 L2 交换机"防自爆"的核心机制——没有它，只要接两根线形成环路，整个网络立刻瘫痪。

### 🔗 链路聚合 (02.08.04) — LAG/LACP

```
聚合前:                       聚合后:
  SW1 ──── SW2  (1 Gbps)       SW1 ══════ SW2 (2 Gbps)
  SW1 ──── SW2  (1 Gbps)       逻辑捆绑成一条 2 Gbps 链路
                                  + 冗余（断一根不影响）
```

### 🏷️ VLAN (02.08.05)

```
没有 VLAN:                     有 VLAN:
  ┌──────────────┐             ┌──────────────┐
  │ 一个广播域    │             │ VLAN 10 │ VLAN 20│
  │ 所有 PC 互通  │             │  PC-A   │  PC-C   │
  │ 广播泛滥      │             │  PC-B   │  PC-D   │
  └──────────────┘             └──────────────┘
                                广播被隔离在各自 VLAN 内
```

**VLAN 间通信**需要 L3 设备（路由器或 L3 交换机）——这正是第3章、第4章的入口。

**Trunk 链路**（跨交换机承载多 VLAN）：

```
SW1 ═══ Trunk ═══ SW2
        (802.1Q Tag)

  帧格式:
  ┌───────┬──────┬──────┬──────┐
  │ DMAC  │ SMAC │ TAG  │ DATA │
  └───────┴──────┴──────┴──────┘
                  │
                  ▼
            VLAN ID (12 bit, 1-4094)
```

### 其他功能速查

|功能|小节|一句话作用|
|---|---|---|
|MAC 地址数|02.08.01|CAM 表容量上限|
|巨型帧 (Jumbo Frame)|02.08.02|9000 字节大帧，提升大数据传输效率|
|端口镜像|02.08.06|把某端口流量复制到监控端口|
|QoS 优先级队列|02.08.07|语音/视频优先，避免卡顿|
|MAC 地址过滤|02.08.08|黑白名单式接入控制|
|基于端口的认证|02.08.09|802.1X，防止非法接入|
|网络管理|02.08.10|SNMP 等管理协议|

## 02.09 交换机架构（回到硬件视角）

这一节呼应第1章 01.04"网络设备构成要素"，把交换机拆到芯片级：

```
交换机内部架构（02.09）

  外部接口
       │
       ▼
  ┌──────────────────────────────────────┐
  │           交换机内部                  │
  │                                        │
  │  ┌────────┐    ┌────────┐             │
  │  │  PHY   │    │  PHY   │   ...       │  ← 02.09.02
  │  │ 模块   │    │ 模块   │             │  物理层信号处理
  │  └───┬────┘    └───┬────┘             │
  │      │              │                 │
  │  ┌───▼────┐    ┌───▼────┐             │
  │  │  MAC   │    │  MAC   │   ...       │  ← 02.09.03
  │  │ 模块   │    │ 模块   │             │  MAC 表学习/查表
  │  └───┬────┘    └───┬────┘             │
  │      │              │                 │
  │      └──────┬───────┘                 │
  │             ▼                         │
  │      ┌─────────────┐                   │
  │      │  交换矩阵    │ ← ASIC 硬件转发  │
  │      │ (Switch     │   (呼应 01.04.07) │
  │      │  Fabric)    │                   │
  │      └─────────────┘                   │
  │                                        │
  │  ┌──────────────────────────────┐      │
  │  │  CPU (控制平面)               │      │  ← 运行 OS, 处理 STP/
  │  │  内存 / 存储                   │      │    VLAN 管理等慢速任务
  │  └──────────────────────────────┘      │
  └──────────────────────────────────────┘

  AUI / MII (02.09.04): MAC 与 PHY 之间的接口标准
```

> 💡 **控制平面 vs 数据平面的具象化**：
> 
> - **数据平面**（转发帧）：PHY → MAC → 交换矩阵(ASIC)，全程硬件，**线速**
>     
> - **控制平面**（STP/VLAN/管理）：CPU 软件处理，**慢速但灵活**
>     
> 
> 这个"两平面分离"的思想贯穿全书，第3章路由器、第4章 L3 交换机都是同一范式。

**读这一章的五条连结意识**（写进笔记的价值点）：

1. **和第1章 01.03 的连结**：第1章讲了"以太网帧长什么样"，第2章讲"交换机怎么处理这个帧"——**帧结构是操作对象，交换机是操作者**。
2. **和第1章 01.04.07 的连结**：第1章提到 ASIC 是"线速转发的秘密"，第2章 02.09 把它具象化为"交换矩阵"——**控制平面走 CPU，数据平面走 ASIC**​ 的两平面模型在此成型。
3. **和第3章的连结**：VLAN 间通信需要 L3 设备 → 引出第3章路由器；STP 解决 L2 环路 → 但 L3 路由器天然隔离广播域，从另一个角度解决问题。
4. **和第4章的连结**：L2 交换机 + VLAN 功能 = 第4章 L3 交换机的雏形。L3 交换机 = L2 交换机 + 路由模块。
5. **和实际组网的连结**：接入层用 L2 交换机（本章）→ 汇聚/核心用 L3 交换机（第4章）→ 出口用路由器（第3章），这是企业网的标准三层架构。
