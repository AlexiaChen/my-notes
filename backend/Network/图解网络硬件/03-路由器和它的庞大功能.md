
# 第3章 读书笔记：路由器和它庞大的功能

> 第2章把 L2 交换机讲透了——它在**同一个广播域（IP 子网）内**，靠 MAC 地址表高速转发以太网帧。
> 
> 但现实网络需要把**不同的子网**连起来：把部门 A 的网段连到部门 B，把内网连到互联网，把北京分公司连到上海分公司。干这件事的就是**路由器**，OSI 第3层（网络层）的设备。
> 
> 作者三轮贤一把这一章写得"庞大"，是因为现代路由器早已不只是"转发 IP 包"——它还做 WAN 接入、VPN、NAT、QoS、认证、冗余、多播……这一章等于把"网络层及网络层以上"的硬件功能**扫了一遍**，为第4章 L3 交换机、第5章 Cisco 路由器实操埋下伏笔。

## 🗺️ 第三章在全书的方位

```
第2章 L2 交换机 ──► 第3章 路由器 ──► 第4章 L3 交换机 ──► 第5章 Cisco 路由器实操
  同子网内转发        跨子网/跨网络互联     交换机+路由功能       具体厂商设备落地
  依据: MAC 表          依据: 路由表          依据: MAC 表+路由表      CLI 配置与运维
```

**L2 交换机 vs L3 路由器**（本章最核心的认知分界线）：

```
┌──────────────────────────────────────────────────────────┐
  │                     IP 网络 (子网 192.168.1.0/24)          │
  │                                                          │
  │   PC-A ──► L2 交换机 ──► L2 交换机 ──► PC-B              │
  │   同广播域内, 交换机看 MAC 地址转发, 不过路由器            │
  └──────────────────────────┬───────────────────────────────┘
                             │
                        ┌────▼────┐
                        │ 路由器   │  ← 跨子网边界
                        │ (L3)    │     依据路由表转发 IP 分组
                        └────┬────┘
                             │
  ┌──────────────────────────▼───────────────────────────────┐
  │                     IP 网络 (子网 10.0.0.0/24)             │
  │                                                          │
  │   PC-C ──► L2 交换机 ──► L2 交换机 ──► PC-D              │
  └──────────────────────────────────────────────────────────┘
```

## 03.01 何为路由器

这一节是定义层，把"路由器是什么、为什么要它、它干什么"三件事说清楚。

**路由器的本质**：

```
路由器 = 主要负责 OSI 第3层(L3)处理的网络硬件
       + 根据路由表在不同网络(IP 子网/广播域)之间转发 IP 分组
       + 搭载各种各样的附加功能(现代路由器)
```

**路由器的必要性**：

```
场景1: 组织内一个 LAN 想连另一个 LAN  → 需要路由器
场景2: 大型 LAN 广播泛滥, 设备负担大   → 划分子网, 子网间通信用路由器
场景3: 内网连互联网 ISP               → 需要路由器
```

> 💡 关键认知：交换机解决"同子网内怎么通"，路由器解决"跨子网怎么通"。VLAN 把广播域切开后，**VLAN 间通信必须过路由器（或 L3 交换机）**——这正是第2章 02.08.05 VLAN 与本章的直接接口。

**路由选择 vs 转发**（两个极易混的概念，作者特意分开讲）：

```
路由选择 (Routing)              转发 (Forwarding)
─────────────────              ─────────────────
  控制平面                         数据平面
  决定"走哪条路"                    把分组从入接口搬到出接口
  由 CPU+路由协议完成               由 ASIC/硬件完成
  产出: 路由表/转发表               执行: 查表 → 换 MAC → 发出去
```

**路由器功能全景**：

- 网络层：路由选择、IP 分组转发
- 数据链路层/物理层：以太网帧处理、WAN 协议处理
- 传输层/应用层（现代路由器）：安全保障、VoIP、QoS、认证
    
> 📌 这一节给整章定调：**路由器早已不是单纯的 L3 设备，而是多功能网络硬件平台**。"庞大的功能"由此而来。

## 03.02 路由器是如何诞生的

```
路由器发展史（03.02）

  世界上最早的商用路由器 (03.02.01)
       │
       ▼
  性能进化路线 (03.02.02)
       │
       ├─ 软件转发时代: CPU 处理每一个包, 慢
       ├─ 硬件辅助时代: ASIC 分担转发, 快
       └─ 现代: 控制平面(CPU) + 数据平面(ASIC) 分离
```

> 📌 **与第2章 02.09 的连结**：交换机和路由器在架构演进上走的是同一条路——都用 ASIC 做线速转发，都把控制平面交给 CPU。这是现代网络设备的通用范式。

## 03.05 IP 路由选择的基础知识 ← 本章技术核心

这是本章**密度最高**的一节，从 IP 地址一直讲到动态路由、VPN、多播。

### 03.05.01 IP 地址管理

```
IP 地址基础
  IPv4: 32 bit, 点分十进制, 如 192.168.0.12
  IPv6: 128 bit, 冒分十六进制
  两者不互换

  地址分类与自然掩码 (有类)
       A: 0.0.0.0/8
       B: 128.0.0.0/16
       C: 192.0.0.0/24
       D: 224.0.0.0/4 (多播)
       E: 240.0.0.0/4 (保留)

  CIDR (无类别域间路由) — 现代主流
       任意长度前缀: 192.168.1.0/26, 10.0.0.0/22 ...
```

**L3 接口的类型**（这一小节特别值得记）：

```
L3 接口的种类
       ├─ 物理接口: 真实端口, 配 IP 后该子网直连
       ├─ 环回接口 (Loopback): 虚拟接口, 代表路由器自身
       ├─ VLAN 接口 (SVI): 为每个 VLAN 配 IP, VLAN 间路由的载体
       ├─ 汇聚接口: 链路聚合后的逻辑接口
       ├─ 子接口: 物理接口上划分的逻辑接口, 用于单臂路由
       └─ 辅助接口: 主 IP 之外的次要 IP
```

> 📌 **与第2章 VLAN 的连结**：VLAN 间路由有两种做法——(1) 单臂路由：路由器一个物理口通过 trunk 接交换机，在路由器上起子接口；(2) SVI：L3 交换机直接在每个 VLAN 上起 VLAN 接口。前者用路由器，后者引出第4章 L3 交换机。

### 03.05.02–03.05.04 路由表与最长匹配

**路由表的表项结构**：

```
路由表表项
  ┌──────────────┬──────────────┬──────────┬──────────┐
  │ 目标网络      │ 下一跳        │ 出接口    │ 度量值    │
  │ 192.168.2.0  │ 10.0.0.2     │ Gi0/1    │ 1        │
  │ /24          │              │          │          │
  └──────────────┴──────────────┴──────────┴──────────┘
      │              │             │          │
      ▼              ▼             ▼          ▼
  去哪个网段     下一站是谁      从哪出去    路径优劣
```

**最长匹配原则**（路由查找的核心算法）：

```
路由表:
    192.168.0.0/16  → 下一跳 A
    192.168.1.0/24  → 下一跳 B
    0.0.0.0/0       → 默认网关 C

  目的 IP: 192.168.1.20
  匹配过程:
    1. 先看有没有 /32 主机路由? 没有
    2. 看 /24: 192.168.1.0/24 匹配! → 选下一跳 B
    3. (不会再看 /16, 因为 /24 更长更具体)

  目的 IP: 192.168.100.5
  匹配过程:
    4. /24 不匹配
    5. /16: 192.168.0.0/16 匹配 → 下一跳 A
    6. 若 A 也没有 → 走默认路由 C
```

> 💡 **最长匹配 = 最具体的路由优先**。这是路由器转发决策的黄金法则。

### 03.05.05 静态路由

```
静态路由 = 管理员手工配置的路由表项

  特点:
    ✅ 确定性高, 路径可控
    ✅ 无协议开销
    ❌ 网络大了配置量爆炸
    ❌ 链路故障不能自动切换

  典型用法:
    - 默认路由 (0.0.0.0/0) 指向 ISP
    - 存根网络 (只有一个出口的小型网络)
    - 浮动静态路由做备份 (调管理距离)
```

### 03.05.06 动态路由

```
动态路由 = 路由器之间通过路由协议自动交换拓扑信息

  AS (自治系统) 内:  IGP (内部网关协议)
    ├─ RIP       距离矢量, 跳数, 最大15跳, 已过时
    ├─ OSPF      链路状态, 最短路径优先, 企业主流
    ├─ IS-IS     链路状态, 运营商常用
    └─ EIGRP     Cisco 私有, 混合型

  AS 之间:  EGP (外部网关协议)
    └─ BGP      互联网 backbone 的协议

  关键概念:
    - 收敛时间: 从拓扑变化到全网路由表稳定的时间
    - AD (管理距离): 多种路由来源共存时的可信度
    - 路由重分发: 不同路由协议之间共享路由信息
```

> 💡 **与第4章的连结**：L3 交换机做 VLAN 间路由时，静态路由和 OSPF 是最常见的两种做法。这一节是理解第4章"L3 交换机路由功能"的基础。

### 03.05.07 IP 隧道与 VPN

```
隧道技术: 把一种协议的数据包封装在另一种协议中传输

  L2 隧道: L2F, PPTP, L2TP  (封装数据链路层帧)
  L3 隧道: GRE, IPsec        (封装网络层分组)

  IPsec VPN 示意:

    PC-A ──► RA ──── IPsec 隧道 ──── RB ──► PC-B
    私有IP      公网IP ║ 公网IP       私有IP
                       ║
                       ▼
              原始 IP 分组被加密封装
              在公网上只看到 RA↔RB 的公网IP通信
```

> 📌 **IPv6 过渡**：IPv6 over IPv4 / IPv4 over IPv6 隧道，是双栈过渡期的核心技术。

### 03.05.08 IP 多播

```
多播: 一对多高效投递 (对比单播一对一, 广播一对全体)

  源 ──► 多播路由器 ──► 复制 ──► 接收者1
                               └──► 接收者2

  管理协议: IGMP (IPv4) / MLD (IPv6)
  路由协议: PIM (Protocol Independent Multicast)
    ├─ PIM-DM: 接收者密集
    └─ PIM-SM: 接收者稀疏
```

## 03.06 路由器搭载的各种附加功能 ← "庞大"二字的根源

这一节是本章名字"庞大的功能"的具象化。

```
路由器附加功能全景（03.06）

  协议支持扩展
    ├─ LAN 交换 (03.06.03): 宽带路由器的 LAN 口之间也能交换
    ├─ 非以太网 WAN 协议 (03.06.04): PPP, HDLC, MPLS, Frame Relay
    └─ 非 TCP/IP 协议簇 (03.06.02): IPX/SPX, AppleTalk (legacy)

  接入方式
    ├─ 拨号接入 (03.06.05): PPPoE, 3G/LTE
    └─ WAN 接入: xDSL, 光纤, CATV Cable Modem

  可靠性
    └─ 冗余 (03.06.06):
        ├─ 热备份: 主备同时运行, 故障自动切换
        ├─ 冷备份: 备机不联网, 故障后人工替换
        └─ VRRP: 虚拟路由器冗余协议
            ┌──────────────────────────────┐
            │  VRRP Group                  │
            │  ┌────────┐    ┌────────┐    │
            │  │ Master │    │ Backup │    │
            │  │ 优先级高│    │ 优先级低│    │
            │  └───┬────┘    └────┬───┘    │
            │      │   虚拟IP      │        │
            │      └────► 192.168.1.1 ◄────┘ │
            │            (终端网关)           │
            └──────────────────────────────┘

  安全与管控
    ├─ 认证 (03.06.07): RADIUS, 802.1X, 管理员认证
    ├─ QoS (03.06.08): 队列调度, 拥塞避免, 流量整形
    └─ 策略控制: ACL, 限速

  虚拟化
    └─ 虚拟路由器 (03.06.09): 一台物理设备跑多个逻辑路由器
```

> 💡 **VRRP 值得重点理解**：它让两台物理路由器对外呈现为一个虚拟路由器（一个虚拟 IP），终端把网关指向这个虚拟 IP。主设备挂了，备设备自动上位，终端无感知。这是企业网"网关高可用"的标准方案。

## 03.08 路由器的架构 ← 回到硬件，呼应第1章 01.04

```
路由器内部架构（03.08）

  ┌────────────────────────────────────────────┐
  │              路由器                          │
  │                                              │
  │  ┌──────────────────────────────────────┐  │
  │  │        控制平面 (CPU + 内存)           │  │  ← 跑路由协议
  │  │  路由引擎: OSPF/BGP/RIP 计算路由表      │  │    生成转发表
  │  └──────────────┬───────────────────────┘  │
  │                 │ 转发表                     │
  │                 ▼                           │
  │  ┌──────────────────────────────────────┐  │
  │  │        数据平面 (ASIC + 交换矩阵)      │  │  ← 线速转发
  │  │                                      │  │
  │  │  入接口 ──► 查转发表 ──► 出接口        │  │
  │  │  (PHY/MAC)    (TCAM)    (PHY/MAC)    │  │
  │  └──────────────────────────────────────┘  │
  │                                              │
  │  线卡 (Line Card) × N  ── 背板 (Backplane)  │
  │  电源 (可冗余)    风扇 (可热插拔)            │
  │  启动流程 (03.08.02): ROM → Bootstrap      │
  │            → IOS 加载 → 配置文件加载         │
  └────────────────────────────────────────────┘
```

**路由器的构成要素**(03.08.01)：机框、风扇、RAM、CPU（ASIC/FPGA）、接口、底盘、硬盘/闪存、电源——和第1章 01.04 讲的"网络设备构成要素"完全一致。

**内部冗余**(03.08.04)：

```
冗余维度
    ├─ 电源冗余: 双电源, 一个挂了另一个顶上
    ├─ 风扇冗余: 可热插拔, N+1
    ├─ 线卡冗余: 主控板 1:1 备份
    ├─ 交换矩阵冗余: 双交换网板
    └─ 路由引擎冗余: 主备 RP (Route Processor)
```

> 📌 **与第2章 02.09 的连结**：交换机和路由器的内部架构是同一个范式——
> 
> **控制平面(CPU)算路 + 数据平面(ASIC)转发，通过背板/交换矩阵连接线卡**。
> 
> 理解了这个范式，后面看 L3 交换机、防火墙、负载均衡器都是同一个套路。


**读这一章的六条连结意识**（写进笔记的价值点）：

1. **和第2章 VLAN 的直接接口**：VLAN 间通信必须过 L3 设备。要么用路由器的子接口做单臂路由，要么用第4章的 L3 交换机做 SVI——**第2章埋的伏笔，在本章 03.05.01 收线**。
2. **和第1章 01.04 的呼应**：路由器内部也是"控制平面(CPU)+ 数据平面(ASIC)+ 背板 + 线卡 + 冗余电源风扇"的结构，与交换机架构同源。
3. **最长匹配是灵魂**：03.05.04 的最长匹配原则贯穿所有 L3 设备——路由器、L3 交换机、防火墙都一样。
4. **静态路由 vs 动态路由的取舍**：静态适合小而稳的网络，动态适合大而变的企业网/运营商网。OSPF 是企业主流，BGP 是互联网主流。
5. **"庞大的功能"的真正含义**：现代路由器早已不只是 L3 转发——WAN 接入、VPN、NAT、QoS、认证、冗余、多播、虚拟化全都做。**路由器 = 网络层多功能硬件平台**。
6. **为第4章 L3 交换机铺路**：L3 交换机 = L2 交换机 + 路由功能。理解了路由器的路由表、最长匹配、静态/OSPF，第4章 L3 交换机就只是"把路由功能搬进交换机 ASIC"而已。
