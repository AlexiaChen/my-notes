
# 第4章 读书笔记：理解 L3 交换机的性能与功能

> 第2章讲透了 L2 交换机——**同 VLAN 内**靠 MAC 表线速转发；
> 
> 第3章讲透了路由器——**跨网络**靠路由表转发，但依赖 CPU，速度有限；
> 
> 第4章的主角 L3 交换机，正是这两者的"合体"：**用 ASIC 硬件把路由功能做进交换机**，让跨 VLAN 通信也能跑出线速。
> 
> 作者三轮贤一把这一章分成四块递进展开 ：
> 
> - **04.01 何为 L3 交换机**：L3 交换机与路由器的本质差异 + 多层交换概念
>     
> - **04.02 L3 交换机是如何诞生的**：历史动因
>     
> - **04.03 L3 交换机的分类**：按形状/用途、按性能
>     
> - **04.04 L3 交换机搭载的特殊功能**：VLAN、VLAN 间路由等核心能力
>     
> 
> 一句话定位：**L3 交换机 = L2 交换机的硬件线速 + 路由器的跨网段能力，但主要服务于局域网内部**。

## 🗺️ 第四章在全书的方位

```
第2章 L2 交换机 ──► 第3章 路由器 ──► 第4章 L3 交换机 ──► 第5章 防火墙
  同VLAN内转发      跨网络转发       内网跨VLAN高速路由     网络安全边界
  依据MAC表         依据路由表       依据MAC表+路由表(ASIC)  会话/策略/NAT/VPN
                     CPU软件转发       控制平面CPU+数据平面ASIC
```

**三台设备的能力边界**（本章最核心的认知框架）：

```
工作层级       转发依据        处理速度       典型位置
  ─────────────────────────────────────────────────────────────────────
  L2 交换机          L2            MAC 地址表       线速(ASIC)     接入层
  L3 交换机          L2+L3         MAC表+路由表     线速(ASIC)     汇聚/核心层
  路由器             L3            IP 路由表        CPU软件转发    网络边界/WAN
  ─────────────────────────────────────────────────────────────────────
```

> 💡 关键洞察：**L3 交换机不是要"杀死"路由器**。路由器擅长的 WAN 接入、NAT、VPN、复杂 QoS、丰富接口类型，L3 交换机仍然做不好或不做；L3 交换机胜在**内网东西向流量的线速转发**​ 。

## 04.01 何为 L3 交换机

### 04.01.01 L3 交换机与路由器的不同

这是本章**最重要**的一节，作者用"控制平面/数据平面分离"来解释 L3 交换机为什么快。

**传统路由器的痛点**：

```
传统路由器:
  ┌──────────────────────────────────┐
  │           路由器                   │
  │                                    │
  │   路由选择 ────► 分组转发 ────► 管理  │
  │   全部由 CPU 软件处理                │
  │                                    │
  │   问题: 管理负载 ↑ → 转发能力 ↓      │
  │         CPU 成为性能瓶颈              │
  └──────────────────────────────────┘
```

**L3 交换机的突破**：把内部硬件分为两个区域

```
L3 交换机:
  ┌────────────────────────────────────────────┐
  │               L3 交换机                      │
  │                                              │
  │  ┌────────────────────┐  ┌──────────────┐  │
  │  │   控制平面 (CPU)    │  │ 数据平面(ASIC)│  │  ← 分离!
  │  │  - 路由选择         │  │ - 分组转发     │  │
  │  │  - 管理功能         │  │ - 线速处理     │  │
  │  │  - 协议计算         │  │ - 硬件查表     │  │
  │  └─────────┬──────────┘  └──────┬───────┘  │
  │            │                    │          │
  │            │   下发转发表        │   执行转发  │
  │            ▼                    ▼          │
  │      FIB + 邻接表          高速转发引擎     │
  └────────────────────────────────────────────┘
```

**核心机制：FIB + 邻接表 → L3 表（FDB）**​

```
控制平面计算出的信息:
  ┌─────────────────┐   ┌─────────────────┐
  │ FIB             │   │ 邻接表           │
  │ (转发信息库)     │   │ (Adjacency)      │
  │ 目的网段→下一跳  │   │ 下一跳IP→MAC地址 │
  └────────┬────────┘   └────────┬────────┘
           │                    │
           ▼                    ▼
  ┌────────────────────────────────────┐
  │          L3 表 (FDB)                │
  │   目的网段 + 下一跳MAC + 出接口      │  ← 整合为1份表项
  │   注册于内存, 由硬件(ASTC)高速检索   │
  └────────────────────────────────────┘
```

> 📌 **Cisco CEF（Cisco Express Forwarding）**：Cisco IOS 中利用 FIB 和邻接表进行 IP 分组传输的方式 。本质上就是上面这套"控制平面算路 → 数据平面硬件查表转发"的范式。

**"一次路由，多次交换"的具体过程**：

```
首包 (由 CPU 处理):
  PC-A (VLAN10) ──► L3交换机
       │
       │ ① 查路由表: 192.168.20.0/24 → VLAN20
       │ ② ARP 解析 PC-B 的 MAC
       │ ③ 建立 L3 表项: (目的IP, 下一跳MAC, 出接口)
       │ ④ 转发分组 (TTL-1, 重新封装MAC)
       │
       ▼
  PC-B (VLAN20)

后续包 (由 ASIC 硬件处理):
  PC-A ──► L3交换机 ──► ASIC 查 L3 表 ──► 直接转发
       │                                   (微秒级, 线速)
       ▼
  PC-B
```

> 💡 这就是 L3 交换机性能的秘密：**首包走 CPU 做完整路由决策，后续包走 ASIC 做硬件交换**。既获得了路由器的跨网段能力，又获得了 L2 交换机的线速性能。

### 04.01.02 多层交换

这一节把视角从 L3 扩展到"多层"：

```
多层交换机的能力光谱:

  L2 交换机     L3 交换机     L4 交换机     L7 交换机
  ──────────────────────────────────────────────────►
  基于MAC       基于IP        基于TCP/UDP    基于HTTP/HTTPS
  转发帧        路由分组      端口号过滤     应用层负载均衡
                + ACL控制     + QoS标记      + 内容识别
  
  绝大多数 L3 交换机都能对 TCP 端口号做 ACL 控制，
  因此在很多场景下也被称为 L4 交换机；
  少数产品能基于 HTTP/HTTPS 等应用层参数做负载均衡，
  这类可称为 L7 交换机
```

> 📌 术语澄清：**"L3 交换机"在市面上往往已是"多层交换机"的代名词**——它至少能做 L2+L3，多数还能做 L4 的 ACL。

## 04.02 L3 交换机是如何诞生的

```
历史动因:
  早期网络: 路由器处理跨LAN通信
  
  问题:
  - 内网跨网段流量暴增 (VLAN 普及, 服务器/客户端跨VLAN访问)
  - 路由器 CPU 转发性能跟不上
  - 路由器端口密度低、价格高
  
  拷问:
  "能不能把路由器的跨网段能力, 用交换机的ASIC硬件来做?"
  
  答案:
  L3 交换机诞生 —— 用 ASIC 集成 IP 转发功能:
  ✓ 检查 IP 包头
  ✓ 修改 TTL
  ✓ 重算 IP 头部校验和
  ✓ 对 IP 包做数据链路层封装
```

> 📌 **与第2章 02.02 的呼应**：正如交换机取代 Hub 是因为"用硬件做帧转发"，L3 交换机取代路由器做内网跨网段转发，是因为"用硬件做包路由"。两次演进是同一个范式：**把软件做的事搬进硬件**。

## 04.03 L3 交换机的分类

### 04.03.01 根据形状和用途分类

```
L3 交换机外形分类:

  桌面式/盒式 (Box-type)
       │  固定端口数, 端口密度中等
       │  企业分支/中小网络核心
       ▼
  机框式 (Chassis-type)  ← 高端 L3 交换机 
       │  由路由引擎、交换结构、线卡、风扇、电源模块构成
       │  企业核心/数据中心/服务提供商
       ▼
  模块化 + 冗余
       ├─ 电源: 1+N 或 N+N 冗余
       ├─ 风扇: 可热插拔, N+1
       └─ 路由引擎: 1+1 冗余
       + 多台设备构成 VRRP 等冗余协议
```

### 04.03.02 根据性能分类

```
性能档位:

  低端 L3 交换机
       │  盒式, 固定端口
       │  转发性能: 数十 Gbps ~ 数百 Gbps
       │  路由表容量: 数千~数万条
       ▼
  中端 L3 交换机
       │  盒式或小型机框
       │  转发性能: 数百 Gbps ~ 数 Tbps
       │  路由表容量: 数万~数十万条
       ▼
  高端 L3 交换机 (机框式)
       │  模块化, 全冗余
       │  转发性能: 数 Tbps ~ 数十 Tbps
       │  路由表容量: 数十万~百万条
       │  作为企业核心交换机用于数据中心或服务供应商
```

> 💡 **选型视角**：看三个数字——**背板带宽、包转发率(pps)、路由表容量(MAC/ARP/路由条目数)**。这三个数字决定了 L3 交换机在哪个量级。

## 04.04 L3 交换机搭载的特殊功能

### 04.04.01 L3 交换机功能的分类

作者把 L3 交换机的功能分为几大类 ：

```
L3 交换机功能矩阵:

  ┌─ L2 功能 (继承第2章)
  │   STP/RSTP, VLAN, LACP, QoS(L2), 端口镜像
  │
  ├─ L3 功能 (本章核心)
  │   静态路由, 动态路由(OSPF/RIP/BGP), 
  │   VLAN 间路由, ACL, QoS(L3), HSRP/VRRP
  │
  ├─ 管理功能
  │   SNMP, RMON, NetFlow, Syslog
  │
  └─ 高级功能
      策略路由(PBR), 多播路由, IPv6 路由
```

> 📌 **关键认知**：在 L3 交换机中，**只有使用这些功能对分组进行的管理是由 CPU（软件）直接处理的；用户之间的通信均是由 ASIC（硬件）处理实现分组的高速转发**​ 。

换句话说，ASIC 处理"数据流"，CPU 处理"控制流"——这正是 04.01.01 说的"控制平面/数据平面分离"在工程上的具体体现。

### 04.04.02 VLAN

这一节呼应第2章 02.08.05，但在 L3 交换机语境下重新讲 VLAN：

```
VLAN 在 L3 交换机上的意义:

  单个 VLAN = 单个广播域 = 单个 IP 子网
  
  VLAN 10 ── 192.168.10.0/24
  VLAN 20 ── 192.168.20.0/24
  VLAN 30 ── 192.168.30.0/24
  
  L3 交换机为每个 VLAN 创建 SVI (Switch Virtual Interface):
  
  interface Vlan10
    ip address 192.168.10.1 255.255.255.0   ← VLAN10 的网关
  interface Vlan20
    ip address 192.168.20.1 255.255.255.0   ← VLAN20 的网关
  interface Vlan30
    ip address 192.168.30.1 255.255.255.0   ← VLAN30 的网关
```

> 💡 **SVI 是 L3 交换机做 VLAN 间路由的载体**——每一个 VLAN 都有一个虚拟接口作为该子网的网关。这是 L3 交换机与 L2 交换机在配置层面最直观的区别。

### 04.04.03 VLAN 环境中的数据流向

这一节讲同 VLAN 内通信的过程（呼应第2章 02.01 的 MAC 学习）：

```
同 VLAN 内通信 (L2 交换):
  
  Host-A (VLAN10) ──► L3交换机 ──► Host-B (VLAN10)
       │                    │
       │ ① ARP 广播         │ ② 交换机记录 Host-A 的 MAC
       │                    │     (MAC表: A ⇢ Port1)
       │ ③ 交换机在 VLAN10 内泛洪 ARP
       │ ④ Host-B 回应, 交换机记录 Host-B 的 MAC
       │ ⑤ 后续单播, 纯 L2 交换
       │
       ▼
  整个过程不涉及 L3 路由, ASIC 直接按 MAC 表转发
```

### 04.04.04 VLAN 之间的路由选择 ← 本章技术高潮

**L2 交换机的局限**（呼应第2章 02.08.05）：

```
L2 交换机跨 VLAN 通信:
  
  VLAN10 ── L2交换机 ── Trunk ──► 路由器 ── Trunk ──► L2交换机 ── VLAN20
  主机A                              (子接口)                  主机B
  
  跨 VLAN 流量必须离开交换机 → 上路由器 → 再回来
  瓶颈: 路由器 CPU 转发, 性能受限
        Trunk 链路带宽受限
        "发卡弯" 路径 (hairpin)
```

**L3 交换机的突破**：

```
L3 交换机跨 VLAN 通信:
  
  Host-A (VLAN10, 192.168.10.10)
       │
       │ ① 目的 IP 192.168.20.10 不在同网段
       │    发送到网关 192.168.10.1 (SVI 10)
       ▼
  ┌──────────────────────────────────────────┐
  │            L3 交换机                       │
  │                                            │
  │  SVI 10 (192.168.10.1)                     │
  │       │                                    │
  │       │ ② 查路由表: 192.168.20.0/24        │
  │       │    → SVI 20 (192.168.20.1)         │
  │       │                                    │
  │       │ ③ 首包: CPU 处理                    │
  │       │    ARP 解析 Host-B 的 MAC           │
  │       │    建立 L3 表项                      │
  │       │                                    │
  │       │ ④ 后续包: ASIC 硬件转发             │
  │       ▼                                    │
  │  SVI 20 (192.168.20.1)                     │
  └───────────────────┬────────────────────────┘
                      │
                      ▼
  Host-B (VLAN20, 192.168.20.10)
```

> 🎯 **这就是 L3 交换机存在的根本价值**：跨 VLAN 路由在交换机**内部**完成，**不再需要把流量送到外部路由器**——路径短了、带宽省了、性能从"路由器 CPU 转发"跃升到"ASIC 线速转发"。

**UDLD（单向链路检测）**​ ：

```
UDLD (Unidirectional Link Detection):
  - 思科开发的 L2 协议, RFC 5171
  - 检测 TX/RX 单向链路故障
  - 光纤链路中, 一端能发另一端收不到的情况
  - 检测到单向链路 → 关闭端口, 避免黑洞路由
  
  这是 L3 交换机在数据中心/企业核心部署时的重要可靠性功能
```

**读这一章的六条连结意识**（写进笔记的价值点）：

1. **与第2章的继承**：L3 交换机"向下兼容" L2 交换机——同 VLAN 内通信完全走 L2 交换逻辑（MAC 学习、泛洪、单播转发），这部分能力直接继承自第2章。
2. **与第3章的继承+革新**：L3 交换机的路由功能（路由表、最长匹配、静态/OSPF、VLAN 间路由）都来自第3章讲的路由器原理；但**把"CPU 软件转发"革新为"ASIC 硬件转发"**——这是 L3 交换机区别于路由器的根本。
3. **"一次路由，多次交换"是灵魂**：首包由控制平面（CPU）做完整路由决策并建立 L3 表项，后续包由数据平面（ASIC）查 L3 表硬件转发。理解了这个机制，就理解了 L3 交换机为什么快。
4. **L3 交换机 ≠ 路由器替代品**：边界功能（NAT、PPPoE、IPsec VPN、广域网接口、深度安全）仍需路由器或防火墙。企业网的标准实践是：
    
    ```
    接入层: L2 交换机（接终端）
    汇聚/核心: L3 交换机（VLAN 间高速路由）
    出口: 路由器 + 防火墙（NAT/VPN/安全）
    ```
    
1. **SVI 是配置层面的标志**：L3 交换机为每个 VLAN 创建 SVI 作为网关，这是它与 L2 交换机在配置上最直观的区别，也是 VLAN 间路由的载体。
2. **为第5章铺路**：L3 交换机解决了"内网跨 VLAN 高速互通"，但**内网的安全边界、出口 NAT、VPN 仍然是路由器和防火墙的职责**——第5章防火墙正是接着这个边界安全问题展开。

- **L2 交换机**解决了同 VLAN 内高速转发
- **路由器**解决了跨网络互联和边界安全
- **L3 交换机**解决了内网跨 VLAN 高速路由
