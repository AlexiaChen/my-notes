```
核心职责          工作层次        决策依据
  ─────────────────────────────────────────────────────────────────
  L2交换机           局域网内部通信    L2             MAC 地址表
  L3交换机           内网高速跨网段    L2+L3          MAC表+路由表(ASIC)
  路由器             跨网络连接        L3             IP 路由表
```

## 05.01 防火墙是怎样的网络硬件

这一节给出防火墙的定义与定位。

**防火墙的本质**：

```
防火墙 = 一种网络安全系统，基于预定义的一组规则
         监控并控制进出网络的流量
         充当内部网络的守门人(gatekeeper)
```

**防火墙 vs 路由器/L3 交换机 的根本差异**：

```
路由器/L3交换机的心智模型:
  "目的地可达吗? 如果可达, 就转发。"
  关注的是: 路径、可达性、转发效率

防火墙的心智模型:
  "这笔流量合法吗? 如果被授权, 才放行。"
  关注的是: 身份、内容、会话状态、威胁情报
```

> 📌 **Check Point 的定义**：防火墙是基于预定义规则来监控和控制进出网络流量的网络安全系统，允许或拒绝特定类型的流量，充当内部网络的守门人。这一定义精准概括了防火墙与传统网络设备的本质区别。

## 05.02 防火墙是如何诞生的

```
防火墙演进史（05.02）

  第一代: 包过滤防火墙 (Packet Filtering)
       │  基于五元组(源IP/目的IP/源端口/目的端口/协议)
       │  无状态, 每个包独立判断
       │  速度快, 但安全性弱
       ▼
  第二代: 状态检测防火墙 (Stateful Inspection)
       │  跟踪连接状态, 动态维护会话表
       │  属于同一连接的数据包整体看待
       │  现代防火墙的主流基础
       ▼
  第三代: 应用层防火墙 / UTM / NGFW
       │  深度包检测(DPI), 能解析应用层内容
       │  集成 IDS/IPS、防病毒、URL 过滤
       │  识别应用而非仅端口
       ▼
  现代: 下一代防火墙 (NGFW)
          应用感知 + 用户身份 + 威胁情报联动
```

> 📌 **与第3章路由器的历史对照**：正如路由器从"CPU 软件转发"演进到"ASIC 硬件转发"，防火墙从"无状态包过滤"演进到"状态检测"再到"应用层深度检测"——都是**在性能与功能之间不断寻找平衡**的演进史。

## 05.03 防火墙如何分类

作者从两个维度分类 ：

### 05.03.01 软件型防火墙

```
软件型防火墙:
  ├─ 运行在通用操作系统上的防火墙软件
  ├─ 例如: Linux iptables, Windows Firewall
  ├─ 优势: 成本低, 灵活, 适合服务器/主机防护
  └─ 局限: 性能受主机硬件限制, 不适合作为网络边界
```

### 05.03.02 硬件型防火墙

```
硬件型防火墙:
  ├─ 专用硬件 + 专用 OS + 防火墙软件的一体化设备
  ├─ 例如: Cisco ASA/Firepower, Palo Alto PA Series, Fortinet FortiGate
  ├─ 优势: 高性能, 高可靠, 专为网络边界设计
  └─ 局限: 成本较高
```

> 💡 企业网络边界几乎清一色硬件防火墙——因为需要**线速的深度包检测能力**，通用服务器软件难以胜任。

## 05.04 防火墙技术类型

这一节是防火墙的"技术谱系"，对应 05.02 的演进史：

```
防火墙技术类型（05.04）

  包过滤 (Packet Filtering / Stateless)
       │  检查五元组, 无状态
       │  每个包独立匹配 ACL
       ▼
  状态检测 (Stateful Inspection)  ← 现代防火墙基石
       │  维护会话表, 跟踪连接状态
       │  首包匹配策略, 后续包匹配会话
       ▼
  应用层代理 (Application Proxy)
       │  理解应用层协议 (HTTP/FTP/SMTP)
       │  深度解析内容, 防御应用层攻击
       ▼
  深度包检测 (DPI, Deep Packet Inspection)
          检查包头和载荷(payload)
          能识别协议、应用、甚至加密流量中的特征
```

**状态检测的工作机制**（这一节最重要的图）：

```
客户端 ──────► 防火墙 ──────► 服务器
       │                │
       │ ① TCP SYN      │
       │───────────────►│ ② 匹配安全策略
       │                │    若允许 → 创建会话表项
       │                │    (源IP, 目的IP, 端口, 协议, 状态)
       │                │
       │ ③ TCP SYN-ACK  │
       │◄──────────────│ ④ 匹配会话表 → 放行
       │                │
       │ ⑤ TCP ACK      │
       │───────────────►│ ⑥ 匹配会话表 → 放行
       │                │
       │ 后续数据包       │
       │───────────────►│ ⑦ 匹配会话表 → 直接放行
       │                │    (不再逐包匹配安全策略)
```

> 📌 **状态检测的核心价值**：首包做完整策略检查，后续包只需匹配会话表——既安全又高效。这是现代防火墙区别于早期包过滤防火墙的根本。

## 05.05 什么是防火墙的网络接口模式

这一节讲防火墙的三种部署模式：

```
防火墙接口模式（05.05）

  路由模式 (Routed Mode)
       │  防火墙作为 L3 设备, 连接不同网段
       │  内网口配内网网关 IP, 外网口配公网 IP
       │  可做 NAT, 可做路由
       │  最常见的部署方式
       ▼
  透明模式 (Transparent Mode / Bridge Mode)
       │  防火墙作为 L2 设备, 透明接入
       │  不改变原有 IP 规划
       │  对现有网络"无感"插入
       │  适合改造既有网络
       ▼
  混合模式 (Mixed Mode)
          同时运行路由模式和透明模式
          不同接口对不同流量采用不同模式
```

**典型部署拓扑**：

```
路由模式部署:
  
  Internet ──► [路由器] ──► [防火墙] ──► [L3交换机] ──► [L2交换机] ──► 终端
              NAT          路由模式       核心           接入
                           (内网网关)
  
  透明模式部署:
  
  Internet ──► [路由器] ──► [防火墙] ──► [L3交换机] ──► 终端
                          透明模式
                          (不改变IP规划,
                           像一根"智能网线")
```

## 05.06 防火墙能够预防的威胁

这一节列出防火墙能挡住的威胁类型 ：

```
防火墙防范的威胁谱系（05.06）

  网络层攻击:
       ├─ IP 欺骗 (Spoofing)
       ├─ 端口扫描 (Port Scan)
       └─ 分段攻击 (Fragmentation Attack)
  
  传输层攻击:
       ├─ SYN Flood (DoS)
       ├─ TCP 序列号预测
       └─ 半开连接耗尽
  
  应用层攻击:
       ├─ SQL 注入
       ├─ XSS 跨站脚本
       ├─ HTTP 畸形请求
       └─ 恶意 URL 访问
  
  其他:
       ├─ 蠕虫扩散
       ├─ 未授权访问
       └─ 数据泄露
```

> 📌 **重要边界**：防火墙主要防范**基于网络流量的威胁**。对于端点内部的威胁（如 U 盘传播病毒）、社会工程学攻击，防火墙力不从心——需要配合杀毒软件、EDR、安全意识培训等纵深防御手段。

## 05.07 防火墙中搭载的各种功能 ← 本章技术核心

这一节是本章最厚重的部分，从 05.07.01 到 05.07.13 共 13 个小节 。我们按逻辑分组提炼：

### 🔗 第一组：防火墙的"心脏"——会话管理（05.07.01）

```
会话管理 (Session Management):

  每个合法连接 → 一条会话表项
  
  会话表项内容:
  ┌─────────────────────────────────────────┐
  │ 源 IP     │ 目的 IP    │ 协议 │ 源端口 │ 目的端口 │ 状态 │
  ├──────────┴──────────┬──┴──────┴─────┬────┴──────┬─┴──────┤
  │ 192.168.1.10 │ 8.8.8.8 │ TCP  │ 50000 │ 443   │ EST   │
  └──────────────────────────────────────────────┘
  
  工作方式:
  - 首包: 匹配安全策略, 若允许则创建会话
  - 后续包: 直接匹配会话表, 快速放行
  - 会话超时: 无流量则老化清除
```

> 💡 会话表容量和新建速率是防火墙性能的关键指标（呼应 05.08）。

### 🔍 第二组：包解析与安全区域（05.07.02–05.07.04）

```
分组结构解析 (05.07.02):
  防火墙深入解析每个包的:
  - L2: MAC 头
  - L3: IP 头 (源/目的 IP, 协议, TTL)
  - L4: TCP/UDP 头 (端口号, 标志位)
  - L7: 应用层数据 (HTTP 方法, URL, 载荷特征)

安全区域 (05.07.03):  ← 防火墙的核心概念
  将网络划分为不同安全级别的区域:
  
  ┌────────────────────────────────────────────┐
  │  Untrust (5)    │  DMZ (50)    │  Trust (85)  │
  │  互联网          │  对外服务器区  │  内部网络     │
  │  安全级别最低     │  中等         │  安全级别最高  │
  └────────────────────────────────────────────┘
  
  区域间流量默认拒绝, 必须由安全策略显式放行
  级别高→级别低: 默认允许 (Trust → Untrust)
  级别低→级别高: 默认拒绝 (Untrust → Trust)
  
  典型流量:
  Trust → Untrust: 内网用户访问互联网 (允许+NAT)
  Trust → DMZ: 内网用户访问自有服务器 (允许)
  Untrust → DMZ: 外部用户访问 Web 服务器 (仅开放 80/443)
  Untrust → Trust: 外部主动访问内网 (默认拒绝)

安全策略 (05.07.04):  ← 防火墙的"交通规则"
  匹配条件:
    源区域 / 目的区域 / 源 IP / 目的 IP / 服务 / 应用
  动作:
    允许 (Permit) / 拒绝 (Deny) / 丢弃 (Drop)
  
  策略匹配流程:
    流量进入 → 匹配源/目的区域 → 顺序匹配安全策略
    ① 匹配到 Permit → 创建会话, 放行
    ② 匹配到 Deny → 丢弃, 记录日志
    ③ 无匹配 → 默认拒绝 (Implicit Deny)
```

### 🌐 第三组：NAT 与 VPN（05.07.05–05.07.06）

```
NAT (05.07.05):  ← 既是连通技术, 也是安全技术

  SNAT (源 NAT):
    内网 IP ──► 公网 IP
    192.168.1.10:50000 ──► 203.0.113.1:50000
    作用: 隐藏内网拓扑 + 节省公网 IP
    
  DNAT (目的 NAT / 端口映射):
    公网 IP:端口 ──► 内网 IP:端口
    203.0.113.1:80 ──► 192.168.1.100:80
    作用: 让外部访问内网服务器 (通常放 DMZ)
    
  PAT (端口复用):
    多个内网 IP 共享一个公网 IP
    靠端口号区分不同会话
    家用路由器 / 企业出口最常用

VPN (05.07.06):  ← 在公网上建"私人隧道"

  IPSec VPN:
    站点到站点的加密隧道 (Site-to-Site)
    总部 ──[加密隧道]── 分支
    
  SSL VPN:
    远程用户接入 (Remote Access)
    出差员工 ──[浏览器/客户端]── 公司内网
    
  VPN 在防火墙上的价值:
  - 远程办公安全接入
  - 分支机构安全互联
  - 所有隧道流量加密, 防窃听
```

### 🛡️ 第四组：威胁防御（05.07.07–05.07.09）

```
DoS 防御 (05.07.07):

  SYN Flood 防御原理:
    攻击者发送海量 TCP SYN, 不完成握手
    → 服务器半开连接耗尽 → 服务不可用
    
  防火墙的防御:
  ┌──────────────────────────────────────────┐
  │  阈值监控: 某源 IP 的 SYN 速率 > 阈值      │
  │  → 临时封锁该源 IP                        │
  │                                          │
  │  SYN Cookie: 不分配资源, 用算法验证 ACK   │
  │  → 合法用户正常通过, 攻击者得不到响应      │
  │                                          │
  │  会话数限制: 单 IP 最大并发会话数          │
  │  → 超过即丢, 防止资源耗尽                  │
  └──────────────────────────────────────────┘

防范基于分组的攻击 (05.07.08):
  - IP 欺骗防护: 检查源 IP 合理性
  - 分片攻击防护: 重组分片, 检测异常
  - 端口扫描检测: 识别扫描行为, 自动封锁
  - 异常协议检测: 不符合 RFC 的包直接丢弃

基于内容的扫描 (05.07.09):
  - 深度包检测 (DPI): 检查包载荷
  - IDS/IPS: 匹配攻击特征库
  - 防病毒: 文件下载时扫描
  - URL 过滤: 阻断恶意网站
  - 应用识别: 识别 Skype/BT/微信等应用
```

### 📊 第五组：管理与虚拟化（05.07.10–05.07.13）

```
监视、报告功能 (05.07.10):
  - 实时流量监控
  - 威胁事件日志
  - 报表生成 (合规性要求)

分组捕获 (05.07.11):
  - 抓包分析, 类似 tcpdump
  - 排障利器

虚拟路由器 (05.07.12):
  - 一台防火墙跑多个虚拟路由实例
  - 不同 VPN/租户用不同路由表

虚拟防火墙 (05.07.13):  ← 云时代的产物
  - 一台物理防火墙虚拟化出多台逻辑防火墙
  - 每个租户/部门独立管理
  - 云计算、多租户场景必备
```

## 05.08 决定防火墙性能的要素

这一节给出了防火墙选型的三大核心指标 ：

```
防火墙性能三要素（05.08）

  ① 同时在线会话数 (Concurrent Sessions)
      防火墙会话表的最大容量
      企业级: 百万级 ~ 千万级
      决定能支撑多少并发连接
      
  ② NAT 表数目 (NAT Table Size)
      NAT 转换表的最大容量
      决定能同时做多少个地址转换
      
  ③ 每秒新建的会话数目 (New Sessions per Second)
      每秒能建立的新连接数
      比并发数更能反映"抗压能力"
      DoS 攻击场景下是生死线
      
  综合性能公式:
      防火墙性能 = f(会话容量, 新建速率, 吞吐带宽, DPI 开启后的性能衰减)
      
  ⚠️ 关键点: 开启 DPI/IPS/防病毒后, 性能通常会衰减 30%~70%
             选型时必须看"全功能开启时的性能"
```

> 💡 **选型陷阱**：厂商宣传的"吞吐量 10 Gbps"往往是**仅包过滤模式下**的数字。开启 DPI + IPS + 防病毒后，实际性能可能只剩 3-5 Gbps。**一定要看"全功能模式下的性能"**。

## 05.09 同信息安全范畴相关的标准

这一节讲防火墙的合规性标准 ：

```
信息安全标准（05.09）

  ISCA: 信息系统安全标准
  FIPS: 联邦信息处理标准 (美国)
        FIPS 140-2: 加密模块的美国政府标准
  ISO/IEC 15408 (Common Criteria, 公共标准):
        国际通用的安全产品评估标准
        EAL1~EAL7 七个保证级别
        企业/政府采购的重要参考
```

> 📌 企业采购防火墙时，特别是政府、金融、运营商行业，**Common Criteria 认证等级**是硬性门槛。

**读这一章的六条连结意识**（写进笔记的价值点）：

1. **与前四章的承接**：前四章解决"通"，本章解决"安全通"。**连通是基础，安全是边界**——没有防火墙，路由器/L3 交换机把网络连起来，但也把威胁放了进来。
2. **与第3章路由器的边界**：路由器也能做 NAT、也能配 ACL、也有 VPN 功能，但**路由器是"兼职"做安全，防火墙是"专职"做安全**。防火墙的安全区域模型、状态检测、DPI、应用识别、IDS/IPS 是路由器不具备或很弱的。
3. **与第4章 L3 交换机的边界**：L3 交换机做内网高速跨 VLAN 路由，但**不做深度安全检测**。企业网的典型架构是：
    
    ```
    Internet → 路由器(NAT/出口) → 防火墙(安全边界) → L3交换机(核心) → L2交换机(接入) → 终端
    ```
    
    防火墙站在"外网和内网之间"以及"内网不同安全区域之间"。
    
1. **状态检测是灵魂**：05.07.01 的会话管理 + 05.04 的状态检测技术，是理解现代防火墙的钥匙。**首包匹配策略，后续包匹配会话**——这一机制既保证了安全，又保证了性能。
2. **安全区域模型**：Trust/DMZ/Untrust 的三区域模型是防火墙配置的基础思维。理解了这个模型，就能理解为什么 DMZ 放对外服务器、为什么 Trust→Untrust 默认允许而反向默认拒绝。
3. **性能要看"全功能模式"**：05.08 的三个指标中，**每秒新建会话数**在 DoS 攻击场景最关键，**并发会话数**决定日常容量，**NAT 表数目**决定出口转换能力。开启 DPI/IPS 后的性能衰减是选型必须考虑的。

至此，**"连通 → 安全连通"**​ 这条主线已经闭合：

- **L2 交换机**解决了同 VLAN 内高速转发
- **路由器**解决了跨网络互联和出口 NAT
- **L3 交换机**解决了内网跨 VLAN 高速路由
- **防火墙**解决了"谁能通过、能防什么威胁"
