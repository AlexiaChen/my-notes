# 第11章 两个表的亲密接触——连接的原理

## 本章主线

连接的本质是把两个关系组合起来，再根据连接条件过滤。SQL 写法描述逻辑结果，优化器决定物理顺序和算法。

$$
R\bowtie_\theta S
=\{(r,s)\mid r\in R,\ s\in S,\ \theta(r,s)=\text{true}\}
$$

## 11.1 连接简介

### 11.1.1 连接的本质

最直接的连接是笛卡尔积后过滤。若 R 有 m 行、S 有 n 行，暴力比较需要接近 m×n 次组合。索引和更好的连接顺序，就是在避免枚举不可能匹配的组合。

连接条件放在 ON 和 WHERE 的位置还会影响外连接语义。理解逻辑结果后，才能判断优化器改写是否等价。

### 11.1.2 连接过程简介

多表连接通常先选一个外表，再用它的每行或一批行去访问内表。真正执行时，连接顺序可能与 SQL FROM 顺序不同。

```mermaid
flowchart LR
    A[选择外表/驱动表] --> B[取一行或一批行]
    B --> C[用常量或外表列访问内表]
    C --> D[应用连接条件]
    D --> E[输出中间结果]
    E --> B
```

驱动表不是 FROM 中写在前面的表，而是优化器认为能最快减少中间结果的表。

### 11.1.3 内连接和外连接

内连接只保留两边都匹配的行；左外连接即使右表没有匹配，也保留左表行并用 NULL 补右侧列。外连接消除和谓词下推必须保证 NULL 补齐语义不被改变。

## 11.2 连接的原理

### 11.2.1 嵌套循环连接

Nested Loop Join 的基本形式是：

```text
for each row in outer:
    scan or lookup inner
```

若外表有 N 行、内表每次访问成本为 C，总成本近似 N×C。关键是让外表候选少、内表能走索引。

### 11.2.2 使用索引加快连接速度

内表连接列有索引时，每个外表值可以做 ref、const 或 range 查找，而不是扫描内表。推荐索引通常从连接列开始，再补过滤、排序或覆盖列。

```sql
SELECT o.id, c.name
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id
WHERE o.created_at >= '2026-01-01';
```

这里 customers.id 的主键索引支持内表点查；orders.created_at 或组合索引决定外表候选数量。

### 11.2.3 基于块的嵌套循环连接

Block Nested-Loop 的思想是把多行外表结果放进连接缓冲区，减少内表重复扫描。现代 MySQL 版本中，相关优化可能由 BNL 名称承载 hash join 等策略，具体是否生效要看版本、优化器开关和 EXPLAIN。

块连接是以内存换 I/O：缓冲区太小，重复扫描多；太大，会挤压连接内存、排序和 Buffer Pool。配置不能脱离工作负载。

## 11.3 总结

- 连接是关系组合，优化器负责避免无意义的笛卡尔积；
- 驱动表由中间结果和成本决定，不由书写顺序决定；
- Nested Loop 的关键是外表少、内表索引好；
- 块连接以内存换重复扫描；
- 连接条件、外连接 NULL 语义和索引列顺序必须一起分析。
