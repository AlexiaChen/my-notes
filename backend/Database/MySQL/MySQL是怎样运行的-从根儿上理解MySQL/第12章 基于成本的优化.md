# 第12章 谁最便宜就选谁——基于成本的优化

## 本章主线

优化器面对多个可行计划。它不能把每个计划都完整执行一遍，于是用统计信息和成本常数估算读多少页、比较多少行、做多少排序和连接，再选择估计值最小的计划。

```mermaid
flowchart LR
    A[SQL 与约束] --> B[枚举访问路径]
    B --> C[估算行数与页数]
    C --> D[估算 CPU/I/O/临时空间]
    D --> E[比较候选计划]
    E --> F[执行成本最低的计划]
```

## 12.1 什么是成本

成本不是现实时间的精确预言，而是用于比较计划的统一尺度。粗略模型：

$$
\text{cost}
\approx
c_{\text{io}}\cdot\text{pages}
+c_{\text{cpu}}\cdot\text{rows}
+c_{\text{tmp}}\cdot\text{temporary work}
$$

即使估计值没有单位，只要能在候选计划之间排序，就有决策价值。模型错误的根源通常是行数估错，而不是乘法本身错。

## 12.2 单表查询的成本

### 12.2.1 准备工作

```sql
CREATE TABLE t (
  id BIGINT PRIMARY KEY,
  status INT NOT NULL,
  created_at DATETIME NOT NULL,
  payload VARCHAR(200)
);
CREATE INDEX idx_status_time ON t(status, created_at);
```

不要只用均匀随机数据测试。真实业务往往有热点状态、时间倾斜和相关列，正是这些分布让估算困难。

### 12.2.2 基于成本的优化步骤

单表优化可以拆成：解析条件和可用索引；为每条索引生成点查、范围、索引扫描候选；估算候选行数、页数和回表次数；计算过滤、排序、分组和临时表成本；比较全表扫描与索引方案；选择估计成本最低的计划。

真正要看的不是用了索引，而是索引扫描多少行、回表多少次、最终返回多少行。

### 12.2.3 基于索引统计数据的成本计算

优化器会使用索引基数、采样页、不同值数量和数据分布估算范围选择性：

$$
\widehat{N}_{\text{result}}
=N_{\text{table}}\times\widehat{\text{selectivity}}
$$

若选择性估计偏小，可能错误选择索引；偏大，可能错误选择全表扫描。长事务、数据突变和统计信息陈旧都会放大误差。

## 12.3 连接查询的成本

### 12.3.1 准备工作

连接实验应准备不同大小的表、连接列上的唯一/非唯一/无索引情况、过滤条件在连接前后的不同位置，以及均匀与倾斜数据。

### 12.3.2 条件过滤（Condition Filtering）

Condition Filtering 估计表通过连接条件和其他过滤条件后还剩多少比例。若外表估计输出变小，后续内表访问次数也会变小。

一个普通 WHERE 条件可能决定整个多表计划，因为它改变了中间结果大小。

### 12.3.3 两表连接的成本分析

对于外表 R、内表 S 的 Nested Loop，可粗略写：

$$
C(R\rightarrow S)
\approx
C_{\text{scan}}(R)
+N_R\cdot C_{\text{lookup/scan}}(S)
$$

交换顺序后，N 和内表访问成本都会变化。没有索引时两种顺序都可能昂贵；有索引时，应选择能产生少量外表行并快速访问内表的方向。

### 12.3.4 多表连接的成本分析

N 张表的连接顺序有大量排列，完全枚举会快速增长。优化器会用动态规划、贪心搜索和剪枝寻找足够好的方案，而不是保证探索所有排列。

统计信息错误会在连接中级联：第一张表少估或多估，第二张表访问次数就会偏离，后面每个表继续放大误差。

## 12.4 调节成本常数

### 12.4.1 mysql.server_cost 表

server_cost 表保存服务器层操作的成本估计，例如比较、排序和临时表。修改它是在告诉优化器某类操作相对更贵或更便宜，不是直接让硬件变快。

### 12.4.2 mysql.engine_cost 表

engine_cost 表描述存储引擎相关成本。官方文档说明，优化器成本模型使用 server_cost 和 engine_cost 表中的估计值，也可以调整这些值（[Optimizer Cost Model](https://dev.mysql.com/doc/refman/8.4/en/cost-model.html)）。

不要把成本常数当成第一调优手段。先修统计信息、索引和查询结构；只有当硬件环境与默认模型长期不匹配，并且有对照实验时，才考虑调整成本表。

## 12.5 总结

- 优化器用成本估算比较计划，不直接测量每个计划；
- 行数估计是单表和连接计划的核心；
- 连接顺序会把估算误差层层放大；
- 成本常数是模型校准工具，不是性能魔法；
- EXPLAIN、实际行数和运行时间要结合起来验证估算质量。
