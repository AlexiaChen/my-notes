# 第10章 条条大路通罗马——单表访问方法

## 本章主线

访问方法回答的是：为了得到这张表的候选行，优化器选择怎样走。EXPLAIN 的 type 是路径分类，不是从好到坏的绝对排行榜；const 也可能因为回表或结果量大而不如一次范围扫描。

## 10.1 访问方法的概念

给定表、索引和条件，优化器要选择全表扫描、索引扫描、点查找或范围扫描。访问方法的目标是减少总成本，而不是最大化“使用索引”。

$$
\text{work}
\approx
\text{pages visited}
\,+\,
\text{candidate rows}
\,+\,
\text{post-filter CPU}
$$

## 10.2 const

当主键或唯一索引使用常量等值条件时，优化器知道最多得到一行，可以把表视为常量表：

```sql
SELECT * FROM users WHERE id = 42;
```

const 的基础是唯一性约束，而不是写了等号。若列没有唯一索引、发生类型转换或条件不完整，就不能得到同样保证。

## 10.3 ref

ref 用非唯一索引做等值匹配，可能返回多行：

```sql
SELECT * FROM orders WHERE customer_id = 10;
```

在连接中，右表索引列也常用前一个表输出的值查找。性能取决于每个键值对应多少行以及是否需要回表。

## 10.4 ref_or_null

ref_or_null 同时查找某个值和 NULL：

```sql
SELECT * FROM t WHERE key_col = 10 OR key_col IS NULL;
```

它体现了 SQL 三值逻辑对访问路径的影响。NULL 不是普通值，优化器需要额外处理 NULL 分支。

## 10.5 range

range 在索引上扫描一个或多个区间，例如等值列表、BETWEEN、不等式和前缀 LIKE。范围边界越窄，候选行越少；范围很宽时，优化器可能认为全表扫描更便宜。

## 10.6 index

index 表示扫描整个二级索引或某个完整索引，而不是扫描整张聚簇数据。若索引比数据行窄，且查询只需索引列，index 可能比 all 便宜；若要回表，优势可能消失。

## 10.7 all

all 是表扫描。它不自动等于坏计划：小表、低选择性条件、需要返回大部分行或索引回表昂贵时，全表扫描可能就是成本最低的路。

## 10.8 注意事项

### 10.8.1 重温二级索引+回表

二级索引先得到主键，再访问聚簇索引。候选行一多，随机回表会主导成本。覆盖索引可以消除回表，但会扩大索引本身。

### 10.8.2 索引合并

Index Merge 可能分别扫描多个索引，再做交集、并集或排序去重。它是优化器的备选方案，不是索引越多越好的证明；如果组合索引能直接表示查询范围，通常更容易得到稳定计划。

检查方法：

```sql
EXPLAIN SELECT ...;
SHOW VARIABLES LIKE 'optimizer_switch';
```

## 10.9 总结

- 访问方法是候选行生成方式；
- const、ref、range 描述不同强度的索引定位；
- index 是完整索引扫描，all 是表扫描；
- 二级索引回表和数据分布决定实际代价；
- EXPLAIN type 只能结合 rows、filtered、Extra 和真实耗时解释。
