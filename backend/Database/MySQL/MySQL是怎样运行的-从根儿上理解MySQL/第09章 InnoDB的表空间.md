# 第9章 存放页面的大池子——InnoDB 的表空间

## 本章主线

页是搬运数据的基本单位，但页不能凭空出现。表空间负责给页分配长期地址；区把连续页组织成更适合 I/O 的块；段把不同用途的区组织成逻辑空间。可以把它理解为：

```text
表空间 → 段 → 区 → 页 → 记录
```

## 9.1 回忆一些旧知识

### 9.1.1 页面类型

表空间中可能包含数据页、索引页、undo 页、段管理页、空闲空间管理页和系统页。页类型告诉 InnoDB 该页如何解析和回收。

### 9.1.2 页面通用部分

File Header、Page Header、File Trailer 等通用结构提供页身份、状态、校验和邻接信息。通用结构是表空间可管理、可恢复的前提。

## 9.2 独立表空间结构

独立表空间通常对应一个表的 .ibd 文件。默认 file-per-table 的价值是隔离空间、便于单表传输和回收，但文件数量多、空间碎片和文件管理复杂度也会增加。

### 9.2.1 区的概念

区是连续的一组页，目的是让空间分配和顺序 I/O 不必逐页管理。默认 16 KiB 页时，常见区大小约为 1 MiB；如果实例使用其他页大小，区的页数和实际字节数要以版本文档为准。

$$
\text{extent bytes}
=\text{pages per extent}\times\text{page size}
$$

区不是保证每次查询都顺序读，而是给分配器一个合理的连续粒度。

### 9.2.2 段的概念

段是同一棵索引或同一用途页的逻辑集合。例如聚簇索引和二级索引会有各自的段。段把“索引在增长”转译成“从表空间领取更多区”。

把段看成租户，把区看成批量配额，把页看成实际房间，能理解为什么删除一部分记录不一定立刻让文件缩小：段可能仍持有已分配区。

### 9.2.3 区的分类

区可能处于空闲、已使用、部分使用或属于某个段的状态。InnoDB 需要维护这些状态，避免两个段同时使用同一页，也要尽量减少小表和小索引造成的内部浪费。

小表早期可能按碎片页分配，避免立刻占用大量完整区；表增长后再转向更规整的区分配。空间大小与已经写入多少用户记录不是同一个概念。

### 9.2.4 段的结构

段通过段入口和页链表记录自己拥有的区、空闲页和已使用页。不同链表服务于不同分配阶段：空闲页可直接使用，部分使用区适合填充，完整区等待新分配。

这种多级链表是典型的分配器设计：用少量元数据换取避免全表扫描的快速空间申请。

### 9.2.5 各类型页面详细情况

表空间开始位置通常有空间管理页，描述表空间大小、区状态和空闲链表；段管理页描述段入口和区链表；索引页保存 B+ 树节点。undo 表空间还会有专用于 undo 的页和回滚段结构。

学习时要把页中有什么和页为什么被分配给这个对象分开。前者是页布局，后者是表空间分配器。

### 9.2.6 Segment Header 结构的运用

Segment Header 把一个索引的逻辑段与实际页/区链表连接起来。创建索引时建立入口；索引增长时从段的空闲结构申请页；删除或重建时回收这些页。

它解释了一个常见运维现象：删除大量数据可能降低逻辑行数，却不一定缩小 .ibd 文件，因为文件空间是否能交还操作系统取决于表重建、空间布局和版本能力。

### 9.2.7 真实表空间对应的文件大小

文件大小包含已分配但未填满的区、页头尾开销、索引和内部碎片。粗略可写为：

$$
\text{file size}
\ge
\text{user data}
\,+\text{indexes}
\,+\text{free allocated space}
\,+\text{metadata}
$$

查看表空间元数据：

```sql
SELECT NAME, SPACE, SPACE_TYPE, FILE_SIZE, ALLOCATED_SIZE
FROM information_schema.INNODB_TABLESPACES;
```

线上空间治理要区分表内可复用空间和操作系统可见空闲空间，处理手段分别是继续写入复用、优化表、重建表或迁移表空间。

## 9.3 系统表空间

系统表空间是共享的 InnoDB 表空间，历史上承担了更多系统数据和表数据。现代 MySQL 默认 file-per-table，undo 也有独立表空间选项，但系统表空间仍可能包含数据字典相关信息、change buffer 或历史遗留对象，具体取决于版本和配置。

共享表空间的优点是管理文件少、共享空间容易；缺点是单个文件可能持续增长，回收和隔离不如独立表空间直观。不要直接删除 ibdata 文件，除非有完整备份、明确重建方案并已停止实例。

## 9.4 总结

- 页是 I/O 单位，区是分配和顺序 I/O 的批量单位；
- 段把索引或 undo 的逻辑需求映射到区和页；
- 表空间文件大小不等于用户数据大小；
- file-per-table 提供隔离和迁移便利，系统表空间提供共享管理；
- 观察空间时必须同时看逻辑行数、索引、已分配空间和可回收空间。
