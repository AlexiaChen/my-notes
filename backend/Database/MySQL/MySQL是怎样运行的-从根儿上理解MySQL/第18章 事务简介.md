# 第18章 从猫爷借钱说起——事务简介

## 本章主线

事务解决的不是“把多条 SQL 放在一起”这么简单，而是让一组状态变化表现为一个可接受的整体。转账要么扣款和入账都发生，要么都不发生；并发读写不能把中间状态暴露给不该看到的人；提交后的结果要能抵抗崩溃。

## 18.1 事务的起源

以转账为例，业务不变量是：

$$
\text{balance}_{A}+\text{balance}_{B}
=\text{constant}
$$

事务机制把这个不变量从应用程序的“希望”变成数据库可以协助维护的约束。

### 18.1.1 原子性（Atomicity）

原子性要求事务内的逻辑修改不可被拆开观察：成功时全部生效，失败时全部撤销。

实现上不是保存一份完整数据库副本，而是记录足够的 undo 信息和事务状态，在回滚时恢复修改。原子性只对同一事务和支持事务的引擎有效；混用非事务引擎会破坏整体语义。

### 18.1.2 隔离性（Isolation）

隔离性规定并发事务彼此能看到什么。完全串行化最简单但吞吐低，所以数据库提供多个隔离级别，用 MVCC 和锁在一致性与并发之间取舍。

隔离不是“互相完全看不见”，而是明确规定哪些版本和哪些锁冲突。

### 18.1.3 一致性（Consistency）

一致性不是 InnoDB 单独提供的按钮，而是事务前后都满足业务约束的结果。数据库可以通过类型、唯一键、外键、检查约束和事务原子性帮助维护，但错误的业务逻辑仍会提交一个“内部合法、业务错误”的状态。

### 18.1.4 持久性（Durability）

持久性要求提交成功后结果在崩溃恢复后仍存在。InnoDB 通过 redo、WAL、刷盘和恢复过程实现；但耐久性还依赖磁盘 flush、文件系统、电源保护和配置。

## 18.2 事务的概念

事务是数据库状态从一个一致点到另一个一致点的受保护变化序列。它有开始、执行、提交或回滚，以及与其他事务并发时的可见性和锁关系。

不要把事务边界随意扩大。事务越长，持有的锁越久、undo 越多、purge 越难前进、失败重试成本越高。

## 18.3 MySQL 中事务的语法

### 18.3.1 开启事务

```sql
START TRANSACTION;
-- 或 BEGIN;
```

可以指定 READ ONLY、隔离级别或 WITH CONSISTENT SNAPSHOT。具体快照何时建立取决于隔离级别和第一次一致性读。

### 18.3.2 提交事务

```sql
COMMIT;
```

提交是对外宣布事务结果的边界。应用收到成功响应后才能认为业务动作完成；网络断开时要设计幂等键和重试策略，避免客户端不知道提交结果而重复扣款。

### 18.3.3 手动中止事务

```sql
ROLLBACK;
```

回滚依赖 undo 记录。回滚不是把执行过的 SQL 文本重新反向执行，而是依据物理修改记录恢复之前的版本。

### 18.3.4 支持事务的存储引擎

事务能力属于存储引擎。InnoDB 支持 ACID、回滚和崩溃恢复；某些非事务引擎即使接受 COMMIT 语法，也不一定具备相同语义。

检查表引擎：

```sql
SELECT TABLE_SCHEMA, TABLE_NAME, ENGINE
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'app';
```

### 18.3.5 自动提交

autocommit 开启时，一条成功的 DML 通常就是一个独立事务：

```sql
SELECT @@autocommit;
SET SESSION autocommit = 0;
```

关闭自动提交后，应用必须显式 COMMIT 或 ROLLBACK。连接池归还连接时若没有清理未提交事务，可能长期持锁。

### 18.3.6 隐式提交

某些 DDL、账户管理、事务控制和锁表语句会隐式提交，具体清单随版本和语句而定。不要把 DDL 混在需要原子回滚的业务事务中，除非已经确认其语义。

### 18.3.7 保存点

保存点允许回滚到事务内部的某个位置：

```sql
SAVEPOINT after_header;
ROLLBACK TO SAVEPOINT after_header;
RELEASE SAVEPOINT after_header;
```

保存点适合批量处理中的局部失败，但不会释放整个事务已持有的所有资源，长事务问题仍然存在。

## 18.4 总结

- 原子性保护一组修改，隔离性规定并发可见性，持久性抵抗崩溃；
- 一致性需要数据库约束和业务逻辑共同完成；
- 事务边界由 START/COMMIT/ROLLBACK、自动提交和隐式提交共同决定；
- undo 支持回滚，redo 支持持久化和崩溃恢复；
- 事务越短、边界越清晰，锁、undo、purge 和重试越容易管理。
