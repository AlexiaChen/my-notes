
# 读书笔记：Chapter 4 - Bounding Volume Hierarchies (BVH)

**核心主题：用"嵌套的保守包围体"包裹对象，以极廉价的"不相交拒绝"換取数量级的查询加速**

## 一、全局视角：BVH 在全书脉络中的位置

回顾前三章的演进路径：

- **第一章**​ 四叉树/八叉树：按**固定空间栅格**递归细分，轴对齐、与对象无关
- **第二章**​ kd树/范围树：轴对齐的"查询驱动"索引，适合窗口/穿刺查询
- **第三章**​ BSP 树：用**任意超平面**切割空间，换取绘制顺序与 CSG 能力
    
本章的 BVH 是另一种哲学——**"对象导向"的层次结构**：

> 不再切割空间本身，而是把**图元（三角形、粒子、物体）** 递归地分组，每组用一个"包围体"包起来。

```
四叉树/八叉树:  空间 → 被切成格子 → 格子里放对象
BSP 树:        空间 → 被平面切开 → 凸区域中含对象
BVH:           对象 → 被分组嵌套 → 每组外包一个包围盒
```

**为什么这种"倒过来"的思路极其强大？**

核心洞察：**如果两组对象的包围体不相交，那么这两组对象内部的所有图元对都不可能相交**。这个简单的排除法则，使得我们可以在 O(logN+K) 时间内完成碰撞检测，而暴力方法是 O(N2) 。

BVH 已成为现代计算机图形学的**支柱性加速结构**：

- **CPU 光线追踪**：Intel Embree（被 Blender Cycles、Arnold、Corona 使用）
- **GPU 硬件光线追踪**：NVIDIA RTX 的 RT Cores 专门加速 BVH 遍历
- **物理引擎宽相位**：Bullet Physics、Box2D 的动态 AABB 树
- **科学计算**：分子动力学、粒子系统的邻近搜索

## 二、逐节深度解读

### 1. BVH 的构造

#### 1.1 构造标准 (Construction Criteria)

构造 BVH 的本质，是在三个相互竞争的目标之间寻找平衡 ：

|目标|含义|冲突|
|---|---|---|
|**紧致性**​ (Tightness)|包围体尽可能贴合对象，减少空区域|紧致的包围体（如 OBB）测试成本高|
|**测试速度**​ (Test Speed)|单个节点的相交测试要快|快速的包围体（如 AABB、球）往往较松散|
|**内存与缓存**​ (Memory/Cache)|节点小巧、布局连续|紧致表示通常需要更多存储|

**包围体类型的权衡**​ ：

- **AABB（轴对齐包围盒）**：只需 6 个 float 存储，slab 方法无分支测试，**实践中占据绝对主导**。偶尔的松散性被其极低的测试成本抵消——"你可以承受访问更多节点，因为每个节点测试极快"。
- **球体 (Sphere)**：测试最简单，但对细长三角形拟合极差，多用于早期游戏引擎和动态对象
- **OBB（有向包围盒）**：最紧致，但 OBB-OBB 相交测试需要 10-15 个分离轴测试，**比 AABB 慢 5-10 倍**
- **k-DOP**：具有 k/2 对固定方向的平行面的凸多面体，18-DOP 在紧密性和测试成本间取得极佳平衡，**Unreal Engine 的碰撞系统采用**
- **胶囊体 (Capsule)**：特别适合动画骨架中的肢体等细长形状
    
> 💡 **核心结论**：AABB 之所以在绝大多数场景下胜出，是因为**单节点测试的极低成本让你有能力访问更多节点**——总体遍历时间反而最短 。

#### 1.2 用于碰撞检测的标准 (Criteria for Collision Detection)

当 BVH 专用于碰撞检测（而非光线追踪）时，构造标准会有所偏移：

- **宽相位 (Broad-phase) 需求**：首要目标是快速排除明显不相交的对象对，AABB 是最佳选择
- **动态场景适应性**：包围体需要易于更新（AABB 仅需更新 min/max 角点）
- **运动包络 (Motion Envelope)**：对于移动对象，使用 **fat AABB**——在对象实际 AABB 基础上按速度扩张 margin：`fat_aabb = aabb.expand(v × Δt × 2)`，避免每帧重构
- 子弹物理引擎和 Box2D 都采用动态 AABB 树作为宽相位
    
#### 1.3 构造算法 (Construction Algorithms)

BVH 构造算法的核心问题：**如何递归地分割图元集合？**

**(a) 自顶向下构造 (Top-down)**​

最常见的方法，从所有图元的根节点开始递归分割：

1. **中点分割 (Midpoint Split)**：
    - 计算节点图元的 AABB
    - 沿最长轴 (x/y/z) 排序
    - 在中点切开
    - 简单，但可能产生不平衡树（退化情况：所有质心共面 → 一侧为空）
2. **表面积启发式 (Surface Area Heuristic, SAH)**：**业界黄金标准**​
    
CSAH​(A,B)=S(C)S(A)​⋅kA​⋅ti​+S(C)S(B)​⋅kB​⋅ti​+ttrav​

其中 S(⋅) 是表面积，k 是子节点图元数，ti​ 是图元相交测试成本，ttrav​ 是节点遍历成本。

**直觉**：射线命中父节点后，命中某个子节点的概率正比于该子节点表面积占父节点表面积的比例。SAH 选择使期望遍历成本最小的分割。

1. **桶化 SAH (Binned SAH)**：将长轴分为 K 个桶（K=32），只在桶边界尝试 K-1 个分割位置，每层复杂度从 O(NlogN) 降到 O(N)，质量几乎无损（K≥16 时）
    
**(b) 自底向上构造 (Bottom-up / LBVH)**​

- 将图元质心坐标编码为 **Morton 码**（Z-order 曲线），空间上相近的图元获得相近的编码
- 按 Morton 码排序
- 自底向上构建树
- **GPU 友好**，可大规模并行，适合实时 BLAS 构建（Vulkan/DXR 场景）
    
**(c) 宽 BVH (BVH4, BVH8)**​

每个节点 4 或 8 个子节点，利用 SIMD 同时测试 4/8 个 AABB，**Embree 等现代光线追踪库采用**。

**(d) 图元重排序**

构建完成后，按 BVH 叶子顺序重排图元，使遍历时被一起访问的三角形在内存中也连续，**极大改善缓存一致性**。

### 2. 更新渐变对象 (Updating Gradual Objects)

这是 BVH 相比 BSP 树、四叉树等静态结构的**关键工程优势**——天然适应动态场景。

#### 核心策略：Refit（重适配）

对于小幅运动，无需重构树，**自底向上遍历，重新计算每个父节点的包围体以包裹其（已移动的）子节点**​ ：

```
def refit(node):
    if node.is_leaf:
        node.bounds = compute_aabb(node.primitives)
    else:
        refit(node.left)
        refit(node.right)
        node.bounds = union(node.left.bounds, node.right.bounds)
```

- **复杂度**：O(n)，可轻松并行化
- **问题**：随着对象漂移，包围体逐渐变得松散，树的质量退化
    
#### 质量退化的应对

当 refit 导致的质量退化超过阈值（如表面积膨胀 > 40%），触发以下修复机制 ：

1. **周期性完全重建**：对于快速形变的几何体（如布料、流体），每帧完全重建并不罕见
2. **树旋转 (Tree Rotations)**：Utah 大学 Thiago 等人的核心贡献
    - 在 refit 的同一次后序遍历中，尝试交换兄弟节点及其孙子节点
    - 如果交换降低了子树的 SAH 成本，则保留交换
    - **关键优势**：旋转与 refit 共享内存访问，几乎零额外成本
    - 效果：动画场景中比单纯 refit 或每帧并行重建都更高效
3. **叶子分裂与合并**：图元移开时分裂叶子，靠近时合并叶子，是"每帧的增量部分排序"而非完全重建
4. **局部 treelet 重建**：只对 SAH 退化超过阈值的局部子树进行重建，保全树的其他部分
    
#### 工程实践模式（DXR/Vulkan 推荐）

```
静态 BLAS（PREFER_FAST_TRACE）→ 构建一次并压缩
动态 BLAS（ALLOW_UPDATE）→ 按节奏 refit/rebuild
TLAS（Top-Level AS）→ 每帧仅更新实例变换
```

这是处理混合静态/动态场景的**实用默认模式**——静态几何体享受紧凑的高质量 BVH，动态对象独立管理更新节奏。

#### 物理引擎中的动态 AABB 树

Bullet Physics 和 Box2D 的做法 ：

- 使用 **fat AABB**（带 margin 扩张）
- 对象移动时，只有当实际 AABB 超出存储的 fat AABB 时才重构该对象在树中的位置
- 利用 **AVL 式树旋转**保持平衡
- 每个移动对象的平均更新成本为 **O(log N) 摊还**，远优于完全重建

### 3. 碰撞检测 (Collision Detection)

BVH 在碰撞检测中的角色是 **broad-phase（宽相位）加速**——快速排除不可能相交的对象对，将候选对缩减到最小，再交给 narrow-phase（窄相位）做精确几何测试。

#### 算法框架

```
查询重叠(node, query, results):
    if not overlap(node.bounds, query):
        return
    if node.is_leaf:
        for obj in node.objects:
            if overlap(obj, query):
                results.append(obj)
    else:
        query_overlap(node.left, query, results)
        query_overlap(node.right, query, results)
```

#### 复杂度分析

- **查询复杂度**：O(log N + K)，其中 K 为返回的结果数
- **对比暴力法**：N=10000 对象时，暴力需要 O(N2/2)=50M 次测试；BVH 平均只需 K≈4 次有效相交测试
- **根本原因**：空间排除法则——"如果两个组的包围体不相交，则组内所有图元对都不可能相交"
    
#### 碰撞检测的特殊考量

1. **成对碰撞枚举**：两个 BVH 的递归遍历可枚举所有相交的叶节点对
2. **运动连续性**：在物理步长内，对象可能"隧穿"穿过彼此。使用 **连续碰撞检测 (CCD)**​ 时，可将对象的运动轨迹包进一个扫掠包围体（swept volume）
3. **宽相位 + 窄相位的两层架构**：
    - BVH 负责 broad-phase：将候选对数从 O(N2) 降到 O(NlogN)
    - GJK、SAT 等精确算法负责 narrow-phase：对候选对做精确相交测试

## 三、章节脉络与全书连接

本章在全书中的枢纽地位：

```
第一章：四叉树/八叉树（空间栅格细分）
    ↓ 从"空间"转向"对象"
第二章：kd树/范围树（轴对齐查询索引）
    ↓ 融入"层次包围"思想
第三章：BSP 树（超平面分割）
    ↓ 放弃"平面分割空间"，改为"分组包围对象"
第四章：BVH
    ↓ 开启
现代：硬件光线追踪、动态物理引擎
```

**与前三章的核心区别**：

|维度|四叉树/八叉树|BSP 树|BVH|
|---|---|---|---|
|分割方式|空间栅格|超平面|**对象分组**​|
|节点含义|空间子区域|凸子空间|**图元集合的包围体**​|
|主要优势|层次细节|绘制顺序、CSG|**查询加速、动态更新**​|
|动态适应性|弱|弱|**强（refit + 旋转）**​|
|典型应用|LOD、体渲染|画家算法、CSG|**光线追踪、碰撞检测**​|

**贯穿始终的"Why"**：

1. **为什么需要 BVH？**​ 因为前三章的结构要么切割空间（与对象分布脱节），要么用平面分割（难以动态更新）。BVH 直接对对象分组，天然适应对象的动态运动和场景变化。
2. **为什么 AABB 是默认选择？**​ 因为单节点测试极廉价，让你可以访问更多节点，总体遍历时间反而最短。这是"用少量冗余访问换极低单节点成本"的典型权衡。
3. **为什么 SAH 是最优分割标准？**​ 因为它基于物理直觉——射线命中子节点的概率正比于其表面积占比。SAH 将"建树"转化为概率期望优化问题。
4. **为什么 BVH 适合动态场景？**​ 因为 refit 操作是自底向上的局部更新，O(n) 且可并行；树旋转在 refit 同一次遍历中恢复树质量；fat AABB 容忍小幅运动。这套组合拳使得 BVH 成为游戏物理和动画的标准加速结构。
5. **为什么现代硬件（RTX）选择 BVH？**​ 因为 BVH 的遍历模式规则、节点布局紧凑、AABB 测试可完全硬件化。RT Cores 专门加速 BVH 遍历和射线-三角形相交，使实时光线追踪成为可能。

## 四、实际应用的延展思考

**BVH 已经成为现代图形管线的基础设施**：

- **电影级渲染**：Arnold、Cycles、Corona 等所有主流 CPU 渲染器都基于 Embree 的 BVH
- **实时光线追踪**：DXR、Vulkan Ray Tracing、Metal Performance Shaders 都以 BVH 为核心抽象
- **游戏物理**：Bullet、Box2D、PhysX 的动态 AABB 树
- **科学计算**：分子动力学模拟中的邻近搜索，GPU 上使用 LBVH 实现百万级粒子的实时碰撞
- **机器人路径规划**：BVH 加速的距离场计算、碰撞约束求解
    
> 💡 **关键工程洞察**（来自生产环境实践）：
> 
> 1. **静态/动态分离**：静态 BLAS + 动态 BLAS + 每帧更新 TLAS，是处理混合场景的最优模式
> 2. **Refit 是廉价的修正**：但它只是治标，树旋转和局部重建才是治本，需要纳入持续的维护预算
> 3. **运动包络保证正确性**：使用 `max_displacement` 计算保守包围，避免重构延迟导致的闪烁
> 4. **GPU refit**：当可能时，在 GPU 上执行 refit 或使用 LBVH 风格的快速重建，隐藏延迟
>     
---

**全书逻辑主线回顾**：

```
空间细分（QTree/Octree）→ 查询索引（kd/Range Tree）→ 平面分割（BSP）→ 对象分组（BVH）
       ↓                      ↓                         ↓                    ↓
   固定栅格              轴对齐查询              任意方向分割            嵌套包围体
   适合 LOD              适合窗口查询            适合顺序与 CSG          适合动态加速
```

BVH 不是终点，而是**连接传统几何算法与现代 GPU 硬件桥梁**的关键一环。理解 BVH 的构造哲学、动态更新策略和查询加速原理，是理解现代实时渲染和物理仿真系统的必修课。
